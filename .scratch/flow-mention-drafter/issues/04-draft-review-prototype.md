## Question

멘션 하나에 대해 **요구·초안·근거**를 검토하고 게시하는 화면은 어떤 모습과 흐름이어야 하는가?

거친 프로토타입(프레임워크와 무관한 HTML 정도)을 만들고, 사용자가 직접 보며 아래를 정한다.

- **트레이 메뉴**: 대기 중인 멘션 목록을 트레이 메뉴에서 보여 줄지, 검토 창 안에서 보여 줄지.
- **멘션 하나에 보여 줄 정보**: 송신자, 원문, Flow 프로젝트, 선택된 저장소(자동으로 골랐다면 그 이유), 요구, 초안, 근거를 어떤 배치와 우선순위로 보여 줄지.
- **편집과 행동**: 초안을 고칠 수 있는 범위와, 다음 행동 각각의 위치.
  - 게시
  - 재생성
  - 저장소를 바꿔서 재생성
  - 무시
- **근거 표시**: 근거(파일과 코드 위치)를 어떻게 보여 주고, 클릭하면 무엇을 할지.
- **상태 표현**: 생성 중, 준비됨, 게시됨, 실패, 무시함 같은 상태를 어떻게 보여 줄지.
- **알림 없이 찾아오는 경로**: 미서명 앱에서는 OS 알림 클릭이 동작하지 않을 수 있다([미서명 앱 macOS 실기 검증](11-tauri-macos-unsigned-check.md) 결과로 확정된다). 그 경우 트레이 아이콘의 상태 표시(배지 등)만으로 새 초안을 알아채고 검토 화면까지 갈 수 있어야 한다.

화면 결정에는 `ui-design` 스킬을 함께 쓴다.

## 산출물

- 프로토타입 파일과, 사용자가 확정한 화면 결정을 이 티켓의 답에 링크한다.

## Answer

2026-10-14에 사용자가 [프로토타입](../prototypes/draft-review/index.html)의 변형 A·B·C를 비교한 뒤 조합을 골랐다. 고른 조합은 같은 파일의 **D 확정안**으로 그렸고, 파일을 열면 기본으로 뜬다.

- 실행: `open .scratch/flow-mention-drafter/prototypes/draft-review/index.html`. 변형은 `?variant=A|B|C|D`나 화면 아래 막대로 바꾼다.
- 데이터는 가짜이고, 게시와 에디터 열기는 흉내만 낸다. 구현에 재사용하지 않는다.
- 비교한 변형
  - A 메일함형: 트레이 클릭 → 목록+상세 창
  - B 트레이 메뉴 큐형: 트레이 메뉴에 멘션 목록, 멘션 하나만 담은 작은 창
  - C 대조 검증형: 원문·초안·근거를 세 열로 나란히 둠

### 화면 구조

- **트레이**: 트레이 아이콘을 누르면 창이 바로 열린다(A).
  - 트레이 메뉴에는 멘션 목록을 두지 않는다. OS 기본 메뉴는 항목마다 한 줄 텍스트만 넣을 수 있기 때문이다.
  - 오른쪽 클릭 메뉴에는 창 열기, 지금 확인, 설정, 종료만 둔다.
- **작은 창**: 트레이를 누르면 항상 작은 창이 트레이 가까이에 뜬다(B).
  - 멘션을 하나씩 본다. 위에서부터 원문 → 에이전트가 이해한 요구 → 초안 순서이고, 근거와 저장소는 접혀 있다.
  - 머리에 대기열 위치(`3 / 4`), ‹ › 이동, 상태 태그, "펼쳐 보기"가 있다.
- **펼친 창**: "펼쳐 보기"를 누르면 목록+상세 창으로 커진다(A). "접어 보기"로 돌아간다.
  - 목록은 검토 대기·생성 중·실패·처리됨으로 묶는다.
  - 상세는 원문 → 요구 → 저장소 → 초안 → 근거 순서다.
- **접기와 펼치기**: 원문, 요구, 초안, 근거, 저장소 영역은 모두 머리를 눌러 접고 펼 수 있다. 생성 중의 진행과 실패의 오류 영역도 마찬가지다.
  - 작은 창은 처음에 원문·요구·초안을 펼치고 근거·저장소를 접어 둔다. 펼친 창은 처음에 모두 펼쳐 둔다.
  - 펼침 상태는 작은 창과 펼친 창이 따로 기억하고, 다른 멘션으로 넘어가도 유지한다.
  - 초안의 근거 번호를 누르면 근거 영역이 펼쳐진다. 요구 영역이 접혀 있을 때 망치 아이콘을 누르면 요구 영역이 펼쳐진다.
- **원문**: 작은 창 맨 위에 멘션 원문을 둔다. 앞선 글(스레드)은 "스레드 보기"로 펼친다.
- **요구**: "에이전트가 이해한 요구"라는 제목을 따로 단다. "요구" 라벨이 본문에 붙어 있으면 무슨 영역인지 알기 어렵다는 피드백이 있었다.

### 편집과 행동

- **초안**: 자유롭게 고칠 수 있다. 편집하면 문장별 근거 번호가 사라지고 "원래 초안으로 되돌리기"가 생긴다.
- **요구 고치기**: 요구 제목 옆 망치 아이콘으로 요구를 고치고 "이 요구로 재생성"한다(C).
- **재생성 메뉴**: 다시 만들기 / 지시를 덧붙여 다시 만들기 / 다른 저장소로 다시 만들기(C). 편집한 초안이 있으면 버릴지 먼저 묻는다.
- **게시**: 누르면 5초 뒤에 게시되고, 그동안 토스트에서 취소할 수 있다. 확인 단계는 따로 두지 않는다.
- **다음 멘션**: 게시하거나 무시하면 바로 다음 준비된 멘션으로 넘어간다(B).
- **무시**: 토스트에서 되돌릴 수 있고, 처리됨 목록에서도 되돌릴 수 있다.
- **버튼 위치**: 바닥 줄 왼쪽에 무시, 오른쪽에 재생성 메뉴와 게시를 둔다. "Flow에서 열기"는 상세 머리에 둔다.

### 근거 표시

- 근거를 소스 코드로 보여 주지 않는다. 근거마다 **자연어 설명**을 쓰고, 그 아래에 파일 이름과 줄 위치를 작게 붙인다.
  - 예: "실제 서비스용 설정에서 재시도 횟수를 5번으로 정해 두었다. 그래서 실제 서비스에서는 3번 대신 5번이 쓰인다." / `application-prod.yml · 88번째 줄`
- 위치 옆의 "에디터에서 열기"를 누르면 에디터에서 그 줄을 연다.
- 초안 문장마다 근거 번호(①②)를 붙인다(C). 번호를 누르면 해당 근거를 펼쳐 강조한다.
- 근거가 없는 문장에는 "근거 없음"을 표시해서, 에이전트가 근거 없이 쓴 문장을 검토자가 알아보게 한다.

### 초안 문체

프로토타입을 검토하던 중에 사용자가 정했다. 초안에 개발자 용어가 너무 많다는 피드백이 있었다.

- 초안은 개발자가 아닌 동료도 이해할 수 있는 쉬운 말로 쓴다.
- 코드 이름, 파일 이름, 설정 키, 기술 약어를 쓰지 않는다. 필요한 개념은 풀어 쓴다.
  - 예: "운영 프로필에서 `settlement.retry.max-attempts`를 5로 덮어쓰고 있습니다" → "실제 서비스용 설정에서 이 값을 5번으로 바꿔 두었습니다"
- 송신자가 질문에 직접 쓴 용어(예: 409, API)는 그대로 쓰되, 뜻을 짧게 덧붙인다.
- 근거의 자연어 설명도 같은 기준을 따른다. 파일 이름과 줄 위치는 검토자가 확인하는 용도로만 근거 아래에 둔다.

### 상태 표현

- 상태는 생성 중, 준비됨, 게시 중(5초 카운트다운), 게시됨, 실패, 무시함이다.
- 작은 창은 머리의 상태 태그와 대기열 위치로 보여 준다(B). 펼친 창은 목록의 상태별 묶음으로 보여 준다.
- 생성 중에는 에이전트 진행 단계를 보여 주고 취소할 수 있다.
- 실패하면 오류와 마지막 단계를 보여 주고, 다시 시도와 무시를 둔다.

### 알림 없이 찾아오는 경로

트레이 아이콘이 기본 경로다. OS 알림은 실패해도 되는 보조 수단으로 둔다. 아이콘을 한 번 누르면 작은 창이 열리므로, 알림 클릭이 동작하지 않아도 검토 화면에 닿는다.

- macOS: 아이콘 옆에 검토 대기 수를 숫자로 표시한다.
- Windows: 아이콘 이미지에 숫자 배지를 그려 넣는다. 작업 표시줄 트레이 아이콘에는 글자를 붙일 수 없다.
- 실패한 멘션이 있으면 빨간 점, 생성 중이면 아이콘 안에 점 세 개를 넣는다.

  - 요구(한 문장)와, 목록 행에 보일 짧은 요약
  - 문장 단위로 나눈 초안과, 문장마다 근거 번호 목록(근거가 없으면 빈 목록)
  - 근거마다 자연어 설명, 파일 경로, 줄 범위
  - 저장소를 자동으로 골랐다면 그 이유(자연어)
  - 재생성 입력으로 사용자가 덧붙인 지시와 사용자가 고친 요구

  - 멘션마다 에이전트를 바꿔 다시 만들 수 있게 하기로 하면, 재생성 메뉴에 항목을 더한다.
