# 저장소 매핑과 자동 선택 규칙 결정

Map: [Flow 멘션 답변 초안 앱](../map.md)
Type: grilling
Mode: HITL
Status: resolved
Blocked by: 02

## Question

멘션에 맞는 저장소를 **어떤 규칙으로 정할지** 결정한다. 직접 등록한 저장소 매핑이 우선이고, 매핑이 없으면 에이전트가 작업 폴더에서 고른다는 전제는 이미 정해져 있다.

- **매핑 단위**: Flow 프로젝트 하나에 저장소를 몇 개까지 연결할지, 여러 개일 때 에이전트에게 어떻게 넘길지 정한다.
- **자동 선택의 위치**: 초안을 만드는 실행 안에서 저장소를 함께 고를지, 저장소를 고르는 실행을 따로 둘지 정한다. [CLI 에이전트 비대화형 실행 능력 조사](02-cli-agent-headless-research.md)의 디렉터리 지정 능력을 근거로 판단한다.
- **확신이 낮을 때**: 에이전트가 저장소를 확신하지 못하거나 고르지 못하면 어떻게 할지 정한다.
- **선택 결과의 재사용**: 자동으로 고른 결과를 저장소 매핑으로 저장할지, 저장한다면 사용자 확인을 거칠지 정한다.
- **작업 폴더 개수**: 작업 폴더를 여러 개 둘 수 있게 할지 정한다. Mac과 Windows를 함께 쓰는 경우의 경로 처리도 포함한다.

## Answer

2026-10-14에 사용자와 grilling으로 정했다. 이 문서에서 저장소를 고르는 실행은 **선택 실행**, 초안을 쓰는 실행은 **초안 실행**이라고 부른다.

### 저장소 매핑

- **매핑 단위**: Flow 프로젝트 하나에 저장소를 개수 제한 없이 여러 개 연결할 수 있다. 매핑의 키는 알림의 `projectId`다.
- **여러 저장소 넘기기**: 연결된 저장소를 모두 읽기 범위로 넘긴다.
  - Claude는 첫 저장소를 cwd로 두고, 나머지를 `--add-dir`로 붙인다.
  - Codex는 `-C`로 첫 저장소를 준다. read-only가 읽기 범위를 좁히지 않으므로, 나머지 경로는 프롬프트로 알린다.
- **매핑을 만드는 곳**: 두 곳이다. 매핑은 필수가 아니다.
  - 설정 화면: 저장소 매핑 목록에서 추가·수정·삭제한다. Flow 프로젝트는 참여 Flow 프로젝트 목록에서 고르고, 저장소는 폴더 선택 창으로 고른다.
    - 참여 Flow 프로젝트 목록은 개인 키 `GET /user/projects/participants`로 가져온다. 응답은 `projectId`, `title`, `projectUrl`이다.
    - 단건 이름은 `GET /user/projects/{projectId}`의 `PROJECT_SETTING[0].TTL`에 있다.
    - 둘 다 공개 문서와 JS 번들로 확인했고, 실제로 호출하지는 않았다.
  - 검토 화면: 저장소 영역의 "이 Flow 프로젝트에 연결" 버튼이다(아래 "선택 결과의 재사용").
  - 작업 폴더만 있어도 자동 선택으로 동작한다. 작업 폴더도 매핑도 없는 멘션은 저장소 확인 필요 상태로 올린다.
- **매핑된 폴더가 사라졌을 때**: 매핑된 저장소 중 하나라도 없으면 자동 선택으로 넘어가지 않는다. 초안을 만들지 않고 저장소 확인 필요 상태로 올리며, 사유는 "연결된 저장소 폴더를 찾을 수 없음"이다.

### 자동 선택

- **실행 분리**: 매핑이 없으면 선택 실행을 먼저 돌리고, 결과로 정해진 저장소에서 초안 실행을 돌린다.
  - 그래서 초안 실행은 매핑이 있을 때와 같은 형태이고, 항상 저장소가 1개 이상 정해진 뒤에만 돈다.
  - 대가로 에이전트를 두 번 호출하므로, 초안이 나오기까지 더 오래 걸린다.
- **후보 목록**: 앱이 작업 폴더에서 후보를 찾는다.
  - 최대 3단계 깊이에서 `.git`이 있는 디렉터리를 찾는다. worktree의 `.git` 파일도 센다.
  - 저장소 안으로는 더 내려가지 않고, 숨김 폴더와 `node_modules`는 건너뛴다.
  - git 저장소가 아닌 코드 폴더는 후보가 아니다. 매핑에는 직접 넣을 수 있다.
  - 후보가 1개면 선택 실행을 건너뛰고 그 저장소를 쓴다. 후보가 0개면 저장소 확인 필요 상태로 올린다.
- **선택 실행의 입력**: 초안 실행과 같은 맥락(멘션 원문, 게시물 제목·본문, 댓글 스레드)에 Flow 프로젝트 이름과 후보 목록을 더한다.
- **선택 실행의 출력**: 판정, 고른 저장소, 이유(자연어)다.
  - 고른 저장소는 출력 스키마의 `enum`으로 후보 목록 안의 값만 받는다.
  - 판정은 세 가지다.
    - 고름: 저장소를 1~3개 고른다. 확신이 낮다고 후보를 모두 넣지 않도록 지침에 적는다.
    - 확신 못함: 후보가 여럿이라 고르지 못했거나, 맞는 저장소가 없는 경우다.
    - 코드와 무관: "내일 회의 가능하세요?"처럼 저장소를 읽을 필요가 없는 멘션이다.
- **고름이 아닐 때**: 초안을 만들지 않고, 검토 화면에 새 상태 **저장소 확인 필요**로 올린다.
  - 에이전트가 쓴 사유와, 후보가 있으면 그 후보를 보여 준다.
  - 행동은 저장소를 골라 만들기, Flow에서 열기, 무시 세 가지다.
  - 트레이 숫자에서는 검토 대기로 센다. OS 알림도 초안이 준비됐을 때처럼 띄운다.

### 선택 결과의 재사용

- 자동으로 고른 결과를 매핑으로 자동 저장하지 않는다. 한 번 잘못 고른 결과가 그 Flow 프로젝트의 이후 멘션에 계속 쓰이는 것을 막기 위해서다.
- 검토 화면의 저장소 영역에 "이 Flow 프로젝트에 연결" 버튼을 둔다. 사용자가 누를 때만 매핑에 저장한다.
  - 버튼은 기존 매핑에 더하지 않고, 지금 구성으로 **덮어쓴다**. 매핑이 이미 있으면 버튼 문구는 "매핑을 이 구성으로 바꾸기"다.
  - 게시할 때 "앞으로도 이 저장소로?"라고 묻는 대화상자는 두지 않는다. 게시는 확인 단계 없이 5초 취소로 정했다.
- **저장소 선택 창**: "다른 저장소로 다시 만들기"와 "저장소를 골라 만들기"가 같은 창을 쓴다.
  - 여러 개를 고를 수 있고, 처음에는 지금 쓰는 저장소들이 체크되어 있다.
  - 후보로 작업 폴더에서 찾은 저장소와 다른 매핑에 쓰인 저장소를 보여 주고, "폴더 직접 고르기"도 둔다.
  - 이 창에서 고른 구성에도 연결 버튼을 둔다.

### 작업 폴더와 경로

- 작업 폴더는 여러 개 둘 수 있다. 선택 실행은 첫 작업 폴더를 cwd로 두고, 나머지를 `--add-dir`로 붙인다(Claude 기준).
- 설정과 매핑은 PC마다 따로 둔다. 매핑은 "Flow 프로젝트 ID → 그 PC의 절대 경로"라서 PC끼리 공유할 수 없다. MVP에는 동기화와 내보내기가 없다.
- 경로는 OS 고유 형식의 절대 경로로 저장한다.
- 네트워크 경로(`\\server\share`)와 Windows의 WSL 경로(`\\wsl.localhost\...`)는 MVP에서 받지 않는다. Claude가 이런 경로를 작업 디렉터리로 추가할 수 없기 때문이다. Windows 팀원에게는 제약이 될 수 있다.

### 다른 곳에 넘기는 것

- [에이전트 실행 계약 결정](07-agent-run-contract.md)
  - 선택 실행도 실행 계약에 들어간다. 스키마, 읽기 전용·비밀 파일 제외, 실행 제어를 초안 실행과 함께 정한다. Codex는 `--skip-git-repo-check`가 필요하다.
  - 초안 실행이 저장소를 여러 개 받으므로, 근거마다 어느 저장소의 파일인지 표시해야 한다.
  - "저장소를 자동으로 골랐다면 그 이유"는 초안 실행이 아니라 선택 실행이 출력한다.
  - 매핑이 있는데 멘션이 코드와 무관할 때, 초안 실행이 무엇을 출력할지 정한다.
- 스펙: 검토 화면의 상태 목록(생성 중, 준비됨, 게시 중, 게시됨, 실패, 무시함)에 저장소 확인 필요를 더한다. 프로토타입은 고치지 않는다.
- 지도의 Not yet specified: 같은 계정으로 여러 PC에서 앱을 동시에 켰을 때 생기는 문제를 적었다.
- ADR은 만들지 않았다. 선택 실행 분리는 나중에 되돌리는 비용이 크지 않다.
