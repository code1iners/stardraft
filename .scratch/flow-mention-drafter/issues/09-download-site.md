## Question

dmg와 exe를 내려받는 **다운로드 사이트**를 어떤 형태로 만들지 정한다.

- **호스팅 위치**: GitHub Releases와 Pages, 사내 서버, 정적 호스팅 서비스 중 어디에 둘지.
- **공개 범위**: 사내 팀원에게만 열지, 공개할지. 사내 한정이라면 접근을 어떻게 막을지.
- **설치 안내**: 미서명 앱이라 설치할 때 뜨는 경고를 넘어가는 방법을 OS별로 어떻게 안내할지. 문구는 [트레이 데스크톱 앱 프레임워크와 미서명 배포 조사](03-tray-app-framework-research.md)를 근거로 한다.
  - [서명 정책 재검토](10-signing-policy-review.md)에서 정한 제약
    - Windows 안내의 첫 단계에서 스마트 앱 컨트롤 상태를 확인하게 한다. 켜져 있으면 "이 PC에서는 아직 실행되지 않으니 배포 담당자에게 알려 달라"고 안내한다.
    - SAC를 끄라는 안내는 하지 않는다. 조사 문서 안내문 초안의 "관리자에게 문의"는 회사 관리 PC가 없다는 전제와 맞지 않으므로 바꾼다.
    - 새 버전을 설치하면 다시 확인을 받는다는 점을 안내한다. Windows는 SmartScreen 경고, macOS는 Keychain 재허용과 알림 권한이 해당한다.
- **버전 관리**: 버전을 어떻게 표시할지, 이전 버전도 내려받을 수 있게 할지.
- **산출물 연결**: [데스크톱 프레임워크와 기술 스택 결정](08-desktop-stack.md)에서 정한 빌드 산출물이 사이트에 반영되는 경로.

화면 결정에는 `ui-design` 스킬을 함께 쓴다.
