## Question

초안이 준비된 **뒤에** 멘션 묶음이 있는 자리가 바뀌면 앱이 어떻게 할지 정한다. 여기서 "준비된 뒤"는 준비됨 상태와 게시 중 상태(5초 카운트다운)를 말한다. 아울러 에이전트에게 넘기는 스레드 맥락의 길이 상한을 정한다.

[멘션 감지 방식 결정](05-mention-detection.md)에서 이미 정한 것은 다시 다루지 않는다.

- 같은 묶음에 새 멘션이 오면 묶음 상태에 따라 합치거나 새 묶음을 만든다(05의 표).
- 생성을 시작하기 직전에 Flow에서 직접 답했는지 확인한다.
- 맥락은 초안을 만들 때마다 새로 조회한다.

정할 것은 다음과 같다.

- **멘션이 아닌 새 글**: 대상 자리에 멘션이 아닌 댓글이나 대댓글이 새로 달리면, 검토 화면에서 알릴지, 초안을 다시 만들지 정한다.
- **준비된 뒤의 직접 답**: 초안이 준비된 뒤에 Flow에서 내가 직접 답한 경우를 어떻게 처리할지 정한다. 다른 PC에서 앱으로 게시한 경우도 Flow에서는 내 글로 보인다.
- **원문의 수정과 삭제**: 멘션된 글이 수정되거나 삭제된 경우를 어떻게 처리할지 정한다. 수정되어 내 표기가 빠진 경우도 포함한다.
  - 대댓글을 달 부모 댓글이 지워지면 게시가 실패할 수 있다. 게시 위치는 [초안 게시 위치와 형식 결정](12-post-placement.md)을 따른다.
- **변화를 알아내는 시점**: 아래 중 언제 다시 조회할지 정한다. 조회 한도(분당 1,000회)와 게시 취소 시간(5초)을 함께 고려한다.
  - 폴링 주기(60초)마다 준비된 묶음의 스레드를 다시 조회한다.
  - 검토 화면에서 그 묶음을 열 때 조회한다.
  - 게시 직전에만 조회한다.
- **스레드 맥락 길이 상한**: 05에서는 맥락 범위를 대상 댓글 스레드 전체와 다른 댓글 최근 20개로 정했다. 이 맥락이 너무 길 때의 총 길이 상한과, 넘치면 무엇부터 뺄지 정한다.
  - [에이전트 실행 계약 결정](07-agent-run-contract.md)은 이 상한을 정하지 않고 닫혔다.
  - 초안 실행의 제한 시간은 10분이다.

## Comments

### 2026-10-15, [초안 게시 위치와 형식 결정](12-post-placement.md)에서 넘어온 것

12가 해결되었다. 이 티켓을 다른 세션이 맡고 있어서 질문 본문은 고치지 않고 여기에 남긴다. 자세한 내용은 12의 답에 있다.

- **게시 실패 처리는 12에서 정했다.**
  - 새 상태 "게시 실패"를 두고, 응답별 사유를 보여 준다. 예를 들어 `404`와 `412`의 사유는 "글이나 댓글이 지워졌습니다"다.
  - 그래서 이 티켓의 "원문의 수정과 삭제"에서는 부모 댓글이 지워진 것을 **게시 전에** 알아챌지만 정하면 된다.
  - 지워진 부모 댓글에 대댓글을 달 때의 실제 응답 코드는 [댓글 쓰기 API 실측](15-comment-write-api-check.md)에서 확인한다.
- **받는 사람이 새로 생겼다.** 게시 본문 앞에서 다시 멘션하는 Flow 구성원이고, 기본값은 묶음에 남은 멘션의 송신자 전원이다. 검토 화면에서 ×로 뺄 수 있다. 준비된 뒤의 변화와 관련해 정할 것이 두 가지 생겼다.
  - 준비된 묶음에 새 멘션이 합쳐지면 새 송신자를 받는 사람에 더할지 정한다.
  - 사용자가 받는 사람에서 누군가를 뺀 것을 05 표의 "사용자가 손댐"으로 볼지 정한다.
- **게시하면 앱이 `commentId` 또는 `replyId`를 기록한다.** "준비된 뒤의 직접 답"을 판정할 때 앱이 올린 글을 구분하는 데 쓸 수 있다.
