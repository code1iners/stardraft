## Question

[초안 게시 위치와 형식 결정](12-post-placement.md)은 쓰기 API에 대한 몇 가지 사실을 모른 채 조건부 규칙으로 닫혔다. 개인 API 키로 시험 게시를 해서 아래를 확인한다. 결과별로 적용할 규칙은 12의 답 "실측 결과에 따른 규칙"에 있다.

1. `contents`에 넣은 `@[이름](ID)` 표기가 실제 멘션으로 처리되는가?
   - Flow 화면에서 멘션으로 보이는가?
   - (구현 후로 넘김) 받는 사람에게 멘션 알림이 가는가?
   - 화면 표시는 나 자신을 멘션해서 혼자 확인할 수 있다. 알림이 가는지는 다른 사람만 확인할 수 있다.
   - 2026-10-15에 사용자가 동료 없이 혼자 실측하고, 알림은 구현한 앱으로 실제 멘션에 답할 때 확인하기로 했다.
2. 줄바꿈(`\n`)과 빈 줄(`\n\n`)이 Flow 화면에 그대로 보이는가? 웹과 데스크톱 앱에서 본다.
3. `contents` 최대 4,000의 단위는 글자인가, 바이트인가?
   - 한글은 UTF-8로 한 글자에 3바이트다. 그래서 한글로 경계를 시험하면 두 단위를 가를 수 있다.
4. 지워진 부모 댓글에 대댓글을 달면 어떤 응답 코드와 본문이 오는가?

문서로 확인한 쓰기 API의 사실은 [flow-api-facts.md](../research/flow-api-facts.md)의 "쓰기" 절에 있다.

## 체크리스트

- 시험은 개인 시험용 Flow 프로젝트에서 한다. 실제 업무 프로젝트에는 시험 글을 남기지 않는다.
- 키는 [Flow 알림 API 실호출로 멘션 데이터 확인](01-flow-alarm-api-check.md)과 같이 터미널 환경변수나 스크립트의 숨김 입력으로만 다룬다. 파일, 채팅, 티켓에는 남기지 않는다.
- REST에는 댓글 삭제 API가 없다.
  - 시험 글은 Flow 화면에서 지우거나, 시험이 끝난 뒤 시험 프로젝트를 지운다.
  - 4번은 시험 댓글 하나를 Flow 화면에서 지운 뒤, 그 댓글에 대댓글 API를 호출한다.
- 쓰기 API 한도는 분당 120회다. 시험 게시는 몇 건이면 충분하다.

### 질문 1. `@[이름](ID)` 표기가 실제 멘션이 되는가? — 화면에서는 예. 알림은 구현 후 확인한다

- **화면**: 나를 멘션한 새 댓글(T1A)과 대댓글(T1B) 모두 Flow 화면에서 멘션으로 보였다(사용자 관찰).
- **저장 형태**: 보낸 문자열이 그대로 저장됐다. 서버가 표기를 바꾸거나 지우지 않는다.

  ```json
  {"case": "T1A", "status": 200, "stored": "@[나](me@masked) PROBE-T1A-1718 나를 멘션한 새 댓글입니다.", "equalsSent": true}
  ```

  - 사용자가 Flow 화면에서 나를 멘션해 쓴 댓글도 `@[나](me@masked) \n…` 같은 형식으로 저장되어 있었다. 화면에서 만든 멘션과 API로 만든 멘션은 저장 형식이 같다.
- **내 알림**: T1A를 올린 뒤 내 멘션 알림을 조회했지만, T1A에 대한 알림은 없었다. 내가 쓴 글에서 나를 멘션해도 내 알림은 생기지 않는 것으로 보인다.
- **받는 사람의 알림**: 확인하지 않았다. 다른 사람만 확인할 수 있어서, 사용자가 구현한 앱으로 실제 멘션에 답할 때 확인하기로 했다.
- **적용**: [초안 게시 위치와 형식 결정](12-post-placement.md)의 받는 사람 줄과 게시 본문 형식을 그대로 둔다. 구현 후 받는 사람에게 알림이 가지 않는다고 확인되면, 12의 "실측 결과에 따른 규칙"대로 받는 사람 줄을 숨긴다.

### 질문 2. 줄바꿈과 빈 줄이 그대로 보이는가? — 예

- **화면**: 새 댓글(T2)과 대댓글(T2R) 모두에서 줄바꿈과 빈 줄이 그대로 보였다(사용자 관찰). 웹과 데스크톱 앱을 나눠서 보고하지는 않았다.
- **저장 형태**: 보낸 문자열이 그대로 저장됐다. `\n`이 `<br>` 등으로 바뀌지 않았다.

  ```json
  {"case": "T2", "status": 200, "newlinesSentStored": [6, 6], "equalsSent": true,
   "stored": "PROBE-T2-1718 줄바꿈 시험\n첫째 문단 첫 문장입니다. 첫째 문단 둘째 문장입니다.\n\n둘째 문단입니다. …"}
  ```

- **적용**: 12대로 문단 사이에 빈 줄 하나(`\n\n`)를 둔다.
- **확인하지 않은 것**: T2 마지막 줄의 `<b>`, `**`, 백틱은 그대로 저장됐다. 화면에서 글자 그대로 보이는지는 따로 보고받지 않았다.

### 질문 3. `contents` 최대 4,000의 단위는? — 글자

- 한글 4,000자(11,972바이트)는 `200`으로 받았다. 다시 조회한 `contents`도 4,000자라서, 잘리지 않고 저장됐다.
- 한글 4,001자는 `400`으로 거절됐다.

  ```json
  {"success": false, "code": 400, "message": "error",
   "error": {"code": "VALIDATION_ERROR", "message": "내용 최대 길이는 4000 입니다.",
             "verbose": [{"code": "too_big", "maximum": 4000, "type": "string", "inclusive": true,
                          "path": ["body", "contents"]}]}}
  ```

- **적용**: 게시 버튼을 끄는 기준과 글자 수 표시를 글자 수로 센다. 받는 사람 표기를 포함한 게시 본문 전체의 길이다.
- **세는 방법(추정)**: `verbose`의 모양이 JavaScript 검증 라이브러리 zod의 오류 형식과 같다. zod는 문자열 길이를 JavaScript `String.length`(UTF-16 코드 단위)로 잰다. 그래서 앱도 `String.length`로 센다.
  - 한글은 어느 방식으로 세도 한 글자가 1이다. 이모지처럼 두 단위를 쓰는 글자만 2로 세진다.
  - 서버가 실제로 다르게 세더라도 `String.length`는 코드 포인트 수보다 작지 않으므로, 앱이 허용한 글이 서버에서 길이로 거절되지는 않는다.
- 길이 초과는 `422`가 아니라 `400`으로 왔다. 12의 응답별 처리 표에서 `400`, `422`를 같은 사유로 묶어 두었으므로 고칠 것이 없다.

### 질문 4. 지워진 부모 댓글에 대댓글을 달면? — `412` `NOT_EXISTS_ERROR`

대댓글이 없던 댓글(T4A)과 대댓글이 달려 있던 댓글(T4B) 모두 같은 응답이 왔다.

```json
{"success": false, "code": 412, "message": "DetailedError",
 "error": {"code": "NOT_EXISTS_ERROR", "message": "댓글이 존재하지 않습니다."}}
```

- **Flow 화면의 삭제**: 대댓글이 있든 없든 확인 대화상자가 뜨고, 확인을 누르면 지워진다(사용자 관찰). 대댓글이 있다고 삭제를 막지 않는다.
- **지운 뒤의 조회**
  - 댓글 목록(`replyYn=Y`)에서 지운 댓글이 빠진다. T4B에 미리 달아 둔 대댓글(T4BR)도 함께 빠졌다. 지워진 표시를 단 항목으로 남지 않는다.
  - 지운 댓글의 대댓글 목록(`GET /user/comments/{postId}/replies/{commentId}`)은 `404`가 아니라 위와 같은 `412` `NOT_EXISTS_ERROR`를 준다.
  - 게시물 상세의 `remarks`에도 지운 댓글이 없었다.
- **적용**
  - 12의 응답별 처리 표대로 `412`는 게시 실패이고, 사유는 "글이나 댓글이 지워졌습니다"다. 고칠 것이 없다.
  - [게시 전 스레드 변화 처리 결정](14-thread-change-before-post.md)은 지워진 글을 "목록에 없거나 `404`"로 판정한다. 대댓글 목록 API가 주는 `412`도 지워진 것으로 봐야 한다. 14의 Comments에 남겼다.

### 함께 알게 된 사실

- **댓글 목록에 시스템 댓글이 섞인다.** 시험 게시물의 댓글 목록에 사람이 쓰지 않은 글이 세 개 있었다.

  | `systemCode` | `contents` (가린 것 포함) |
  | :- | :- |
  | `S38^^test^^PROBE-SETUP@$%` | `제목을 'test'에서 'PROBE-SETUP'으로 변경하였습니다.` |
  | `S45_2^^대기^^진행` | `가가가 '가가'가가 '가가'가가 가가가가가가가.` (업무 상태 변경으로 보인다) |
  | `S41^^'나'` | `가가가가 '가'가가가가가가가.` |

  - 사람이 쓴 댓글은 `systemCode`가 빈 문자열이었다.
  - 시스템 댓글의 `registerId`는 그 행동을 한 사람이다. 여기서는 나였다.
  - 그래서 `systemCode`를 보지 않으면, 내가 제목이나 업무 상태를 바꾼 것이 "내 답"으로 잡힌다. 14의 "이미 답함" 판정과 맥락 구성에 영향이 있어 14의 Comments에 남겼다.
- **`GET /user/employees/me`와 `GET /user/search/posts`가 개인 키로 동작했다.** 제목을 바꾼 지 몇 분 안에 검색으로 시험 게시물을 찾았다. 문서 사실은 [flow-api-facts.md](../research/flow-api-facts.md)에 있다.
- **호출 한도**: 쓰기 11건과 조회 10건을 호출했고 `429`는 없었다. 쓰기는 17:20:08~17:20:53 사이에 몰려 있었다.

### 정리

- 시험 게시물에 남은 시험 글을 Flow 화면에서 지운다. REST로는 지울 수 없다.
  - `PROBE-T1A-1718` 댓글과 그 대댓글 `PROBE-T1B-1718`

  - `PROBE-T3-1718`로 시작하는 4,000자 댓글
  - T4A와 T4B는 실측 중에 지웠다.
- 시험 게시물의 제목을 원래대로(`test`) 되돌릴지 정한다.
