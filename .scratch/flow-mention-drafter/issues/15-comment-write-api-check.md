## Question

[초안 게시 위치와 형식 결정](12-post-placement.md)은 쓰기 API에 대한 몇 가지 사실을 모른 채 조건부 규칙으로 닫혔다. 개인 API 키로 시험 게시를 해서 아래를 확인한다. 결과별로 적용할 규칙은 12의 답 "실측 결과에 따른 규칙"에 있다.

1. `contents`에 넣은 `@[이름](ID)` 표기가 실제 멘션으로 처리되는가?
   - Flow 화면에서 멘션으로 보이는가?
   - 받는 사람에게 멘션 알림이 가는가?
   - 화면 표시는 나 자신을 멘션해서 혼자 확인할 수 있다. 알림이 가는지는 다른 사람만 확인할 수 있다.
2. 줄바꿈(`\n`)과 빈 줄(`\n\n`)이 Flow 화면에 그대로 보이는가? 웹과 데스크톱 앱에서 본다.
3. `contents` 최대 4,000의 단위는 글자인가, 바이트인가?
   - 한글은 UTF-8로 한 글자에 3바이트다. 그래서 한글로 경계를 시험하면 두 단위를 가를 수 있다.
4. 지워진 부모 댓글에 대댓글을 달면 어떤 응답 코드와 본문이 오는가?

문서로 확인한 쓰기 API의 사실은 [flow-api-facts.md](../research/flow-api-facts.md)의 "쓰기" 절에 있다.

## 체크리스트

- 시험은 개인 시험용 Flow 프로젝트에서 한다. 실제 업무 프로젝트에는 시험 글을 남기지 않는다.
  - 1번의 알림 확인을 위해 협조해 줄 동료 한 명을 이 프로젝트에 초대한다.
- 키는 [Flow 알림 API 실호출로 멘션 데이터 확인](01-flow-alarm-api-check.md)과 같이 터미널 환경변수나 스크립트의 숨김 입력으로만 다룬다. 파일, 채팅, 티켓에는 남기지 않는다.
- REST에는 댓글 삭제 API가 없다.
  - 시험 글은 Flow 화면에서 지우거나, 시험이 끝난 뒤 시험 프로젝트를 지운다.
  - 4번은 시험 댓글 하나를 Flow 화면에서 지운 뒤, 그 댓글에 대댓글 API를 호출한다.
- 쓰기 API 한도는 분당 120회다. 시험 게시는 몇 건이면 충분하다.

### 실행 순서

1. **시험 환경 준비** (Flow 화면)
   - 개인 시험용 Flow 프로젝트를 만들고, 협조할 동료 한 명을 초대한다.
   - 그 프로젝트에 내가 시험 게시물을 하나 쓴다. 제목과 본문은 아무 내용이나 된다.
   - 동료에게 그 게시물에 댓글 하나를 부탁한다. 댓글에는 `PROBE-SETUP` 글자와 나를 지목한 멘션을 넣는다.
     - 스크립트는 이 댓글이 만든 내 알림으로 시험 게시물을 찾고, 동료의 이름과 ID를 가져온다.
     - 이 댓글은 Flow 화면에서 만든 멘션이다. 그래서 API로 만든 멘션과 화면·저장 형태를 비교하는 기준이 된다.
2. **[점검 스크립트](../research/flow-comment-write-probe.py) 실행** (저장소 루트)

   ```bash
   python3 -I .scratch/flow-mention-drafter/research/flow-comment-write-probe.py
   ```

   - 키는 화면에 보이지 않는 입력으로 받는다.
   - 시험 게시물의 제목·링크와 나·동료를 보여 준다. `yes`를 입력해야 글을 올린다.
   - 알림 목록에서 `PROBE-SETUP` 댓글을 찾지 못하면 postId를 묻는다. `FLOW_PROBE_POST_ID` 환경변수로 넘길 수도 있다.
   - 쓰기 요청은 거절될 것으로 보는 요청을 포함해 13~15건이다. 모든 글에 `PROBE-<시험>-<HHMM>` 표지를 단다.

     | 질문 | 글 |
     | :- | :- |
     | 1 | T1A: 동료와 나를 멘션한 새 댓글(12의 게시 본문 형식). T1B: 멘션 없는 대조용 새 댓글. T1C·T1D: T1B에 단 멘션 대댓글과 대조용 대댓글 |
     | 2 | T2: 줄바꿈·빈 줄 시험 댓글. T2R: 그 대댓글. T2의 마지막 줄은 Flow가 HTML·마크다운으로 해석하는지 덤으로 본다 |
     | 4 | T4A: 지울 댓글. T4B: 지울 댓글과 미리 단 대댓글 T4BR |
     | 3 | 4,001자와 4,000자 한글 댓글. 4,000자가 거절되면 4,000바이트 안팎의 댓글 둘을 더 올린다 |

3. **중간 확인** (스크립트가 멈추면)
   - Flow 웹에서 T4A와 T4B 댓글을 지운다. 대댓글이 달린 T4B를 지울 때 Flow가 무엇을 보여 주는지 기억해 둔다.
   - 동료에게 T1A~T1D 중 어떤 글이 알림으로 왔고 알림 문구가 무엇인지 묻는다. T1A·T1C가 멘션이고 T1B·T1D는 대조용이다.
   - Enter를 누르면 스크립트가 지운 댓글에 대댓글을 달고, 길이 시험을 한다.
4. **화면 확인**: 스크립트가 끝에 출력하는 네 가지를 웹과 데스크톱 앱에서 본다.
5. **결과 파일 확인**: [flow-comment-write-probe-result.json](../research/flow-comment-write-probe-result.json)을 훑어 가려지지 않은 이름이나 ID가 없는지 본다.
   - 나와 동료는 `나`·`동료`·`me@masked`·`peer@masked`로 바뀐다.
   - PROBE 표지가 없는 글은 글자를 가린다.
   - 알림 목록과 게시물 상세의 원문은 남기지 않는다.
6. 에이전트에게 화면 관찰과 동료의 알림 답을 알린다. 에이전트가 결과 파일과 관찰로 `## Answer`를 쓴다.
7. **정리**: 확인이 끝나면 시험 댓글을 Flow 화면에서 지우거나 시험 프로젝트를 지운다.

## 완료 조건

1~4번 각각에 결과와, 근거가 되는 응답 예시나 화면 관찰이 기록되어 있다.
