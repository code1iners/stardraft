## Question

Stardraft를 처음 켰을 때 감지를 시작하기까지의 **순서와 화면**을 정한다. 설정 화면의 구성과, 설정이 바뀔 때의 처리도 함께 정한다. 화면 결정에는 `ui-design` 스킬을 쓰고, 필요하면 `prototype`으로 화면을 그려 본다.

정할 것:

- **개인 API 키**
  - 키를 입력받은 직후 `GET /user/employees/me`로 내 ID와 이름을 확인하는 단계를 어떻게 보여 줄지. 이 API가 개인 키로 동작한다는 것은 [댓글 쓰기 API 실측](15-comment-write-api-check.md)에서 확인했다.
  - 키를 다시 입력하는 경로. "키 확인 필요"가 뜨는 경우는 두 가지다.
    - 폴링에서 `401`이 온 경우
    - `safeStorage` 복호화에 실패한 경우. 키체인 허락을 거부했거나, 키체인 항목이 지워졌을 때다.
  - 다른 계정의 키로 바꿀 때 기준점과 처리 상태를 어떻게 초기화할지. 상태는 `state.db`, 설정은 `settings.json`으로 나뉘어 있으므로 상태만 비울 수 있다.
  - 키체인 재허용 대화상자를 미리 설명하는 방법. [서명 정책 재검토](10-signing-policy-review.md)에서 미서명 앱은 업데이트할 때마다 키체인 접근 허용을 다시 물을 수 있고, 이것은 감수하기로 했다. 대화상자에는 항목 이름 `Stardraft Safe Storage`가 나온다.
- **작업 폴더**: 지정하는 순서와 화면. 여러 개를 둘 수 있고, 네트워크·WSL 경로는 받지 않는다([저장소 매핑과 자동 선택 규칙 결정](06-repo-mapping.md)).
- **에이전트**
  - **CLI 경로 찾기**: GUI 앱은 셸의 PATH를 물려받지 못한다. Electron에는 공식 보정 도구가 없다. 그래서 두 방법 중에서 정한다.
    - 로그인 셸에서 PATH를 한 번 읽어 오기(`$SHELL -ilc`)
    - 사용자가 CLI의 절대 경로를 직접 지정하기
  - **점검 단계**
    - 로그인 상태 확인: `claude auth status`, `codex login status`
    - CLI 버전 확인과 점검 실행(로그인 확인 + 최소 스키마 실행)
    - 이 단계들은 [에이전트 실행 계약 결정](07-agent-run-contract.md)에서 정했다.
  - **기본 에이전트와 에이전트별 모델**: Codex는 [비밀 파일 제외 실측](13-secret-exclusion-check.md)을 통과해야 선택지에 나온다.
- **나머지 설정 항목**의 구성
  - 비밀 파일 패턴 추가
  - 추가 지침
  - "에디터에서 열기"에 쓸 에디터
- **시험 실행**: [멘션 감지 방식 결정](05-mention-detection.md)에 따라 첫 실행에는 과거 멘션을 가져오지 않는다. 그래서 온보딩에 최근 멘션 하나로 시험해 보는 단계를 둘지 정한다.
- **함께 정할 것**
  - 로그인 시 자동 시작을 기본으로 켤지
  - OS 알림 권한을 언제 물을지
  - [미서명 앱 macOS 실기 검증](11-tauri-macos-unsigned-check.md)에서 macOS 27은 첫 알림 때 배너로 권한을 물었고, 로그인 항목을 추가하면 macOS가 알림을 띄웠다.

## 정해진 것

이 질문의 전제다. [데스크톱 프레임워크와 기술 스택 결정](08-desktop-stack.md)에서 정했다.

- 키는 설정 화면에서만 받아 `safeStorage`로 보관한다. `.env`나 환경 변수로 받는 경로는 없다.
- 설정은 OS 표준 앱 데이터 폴더의 `settings.json`에 두고, 위치는 바꿀 수 없다.
- 소스에서 실행할 때는 `Stardraft Dev`라는 이름으로 데이터와 키체인 항목을 따로 쓴다.
