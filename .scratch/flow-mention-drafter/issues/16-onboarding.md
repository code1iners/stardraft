## Question

Stardraft를 처음 켰을 때 감지를 시작하기까지의 **순서와 화면**을 정한다. 설정 화면의 구성과, 설정이 바뀔 때의 처리도 함께 정한다. 화면 결정에는 `ui-design` 스킬을 쓰고, 필요하면 `prototype`으로 화면을 그려 본다.

정할 것:

- **개인 API 키**
  - 키를 입력받은 직후 `GET /user/employees/me`로 내 ID와 이름을 확인하는 단계를 어떻게 보여 줄지. 이 API가 개인 키로 동작한다는 것은 [댓글 쓰기 API 실측](15-comment-write-api-check.md)에서 확인했다.
  - 키를 다시 입력하는 경로. "키 확인 필요"가 뜨는 경우는 두 가지다.
    - 폴링에서 `401`이 온 경우
    - `safeStorage` 복호화에 실패한 경우. 키체인 허락을 거부했거나, 키체인 항목이 지워졌을 때다.
  - 다른 계정의 키로 바꿀 때 기준점과 처리 상태를 어떻게 초기화할지. 상태는 `state.db`, 설정은 `settings.json`으로 나뉘어 있으므로 상태만 비울 수 있다.
  - 키체인 재허용 대화상자를 미리 설명하는 방법. [서명 정책 재검토](10-signing-policy-review.md)에서 미서명 앱은 업데이트할 때마다 키체인 접근 허용을 다시 물을 수 있고, 이것은 감수하기로 했다. 대화상자에는 항목 이름 `Stardraft Safe Storage`가 나온다.
- **작업 폴더**: 지정하는 순서와 화면. 여러 개를 둘 수 있고, 네트워크·WSL 경로는 받지 않는다([저장소 매핑과 자동 선택 규칙 결정](06-repo-mapping.md)).
- **에이전트**
  - **CLI 경로 찾기**: GUI 앱은 셸의 PATH를 물려받지 못한다. Electron에는 공식 보정 도구가 없다. 그래서 두 방법 중에서 정한다.
    - 로그인 셸에서 PATH를 한 번 읽어 오기(`$SHELL -ilc`)
    - 사용자가 CLI의 절대 경로를 직접 지정하기
  - **점검 단계**
    - 로그인 상태 확인: `claude auth status`, `codex login status`
    - CLI 버전 확인과 점검 실행(로그인 확인 + 최소 스키마 실행)
    - 이 단계들은 [에이전트 실행 계약 결정](07-agent-run-contract.md)에서 정했다.
  - **기본 에이전트와 에이전트별 모델**: Codex는 [비밀 파일 제외 실측](13-secret-exclusion-check.md)을 통과해야 선택지에 나온다.
- **나머지 설정 항목**의 구성
  - 비밀 파일 패턴 추가
  - 추가 지침
  - "에디터에서 열기"에 쓸 에디터
- **시험 실행**: [멘션 감지 방식 결정](05-mention-detection.md)에 따라 첫 실행에는 과거 멘션을 가져오지 않는다. 그래서 온보딩에 최근 멘션 하나로 시험해 보는 단계를 둘지 정한다.
- **함께 정할 것**
  - 로그인 시 자동 시작을 기본으로 켤지
  - OS 알림 권한을 언제 물을지
  - [미서명 앱 macOS 실기 검증](11-tauri-macos-unsigned-check.md)에서 macOS 27은 첫 알림 때 배너로 권한을 물었고, 로그인 항목을 추가하면 macOS가 알림을 띄웠다.

## 정해진 것

이 질문의 전제다. [데스크톱 프레임워크와 기술 스택 결정](08-desktop-stack.md)에서 정했다.

- 키는 설정 화면에서만 받아 `safeStorage`로 보관한다. `.env`나 환경 변수로 받는 경로는 없다.
- 설정은 OS 표준 앱 데이터 폴더의 `settings.json`에 두고, 위치는 바꿀 수 없다.
- 소스에서 실행할 때는 `Stardraft Dev`라는 이름으로 데이터와 키체인 항목을 따로 쓴다.

## Answer

2026-10-18에 사용자와 그릴링으로 정했다. 화면은 [프로토타입](../prototypes/onboarding/index.html)에서 에이전트 연결 표시 변형 A·B·C를 비교해 정했다.

- 실행: `open .scratch/flow-mention-drafter/prototypes/onboarding/index.html`. 변형은 `?variant=A|B|C`나 `#A|#B|#C`, 또는 화면 아래 막대로 바꾼다. 기본은 확정한 B다.
- 데이터는 가짜이고, Flow 호출·에이전트 실행·알림은 흉내만 낸다. 구현에 재사용하지 않는다.
- 비교한 변형은 에이전트 칸만 다르다. A 단계 아이콘형, **B 연결선형(확정)**, C 큰 그림형이다.

### 첫 실행의 흐름

- **시작하기 전용 창은 두지 않는다.** 처음 설정과 나중 수정을 같은 설정 창에서 한다. 사용자가 제안한 구조다.
- **첫 실행**에는 트레이 옆 작은 창을 자동으로 띄운다.
  - 메뉴 막대 앱이라 Dock 아이콘이 없고, Windows는 새 트레이 아이콘이 숨김 영역에 들어간다. 그래서 아무 창도 없으면 사용자가 앱을 놓친다.
  - 작은 창이 트레이 근처에 뜨므로 아이콘 위치도 함께 알려 준다.
- **설정 전 작은 창**
  - "멘션 감지를 시작하려면 세 가지를 설정해야 합니다"와 필수 세 줄(Flow 개인 API 키, 에이전트, 작업 폴더)을 둔다. 줄마다 상태(✓ 또는 필요)를 보여 준다.
  - 줄을 누르면 설정 창의 해당 칸이 열린다. 아래에 [설정 열기]가 있다.
  - 세 가지가 다 되면 버튼이 [감지 시작]으로 바뀌고 안내 두 줄이 붙는다(아래 "마무리").
- **설정 창 맨 위 첫 설정 띠**
  - "필수 설정 n/3", 남은 항목, 다음 항목으로 가는 버튼을 둔다.
  - 세 가지가 다 되면 띠에 [감지 시작]과 안내 두 줄이 나온다. 감지를 시작한 뒤에는 다시 나오지 않는다.
  - 왼쪽 칸 목록에서 아직 끝나지 않은 필수 칸에 점을 찍는다.
- 작은 창은 트레이 팝오버라서 설정 창을 열면 닫힌다.
- **중간에 닫으면** 통과한 항목(확인된 키 등)은 저장되어 있다. 트레이 아이콘에 노란 점("설정 필요")을 달고, 트레이를 누르거나 앱을 다시 켜면 설정 전 작은 창이 다시 뜬다.
- 키를 먼저 넣으라는 순서 강제는 없다. 매핑을 온보딩에서 받지 않으므로 키에 기대는 단계가 없다.
- 설정 창이 열려 있는 동안 macOS Dock 아이콘(Windows는 작업 표시줄 단추)을 보여 준다. 다른 창 뒤로 간 설정 창을 찾을 수 있게 하기 위해서다.

### 감지를 시작하는 조건

- **필수 항목**: 확인된 키, 에이전트 연결(아래 "용어"), 작업 폴더 1개 이상.
- **저장소 매핑**은 온보딩에서 받지 않는다. [저장소 매핑과 자동 선택 규칙 결정](06-repo-mapping.md)대로 설정 창이나 검토 화면의 "이 Flow 프로젝트에 연결"로 쌓는다.
- 작업 폴더를 선택 사항으로 두지 않은 이유: 없으면 모든 멘션이 "저장소 확인 필요"로 와서 매번 저장소를 직접 골라야 한다.
- **기준점**(가장 최근 `alarmId`)은 [감지 시작]을 누를 때 잡는다. 키를 확인할 때 잡으면, 온보딩을 미뤘다가 끝낼 때 그사이 멘션(최대 72시간)이 한꺼번에 처리된다.

### 개인 API 키

- **입력 칸 위 안내**: "Flow 웹의 내 API 키에서 발급합니다. 메뉴가 보이지 않으면 회사 관리자가 개인 키 발급을 허용해야 합니다." 회사마다 Flow 주소가 달라서 링크는 걸지 않는다.
- **확인**: [확인]을 누르면 `GET /user/employees/me`를 부른다. 성공하면 이름, 소속, 이메일을 담은 계정 카드와 "연결됨"을 보여 준다. "이 계정이 맞나요?" 같은 확인 버튼은 두지 않는다.
- **실패 문구**는 원인별로 나눈다.
  - `401`: "키가 맞지 않습니다. Flow에서 다시 복사해 붙여 넣어 주세요."
  - 네트워크 오류: "Flow에 연결할 수 없습니다"와 다시 시도 버튼
  - `429`: 잠시 뒤 자동으로 다시 시도한다.
- 확인에 성공했을 때만 `safeStorage`로 저장한다. 키를 바꾸다 실패하면 옛 키와 계정을 그대로 둔다.
- **계정 비교**: 확인할 때 받은 `userId`를 `state.db`에 저장해 두고 새 키의 `userId`와 비교한다. `state.db`에 두므로, 복호화에 실패해 옛 키를 읽지 못해도 비교할 수 있다.
  - **같은 계정**(키 재발급, 키체인 거부 뒤 다시 입력): 상태를 그대로 두고 기준점부터 이어서 감지한다. [멘션 감지 방식 결정](05-mention-detection.md)의 72시간 규칙을 따른다.
  - **다른 계정**: 먼저 확인을 받는다. 문구는 "OOO 계정의 키입니다. 지금까지의 멘션·초안·기록을 지우고 이 계정으로 처음부터 시작합니다"다.
    - 확인하면 `state.db`를 비운다. 진행 중인 실행과 게시 카운트다운은 취소하고, 기준점은 첫 실행처럼 다시 잡는다.
    - `settings.json`(작업 폴더, 매핑, 에이전트, 지침, 패턴, 에디터)은 그대로 둔다. 다른 회사 계정이면 매핑이 엉뚱한 Flow 프로젝트를 가리키지만, 쓰이지 않을 뿐이다.
  - 옛 계정 상태를 따로 보관해 계정을 오가는 기능은 없다.

### 전역 문제의 표시

"키 확인 필요"(폴링 `401`, 복호화 실패)와 [에이전트 실행 계약 결정](07-agent-run-contract.md)의 전역 실패(CLI 없음, 미로그인, 버전 낮음, 점검 실행 실패)를 같은 방식으로 보여 준다.

- **트레이 아이콘**: "!"를 표시한다. macOS는 아이콘 옆 글자, Windows는 아이콘에 그린 빨간 배지다. 검토 대기 숫자보다 앞선다.
- **작은 창 맨 위 띠**: 원인과 행동 버튼 하나를 둔다.
  - 401: "Flow가 키를 거부했습니다. 키가 삭제됐거나 바뀌었을 수 있습니다."
  - 복호화 실패: "저장된 키를 읽을 수 없습니다. 키체인 접근을 거부했거나 항목이 지워졌을 수 있습니다." Windows는 DPAPI에 맞춘 문구를 쓴다.
  - 버튼은 키 문제면 "키 다시 입력", 에이전트 문제면 "에이전트 확인"이고, 설정 창의 해당 칸으로 간다.
- **오른쪽 클릭 메뉴**: 맨 위에 같은 항목을 둔다.
- **OS 알림**: 한 번 띄운다.
  - 같은 원인으로는 해결되기 전까지 다시 띄우지 않는다. 해결된 뒤 다시 생기면 다시 띄운다.
  - 07의 "트레이에서 한 번만 알린다"를 이렇게 구체화한다. 트레이의 "!"만으로는 감지가 몇 시간째 멈춰도 모를 수 있기 때문이다.

### 키체인 재허용 대화상자

- ad-hoc 서명한 앱은 키체인 항목을 만든 그 빌드에만 허용이 붙는다. 그래서 첫 실행에는 대화상자가 뜨지 않고, 업데이트 뒤 처음 키를 읽을 때 뜰 것으로 본다(추론).
- 이 대화상자는 Mac 로그인 암호를 요구하고, 버튼이 "항상 허용 / 거부 / 허용" 세 개다. "허용"만 누르면 앱을 켤 때마다 다시 묻는다.
- **온보딩에서는 설명하지 않는다.** 당장 뜨지 않는 창을 미리 설명해도 기억에 남지 않는다.
- **업데이트로 재시작하기 직전에 안내한다.** 문구는 "다시 켜지면 macOS가 'Stardraft Safe Storage' 사용을 묻습니다. Mac 로그인 암호를 넣고 '항상 허용'을 누르세요."다. 이 문구는 [앱 내 업데이트 방식 결정](22-in-app-update-design.md)에 넘겼다. 다운로드 사이트의 안내(09)는 그대로 둔다.
- "거부"를 누르면 복호화 실패가 되어 "키 확인 필요"로 간다. 같은 계정의 키를 다시 넣으면 상태가 이어진다.
- [앱 내 업데이트 macOS 실기 검증](21-in-app-update-macos-check.md)에서 첫 실행에도 대화상자가 뜨는 것으로 나오면, 키 칸의 [확인] 옆에 같은 문구를 넣는다.

### 에이전트

- **CLI 경로 찾기**: 아래 순서로 찾는다.
  1. macOS는 로그인 셸(`$SHELL -ilc`)을 한 번 띄워 `command -v`와 PATH를 읽는다.
     - 제한 시간은 5초다.
     - rc 파일이 찍는 다른 출력과 섞이지 않게 표지 문자열로 출력을 감싼다.
     - Windows는 앱이 받은 PATH에서 찾는다.
  2. 못 찾으면 알려진 설치 위치를 본다. `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `%USERPROFILE%\.local\bin`, `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin` 등이다.
  3. 그래도 없으면 "직접 지정"(파일 선택)으로 받는다.
  - 찾은 **절대 경로를 `settings.json`에 저장**하고 화면에 보여 준다. 매번 다시 찾지 않고, 그 경로가 사라졌거나 "다시 찾기"를 누를 때만 다시 찾는다.
  - 자식 프로세스의 PATH에는 1에서 읽은 PATH를 넣는다. npm으로 설치한 CLI는 PATH에서 `node`를 찾아야 하기 때문이다. 07의 환경 변수 규칙(API 키 변수를 넘기지 않음)은 그대로다.
  - Windows의 `WindowsApps\Claude.exe`(데스크톱 앱)는 후보에서 뺀다.
- **연결 확인**: 에이전트 칸을 열면, 설치를 찾은 에이전트마다 네 단계를 자동으로 차례대로 돌린다. 실패하면 그 단계에서 멈춘다.
  1. 찾기
  2. 버전: 07의 필수 플래그를 지원하는 버전인지 본다. 예를 들어 `--restricted`는 2.1.248 이상에서 지원한다.
  3. 로그인: `claude auth status` 등을 **앱이 실제로 실행할 때와 같은 환경 변수로** 돌린다. 로그인 방식이 `api_key_helper`이면 지원하지 않는 방식으로 안내한다.
  4. 작동 확인: 07의 점검 실행(로그인 확인 + 최소 스키마 실행)이다. "10초쯤 걸리고 사용량을 조금 씁니다"를 표시한다.
  - 화면에서는 이 단계를 "작동 확인"이라고 부른다. "시험"은 최근 멘션으로 하는 시험에 쓰므로 겹치지 않게 했다.
- **연결 표시: B 연결선형**. 사용자가 텍스트를 줄이고 그림 위주로 보여 달라고 해서, 세 변형을 비교한 뒤 골랐다.
  - Stardraft와 에이전트 아이콘을 선으로 잇는다. 선의 네 마디가 네 단계다. 끝난 단계는 초록 선, 진행 중인 단계는 움직이는 점선, 남은 단계는 회색 점선이다.
  - 연결되면 "✓ Claude Code 연결됨"을 표시한다.
  - 실패하면 그 마디가 끊기고 원인(설치 필요, 업데이트 필요, 로그인 필요 등)을 적는다. 아래에 그림 카드 네 장을 둔다.
    1. 터미널(Windows는 PowerShell) 열기
    2. 명령 붙여 넣고 Enter(명령 복사 버튼)
    3. 원인별 다음 행동(브라우저에서 로그인, 완료 줄 기다리기 등)
    4. 다시 확인 버튼
  - 명령으로 고칠 수 없는 실패(작동 확인 실패 등)는 카드 대신 한 줄 안내와 다시 확인 버튼만 둔다.
  - 경로, 버전, 로그인 방식, CLI 오류 원문은 "자세히" 안에만 둔다. 설치를 찾지 못했으면 찾아본 곳을 보여 주고 "직접 지정"을 둔다.
  - 카드의 명령은 **앱이 실제로 쓰는 환경 그대로** 보여 준다. 그래서 [비밀 파일 제외 실측](13-secret-exclusion-check.md)에서 Codex 전용 `CODEX_HOME`을 쓰기로 하면, 그 환경 변수까지 들어간 명령이 보인다.
  - 앱이 터미널을 대신 열어 로그인시키는 기능은 만들지 않는다. OS마다 방법이 다르고, 쓰는 터미널 앱도 제각각이다.
- **기본 에이전트**
  - Codex는 13을 통과한 OS에서만 후보가 된다.
  - 연결된 에이전트가 하나면 자동으로 기본 에이전트가 되고, 고르는 칸은 보이지 않는다. 둘 이상이면 고르게 하고 Claude Code를 미리 골라 둔다.
  - 연결되지 않은 에이전트는 기본으로 고를 수 없다.
- **모델**: 에이전트마다 선택 상자로 고른다. 직접 입력은 두지 않고, 온보딩의 필수 항목도 아니다. 07의 "에이전트별 모델 칸"(자유 입력)을 이렇게 바꾼다.
  - 첫 항목은 "기본 모델(에이전트가 정함)"이다. 이것을 고르면 `--model`을 넘기지 않는다.
  - Claude Code: 계열 별칭 Fable, Opus, Sonnet을 앱에 넣어 둔다. 별칭은 그 계열의 최신 모델을 가리키므로, 새 모델이 나와도 목록을 고칠 필요가 없다(2.1.302 `--help`에서 확인).
  - Codex: 연결을 확인할 때 `codex debug models`에서 `visibility`가 `list`인 모델을 읽는다(0.163.0에서 확인). 명령이 실패하거나 형식이 바뀌면 "기본 모델"만 보여 준다.
  - 저장한 모델이 목록에서 사라지면 기본 모델로 몰래 바꾸지 않는다. "(목록에 없음)"을 붙여 남겨 보여 준다.

### 작업 폴더

- "폴더 추가…"는 OS 폴더 선택 창으로 받고, 여러 개를 한 번에 고를 수 있다.
- 추가하면 바로 06 규칙(3단계 깊이까지 `.git` 찾기)으로 훑어 "저장소 12개"처럼 보여 준다. 펼치면 저장소 이름이 나온다.
  - 0개면 경고하되 추가는 막지 않는다.
  - 고른 폴더 자체가 저장소면 그 하나를 후보로 센다.
- 네트워크·WSL 경로는 이유를 보여 주고 받지 않는다.
- 홈 폴더 아래 흔한 이름 중 저장소가 들어 있는 폴더를 "이 PC에서 찾은 폴더"로 보여 주고 [추가]를 단다. `~/workspace`, `~/projects`, `~/dev`, `~/code`, `~/src`, `~/IdeaProjects` 등이다.

### 설정 창

- 트레이 오른쪽 클릭 메뉴의 "설정…"이나 작은 창에서 연다. 왼쪽에 칸 목록(약 180px), 오른쪽에 그 칸의 내용이 있다.
  1. Flow 계정: 연결된 계정, 키 바꾸기
  2. 에이전트: 연결 표시, 기본 에이전트, 에이전트별 모델
  3. 저장소: 작업 폴더, 저장소 매핑(06)
  4. 초안: 추가 지침, 비밀 파일 패턴(기본 목록은 읽기 전용, 그 아래 추가 패턴), 최근 멘션으로 시험
  5. 일반: 로그인 시 자동 시작, 알림 시험, 에디터, 업데이트(22에서 정함), 데이터·로그 폴더 열기, 버전
- **저장**: 바꾸는 즉시 적용하고, "저장" 버튼은 두지 않는다. 예외는 두 가지다.
  - 키: 확인에 성공했을 때 저장한다.
  - 여러 줄 입력(추가 지침): 칸을 벗어날 때 저장하고 옆에 "저장됨"을 표시한다.
- **설정이 바뀔 때**
  - 에이전트, 모델, 추가 지침, 작업 폴더: 실행 중인 실행은 그대로 끝내고, 다음 실행부터 새 값을 쓴다. 이미 만든 초안은 다시 만들지 않는다.
  - 비밀 파일 패턴 추가: 안전에 관한 설정이라 다르게 다룬다.
    - 실행 중인 실행은 취소하고 대기열 맨 앞에 다시 넣어, 새 패턴으로 다시 돌린다.
    - 게시하지 않은 초안은 근거 경로를 새 패턴으로 다시 검사한다. 걸리면 07대로 결과를 버리고 실패("비밀 파일을 근거로 듦")로 둔다.
  - 작업 폴더를 지워도 그 안을 가리키는 매핑은 그대로 둔다. 매핑은 절대 경로라서 작업 폴더와 따로 움직인다.
- **에디터에서 열기**: [초안 검토 화면 프로토타입](04-draft-review-prototype.md)에서 근거 위치 옆에 두기로 한 버튼이다.
  - 설치된 에디터(VS Code, Cursor, JetBrains IDE, Zed, Sublime Text)를 찾는다. 각 에디터에서 특정 줄로 여는 방법(URL 스킴이나 CLI)은 앱에 넣어 둔다.
  - 기본값을 미리 정하지 않는다. 처음 누를 때 찾은 목록에서 고르게 하고, 고른 것을 기억한다. 찾은 에디터가 없으면 OS 기본 앱으로 파일만 연다.
  - "직접 지정"은 `{file}`, `{line}` 자리를 넣은 명령 한 줄로 받는다. 설정의 일반 칸에서 바꾼다.

### 최근 멘션으로 시험

첫 실행에는 과거 멘션을 가져오지 않는다(05). 그래서 누가 멘션하기 전까지는 앱이 동작하는지 볼 수 없다. 이를 위해 시험용 실행을 둔다. 사용자가 "말 그대로 시험용"으로 정했다.

- **버튼 위치**
  - 감지 중 멘션이 없을 때의 작은 창 빈 화면
  - 설정의 초안 칸. 추가 지침을 바꾼 뒤 결과를 볼 때도 쓴다.
  - 감지를 시작한 뒤에만 쓸 수 있다. 대기열이 돌아야 시험이 진행되기 때문이다.
- **멘션 고르기**: 최근 멘션 10건을 송신자, Flow 프로젝트, 첫 줄, 시각으로 보여 주고 하나를 고른다.
  - 05의 판정 규칙을 통과한 멘션만 넣는다. 72시간 제한은 두지 않는다.
  - 이미 답한 멘션에는 "답함"을 붙이고, 그래도 고를 수 있다.
  - 자동으로 고르지 않는다. 최근 멘션 하나가 코드와 무관한 경우가 많다.
- **실행**: 실제와 똑같이 돌린다. 실제 에이전트와 저장소로 선택 실행과 초안 실행을 하고, 대기열 맨 앞에 들어가며, 사용량도 쓴다.
  - 트레이 숫자와 OS 알림("[시험] …")도 평소처럼 나온다. 알림을 눌러 검토 화면까지 가는 경로를 함께 시험하려는 것이다.
- **시험 묶음에서 바뀌는 점**
  - "시험" 표시와 "Flow에는 아무것도 올라가지 않습니다" 안내를 붙인다.
  - 게시 버튼 대신 [시험 끝내기]를 둔다. 재생성, 지시 덧붙이기, 저장소 바꾸기, 근거 보기, "이 Flow 프로젝트에 연결"은 모두 된다.
  - 직접 답했는지 확인하는 단계(05)와 스레드 변화 감시(14)는 건너뛴다.
  - 코드와 무관한 멘션이면 06대로 "저장소 확인 필요"로 끝난다.
  - 시험 끝내기나 무시를 누르면 묶음을 지운다. 처리됨 목록과 기준점에는 남기지 않는다.
  - 시험은 한 번에 하나만 돌린다.

### 마무리

- **[감지 시작] 곁의 안내 두 줄**
  - "로그인할 때 Stardraft가 자동으로 켜집니다. 설정의 일반에서 끌 수 있습니다."
  - macOS: "곧 macOS가 알림 허용을 묻습니다. 허용하면 초안이 준비될 때 알려 드립니다. 허용하지 않아도 메뉴 막대 아이콘의 숫자로 확인할 수 있습니다."
  - Windows는 알림 권한을 묻지 않으므로, 작업 표시줄 아이콘의 숫자로도 확인할 수 있다는 것만 안내한다.
- **로그인 시 자동 시작**은 기본으로 켠다. 앱이 켜져 있어야 감지하기 때문이다. 켜면 macOS가 "로그인 항목 추가됨" 알림을 띄운다.
- **[감지 시작]을 누르면**
  - 기준점을 잡고, 설정 창을 닫고, 트레이 옆 작은 창(빈 화면)을 띄운다.
  - 바로 "멘션 감지를 시작했습니다" 알림을 띄운다. macOS 27은 첫 알림 때 배너로 권한을 묻는다(11). 그래서 사용자가 화면을 보고 있을 때 권한을 묻게 된다.
  - 첫 초안이 준비될 때까지 미루면, 몇 시간 뒤 다른 일을 하다가 배너를 놓치거나 거절하기 쉽다. 거절해도 트레이로 동작한다.
- **Windows**: 작은 창에 "Stardraft 아이콘은 작업 표시줄 오른쪽 ^ 안에 있습니다. 끌어서 꺼내 두면 검토할 초안 수가 보입니다."를 넣는다.
