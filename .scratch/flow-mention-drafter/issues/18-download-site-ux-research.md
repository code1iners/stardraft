## Question

비슷한 데스크톱 앱 다운로드 사이트 **10곳**의 화면과 흐름을 조사한다. 목적은 [다운로드 사이트 화면 프로토타입](19-download-site-prototype.md)이 참고할 패턴을 모으는 것이다.

**고르는 기준**
- 메뉴바·트레이 소형 앱 3~4곳: Raycast, Rectangle, Stats, Maccy, Ice 같은 곳
- 서명이나 공증 없이 배포하면서 설치 경고(Gatekeeper, SmartScreen) 넘기기를 안내하는 오픈소스 앱 3곳
- AI·개발 도구 데스크톱 앱 3곳: Cursor, Ollama, LM Studio, Zed, Claude 데스크톱 같은 곳

**곳마다 기록할 것**
- 첫 화면 구성
- OS·칩 감지 방식과, 감지가 틀렸을 때 바꾸는 방법
- 설치 안내의 형태: 단계 수, 스크린숏, 대화상자 재현 여부
- 상호작용과 모션: 설치를 돕는 상호작용과 시각 연출을 모두 본다. 모션이 설명에 도움이 되는지, 장식인지도 구분한다.
- 버전, 변경 내역, 이전 버전을 보여 주는 방식
- 모바일 폭에서의 모습
- 데스크톱 폭과 모바일 폭 스크린숏

**전제**
- [다운로드 사이트 형태 결정](09-download-site.md)에서 정한 내용 요건(소개, 다운로드, 준비물, 설치 안내, 업데이트, 변경 내역, 이전 버전, 삭제)을 기준으로 비교한다.
- 사용자는 "인터랙티브"를 설치를 돕는 상호작용과 시각 연출 **둘 다**로 정했다.

## Answer

2026-10-17에 조사를 마쳤다. 사이트별 기록은 [다운로드 사이트 UI/UX 사례 조사](../research/download-site-ux-cases.md)에, 스크린숏 26장은 [research/download-site-ux/](../research/download-site-ux/)에 있다. Playwright와 headless Chrome으로 열었다. OS는 macOS 그대로 두고 UA만 바꿔 봤다.

- **고른 10곳**
  - 메뉴바·트레이 앱: Raycast, Rectangle, Maccy, Espanso
  - 미서명 오픈소스 앱: Stretchly, Flameshot, AeroSpace. Stretchly는 ad-hoc 서명한 Electron 트레이 앱이라 Stardraft와 가장 비슷하다.
  - AI·개발 도구: Cursor, LM Studio, Zed
- **공통 패턴**
  - OS 감지는 대표 버튼 하나만 바꾸고, 그 옆에 지원 환경 한 줄을 붙인다.
  - 칩까지 가르는 곳은 Cursor 하나다.
  - 이전 버전은 대개 GitHub 목록으로 보낸다. 사이트 안에 목록을 둔 곳은 세 곳이다.
  - SHA256을 다운로드 페이지에 보여 주는 곳은 없다.
- **비어 있는 자리**: 아래는 10곳 모두 하지 않았다. 그래서 Stardraft가 새로 채워야 한다.
  - 대화상자를 HTML로 재현하는 것
  - 설치를 설명하는 모션
  - 스마트 앱 컨트롤 확인 안내
  - 업데이트 때 다시 확인받는다는 안내
  - 모션을 쓰는 다섯 곳은 모두 reduced-motion 설정에서도 계속 움직였다.
- **가져올 것**
  - 감지한 OS의 대표 버튼 → 바로 밑 다른 OS 링크 → 전체 목록으로 이어지는 구조
  - 지원하지 않는 환경에서 이유를 붙여 띄우는 모달(Raycast)
  - 번호를 단 대화상자 스크린숏(Espanso)
  - 실수하기 쉬운 지점과 완료 기준을 적은 단계 안내(Flameshot)
  - 업데이트 전 앱 종료 안내와 삭제 명령(Stretchly)
  - 모바일 화면의 "다운로드 링크 복사"(LM Studio)
- **피할 것**
  - 장식용 배경 모션
  - 등장 애니메이션 뒤에 숨긴 다운로드 버튼
  - 어두운 SaaS풍 화면, 회전 그라데이션 테두리, 알약 버튼 남발. `ui-design` 금지 항목과 겹친다.
  - 제품 시연 카드
  - 페이지마다 다른 버전 표시
  - macOS 15부터 막힌 "우클릭 > 열기" 안내. 세 곳이 아직 이렇게 안내한다.
- **설치 경고 안내를 가장 잘한 곳**: macOS는 Flameshot, Windows는 Espanso다.
- **구성 제안**
  - A안: 한 페이지 문서형이다. OS 탭 안에 번호 단계와 "여기서 막히면" 펼침을 둔다. 모션은 없다.
  - B안: 단계 진행형 체크리스트다. 단계마다 "됐어요/안 돼요"를 두고, "안 돼요"를 누르면 막힌 경우의 분기로 간다. 모션은 설명용만 쓴다.
  - C안: B안에 HTML 대화상자 재현 연습을 더한다. OS 버전마다 재현을 고쳐야 하고, 진짜 OS 창으로 오인될 위험이 있다.
  - 조사자의 판단은 B안을 기본으로 하고, C안의 재현은 Windows 화면 한 곳에서만 시험해 보는 것이다.
  - 최종 선택은 [다운로드 사이트 화면 프로토타입](19-download-site-prototype.md)에서 사용자와 정한다.
