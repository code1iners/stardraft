# 25: Flow 계정 연결과 키 보관

**Spec:** [스펙](../spec.md) 3절, 13절 "개인 API 키"

**What to build:** 설정 창 "Flow 계정" 칸에 개인 API 키를 넣고 [확인]을 누르면 이름·소속·이메일 계정 카드와 "연결됨"이 보인다. 키는 OS 키 보관소로 보호되어 저장된다. 다른 계정의 키로 바꾸면 확인을 받고 기록을 비운다.

**Blocked by:** 24

**Status:** ready-for-agent

- [ ] 입력 칸 위에 "Flow 웹의 내 API 키에서 발급합니다. 메뉴가 보이지 않으면 회사 관리자가 개인 키 발급을 허용해야 합니다."가 있고 링크는 없다.
- [ ] [확인]은 `GET /user/employees/me`를 `x-flow-api-key` 헤더로 부른다. API 주소 `https://api.flow.team`는 코드 한 곳에만 있다. Flow 어댑터의 첫 조각이다.
- [ ] 성공하면 계정 카드와 "연결됨"을 보이고, 그때만 `safeStorage` 비동기 API로 암호화해 데이터 폴더의 파일에 저장한다. `shouldReEncrypt`면 다시 암호화한다. 실패하면 옛 키와 계정을 그대로 둔다.
- [ ] 실패 문구: `401` "키가 맞지 않습니다. Flow에서 다시 복사해 붙여 넣어 주세요.", 네트워크 오류 "Flow에 연결할 수 없습니다"와 다시 시도, `429`는 잠시 뒤 자동 재시도.
- [ ] 확인 때 받은 `userId`를 `state.db`에 둔다. 같은 계정이면 상태를 유지하고, 다른 계정이면 "OOO 계정의 키입니다. 지금까지의 멘션·초안·기록을 지우고 이 계정으로 처음부터 시작합니다"로 확인을 받은 뒤 `state.db`를 비우고 `settings.json`은 둔다.
- [ ] `.env`나 환경 변수로 키를 받는 경로가 없다. 개발 모드의 키체인 항목 이름이 `Stardraft Dev Safe Storage`로 분리되는지 확인해 기록한다.
- [ ] 가짜 `fetch`로 성공·401·네트워크·429 경로와 계정 비교가 테스트된다.
