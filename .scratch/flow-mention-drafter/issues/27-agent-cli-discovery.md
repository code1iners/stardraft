# 27: 에이전트 CLI 찾기와 로그인 확인

**Spec:** [스펙](../spec.md) 13절 "에이전트"

**What to build:** 설정 창 "에이전트" 칸을 열면 앱이 Claude Code CLI를 찾고 버전과 로그인을 차례로 확인해 연결선 그림으로 보여 준다. 실패하면 그 마디가 끊기고 터미널에 붙여 넣을 명령이 든 그림 카드가 나온다. 못 찾으면 찾아본 곳과 "직접 지정"이 보인다. (네 번째 단계 "작동 확인"은 28.)

**Blocked by:** 24

**Status:** ready-for-agent

- [ ] macOS는 로그인 셸(`$SHELL -ilc`)을 한 번 띄워 `command -v`와 PATH를 표지 문자열로 감싸 읽는다(제한 5초). zsh, bash, fish에서 동작하고 rc 파일이 멈출 때 5초 제한이 걸리는지 확인해 기록한다. Windows는 앱이 받은 PATH를 쓴다.
- [ ] 못 찾으면 알려진 설치 위치를 보고, 그래도 없으면 파일 선택으로 직접 지정한다. Windows의 `WindowsApps\Claude.exe`는 후보에서 뺀다.
- [ ] 찾은 절대 경로를 `settings.json`에 저장해 보여 주고, 경로가 사라졌거나 "다시 찾기"를 누를 때만 다시 찾는다. 읽은 PATH는 자식 프로세스용으로 보관한다.
- [ ] 버전 단계는 필수 플래그 지원 여부(예: `--restricted`는 2.1.248 이상)를 보고, 낮으면 "업데이트 필요"로 끊는다.
- [ ] 로그인 단계는 `claude auth status`를 앱이 실제로 쓰는 환경 변수(API 키 변수 제외, 읽은 PATH)로 돌린다. `api_key_helper` 방식은 지원하지 않는다고 안내한다. 미로그인 때의 실제 출력과 종료 코드를 확인해 기록한다.
- [ ] 연결선 표시: 네 마디(찾기·버전·로그인·작동 확인), 끝난 단계 초록 선, 진행 중 움직이는 점선, 남은 단계 회색 점선. 네 번째 마디는 이 티켓에서 "다음 단계"로 비워 둔다.
- [ ] 실패 카드 네 장(터미널/PowerShell 열기, 명령 붙여 넣기와 복사 버튼, 원인별 다음 행동, 다시 확인)이 있고, 화면의 명령(`claude auth login`, `claude update`, 설치 명령)이 실제 CLI와 맞는지 확인해 기록한다. 경로·버전·로그인 방식·오류 원문은 "자세히" 안에만 있다.
- [ ] 가짜 프로세스 실행기로 찾기·버전·로그인 각 단계의 성공과 실패가 테스트된다.
