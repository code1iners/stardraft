# 28: 작동 확인과 기본 에이전트·모델

**Spec:** [스펙](../spec.md) 6절 "Claude Code 실행 방식", "공통 실행 규칙", "에이전트와 모델 선택"

**What to build:** 에이전트 연결의 네 번째 단계 "작동 확인"이 돈다. 앱이 Claude Code를 실제 실행 계약의 필수 플래그 묶음으로 한 번 불러 최소 스키마 결과를 받으면 "✓ Claude Code 연결됨"이 된다. 그 아래에서 기본 에이전트와 모델을 고른다. CLI가 없거나 미로그인이거나 버전이 낮거나 작동 확인이 실패하면 전역 문제로 표시된다.

**Blocked by:** 27

**Status:** ready-for-agent

- [ ] Claude Code 실행기 어댑터가 생긴다. 필수 플래그 묶음(스펙 6절)을 그대로 쓰고, 비밀 파일 deny 규칙은 `Read(//**/<패턴>)` 형식으로 기본 목록을 넣으며, 환경 변수는 앱이 구성하고 `ANTHROPIC_API_KEY`·`CODEX_API_KEY`를 넘기지 않는다.
- [ ] 점검 실행은 로그인 확인과 최소 스키마 실행 한 번이다. 화면 이름은 "작동 확인"이고 "10초쯤 걸리고 사용량을 조금 씁니다"를 표시한다. `stream-json`의 마지막 `result` 메시지에서 `structured_output`을 꺼낸다.
- [ ] 점검 실행은 앱 시작 시, 전역 실패가 의심될 때, CLI 버전이 바뀐 것을 알아챘을 때, 에이전트 칸을 열 때 돈다.
- [ ] CLI 없음, 미로그인, CLI 업데이트 필요, 점검 실행 실패가 26의 전역 문제로 표시되고 버튼 [에이전트 확인]이 에이전트 칸을 연다. 원인이 해결되면 표시가 사라진다.
- [ ] 연결된 에이전트가 하나면 자동으로 기본이 되고 고르는 칸이 보이지 않는다. 둘 이상이면 Claude Code를 미리 고른다(둘째 에이전트는 51).
- [ ] 모델 선택 상자: 첫 항목 "기본 모델(에이전트가 정함)"이면 `--model`을 넘기지 않는다. Claude Code는 Fable, Opus, Sonnet 별칭을 앱에 넣어 두고, 별칭이 더 있는지 `--help`로 확인해 기록한다. 저장한 모델이 목록에서 사라지면 "(목록에 없음)"을 붙여 남긴다.
- [ ] 가짜 프로세스 실행기와 가짜 stream-json 스트림으로 인수 묶음, 환경 변수, `structured_output` 추출, 실패 분류가 테스트된다.
