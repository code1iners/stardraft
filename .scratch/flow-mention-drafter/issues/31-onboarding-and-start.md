# 31: 첫 실행 온보딩과 감지 시작

**Spec:** [스펙](../spec.md) 13절 "첫 실행의 흐름", 8절 "작은 창"의 다른 상태

**What to build:** 앱을 처음 켜면 트레이 옆 작은 창이 자동으로 뜨고 필수 세 가지(Flow 개인 API 키, 에이전트, 작업 폴더)의 상태를 보여 준다. 줄을 누르면 설정 창의 해당 칸이 열리고, 설정 창 맨 위 띠가 "필수 설정 n/3"을 보인다. 셋이 다 되면 [감지 시작]이 나타나고, 누르면 기준점을 잡고 "멘션 감지를 시작했습니다" 알림이 뜨며 로그인 시 자동 시작이 켜진다.

**Blocked by:** 25, 28, 29

**Status:** resolved

- [x] 첫 실행에 작은 창이 자동으로 뜬다. 필수 설정 전 화면에는 안내 문장, 세 줄과 상태(✓/필요), [설정 열기]가 있다. 트레이에 노란 점("설정 필요")이 뜬다.
- [x] 설정 창 첫 설정 띠에 "필수 설정 n/3", 남은 항목, 다음 항목 버튼이 있고, 칸 목록의 끝나지 않은 필수 칸에 점이 찍힌다. 감지를 시작한 뒤에는 띠가 다시 나오지 않는다.
- [x] 중간에 닫아도 통과한 항목은 저장되어 있고, 트레이를 누르거나 다시 켜면 같은 화면이 뜬다. 순서 강제는 없다.
- [x] [감지 시작]은 확인된 키, 에이전트 연결, 작업 폴더 1개 이상일 때만 보인다. 곁에 안내 두 줄(자동 시작, macOS 알림 허용 / Windows는 숫자 안내)이 있다.
- [x] 누르면 알림 목록을 한 번 조회해 가장 최근 `alarmId`를 기준점으로 `state.db`에 저장하고, 설정 창을 닫고, 빈 작은 창([최근 멘션으로 시험] 자리 포함)을 띄우고, 바로 시작 알림을 띄운다.
- [x] 로그인 시 자동 시작을 켠다(`setLoginItemSettings`). 설정 "일반"에 토글 자리를 둔다.
- [x] Windows 첫 실행 작은 창에 숨김 영역 안내 문구가 있다.
- [x] 가짜 포트로 "세 가지 전/후" 전환과 기준점 저장이 테스트된다.

## Comments

### 2026-10-20 구현과 검증 기록

**구조**

- core `src/core/onboarding/onboarding.ts`의 `Onboarding`이 필수 세 가지와 [감지 시작]을 맡는다.
  - 필수 세 가지(`flow-key`, `agent`, `work-folders`)의 상태는 `done`/`needed`/`checking`이다. 각 칸의 모듈이 저장한 상태에서 부를 때마다 읽으므로, 중간에 닫아도 통과한 항목은 그대로이고 순서 강제도 없다.
    - 확인된 키: 계정이 연결되어 있고 "키 확인 필요"가 없을 때다.
    - 에이전트: 연결 확인이 `connected`면 ✓, `failed`면 필요, 시작할 때 확인이 도는 동안(`idle`·`checking`)은 "확인 중"이다.
    - 작업 폴더: 1개 이상이다.
  - 입력(계정, 전역 문제, 에이전트 연결, 작업 폴더)이 바뀔 때마다 `refresh()`가 다시 보고, 화면에 보이는 상태가 달라졌을 때만 알린다.
  - `startDetection()`: 필수 세 가지가 다 됐고 아직 시작 전일 때만 돈다. 시작하는 동안 다시 눌러도 한 번만 돈다.
    1. 지금 키로 `GET /user/alarms?filters=MENTION&size=20`을 한 번 부른다. 다음 쪽은 받지 않는다.
    2. 그 쪽의 가장 큰 `alarmId`를 `state.db` 기준점으로 저장한다. 알림이 하나도 없으면 `0`으로 저장해 그 뒤의 멘션을 모두 처리한다.
    3. `settings.json`의 `detectionStarted`를 켠다.
    4. 로그인 시 자동 시작을 켠다.
    5. 설정 창을 닫고 빈 작은 창을 띄운다.
    6. "멘션 감지를 시작했습니다" 알림을 띄운다.
  - 실패 처리
    - `401`이면 "키 확인 필요"를 올린다. 연결 실패, 요청 한도, 모르는 응답, 저장 실패는 각각의 실패로 둔다.
    - 실패하면 아무것도 바꾸지 않고 [감지 시작] 아래에 이유를 보인다.
    - 필수 항목이 바뀌면(예: 거부된 키를 다시 확인함) 지난 실패 문구를 지운다.

    - 셸에서 켜면 앱이 앞에 오지 않아 작은 창이 포커스를 받자마자 닫혔다. `app.focus({ steal: true })`를 더한 뒤에는 앱이 앞으로 오고 작은 창이 포커스를 받아 유지됐다. 3초쯤 뒤 이 환경의 다른 앱이 앞으로 오면서 닫혔는데, 이는 팝오버의 정상 동작이다.

- Finder에서 처음 켰을 때 작은 창이 트레이 옆에 떠서 유지되는 모습. 위 실기는 Electron 객체 수준이고, 이 환경은 다른 앱이 포커스를 가져가 화면을 캡처하지 못했다.
- 메뉴 막대의 노란 점(ANSI 색 `●`)이 실제로 노랗게 보이는지와 툴팁 "설정 필요". Electron 문서상 `setTitle`은 ANSI 색을 받지만 화면으로 확인하지 못했다.
- 서명한 빌드에서의 확인(59의 미서명 macOS 점검 목록)
  - [감지 시작] 직후 "멘션 감지를 시작했습니다" 알림과 macOS 알림 권한 배너
  - 로그인 항목 등록("로그인 항목 추가됨" 알림)과 실제 로그인 시 자동 시작
  - "일반" 토글로 끄면 로그인 항목에서 빠지는지
- Windows(60)
  - 트레이 노란 점 배지(100%·200% 배율)
  - 첫 실행 작은 창이 트레이 근처에 뜨는지와 숨김 영역 안내
  - 로그인 시 자동 시작
