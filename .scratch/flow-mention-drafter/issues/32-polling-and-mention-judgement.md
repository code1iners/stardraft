# 32: 알림 폴링과 멘션 판정

**Spec:** [스펙](../spec.md) 4절 "폴링", "나를 지목했는지 판정"

**What to build:** 감지를 시작하면 60초마다 Flow 알림을 조회해 나를 직접 지목한 업무 멘션만 골라내고, 새 멘션이 생기면 트레이 숫자가 오르고 OS 알림이 뜬다. `@전체`, 담당자 지정, 내가 쓴 글, 72시간보다 오래된 알림은 걸러진다. Flow의 읽음 상태는 바뀌지 않는다.

**Blocked by:** 31

**Status:** ready-for-agent

- [ ] `GET /user/alarms?filters=MENTION&size=20`(`readYn` 생략)을 60초마다, 그리고 앱 시작·잠자기에서 깨어남·"지금 확인" 때 바로 조회한다. 읽음 처리 API는 절대 부르지 않는다.
- [ ] 기준점(가장 큰 `alarmId`)을 쓰고, 기준점 이하·72시간 초과·`hasNext: false` 중 하나를 만나면 페이지 넘기기를 멈춘다. 페이지 사이의 중복은 멘션 위치로 거른다. 기준점은 조회 뒤 갱신된다.
- [ ] 오류: `429`는 `Retry-After`, 네트워크 오류는 다음 주기, `401`은 폴링을 멈추고 "키 확인 필요"(26).
- [ ] 멘션 위치 구분(본문·댓글·대댓글)과 판정: 댓글·대댓글은 `contents`의 `@[…](내 ID)`, 본문은 `content` JSON TEXT 컴포넌트의 `MENTIONS` 또는 `CONTENTS` 표기. 대댓글이 처음 10개에 없으면 대댓글 API로 페이지를 넘긴다. 내 ID는 `receiverId`이며 25의 `userId`와 같아야 한다.
- [ ] 버리는 알림: 송신자가 나, `404`/`403`, 수정되어 표기 사라짐, 72시간 초과, 최소 기록에 있는 멘션 위치의 재알림(최소 기록 자체는 47이 완성하되 판정 입구는 여기서 둔다).
- [ ] 판정을 통과한 멘션은 멘션 위치로 식별되어 `state.db`에 저장되고, 트레이 숫자와 OS 알림이 뜬다(작은 창 표시는 33).
- [ ] 가짜 Flow API와 가짜 시계로 기준점, 72시간, 페이지 넘김 중 중복, 판정 규칙 전부, 오류 경로가 테스트된다. 픽스처는 가짜 데이터다.
