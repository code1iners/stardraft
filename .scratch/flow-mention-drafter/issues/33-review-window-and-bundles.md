# 33: 작은 창·펼친 창과 멘션 묶음

**Spec:** [스펙](../spec.md) 4절 "멘션의 식별과 멘션 묶음", "이미 답함 판정", 7절, 8절

**What to build:** 감지된 멘션이 멘션 묶음으로 묶여 작은 창에 하나씩 보인다. 머리에 대기열 위치와 상태 태그, "펼쳐 보기"가 있고, 원문 영역에 묶인 멘션 전부가 시간순으로 보인다. [무시]와 "Flow에서 열기"가 되고, 펼친 창의 목록은 검토 대기·생성 중·실패·처리됨으로 묶인다. 처리됨에서 되돌릴 수 있다. 감지 때 Flow에 이미 내 답이 있으면 "이미 답함"으로 바로 처리된다. 이 티켓에서는 초안을 만들지 않으므로 모든 묶음이 "저장소 확인 필요" 상태로 올라온다(35·38이 대체한다).

**Blocked by:** 32

**Status:** resolved

- [x] 묶음 키 `(postId, remarkId)`. 댓글 멘션과 그 대댓글 멘션은 한 묶음, 본문은 게시물마다 한 묶음, 다른 댓글 스레드는 다른 묶음이다. 처리됨 묶음에 새 멘션이 오면 새 묶음이 되고 되돌려도 합치지 않는다. 저장소 확인 필요 묶음에 새 멘션이 오면 합치고 "새 멘션 1건"을 표시한다.
- [x] 감지 시점 "이미 답함": 댓글 스레드 묶음은 그 스레드의 멘션 이후 내 대댓글, 본문 묶음은 게시물의 멘션 이후 내 댓글. `systemCode`가 있는 글은 제외. `registeredDateTime` 비교. 앞선 멘션은 빼고 모두 빠지면 초안 없이 "이미 답함".
- [x] 작은 창: 대기열 위치(`3 / 4`), ‹ › 이동, 상태 태그, "펼쳐 보기", 원문 영역("멘션 3건", 시간순), 상세 머리의 "Flow에서 열기"(`projectUrl`·`connectUrl`), 바닥 줄 왼쪽 [무시]. 순서는 가장 오래된 미처리 멘션 순. 영역 접기·펼치기와 창별 기억.
- [x] 펼친 창: 목록 네 묶음, 행에 송신자·상태·시각, 처리됨 아래 보관 안내 문구, "접어 보기".
- [x] 무시는 토스트와 처리됨 목록에서 되돌릴 수 있다. 되돌린 묶음은 4절의 재판정 규칙을 위한 기록(그때 있던 내 답)을 남긴다.
- [x] 트레이 숫자는 준비됨+저장소 확인 필요 수이고, 알림 클릭은 그 묶음을 연 작은 창을 띄운다.
- [x] 렌더러는 상태 스냅숏과 변경 이벤트만으로 그린다. 가짜 Flow API로 묶음 생성·합치기·이미 답함·되돌리기가 테스트된다.

**결정과 이유**

- 합치기
  - 같은 자리에 처리되지 않은 묶음이 여럿이면(처리됨 묶음을 되돌린 뒤) 가장 최근에 만든 묶음에 합친다. 스펙은 "되돌려도 합치지 않는다"까지만 정했다.
  - "새 멘션 N건"은 합친 멘션 가운데 묶음에 남은 것만 센다. 감지 때 이미 답한 멘션은 세지 않는다. 되돌리면 0으로 돌린다.
- 이미 답함
  - 내 답이 멘션보다 늦어야 답으로 본다. 같은 초이거나 시각을 읽을 수 없으면 답하지 않은 것으로 본다. 잘못 건너뛰면 멘션을 놓친다는 스펙의 방향을 따랐다.
  - 내 답을 조회하지 못하면 답하지 않은 것으로 보고 올린다. 이미 아는 답은 그대로 쓴다.
  - 감지 때는 새 멘션이 든 묶음 전체를 다시 판정한다. 그래서 그 사이 답한 앞선 멘션도 빠진다.
  - 내 ID는 키 확인 때 얻은 `userId`와, 판정을 통과한 알림의 `receiverId` 둘 다 쓴다.
- 되돌리기
  - 이미 답함에서 되돌리면 그때 Flow를 새로 조회해 내 답 전부를 이후 판정에서 빼기로 기록한다. 조회하지 못하면 판정 때 기록한 답만 뺀다.
  - 무시함에서 되돌리면 답을 빼지 않는다. 스펙 4절의 빼기 규칙은 이미 답함·원문 사라짐에서 되돌릴 때의 것이고, 빼면 이미 답한 앞선 멘션이 되살아난다.
  - 초안이 없으므로 둘 다 저장소 확인 필요로 돌아간다(35·38이 생성 중으로 바꾼다).
- 원문
  - 화면에 보이려고 `state.db`에 둔다(전체 기록). 맥락은 34가 초안을 만들 때 새로 조회한다.
  - 이미 답함 묶음은 빠진 멘션까지 모두 보이고, 그 밖의 묶음은 남은 멘션만 보인다.
- OS 알림
  - 새로 저장소 확인 필요가 된 묶음에만 띄우고, 조회 한 번에 하나다.
  - 합치기와 이미 답함에는 띄우지 않는다(스펙 8절 "띄우는 때"). 32의 "새 멘션" 알림을 이것으로 바꿨다.
- 창
  - 펼친 창은 일반 창이다. 크기를 바꿀 수 있고 포커스를 잃어도 닫히지 않는다.
  - 펼쳐 보기와 접어 보기는 main이 창을 닫고 연다. 보고 있던 묶음을 주소로 넘긴다.
  - 접어 보기 뒤 macOS에서는 앱을 앞으로 가져와 작은 창이 포커스를 잃고 닫히지 않게 한다.
- 영역 펼침
  - main 메모리에 창별로 둔다(앱이 켜져 있는 동안).
  - 처음에는 작은 창은 원문을 펴고 저장소를 접으며, 펼친 창은 모두 편다.
- "Flow에서 열기"
  - `connectUrl`을 먼저 쓰고, 없으면 참여 목록의 `projectUrl`을 쓴다. https 주소만 연다.
  - Flow 프로젝트 이름도 참여 목록을 받았을 때만 보인다.
- 저장소 영역은 저장소 확인 필요 묶음에만 두고 "아직 이 묶음에 쓸 저장소를 정하지 않았습니다." 한 줄을 보인다. 사유·후보·[저장소를 골라 만들기]는 38·39 몫이다.
- 목록
  - 행에는 송신자·시각·게시물·상태를 보인다. 요구 요약은 35 몫이다.
  - 빈 목록 묶음은 숨긴다(프로토타입과 같다).
- Windows 알림 클릭: 전역 처리기가 어느 알림을 눌렀는지 알려 주지 않는다. 그래서 마지막으로 띄운 묶음 알림의 묶음을 연다(실기 미확인).
- 7일이 지난 묶음의 되돌리기 막기와 정리는 47 몫이다.

    - 알림을 누르자 그 묶음(`bundle=1`)을 연 작은 창이 떴다.
    - 저장소 확인 필요 묶음에 새 멘션 505가 오자 합쳐졌다.
      - "새 멘션 1건"과 "멘션 3건"이 보였다.
      - 알림은 없었고 트레이 숫자도 그대로였다.
    - 앱 종료도 오류 없이 끝났다.

**리뷰에서 반영하지 않은 것**

  - 스펙의 렌더러 테스트는 스냅숏 렌더링만 최소로 둔다.
