# 34: 맥락 조회와 길이 상한

**Spec:** [스펙](../spec.md) 4절 "맥락 수집"

**What to build:** 묶음마다 에이전트에게 넘길 맥락(게시물 제목·본문, 대상 댓글 스레드 전부, 다른 댓글 최근 20개)을 Flow에서 새로 조회해 하나의 문서로 만들고 비교 기준으로 저장한다. 작은 창 원문 영역의 "스레드 보기"로 앞선 글을 펼쳐 볼 수 있다.

**Blocked by:** 33

**Status:** resolved

- [x] 본문은 `content` JSON의 TEXT 컴포넌트에서 꺼내고, 첨부는 파일 이름만, 이미지는 넣지 않는다. 대상 댓글 스레드는 대댓글 API로 끝까지 가져온다. 다른 댓글은 최근 20개, 댓글마다 대댓글 처음 10개.
- [x] `systemCode`가 있는 시스템 댓글은 맥락에 넣지 않고 20개 집계에도 세지 않는다.
- [x] `@[이름](ID)` 표기를 이름 표기로 바꾼다. Flow 사용자 ID는 문서에 들어가지 않는다.
- [x] 30,000자 상한과 빼는 순서(다른 댓글의 대댓글 → 다른 댓글 → 댓글 스레드 묶음의 본문 앞 10,000자 → 대상 스레드의 비멘션 대댓글), 절대 빼지 않는 것, "[다른 댓글 12개 생략]" 표시, 뺀 항목 수 기록.
- [x] 조회 결과를 비교 기준으로 묶음에 저장한다(변화 감시는 45). 조회는 초안을 만들 때마다 새로 한다.
- [x] 원문 영역의 "스레드 보기"가 맥락의 앞선 글을 펼친다.
- [x] 가짜 응답으로 수집 범위, 페이지 넘김, 자르기 순서와 표시, 표기 변환이 테스트된다.

## Comments

### 2026-10-21 구현과 검증 기록

**구조**

- Flow 어댑터(`src/core/flow/`)
  - `http-flow-api.ts`
    - 게시물의 `registerName`·`registeredDateTime`과 첨부 파일 이름을 읽는다. 파일 이름은 FILE 컴포넌트와 `attachments[]`(`fileName`·`ORCP_FILE_NM`·`FILE_NM`)에서 읽는다.
    - 댓글·대댓글의 `registerName`과 `attachments[].fileName`을 읽는다.
    - 이미지(IMAGE 컴포넌트, `imageAttachments[]`)는 읽지 않는다.
  - `bundle-context.ts`
    - `collectBundleContext(api, bundle, now)`: 맥락을 새로 조회한다. 게시물, 댓글 전부(쪽 넘김), 대상 댓글 스레드의 대댓글 전부(`replyHasNext`면 대댓글 목록 API로 끝까지)를 받는다.
      - 시스템 댓글(`systemCode`가 비어 있지 않음)은 다른 댓글을 고르기 전에 빼므로 20개 집계에 들지 않는다.
      - 다른 댓글은 최근 20개이고, 댓글마다 댓글과 함께 받은 처음 10개의 대댓글을 담는다.
      - 실패 사유: Flow API 실패, 또는 머리 댓글이 목록에 없을 때 `thread-gone`.
    - `contextDocument(context)`: 에이전트에게 넘길 문서와 뺀 것(`omissions`)을 돌려준다. `omittedItemCount`가 뺀 항목 수를 센다.
      - 멘션 표기 `@[이름](ID)`는 `@이름`으로 바꾼다.
      - 첨부는 "첨부 있음(파일 이름)"으로 쓴다.
      - 30,000자를 넘으면 스펙 순서대로 하나씩 빼고 다시 잰다. 순서는 다른 댓글의 대댓글 → 다른 댓글 → 본문 앞 10,000자(댓글 스레드 묶음만) → 대상 스레드의 멘션이 아닌 대댓글이다.
      - 뺀 자리에는 생략 표시를 넣는다: "[다른 댓글 N개 생략]", "[대댓글 N개 생략]", "[본문 뒷부분 생략]".
      - 절대 빼지 않는 것만으로 넘치면 그대로 둔다.
    - 글자 수는 코드 포인트로 센다.
  - `flow-time.ts`의 `readableFlowTime`: 문서에 쓰는 시각(`yyyy-MM-dd HH:mm`).

  - 같은 묶음을 거듭 조회하면 마지막으로 시작한 조회의 결과만 저장한다.
  - 결과는 한 번에 저장해 듣는 쪽에 한 번 알린다.

  - 펼침은 보고 있는 묶음에만 두고, 다른 묶음으로 넘어가면 접힌다(렌더러 지역 상태).

**결정과 이유**

- 조회 시점
  - 아직 초안 실행이 없어서, 초안 생성이 시작될 지점(새 묶음, 처리되지 않은 묶음에 합치기, 되돌리기)에서 새로 조회해 저장한다.
  - 감지 때 받은 내용은 쓰지 않는다. 이미 답함이 된 묶음은 조회하지 않는다.
- "스레드 보기"의 범위
  - 댓글 스레드 묶음은 게시물 본문과 대상 댓글 스레드 전부다.
  - 본문 묶음은 본문과 다른 댓글(대댓글 포함)이다. 본문 묶음에는 본문보다 앞선 글이 없다. 그래서 스펙의 "본문 묶음이면 다른 댓글이 스레드 맥락"을 따라 댓글을 펼친다.
  - 펼칠 글이 멘션뿐이거나 맥락이 없으면 버튼을 두지 않는다.
- 다른 댓글의 대댓글
  - Flow가 댓글과 함께 주는 처음 10개 가운데 시스템 대댓글을 뺀다. 그래서 10개보다 적을 수 있다.
  - 대댓글 목록 API로 더 받지 않는다. 스펙은 "처음 10개"이고, 시스템 댓글을 세지 않는 규칙은 다른 댓글 20개에만 있다.
- 본문을 자를 때: 표기를 이름으로 바꾼 뒤 자른다. 원문을 자르면 경계에 걸린 표기에서 사용자 ID 일부가 남는다(리뷰에서 찾아 고침).
- 다른 댓글의 순서: Flow가 준 순서를 그대로 믿지 않고 `registeredDateTime`, 같으면 ID 크기로 정렬한다.
