# 35: 초안 실행과 표시

**Spec:** [스펙](../spec.md) 6절 "입력", "출력"(스키마·초안 형태·구조 실패·스트리밍), "실행 제어"(타임아웃·취소), "초안 문체와 지침", "실행 기록", 8절 "상세의 영역"

**What to build:** 저장소 매핑이 있는 Flow 프로젝트의 멘션 묶음에 Claude Code 초안 실행이 돌아, 작은 창에 "에이전트가 이해한 요구", 문장마다 근거 번호가 붙은 초안, 자연어 설명과 파일·줄 위치가 있는 근거, 쓴 저장소, 실행 줄("Claude Code · 2분 14초")이 보인다. 생성 중에는 진행 단계 한 줄과 읽은 파일 수가 보이고 취소할 수 있다. 생성 직전에 Flow에 이미 내 답이 있으면 실행하지 않고 "이미 답함"이 된다. 매핑된 폴더가 하나라도 없으면 "연결된 저장소 폴더를 찾을 수 없음" 사유로 저장소 확인 필요가 된다. 매핑이 없는 묶음은 아직 저장소 확인 필요로 남는다(38이 대체).

**Blocked by:** 28, 30, 34

**Status:** ready-for-agent

- [ ] 입력 문서: 멘션 원문 전부(답할 대상 표시)와 멘션 위치, 34의 맥락, 송신자 이름, 내 이름, Flow 프로젝트 이름, 첨부 표시, 읽을 범위. stdin으로 넘긴다. Flow ID와 API 키는 넘기지 않는다.
- [ ] 기본 지침(쉬운 말, 합니다체, 결론 먼저, 5문장 이내 2문단, 인사·서명 없음, 단정 금지, 데이터 구획 규칙, 코드와 무관한 멘션 처리, 추가 지침 우선순위)을 `--append-system-prompt-file`로 넣는다.
- [ ] 초안 실행 스키마(`requirement`, `paragraphs`/`sentences`/`evidence` 번호, `evidence` 항목의 `id`·`explanation`·`repository`·`path`·`start_line`·`end_line`)를 `--json-schema`로 강제한다. 첫 저장소가 cwd, 나머지는 `--add-dir`.
- [ ] 구조 실패는 1회 재시도 뒤 실패. 초안 문장 0개는 "빈 초안" 실패. 타임아웃 10분. 취소는 프로세스 트리를 종료하고 "취소함" 실패로 둔다(자식 프로세스 정리 여부를 확인해 기록). 실패 화면에 오류와 마지막 단계, [다시 시도] [무시].
- [ ] 진행 단계: 도구 이벤트를 "파일 읽는 중: …", "검색 중: …"로 바꿔 마지막 한 줄과 읽은 파일 수를 보인다.
- [ ] 실행 기록(에이전트·CLI 버전·모델·시각·결과·마지막 단계·고친 불일치·뺀 항목 수·비용)을 저장하고, 상세 머리에 한 줄만 보인다("맥락 일부 생략" 포함).
- [ ] 생성 직전 "이미 답함" 확인(33의 규칙 재사용). 한 번에 하나만 실행하는 직렬 대기열의 기본형(우선순위는 37).
- [ ] 상태 생성 중 → 준비됨/실패 전환, 트레이 점 세 개, 준비됨 OS 알림. 생성 중 묶음에 새 멘션이 오면 실행을 취소하고 합쳐 처음부터 다시 만든다.
- [ ] 가짜 실행기·가짜 stream-json으로 입력 문서 구성, 스키마 결과 표시, 구조 실패, 타임아웃, 취소, 진행 단계가 테스트된다.
