**Spec:** [스펙](../spec.md) 6절 "입력", "출력"(스키마·초안 형태·구조 실패·스트리밍), "실행 제어"(타임아웃·취소), "초안 문체와 지침", "실행 기록", 8절 "상세의 영역"

**What to build:** 저장소 매핑이 있는 Flow 프로젝트의 멘션 묶음에 Claude Code 초안 실행이 돌아, 작은 창에 "에이전트가 이해한 요구", 문장마다 근거 번호가 붙은 초안, 자연어 설명과 파일·줄 위치가 있는 근거, 쓴 저장소, 실행 줄("Claude Code · 2분 14초")이 보인다. 생성 중에는 진행 단계 한 줄과 읽은 파일 수가 보이고 취소할 수 있다. 생성 직전에 Flow에 이미 내 답이 있으면 실행하지 않고 "이미 답함"이 된다. 매핑된 폴더가 하나라도 없으면 "연결된 저장소 폴더를 찾을 수 없음" 사유로 저장소 확인 필요가 된다. 매핑이 없는 묶음은 아직 저장소 확인 필요로 남는다(38이 대체).

  - 작은 창·펼친 창의 요구·초안·근거·저장소·실행 줄·진행·오류 영역의 배치와 접기·펴기, [취소]·[다시 시도]
  - macOS 메뉴 막대의 "⋯"(생성 중)과 빨간 점(실패), Windows 트레이의 점 세 개·빨간 점 배지
  - "초안 준비됨" OS 알림이 뜨고, 누르면 그 묶음이 열리는지
  - 이유: 렌더러 테스트는 정적 렌더링만 하고, 트레이와 OS 알림은 실제 Electron 실행이 필요하다.
- 실제 Claude Code CLI
  - 초안 실행 스키마로 `structured_output`이 오는지
  - stream-json의 실제 모양이 앱이 읽는 필드와 맞는지: `tool_use`의 `file_path`·`pattern`, `tool_result`의 `is_error`, init의 `model`, result의 `usage`·`total_cost_usd`
  - 이유: 실제 CLI 실행은 사용자의 사용량을 쓴다. 이 티켓은 항목 9대로 가짜 stream-json으로 검사했다.
- 취소·시간 초과·앱 종료 뒤의 자식 프로세스 정리: 패키지한 GUI 앱(macOS, 59)과 Windows(`.cmd` 래퍼 포함, 60)
- 실제 Flow 계정: 생성 직전의 맥락 조회와 "이미 답함" 판정이 실제 응답으로 도는지
