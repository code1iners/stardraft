# 36: 출력 검증

**Spec:** [스펙](../spec.md) 6절 "출력"(형식 위반·근거 위치 검증)

**What to build:** 에이전트 출력이 스키마에는 맞지만 내용이 어긋나면 앱이 근거가 줄어드는 쪽으로 고쳐 보여 주고, 근거로 든 파일·줄이 실제로 있는지 확인해 없으면 "위치를 찾을 수 없음"으로 표시한다. 근거가 비밀 파일이면 결과를 버리고 "비밀 파일을 근거로 듦" 실패가 된다.

**Blocked by:** 35

**Status:** resolved

- [x] 내용 불일치 표 여섯 행(없는 번호 제거, 참조 없는 근거는 끝에, 번호 다시 매김, 고친 요구로 덮어쓰기, 넘기지 않은 `repository`, 문장 0개)이 구현되고 고친 내용은 화면 없이 실행 기록에만 남는다.
- [x] 근거 위치 검증 세 가지(저장소 안 경로인지 — `..`·절대 경로·심볼릭 링크 차단, 파일 존재, 줄 범위)에 실패한 근거는 "위치를 찾을 수 없음"으로 표시되고 "에디터에서 열기"가 꺼지며 번호는 유지된다.
- [x] 근거 경로가 비밀 파일 패턴(기본 목록)에 맞으면 결과 전체를 버리고 실패("비밀 파일을 근거로 듦")로 두며 초안을 보여 주지 않는다. 대기열은 멈추지 않는다.
- [x] 임시 디렉터리의 가짜 저장소와 가짜 출력으로 여섯 행과 세 가지 검증, 비밀 파일 경로가 테스트된다.

## Comments

### 2026-10-21 구현과 검증 기록

**구조**

- 출력 검증 `src/core/drafts/draft-check.ts`(`checkDraftOutput`)
  - 스키마 모양을 통과한 초안 실행의 출력을 저장하기 전에 검증한다. 순서는 비밀 파일 근거 → 내용 불일치 → 근거 위치다.
  - 대기열(`DraftQueue.generate`)이 `saveDraft` 직전에 부른다. 고친 내용은 그 실행의 `RunRecord.fixes`에만 남기고 화면에는 알리지 않는다.
- 내용 불일치 표의 처리
  - 없는 근거 번호: 그 번호를 지운다. 남은 번호가 없으면 근거 없는 문장이다. 한 문장에 거듭 나온 번호도 하나로 줄인다.
  - 참조 없는 근거: 지우지 않고 원래 순서대로 목록 끝에 둔다.
  - 번호 겹침·건너뜀: 문장에 처음 나온 순서대로 1부터 다시 매긴다. 같은 번호의 근거가 여럿이면 처음 것만 그 번호로 가리키고, 나머지는 참조 없는 근거로 끝에 간다.
  - 고친 요구: `fixedRequirement`가 있으면 요구 문장을 덮어쓰고 요약은 에이전트가 새로 만든 것을 쓴다. 지금은 요구 고치기 재생성이 없어 대기열이 `null`을 넘긴다(41에 넘김).
  - 넘기지 않은 `repository`: 위치를 찾을 수 없는 근거로 둔다.
  - 문장 0개: 35에서 만든 "빈 초안" 실패 그대로다(검증 전에 걸러진다).
- 근거 위치 검증
  - 저장소 안 경로인지 본다. `..` 조각, POSIX·Windows 절대 경로(드라이브 문자, UNC)를 받지 않는다. 저장소 루트와 근거 파일의 심볼릭 링크를 모두 풀어 저장소 밖이면 받지 않는다.
  - 파일이 있는지(일반 파일), 줄 범위가 1 이상·시작 ≤ 끝·파일 줄 수 이하인지 본다. 줄 수는 나눠 읽어 센다.
  - 실패한 근거는 `DraftEvidence.located = false`로 남는다. 번호와 문장은 그대로다.
  - 화면(작은 창·펼친 창의 근거 영역)은 위치 대신 "위치를 찾을 수 없음"을 경고 색으로 보인다.
- 비밀 파일 근거
  - 기본 목록과 추가 패턴(`withDefaultSecretPatterns`)으로 판정한다. 맞으면 결과 전체를 버리고 `secret-evidence`("비밀 파일을 근거로 듦") 실패로 둔다. 다시 실행하지 않고, 대기열은 다음 묶음으로 넘어간다.
  - 판정하는 경로는 세 가지다.
    - 에이전트가 적은 경로(넘긴 저장소가 아니거나 참조 없는 근거여도)
    - 링크를 푼 저장소 안 경로
    - 링크가 저장소 밖을 가리키면 그 절대 경로
  - 패턴 매칭(`matchesSecretPattern`)은 실행기 deny 규칙처럼 어느 깊이에서든 맞춘다. 폴더에 맞는 패턴은 그 안 전부에 맞고, 가운데 `**`는 0단계도 맞는다. 대소문자는 가리지 않는다. 판정이 넓어지는 쪽이다.
- 저장: `state.db` 형식 7. 이미 있던 초안의 근거에 `located: true`를 넣는다. 검증 전에 만든 초안이라 보이던 대로 둔다.

**리뷰 반영** (Standards·Spec 두 축)

- 반영한 것
  - 저장소 밖 비밀 파일(예: `~/.ssh/id_rsa`)을 가리키는 링크가 "위치를 찾을 수 없음"으로만 끝나던 것을 비밀 파일 근거로 판정한다.
  - 패턴 매칭: 사용자가 추가한 `credentials`, `credentials/` 같은 폴더 패턴이 폴더 안 파일에 맞는다. `a/**/b`가 `a/b`에도 맞는다.
  - 근거마다 링크 풀기를 여러 번 하던 중복을 없앴다. 한 번의 검사 안에서는 저장소·경로별로 한 번만 푼다.
  - 줄 수를 파일 전체를 읽지 않고 나눠 읽어 센다.
  - 대기열: 검증 함수 이름을 `checkVerdict`로 바꿨다. 실행 기록의 결과는 검증 뒤에 한 곳에서 정한다.
- 반영하지 않은 것
  - 패턴의 `[...]` 문자 클래스는 글자 그대로 맞춘다. 기본 목록에 없고, 추가 패턴 입력(50)에서 다룰 수 있다.
  - 근거 `repository`를 표기 차이(끝 구분자)만 무시하고 대소문자는 가려 비교한다. 다르면 위치를 찾을 수 없는 쪽이라 안전하다.
  - 실행 기록 `fixes`에 위치를 찾지 못한 근거와 비밀 파일 판정도 넣는다. 스펙의 "고친 내용 불일치 목록"보다 넓지만, 넘기지 않은 저장소 행이 위치 실패와 같은 처리라 한 목록에 둔다.
  - 대기열 테스트의 `settle()`은 실제 시간을 조금(10ms씩 3번) 기다린다. 근거 위치 검증이 임시 폴더의 실제 파일을 읽기 때문이다. 여러 번 돌려 흔들리지 않음을 확인했다.
