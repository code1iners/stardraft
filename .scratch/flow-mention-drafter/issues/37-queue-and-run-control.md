# 37: 대기열과 실행 제어

**Spec:** [스펙](../spec.md) 6절 "실행 제어", "공통 실행 규칙"(버전 확인·점검 실행)

**What to build:** 여러 묶음이 한꺼번에 와도 에이전트는 한 번에 하나만 돌고, 사용자가 누른 재생성과 다시 시도는 맨 앞에 들어간다. 일시적인 실패는 한 번 자동으로 다시 시도한다. CLI가 사라지거나 로그아웃되면 대기열 전체가 멈추고 전역 문제로 한 번만 알리며, 해결되면 저절로 다시 돈다.

**Blocked by:** 35

**Status:** ready-for-agent

- [ ] 직렬 대기열에 우선순위가 있다. 사용자 행동(재생성·다시 시도)은 맨 앞, 한 묶음의 선택 실행 뒤 초안 실행은 맨 앞(38에서 사용).
- [ ] 자동 재시도는 일시적 실패(구조화 출력 없음, 모델 과부하, 네트워크 오류)에만 1회이고, 타임아웃·취소·형식 위반·앱 종료 중단은 세지 않는다.
- [ ] 전역 실패(CLI 없음, 미로그인, 버전 낮음, 점검 실행 실패)는 묶음을 실패 처리하지 않고 대기열을 멈춘 뒤 26의 전역 문제로 알린다. 원인이 해결되면 자동으로 재개한다. 로그인 사전 점검은 시작 시와 전역 실패 의심 시에만 한다.
- [ ] 실행 전에 CLI 버전이 바뀐 것을 알아채면 점검 실행을 먼저 돌리고, 실패하면 대기열을 멈춘다.
- [ ] 설정 변경 반영: 에이전트·모델·추가 지침·작업 폴더는 다음 실행부터, 비밀 파일 패턴 추가는 50에서 다룬다.
- [ ] 가짜 실행기·가짜 시계로 순서, 우선순위, 재시도 조건, 전역 실패 멈춤과 재개가 테스트된다.
