# 38: 자동 선택

**Spec:** [스펙](../spec.md) 5절 "자동 선택의 흐름", "매핑이 있는데 코드와 무관한 멘션", 6절 "선택 실행의 스키마"와 선택 실행 불일치 표

**What to build:** 저장소 매핑이 없는 묶음은 작업 폴더에서 찾은 후보를 놓고 선택 실행이 먼저 돌고, 고른 저장소로 초안 실행이 바로 이어진다. 화면에는 "생성 중" 하나로 보이고 진행 단계만 "저장소 고르는 중" → "초안 쓰는 중"으로 바뀐다. 확신하지 못하거나 코드와 무관하면 초안 없이 "저장소 확인 필요"에 에이전트의 사유와 후보가 보인다.

**Blocked by:** 29, 35

**Status:** ready-for-agent

- [ ] 후보가 1개면 선택 실행을 건너뛰고 그 저장소를 쓴다. 0개(작업 폴더 없음·비어 있음)면 저장소 확인 필요.
- [ ] 선택 실행: 입력은 초안 실행과 같은 맥락 + Flow 프로젝트 이름 + 후보 목록, 읽기 범위는 작업 폴더 전부(첫 폴더 cwd, 나머지 `--add-dir`), 선택 실행 전용 지침, 타임아웃 5분, 같은 맥락 길이 상한.
- [ ] 출력 스키마: 판정(`chosen`/`unsure`/`unrelated`), 후보 `enum` 배열, 이유. 불일치 표(0개면 확신 못함, 4개 이상이면 앞 3개, 빈 이유는 "이유 없음").
- [ ] 고름이 아니면 저장소 확인 필요 상태로 사유·후보를 보이고 [저장소를 골라 만들기](창은 39) [Flow에서 열기] [무시]를 둔다. OS 알림을 띄우고 트레이 숫자에 센다.
- [ ] 저장소 영역에 자동으로 고른 이유를 보인다. 자동 선택 결과를 매핑으로 자동 저장하지 않는다.
- [ ] 가짜 실행기로 세 판정과 불일치 표, 후보 0·1·여럿 경로, 잇기 순서가 테스트된다.
