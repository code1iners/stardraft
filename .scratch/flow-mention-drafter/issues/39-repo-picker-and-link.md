# 39: 저장소 선택 창과 연결 버튼

**Spec:** [스펙](../spec.md) 5절 "선택 결과의 재사용", "저장소 선택 창", 6절 재생성 표의 "다른 저장소로 다시 만들기"

**What to build:** "저장소를 골라 만들기"와 재생성 메뉴의 "다른 저장소로 다시 만들기"가 같은 저장소 선택 창을 연다. 여러 개를 고를 수 있고, 작업 폴더의 저장소와 다른 매핑에 쓰인 저장소가 후보로 보이며 "폴더 직접 고르기"도 있다. 저장소 영역의 "이 Flow 프로젝트에 연결"을 누르면 지금 구성이 매핑으로 저장된다.

**Blocked by:** 38

**Status:** resolved

- [x] 선택 창은 처음에 지금 쓰는 저장소가 체크되어 있고, 고른 구성으로 초안 실행을 돌린다(처음 입력 + 바뀐 읽기 범위, 직전 결과 없음, 지시 초기화).
- [x] 연결 버튼은 기존 매핑에 더하지 않고 덮어쓴다. 매핑이 있으면 문구가 "매핑을 이 구성으로 바꾸기"다. 선택 창 안에도 연결 버튼이 있다.
- [x] 게시 때 "앞으로도 이 저장소로?" 대화상자는 없다.
- [x] 가짜 설정 저장소로 덮어쓰기와 재생성 입력이 테스트된다.

- 저장소 선택 창 `RepoPicker`(`src/core/repos/repo-picker.ts`). 한 번에 하나만 열고 상태는 main이 가진다.
  - 후보 무리 순서
    1. 지금 쓰는 저장소(체크함)
       - 준비됨: 초안의 저장소
       - 선택 실행이 고르지 않음: 에이전트가 짚은 후보
       - 폴더가 사라짐: 고른 구성이나 매핑에서 남은 폴더
    2. 작업 폴더에서 찾은 저장소. 창을 열 때마다 설정의 작업 폴더를 새로 훑는다.
    3. 다른 Flow 프로젝트의 매핑에 쓰인 저장소. 폴더를 찾을 수 없는 것은 뺀다.
    4. "폴더 직접 고르기"로 더한 폴더(체크함). 경로는 main이 폴더 선택 창에서 받는다.
  - 같은 저장소는 앞 무리에 한 번만 든다. 체크 명령은 후보에 있는 경로만 받는다.
  - [이 저장소로 만들기]/[이 저장소로 다시 만들기]: 체크한 저장소를 후보 순서대로 넘기고 창을 닫는다.
  - 창 안의 연결 버튼: 체크한 구성으로 매핑을 덮어쓰고 창은 그대로 둔다.
  - 묶음이 고를 수 없는 상태가 되면(생성 중, 처리됨 등) 저절로 닫는다.
- 연결 버튼 `RepoMappings.replaceRepos`
  - 기존 매핑에 더하지 않고 덮어쓴다. 같은 폴더는 한 번만 둔다. 빈 구성으로는 지우지 않는다.
  - 멘션이 온 Flow 프로젝트라 참여 목록을 받지 못했어도 받는다.
  - 저장소 영역의 버튼(`RepoPicker.linkBundle`)은 렌더러가 보낸 경로를 받지 않고 묶음의 초안에서 구성을 읽는다.
  - 문구: 매핑이 없으면 "이 Flow 프로젝트에 연결", 있으면 "매핑을 이 구성으로 바꾸기"다(`RepoMappings.matchOf`, 순서까지 비교).
- 화면

  - 준비됨 저장소 영역: 쓴 저장소와 자동으로 고른 이유 아래에 연결 버튼이 있다.
  - 바닥 줄: 준비됨 묶음에 재생성 메뉴 [다시 만들기 ▾]를 두고 "다른 저장소로 다시 만들기"를 넣었다.
  - 선택 창: 작은 창과 펼친 창에서 같은 시트(`RepoPickerSheet`)로 창 전체를 덮는다. 후보는 무리별 체크 상자이고, "N개 고름"과 [닫기]가 있다.
  - 작은 창은 포커스를 잃으면 닫힌다. 그래서 "폴더 직접 고르기"의 폴더 선택 창이 떠 있는 동안에는 닫지 않는다(`AppWindows.pickFoldersOverReview`).
  - 게시 때 "앞으로도 이 저장소로?" 대화상자는 만들지 않았다.

**스펙과 다르거나 스펙에 없던 결정** (검토 대상)

- 고른 구성(`userRepos`)은 묶음에 남는다.
  - 그 뒤 생성(다시 시도, 되돌리기, 41의 다시 만들기)도 매핑보다 이 구성을 먼저 쓴다.
  - 스펙의 "다시 만들기 = 처음과 같은 구성"을 이렇게 읽었다. 설정에서 매핑을 바꿔도 이미 고른 묶음에는 반영되지 않는다.
- 이미 이 구성이 매핑이면(순서까지 같으면) 연결 버튼을 끄고 "이 Flow 프로젝트의 저장소 매핑이 이 구성입니다."를 보인다. 스펙에는 두 문구만 있다.
- cwd는 체크한 순서가 아니라 후보 목록 순서의 첫 저장소다. 지금 쓰는 저장소가 맨 앞이라, 처음 구성의 cwd가 유지된다.
- "다른 매핑에 쓰인 저장소"에는 같은 Flow 프로젝트의 매핑을 넣지 않는다. 그 저장소는 보통 지금 쓰는 저장소다.
- 고른 폴더가 사라지면 새 사유를 만들지 않고 `missing-folders`를 다시 쓴다. 문구만 "고른 저장소 폴더를 찾을 수 없음"으로 바꾼다.
- 재생성 메뉴에는 지금 "다른 저장소로 다시 만들기" 하나만 있다. 나머지 항목은 41 몫이다.
- 재생성 메뉴는 `<details>` 기반의 간단한 메뉴다.

    - 다른 매핑 후보에서 같은 Flow 프로젝트의 매핑을 뺐다.
    - 고른 폴더가 사라졌을 때 "연결된 저장소 폴더"라고 보이지 않게 했다.
    - 저장소 영역 연결 버튼 경로를 core로 옮겨 시험했다.
  - Standards
    - 지역 변수 주석 누락을 채웠다.
    - 폴더 확인(`missingFolders`)과 고를 수 있는 상태(`canPickRepos`)를 한 곳에서 쓴다.
    - 이름을 맞췄다: `runRepos`, `RepoCheckBodyProps`.
    - 선택 창이 스스로 묶음을 찾게 해 렌더러 중복을 없앴다.
- 반영하지 않은 것

- 용어집의 빈틈: "저장소 선택 창"과 "구성"은 스펙에는 있지만 `GLOSSARY.md`에는 없다. 용어를 정리할 때 넣을지 정한다.
