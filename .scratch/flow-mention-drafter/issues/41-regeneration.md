# 41: 재생성

**Spec:** [스펙](../spec.md) 6절 "재생성 입력" 표, 4절 "처리 중인 묶음에 새 멘션이 올 때" 표의 준비됨 행, 8절 "행동과 버튼"

**What to build:** 바닥 줄의 재생성 메뉴에서 "다시 만들기", "지시를 덧붙여 다시 만들기"를 고르거나, 요구 제목 옆 망치 아이콘으로 요구를 고쳐 "이 요구로 재생성"할 수 있다. 편집한 초안이 있으면 버릴지 먼저 묻는다. 준비됨 묶음에 새 멘션이 오면 손대지 않았을 때는 자동으로 다시 만들고, 손댔으면 "새 멘션 1건"과 [다시 만들기]만 띄운다.

**Blocked by:** 38, 40

**Status:** resolved

- [x] 재생성은 매번 새 실행이고 대기열 맨 앞에 들어간다. 입력 표: 다시 만들기(같은 구성), 지시 덧붙이기(처음 입력 + 직전 결과 + 지시 전부), 요구 고치기(처음 입력 + 고친 요구, 직전 결과 없음, 에이전트는 요구를 그대로 출력하고 요약만 새로). 요구를 고치면 지시를 초기화한다. 편집본은 넘기지 않는다.
- [x] 자동으로 저장소를 고른 묶음에서 이 세 경로는 선택 실행을 다시 돌리지 않는다.
- [x] 재생성하면 이전 초안과 비교 기준을 바로 지운다.
- [x] 준비됨 묶음 합치기: 초안·요구·지시를 손대지 않았으면 합치고 자동 재생성, 손댔으면 합치기만. 받는 사람을 뺀 것은 손댐이 아니며, 새 멘션의 송신자는 전에 뺐더라도 다시 더한다. 실패 묶음에 새 멘션이 오면 합치고 자동 재시도.
- [x] 가짜 실행기로 네 경로의 입력 구성과 합치기 표가 테스트된다.

## Comments

### 2026-10-21 구현과 검증 기록

**구조**

- 재생성 요청 `MentionBundles.regenerate(bundleId, RegenerationRequest)` (`core/bundles/mention-bundles.ts`)
  - 경로는 `RegenerationPath`(`core/drafts/draft.ts`): `again`(다시 만들기), `directive`(지시를 덧붙여 다시 만들기), `requirement`(요구 고치기). 다른 저장소로 다시 만들기는 기존 `regenerateWithRepos`이고 지시와 고친 요구를 지운다.
  - 준비됨 묶음만 받는다. 생성 중으로 올리면서 직전 초안·편집본·비교 기준(`context`)·새 멘션 수를 바로 지운다(`clearedForRegeneration`).
  - 경로별 값은 `regenerationInputsOf` 한곳에서 정한다.
    - 다시 만들기: 지시는 그대로 두고 고친 요구는 지운다.
    - 지시 덧붙이기: 앞뒤 공백을 뗀 지시를 끝에 더한다.
    - 요구 고치기: 줄바꿈을 공백으로 이어 한 문장으로 두고, 지시를 비운다.
    - 빈 지시나 빈 요구는 받지 않는다.
  - 다음 초안 실행에 넘길 것은 `MentionBundle.regeneration`(`Regeneration`)에 둔다.
    - `previous`: 지시 덧붙이기일 때만 직전 초안의 요구·초안·근거(`PreviousResult`)를 담는다. 편집본은 넣지 않는다.
    - `autoSelected`: 직전 초안이 자동 선택으로 정한 저장소와 그 내력이다.
    - 초안을 저장하면 지운다. 실패하면 남겨서 [다시 시도]가 같은 입력으로 다시 만든다.
- 묶음 필드: `directives`(덧붙인 지시, 순서대로), `fixedRequirement`, `regeneration`. `state.db` 형식 11에 `directives`, `fixed_requirement`, `regeneration` 열을 더했다.
- 초안 실행(`core/drafts/draft-queue.ts`, `draft-input.ts`)
  - 재생성은 매번 새 실행이고 `'user'` 우선순위로 대기열에 들어가 감지 묶음보다 앞선다(다시 시도와 같은 자리).
  - 입력 문서
    - 지시 덧붙이기면 "# 직전 결과"와 "# 덧붙인 지시" 전부를 넣는다.
    - 요구 고치기면 "# 고친 요구"를 넣는다.
    - 다시 만들기면 처음과 같은 구성이다(Flow 내용은 실행 직전에 새로 조회).
  - 지침에는 "# 고친 요구가 있으면 다시 해석하지 않고 requirement.text에 그대로 쓰고 summary만 새로 쓴다"는 규칙을 넣었다. 출력의 요구가 달라도 앱이 고친 요구로 덮어쓰고, 실행 기록의 고친 것(`fixes`)에 남긴다.
  - `regeneration.autoSelected`가 있고 저장소 매핑이 여전히 없으면 선택 실행 없이 그 저장소로 초안 실행만 돌린다.
- 새 멘션 합치기(`applyDetection` → `mergedNewMentions`)
  - 준비됨 묶음
    - 손대지 않았으면(`isDraftTouched`가 거짓) 다시 만들기로 생성 중에 올린다.
    - 손댔으면 "새 멘션" 수만 센다. 손댐은 편집본, 고친 요구, 덧붙인 지시 가운데 하나라도 있는 것이다. 받는 사람 빼기는 손댐이 아니다.
  - 실패 묶음은 다시 시도로 생성 중에 올린다. 재생성 중에 실패했으면 같은 재생성 입력에 새 멘션을 넣는다.
  - 새 멘션의 송신자는 전에 뺐더라도 받는 사람에 다시 더한다.
- 화면(`renderer/src/BundleDetail.tsx`)
  - 바닥 줄 재생성 메뉴: 다시 만들기 / 지시를 덧붙여 다시 만들기 / 다른 저장소로 다시 만들기.
    - 지시를 고르면 바닥 줄이 지시 칸(`DirectiveForm`)이 된다. 앞서 덧붙인 지시가 있으면 목록으로 보인다.
    - 편집본이 있을 때 다시 만들기나 다른 저장소를 고르면 먼저 "편집한 초안을 버리고 다시 만들까요?"를 묻는다(`DiscardEditConfirm`).
  - "에이전트가 이해한 요구" 제목 옆 망치 버튼을 누르면 접혀 있던 영역을 펼치고 요구 칸(`RequirementEditor`)을 연다. 칸에는 지금 요구가 채워져 있고 [이 요구로 재생성] 버튼이 있다. 덧붙인 지시가 있으면 "덧붙인 지시 N개는 지워집니다"를 보인다.
  - 지시 칸과 요구 칸에서 편집본이 있으면 "편집한 초안은 버리고 다시 만듭니다."를 보이고, 버튼 이름도 "편집본을 버리고 …"로 바꾼다.
  - 알림 줄: "새 멘션 N건"과 [다시 만들기]. 편집본이 있으면 같은 줄에서 먼저 묻는다.
- IPC 명령: `regenerate-bundle`, `regenerate-with-directive`, `fix-requirement`. 지시와 고친 요구의 길이 상한은 `REGENERATION_TEXT_MAX_LENGTH`다. 로그는 `directive`·`directives` 필드 값을 가린다.

**스펙과 다르거나 스펙에 없던 결정** (검토 대상)

- 다시 만들기(새 멘션으로 자동으로 다시 만드는 경우 포함)는 고친 요구를 지우고, 덧붙인 지시는 묶음에 남긴다. 다만 입력에는 넣지 않는다.
  - 스펙은 지시를 초기화하는 경우로 요구 고치기와 저장소 바꾸기만 적었다. 그래서 다음에 지시를 덧붙이면 "지금까지 덧붙인 지시 전부"가 함께 간다.
  - 그 결과 지시를 한 번이라도 덧붙인 묶음은 다시 만든 뒤에도 "손댐"으로 본다. 그 뒤에 새 멘션이 오면 자동으로 다시 만들지 않고 "새 멘션 1건"만 띄운다. 다르게 하려면 스펙에서 정해야 한다.
- 사용자 행동끼리는 누른 순서대로 돈다. 재생성은 다시 시도와 같은 `'user'` 자리에 들어가며, 이미 기다리는 사용자 행동이나 시험 묶음이 있으면 그 뒤에 선다.
- 자동으로 고른 저장소의 폴더가 사라졌으면 재생성에서 자동 선택을 다시 돌린다. 스펙에 없던 보완이다.
- 요구 고치기에서 편집본이 있으면 따로 확인 줄을 띄우지 않는다. 대신 칸 안의 안내와 버튼 이름("편집본을 버리고 이 요구로 재생성")으로 묻는다. 지시 칸도 같다. 다시 만들기와 다른 저장소는 확인 줄을 띄운다.
- "지시"의 코드 이름은 `directive(s)`다. 글로서리가 지침(`instructions`)과의 혼동을 막고 있어서다.
