# 43: 게시

**Spec:** [스펙](../spec.md) 9절 "게시 위치", "게시 본문", "게시 성공", "보내기 전 기록", 7절의 게시 중 상태

**What to build:** [게시]를 누르면 5초 카운트다운 토스트가 뜨고 그동안 취소할 수 있다. 끝나면 받는 사람 멘션 표기 뒤에 편집기 텍스트를 이은 게시 본문이 본문 묶음은 새 댓글로, 댓글 스레드 묶음은 그 댓글의 대댓글로 올라간다. 게시됨이 되면 바로 다음 묶음으로 넘어간다.

**Blocked by:** 40

**Status:** ready-for-agent

- [ ] 게시 본문: `@[이름](ID)` 표기를 공백으로 이어 맨 앞에 두고 공백 하나 뒤에 편집기 텍스트(앞뒤 공백 제거)를 같은 줄에서 잇는다. 받는 사람이 없으면 텍스트만. 근거·번호·AI 표시는 없다.
- [ ] 위치: `remarkId`가 `-1`이면 `POST /user/comments/{postId}`, 아니면 `POST /user/comments/{postId}/replies/{remarkId}`.
- [ ] [게시]는 텍스트가 비었거나 4,000자를 넘거나 게시 결과 확인 중이면 꺼진다. 확인 창은 없다.
- [ ] 보내기 직전에 "게시 요청 보냄"과 게시 본문을 `state.db`에 먼저 적는다. 성공하면 `commentId`/`replyId`를 기록하고 게시됨으로 둔다.
- [ ] 카운트다운 중 들어온 새 멘션은 합치지 않고 새 묶음이 된다(게시 전 확인이 끝난 뒤 기준은 46에서 정밀화).
- [ ] 게시하거나 무시하면 다음 준비된 묶음으로 넘어간다. 게시 중 상태는 검토 대기 목록에 남되 트레이 숫자에서는 빠진다.
- [ ] 가짜 Flow API와 가짜 시계로 본문 조립, 위치, 카운트다운과 취소, 보내기 전 기록, 성공 기록이 테스트된다.
