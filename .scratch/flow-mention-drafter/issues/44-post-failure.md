# 44: 게시 실패와 응답 없음

**Spec:** [스펙](../spec.md) 9절 "게시 실패", "올라갔는지 알 수 없을 때의 확인"

**What to build:** 게시가 실패하면 다른 묶음을 보고 있어도 토스트("게시하지 못했습니다: 김철수님 멘션")가 뜨고 트레이에 빨간 점이 생기며 실패 목록에 들어간다. 상세 머리에 쉬운 말 사유가 보이고 초안은 그대로 남아 [다시 게시]할 수 있다. Flow가 응답하지 않으면 실제로 올라갔는지 다시 조회해 정한다.

**Blocked by:** 43

**Status:** resolved

- [x] 응답별 표: `403` 권한 없음, `404`/`412` 지워짐, `400`/`422` 받지 않음, `429`는 `Retry-After` 뒤 한 번 더 보내고 또 실패하면 한도 초과, `401`은 묶음 실패가 아니라 "키 확인 필요"와 준비됨 유지, 응답 없음/`5xx`는 확인 절차.
- [x] 확인 절차: 그 자리(게시물 댓글 또는 스레드 대댓글)를 다시 조회해 이 PC가 기록한 적 없는 내 글 가운데 게시 본문과 똑같은 글을 찾는다. 찾으면 게시됨과 ID 기록, 못 찾으면 게시 실패("Flow가 응답하지 않았습니다"). 그대로 재시도하지 않는다.
- [x] 게시 실패 상태: 실패 목록, 빨간 점, 토스트 한 번, 상세 머리 사유, 편집 가능, [다시 게시] [무시].
- [x] 가짜 Flow API로 응답 코드 전부와 내용 일치 확인이 테스트된다.

## Comments

### 2026-10-22 구현과 검증 기록

**구조**

- 묶음 상태 `post-failed`(게시 실패)
  - 실패 목록에 들고 트레이 빨간 점의 대상이며(`MentionBundles.hasFailure`), 트레이 숫자에는 세지 않는다.
  - 할 수 있는 일: 편집, 받는 사람 빼기, [다시 게시], [무시]. 다시 만들기(재생성 메뉴, 요구 고치기 망치)는 막았다(`canRegenerate`는 준비됨만).
  - 새 멘션은 준비됨과 같이 합쳐지고 "새 멘션 N건"을 센다.
- 게시 기록(`PostingRecord`)에 `failure`(사유)를 더했다: `forbidden`, `gone`, `rejected`, `rate-limited`, `no-response`.
  - `state.db` 열은 그대로이고(JSON), 사유가 없는 형식 12의 기록은 `failure: null`로 읽는다.
  - 결과(`postedId`, `failure`)가 모두 없는 게시 기록이 "올라갔는지 모르는 게시"다.
- 응답별 처리(`core/posting/posting.ts`)

  | 응답 | 처리 |
  | :- | :- |
  | `403` | 게시 실패, 사유 `forbidden` |
  | `404`, `412` | 게시 실패, 사유 `gone` |
  | `400`, `422`와 그 밖의 거절 | 게시 실패, 사유 `rejected` |
  | `429` | 기다렸다가 한 번 더 보낸다. 다시 `429`면 게시 실패, 사유 `rate-limited` |
  | `401` | "키 확인 필요"를 올리고 준비됨으로 둔다 |
  | 응답 없음, `5xx`, 모르는 응답, 요청 예외 | 확인 절차 |

  `429`를 기다리는 동안 묶음은 게시 중("게시 결과 확인 중")으로 남는다.
- 확인 절차(`Posting.checkOutcome`)
  - 그 자리(본문 묶음은 게시물 댓글, 댓글 스레드 묶음은 그 스레드의 대댓글)를 `MentionJudge.myWritings`로 다시 조회한다.
  - 이 PC가 기록한 적 없는(`MentionBundles.postedIds`) 내 글 가운데 내용이 게시 본문과 똑같은 글을 찾는다. 찾으면 그 ID로 게시됨이고, 못 찾으면 사유 `no-response`로 게시 실패다. 그대로 다시 보내지 않는다.
  - 조회하지 못하면(네트워크, `5xx`, `429`, `401`, 쓸 키 없음, 예외) 게시 중으로 둔 채 60초(`429`면 `Retry-After`) 뒤 다시 확인한다.
- 화면
  - 실패한 순간 `Posting.onFailed`가 한 번 알리고, main이 열린 창에 `post-failed` 이벤트를 보낸다.
  - 창은 "게시하지 못했습니다: 김철수님 멘션" 토스트를 5초 동안 띄운다. 다른 묶음을 보고 있어도 뜬다.
  - 상세 머리(작은 창·펼친 창)에 사유 한 줄을 보인다.
    - "이 글에 댓글을 쓸 권한이 없습니다"
    - "글이나 댓글이 지워졌습니다"
    - "Flow가 글을 받지 않았습니다(길이 등)"
    - "Flow 요청 한도를 넘었습니다"
    - "Flow가 응답하지 않았습니다"
  - 바닥 줄은 [무시]와 [다시 게시]다. 게시할 수 없는 글로 고쳤으면 [다시 게시]를 끈다.
- 가짜 Flow API에 두 가지를 더했다.
  - `loseResponseOn`: 요청은 처리하고 응답만 잃는 대본
  - `removeComment`: 댓글 지우기

**검증** (마지막 변경 뒤, macOS, Node 24)

- `pnpm typecheck`, `pnpm lint` 통과
- `pnpm test`: 42개 파일, 테스트 768개 통과
- 게시(가짜 Flow API·가짜 시계·메모리 저장소)
  - 응답별 처리: `403`, `404`, `412`, `400`, `422`, 그 밖의 `409`, `401`
  - `429`
    - 3초 뒤 다시 보내 성공(2,999ms에는 보내지 않음)
    - 두 번째도 `429`면 실패
    - `Retry-After` 없음은 10초
    - 60초 초과는 바로 실패
  - 확인 절차
    - 응답만 잃고 올라감(`network`, `502`, 모르는 응답)과 본문 묶음 → 게시됨, POST 한 번
    - 올라가지 않음(`503`) → `no-response`
    - 한 글자 다른 글, 남이 쓴 같은 글, 다른 묶음이 기록한 같은 본문은 올라간 글로 보지 않음
    - 조회 실패나 조회 예외 → 60초 뒤 다시 확인해 게시됨
    - 머리 댓글 지워짐 → `gone`, 게시물 `403` → `forbidden`
    - 요청 예외 → 확인을 거쳐 `no-response`, 로그에 게시 본문 없음
  - 게시 실패 상태
    - 실패 알림 한 번, 빨간 점, 트레이 숫자 0
    - 편집과 받는 사람 빼기 뒤 [다시 게시]가 5초를 다시 세고 고친 본문을 올림
    - 무시는 되고 재생성은 막힘
- `state.db`: 사유 왕복, 형식 12의 사유 없는 기록 읽기
- 스냅숏: 게시 실패의 목록 묶음, 사유, `canEdit`, `canRegenerate`, `canPost`. 게시 실패가 아니면 사유 없음.
- 렌더러: 태그, 사유 한 줄 다섯 가지, [무시]·[다시 게시]와 끄기, 재생성 메뉴·망치 없음, 펼친 창 실패 목록, 실패 토스트 문구
- 빌드: 작업 폴더 밖 임시 폴더로 `electron-vite build` 성공

- 실제 창에서 게시가 실패했을 때 다른 묶음을 보고 있어도 토스트가 한 번 뜨고, 트레이에 빨간 점이 생기는지

**스펙과 다르거나 스펙에 없던 결정** (검토 대상)

- `429` 대기 시간
  - `Retry-After`가 없으면 10초를 기다리고, 1초보다 짧으면 1초를 기다린다.
  - 60초를 넘으면 기다리지 않고 바로 "Flow 요청 한도를 넘었습니다"로 게시 실패다. 묶음이 오래 게시 중에 묶이지 않게 하려는 것이고, 키 확인(`flow-account.ts`)의 규칙과 같다.
  - 스펙은 "`Retry-After`만큼 기다렸다가"이며 상한을 두지 않았다.
- 확인 절차의 실패 사유
  - 다시 조회했을 때 자리가 지워졌으면 "글이나 댓글이 지워졌습니다", 볼 수 없으면 "이 글에 댓글을 쓸 권한이 없습니다"로 정한다. 스펙은 못 찾으면 모두 "Flow가 응답하지 않았습니다"다.
  - 조회하지 못하면 실행 중에도 60초마다 다시 확인한다. 스펙은 다시 켤 때만 "다음 폴링에서 다시"를 정했다.
  - 키를 고치지 않는 동안(`401`)에는 게시 중으로 남고, 확인할 때마다 "키 확인 필요"를 다시 알린다.
- 그 밖의 거절(`409` 등 `4xx`, 응답 코드가 표에 없는 것)은 "Flow가 글을 받지 않았습니다(길이 등)"로 둔다.
- 확인 절차는 계정 ID 하나로 내 글을 가린다. 이것은 같은 자리의 내 답 조회(`findMyAnswers`, `collectContext`)와 같은 규칙이다. 감지가 함께 쓰는 알림의 `receiverId`는 멘션에 저장하지 않아 쓰지 않는다.
- 게시 실패 토스트는 실패한 순간 열린 창에만 뜬다. 창이 닫혀 있었으면 빨간 점과 실패 목록으로 알 수 있다.
- 게시 실패에서 받는 사람 빼기를 "편집"에 넣어 허용했다.
