# 45: 준비된 뒤의 변화 감시

**Spec:** [스펙](../spec.md) 11절, 4절 "이미 답함 판정"의 앱이 올린 글의 범위와 되돌린 뒤 재판정, 8절 알림 줄과 태그

**What to build:** 사용자 행동을 기다리는 묶음의 스레드를 폴링마다 다시 조회해, 새 글이나 원문 수정이 있으면 초안 위에 "초안을 만든 뒤 새 글 2건 · 원문 수정됨"과 [다시 만들기]가 뜨고 원문 영역에 "새 글"·"수정됨" 태그가 붙는다. Flow에 내 답이 생기면 "이미 답함"으로, 멘션이 모두 사라지면 "원문 사라짐"으로 자동으로 옮겨지되 초안은 남는다. 되돌리면 같은 이유로 다시 옮겨지지 않는다.

**Blocked by:** 34, 43

**Status:** ready-for-agent

- [ ] 대상은 준비됨·실패·게시 실패·저장소 확인 필요이고, 폴링 뒤 묶음마다 재조회한다. 검토 화면을 열 때는 조회하지 않는다. 비교 기준은 34가 저장한 내용이다.
- [ ] 범위: 댓글 스레드 묶음은 그 스레드 전체, 본문 묶음은 본문과 댓글(대댓글 제외). 다른 댓글·첨부·시스템 댓글·댓글 스레드 묶음의 본문 수정은 범위 밖. 초안 없는 묶음은 이미 답함·원문 사라짐만 판정.
- [ ] 변화별 처리 표 네 행. 알리기만 하는 경우 자동 재생성은 없고 트레이 숫자·점은 바뀌지 않는다. 보고 있던 묶음이 이미 답함이 되면 화면을 넘기지 않고 태그만 바꾸며 "Flow에 이미 내 답이 있습니다 · 되돌리기"를 띄운다.
- [ ] 사라짐 판정: 목록에 없음·`404`, 대댓글 목록 `412`, 표기 제거, `403`, 머리 댓글 삭제(대댓글이 남아도 묶음 전체). 네트워크·`5xx`·`429`는 아님. 일부 남으면 준비됨 유지와 "멘션 1건 사라짐", 송신자에게 남은 멘션이 없으면 받는 사람에서 뺀다.
- [ ] 이 PC가 게시한 글은 게시를 누를 때 조회한 내용에 있던 멘션에만 답한 것으로 보고, 다른 글은 `registeredDateTime`으로 판정한다. 되돌리면 그때의 내 답과 사라진 멘션을 기록해 이후 판정에서 뺀다.
- [ ] 가짜 Flow API와 가짜 시계로 표 네 행, 사라짐 판정 전부, 재판정, 범위 규칙이 테스트된다.
