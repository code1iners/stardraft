# 45: 준비된 뒤의 변화 감시

**Spec:** [스펙](../spec.md) 11절, 4절 "이미 답함 판정"의 앱이 올린 글의 범위와 되돌린 뒤 재판정, 8절 알림 줄과 태그

**What to build:** 사용자 행동을 기다리는 묶음의 스레드를 폴링마다 다시 조회해, 새 글이나 원문 수정이 있으면 초안 위에 "초안을 만든 뒤 새 글 2건 · 원문 수정됨"과 [다시 만들기]가 뜨고 원문 영역에 "새 글"·"수정됨" 태그가 붙는다. Flow에 내 답이 생기면 "이미 답함"으로, 멘션이 모두 사라지면 "원문 사라짐"으로 자동으로 옮겨지되 초안은 남는다. 되돌리면 같은 이유로 다시 옮겨지지 않는다.

**Blocked by:** 34, 43

**Status:** resolved

- [x] 대상은 준비됨·실패·게시 실패·저장소 확인 필요이고, 폴링 뒤 묶음마다 재조회한다. 검토 화면을 열 때는 조회하지 않는다. 비교 기준은 34가 저장한 내용이다.
- [x] 범위: 댓글 스레드 묶음은 그 스레드 전체, 본문 묶음은 본문과 댓글(대댓글 제외). 다른 댓글·첨부·시스템 댓글·댓글 스레드 묶음의 본문 수정은 범위 밖. 초안 없는 묶음은 이미 답함·원문 사라짐만 판정.
- [x] 변화별 처리 표 네 행. 알리기만 하는 경우 자동 재생성은 없고 트레이 숫자·점은 바뀌지 않는다. 보고 있던 묶음이 이미 답함이 되면 화면을 넘기지 않고 태그만 바꾸며 "Flow에 이미 내 답이 있습니다 · 되돌리기"를 띄운다.
- [x] 사라짐 판정: 목록에 없음·`404`, 대댓글 목록 `412`, 표기 제거, `403`, 머리 댓글 삭제(대댓글이 남아도 묶음 전체). 네트워크·`5xx`·`429`는 아님. 일부 남으면 준비됨 유지와 "멘션 1건 사라짐", 송신자에게 남은 멘션이 없으면 받는 사람에서 뺀다.
- [x] 이 PC가 게시한 글은 게시를 누를 때 조회한 내용에 있던 멘션에만 답한 것으로 보고, 다른 글은 `registeredDateTime`으로 판정한다. 되돌리면 그때의 내 답과 사라진 멘션을 기록해 이후 판정에서 뺀다.
- [x] 가짜 Flow API와 가짜 시계로 표 네 행, 사라짐 판정 전부, 재판정, 범위 규칙이 테스트된다.

## Comments

### 2026-10-22 구현과 검증 기록

**구조**

- 감시 시점
  - `MentionDetection`은 알림 조회를 끝까지 마친 폴링마다 `MentionBundles.watchWaiting()`을 부른다.
  - 알림 목록이나 판정에서 키 거부·연결 실패·요청 한도로 멈춘 폴링에서는 부르지 않는다. 감시가 예외로 끝나도 폴링은 이어 간다.
  - 검토 화면을 열 때는 조회하지 않는다.
- 대상과 조회
  - `isWatched`는 준비됨·실패·게시 실패·저장소 확인 필요다. 대기열 순서로 하나씩 `collectContext`(34의 맥락 조회)를 부른다.
  - 쓸 키가 없거나 `401`·네트워크 오류·`429`이면 이번 감시를 멈춘다. `5xx`와 모르는 응답이면 그 묶음만 건너뛴다.
  - 생성 중·게시 중·처리됨 묶음은 감시하지 않는다. 조회하는 사이 상태가 바뀐 묶음에는 반영하지 않는다.
- 판정(`applyWatch`)
  - 새로 찾은 내 답으로 감지 때와 같은 규칙(`judgeAnswered`)을 다시 판정한다.
  - 사라진 멘션은 `BundledMention.gone`으로 묶음에서 뺀다. `activeMentions`에서 빠지므로 대기열 순서와 받는 사람에도 들지 않는다.
  - 남아 있던 멘션이 모두 빠지면 처리됨으로 옮긴다. 이번에 하나라도 내 답으로 빠졌으면 "이미 답함"(`already-answered`), 아니면 "원문 사라짐"(`source-gone`, 새 상태)이다. 초안과 편집본은 그대로 둔다.
  - 초안이 있는 묶음만 조회한 맥락을 `MentionBundle.watchedContext`(감시 내용)로 둔다. 비교 기준(`MentionBundle.context`)은 바꾸지 않는다.
  - 조회 시각 말고 바뀐 것이 없으면 저장하지도 알리지도 않는다. OS 알림은 띄우지 않는다.
- 사라짐 판정(Flow 어댑터)
  - `collectBundleContext`가 묶음의 멘션 가운데 사라진 것(`goneMentions`)을 함께 돌려준다.
    - 목록에 없는 대댓글, 수정되어 내 표기가 빠진 글이 해당한다.
    - 본문은 `MENTIONS`와 표기를 둘 다 보며, 감지와 같은 `postBodyMentions`를 쓴다.
  - `isSourceGone`에 `412`를 더했다. 게시물 `404`·`403`, 머리 댓글 없음, 대댓글 목록 `412`면 묶음 전체가 사라진 것이다.
  - `MentionJudge`도 `412`를 지워짐으로 본다.
    - 감지에서는 그 알림을 버린다.
    - 게시 결과 확인에서는 "글이나 댓글이 지워졌습니다"로 정한다(44가 넘긴 것).
- 변화 계산(`bundleChanges`, `core/flow/context-changes.ts`)
  - 지켜볼 범위의 글(`watchedWritings`): 댓글 스레드 묶음은 머리 댓글과 대댓글 전부, 본문 묶음은 본문과 댓글이다.
  - 비교 기준에 없던 글은 새 글, 글이 바뀐 글은 수정된 글이다. 첨부의 변화와 시스템 댓글(맥락에 없음)은 보지 않는다.
- 이 PC가 게시한 글이 답한 범위
  - 게시 기록에 `answeredMentions`(그 글이 답한 멘션 위치)를 더했다.
  - `judgeAnswered`는 이 PC가 게시한 글(`postedRanges`)을 그 범위의 멘션에만, 시각과 관계없이 답한 것으로 본다. 다른 글은 `registeredDateTime`으로 판정한다.
  - 43의 `notPostedByOtherBundles`를 대신하며, 감지·초안 실행 직전·감시·되돌리기가 모두 이 규칙을 쓴다.
- 되돌리기
  - 이미 답함·원문 사라짐에서 되돌리면 그때 Flow에 있는 내 답을 새로 조회해 `excluded`로 기록한다.
  - 사라진 멘션은 `goneExcluded`로 기록하고 다시 묶음에 넣는다(받는 사람도 돌아온다). 이후 판정은 둘을 빼고 한다.
  - 초안이 있으면 그대로 준비됨, 없으면 생성 중(또는 저장소 확인 필요)이다.
- `state.db` 형식 13: `mention.gone`, `mention.gone_excluded`, `mention_bundle.watched_context`. 게시 기록 JSON에 `answeredMentions`.
- 화면
  - 스냅숏은 `BundleSnapshot.changes`(새 글 수, 원문 수정 여부, 사라진 멘션 수)를 넘긴다.
  - 멘션은 지금 내용과 `edited`, "스레드 보기"의 글은 `change`(`new`·`edited`)를 넘긴다.
  - 초안 위 알림 줄은 "새 멘션 1건 · 초안을 만든 뒤 새 글 2건 · 원문 수정됨 · 멘션 1건 사라짐"처럼 한 줄로 잇고, 준비됨이면 [다시 만들기]를 둔다.
  - 원문 영역은 수정된 멘션에 "수정됨"을 붙이고, 새로 달린 글을 멘션 뒤에 "새 글"로 보인다. "스레드 보기"에도 같은 태그를 붙인다.
  - 상태 태그 "원문 사라짐", 처리됨 안내 "Flow에서 멘션이 모두 사라져 처리했습니다."를 더했다.
  - 보던 묶음이 보는 사이 이미 답함·원문 사라짐이 되면(`resolveSelection`) 다음 묶음으로 넘기지 않고 태그만 바뀐다. 이미 답함이면 "Flow에 이미 내 답이 있습니다 · 되돌리기"를 띄운다.

**결정과 이유** (스펙에 없거나 스펙을 해석한 것, 검토 대상)

- 본문 묶음의 지켜볼 댓글(34가 45에 넘긴 결정)
  - 비교 기준에 든 최근 댓글 20개와 그 뒤에 달린 댓글을 본다.
  - 비교 기준의 가장 오래된 댓글보다 앞선 댓글은 에이전트가 보지 않은 글이라 새 글로도, 수정으로도 세지 않는다.
  - 감시 내용도 최근 20개라, 한 주기에 새 댓글이 20개를 넘게 달리면 20건까지만 센다.
- 게시한 글이 답한 범위의 채우는 값
  - 스펙은 "게시를 누를 때 조회한 내용에 있던 멘션"이다. 그 조회는 46이 만든다.
  - 그 전까지는 게시 요청을 보낼 때 묶음에 남은 멘션으로 채운다. 게시 중에는 새 멘션이 합쳐지지 않아 [게시]를 누를 때와 같다.
  - 범위가 생기기 전의 게시 기록(형식 12)은 그 묶음의 멘션으로 읽는다. 43이 판정하던 것과 같다.
- 수정과 사라짐을 함께 셀 때
  - 표기만 지워진 멘션 글은 "멘션 N건 사라짐"으로만 알리고 "원문 수정됨"으로 세지 않는다.
  - 내 답으로 이미 빠진 멘션은 사라져도 사라진 멘션 수에 세지 않는다.
- 새 글로 세지 않는 것
  - 묶음의 멘션 글은 "새 멘션 N건"으로 따로 알린다.
  - 되돌릴 때 기록한 내 답은 사용자가 보고 되돌린 것이다. 세면 되돌린 뒤 바로 누른 게시가 46의 확인에서 멈춘다.
- 초안이 없는 묶음
  - 이미 답함과 원문 사라짐만 판정하고, 알림 줄과 맥락 갱신은 하지 않는다.
  - 일부가 사라진 멘션은 묶음에서 뺀다. 나중에 만들 초안이 지워진 멘션에 답하고 그 송신자를 받는 사람에 넣지 않게 하려는 것이다.
- 알림 줄과 원문 영역
  - 새 멘션과 변화를 두 줄이 아니라 한 줄로 이었다. [다시 만들기]가 둘이 되지 않게 하려는 것이다.
  - 새로 달린 글은 "스레드 보기"를 펼치지 않아도 멘션 뒤에 보인다. 알림 줄의 "새 글 N건"이 무엇인지 바로 보이게 하려는 것이다.
- 화면 유지와 이미 답함 줄
  - 보는 사이 옮겨진 경우에만 적용한다. 다른 경우의 대기열 따라가기는 예전과 같다.
  - "Flow에 이미 내 답이 있습니다 · 되돌리기"는 옮겨진 직후 그 묶음을 보는 동안만 띄운다. 나중에 처리됨 목록에서 열면 바닥 줄의 안내와 [되돌리기]만 있다.
  - 원문 사라짐은 스펙에 따로 문구가 없어 태그와 처리됨 안내만 바꾼다.
