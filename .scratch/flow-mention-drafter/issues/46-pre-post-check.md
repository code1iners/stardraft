# 46: 게시를 누를 때의 확인

**Spec:** [스펙](../spec.md) 10절

**What to build:** [게시]를 누르는 순간 Flow를 한 번 더 조회해, 이미 내 답이 있거나 원문이 사라졌거나 화면에 없던 새 글·수정이 있으면 카운트다운 안에서 게시를 멈추고 토스트로 알린다. 이미 알림 줄에 떠 있던 변화뿐이면 그대로 게시한다. 조회가 실패하거나 늦으면 그대로 게시한다.

**Blocked by:** 45

**Status:** resolved

- [x] 확인 결과 표 다섯 행이 구현된다. 멈춘 토스트 문구는 "게시하지 않았습니다: Flow에 이미 내 답이 있음 · 되돌리기", "게시하지 않았습니다: 새 글 1건 · 보기".
- [x] 나를 멘션한 새 글도 멈춘다. 멈춘 뒤 다음 폴링의 알림은 준비됨 합치기 규칙으로 합쳐진다. 확인이 끝난 뒤 들어온 멘션만 "게시 중 행"(합치지 않음)을 적용한다.
- [x] 카운트다운이 끝난 뒤 5초가 지나도 조회가 끝나지 않으면 게시한다.
- [x] 조회한 내용을 "이 PC가 게시한 글이 답한 범위"로 저장한다.
- [x] 가짜 Flow API와 가짜 시계로 다섯 행과 시간 경계가 테스트된다.

## Comments

### 2026-10-22 구현과 검증 기록

**구조**

- 확인의 시작과 시간
  - `Posting.post`는 묶음을 게시 중으로 두는 순간 `MentionBundles.checkBeforePost`를 시작한다.
  - 확인이 게시를 멈추면 카운트다운도 지운다. 그 묶음은 바로 다시 [게시]할 수 있다.
  - 카운트다운이 끝날 때 확인이 끝났으면(통과 또는 조회 실패) 게시 요청을 보낸다.
  - 끝나지 않았으면 5초(`POST_CHECK_GRACE_MS`)를 더 기다린다.
    - 그 안에 끝나면 결과를 따른다. 통과하면 그 자리에서 보내고, 멈추면 보내지 않는다.
    - 5초가 지나면 `endPostCheck`로 확인을 끝난 것으로 표시하고 그대로 보낸다. 늦게 온 결과는 버린다.
  - 카운트다운 중 [취소]하면 확인도 버린다. 다시 누르면 새로 조회한다.
- 확인 상태(`MentionBundles`의 `postChecks`)
  - 메모리에만 둔다. 앱이 꺼져 카운트다운이 끊기면 함께 버려진다.
  - 게시 중이 되는 줄(lane) 안에서 만든다. 게시 요청을 보내거나, 취소·멈춤·준비됨으로 돌아갈 때 지운다.
- 판정(`checkBeforePost`)
  - `collectContext`로 다시 조회하고, 45의 `applyWatch`(감시와 같은 규칙)로 반영한다. 관찰 변환(`observationOf`)은 감시와 함께 쓴다.

  | 결과 | 처리 |
  | :- | :- |
  | 남은 멘션이 모두 내 답으로 빠짐 | "이미 답함"으로 옮김. 멈춤 `already-answered` |
  | 남은 멘션이 모두 사라짐(표기만 제거, 머리 댓글 삭제, `404`·`403`·`412` 포함) | "원문 사라짐"으로 옮김. 멈춤 `source-gone` |
  | 화면에 없던 변화(`unseenChanges`) | 준비됨으로 돌리고 감시 내용을 갱신해 알림 줄을 붙임. 멈춤 `changed` |
  | 이미 알림 줄에 떠 있던 변화뿐 | 통과 |
  | 조회 실패(쓸 키 없음, 네트워크, `5xx`, `429`, `401`, 예외) | 그대로 게시 |

  - 화면에 없던 변화는 화면에 보이던 내용(감시 내용, 없으면 비교 기준)과 조회한 내용을 견준다.
    - 새 글에는 알림이 아직 오지 않은, 나를 멘션한 글도 든다.
    - 알림 줄에 떠 있던 글이 그 뒤에 또 고쳐졌으면 수정으로 센다.
  - 새로 사라진 멘션(일부)도 멈춘다. 게시 본문의 받는 사람이 바뀌기 때문이다.
- 확인 전에 들어온 멘션
  - `openBundleAt`은 확인이 끝나지 않은 게시 중 묶음에도 합친다. 합치면 게시를 멈추고 준비됨 규칙을 적용한다.
    - 손댄 초안은 "새 멘션 N건"이 붙는다.
    - 손대지 않은 초안은 자동으로 다시 만든다.
  - 확인이 끝난 뒤 들어온 멘션은 예전처럼 합치지 않고 새 묶음이 된다.
  - 확인이 멈춘 뒤 다음 폴링에 온 알림은 준비됨 묶음에 그대로 합쳐진다.
- 이 PC가 게시한 글이 답한 범위
  - 확인을 통과하면, 조회한 내용에 있던 묶음의 멘션과 묶음 자리에서 지금 나를 지목한 글의 멘션 위치를 함께 둔다. 후자는 `BundleContextResult.myMentions`로, 알림 줄의 새 글로 보인 멘션도 든다.
  - 게시 요청을 보낼 때 `PostingRecord.answeredMentions`로 저장한다.
  - 조회하지 못했거나 늦어 결과 없이 게시했으면, 예전처럼 게시 요청을 보낼 때 묶음에 남은 멘션이다.
- 화면
  - 멈추면 `MentionBundles.onPostStopped`가 알리고, main이 열린 창에 `post-stopped` 이벤트(`PostStopSnapshot`)를 보낸다.
  - 창은 카운트다운 토스트가 사라진 자리에 5초 동안 토스트를 띄운다.
    - "게시하지 않았습니다: Flow에 이미 내 답이 있음" + [되돌리기]
    - "게시하지 않았습니다: Flow에서 멘션이 사라짐" + [되돌리기]
    - "게시하지 않았습니다: 새 글 1건" + [보기]
  - [되돌리기]는 묶음을 되돌리고 그 묶음을 보이며, [보기]는 그 묶음을 보인다.
  - 게시 실패 토스트와 같은 훅(`useEventToasts`)을 쓴다.
- 가짜 Flow API에 `hold(path)`(응답 붙잡기)를 더했다.

**결정과 이유** (스펙에 없거나 스펙을 해석한 것, 검토 대상)

- 원문 사라짐 토스트 문구
  - 스펙에 없어 "게시하지 않았습니다: Flow에서 멘션이 사라짐 · 되돌리기"로 정했다. 처리됨 안내("Flow에서 멘션이 모두 사라져 처리했습니다.")와 말을 맞췄다.
- 변화 토스트
  - 화면에 없던 변화를 알림 줄처럼 " · "로 잇는다. 예: "새 멘션 1건 · 새 글 2건 · 원문 수정됨 · 멘션 1건 사라짐".
  - 확인 중 알림으로 합쳐진 멘션은 "새 글"이 아니라 "새 멘션 N건"으로 쓴다. 상세의 알림 줄과 같은 말이다.
- 일부 멘션이 사라진 것도 "화면에 없던 원문 수정"으로 보고 멈춘다. 받는 사람과 답할 멘션이 바뀌기 때문이다.
- 확인 전에 들어온 멘션
  - 스펙은 "확인이 끝나기 전에 들어온 멘션은 10절이 다룬다"이다.
  - 조회가 그 글을 놓쳤을 수 있으므로, 알림이 확인보다 먼저 오면 그 자리에서 합치고 멈춘다. 새 묶음으로 갈라지지 않게 하려는 것이다.
- 답한 범위
  - "조회한 내용에 있던 멘션"을 멘션 위치로만 저장한다(12절의 "게시를 누를 때 조회한 내용"). 조회한 맥락 글 전체는 저장하지 않는다. 판정에 쓰는 것은 위치뿐이고, 47의 최소 기록도 위치만 남긴다.
  - 범위에는 묶음 자리의 글만 넣는다. 본문 묶음의 게시물 아래 댓글 멘션은 다른 자리(댓글 스레드 묶음)의 멘션이고, 그 자리의 답이 아니다.
- 대기 중 표시
  - 카운트다운이 끝나 확인을 기다리는 5초 동안 [취소]는 없다(스펙: 카운트다운 중에만 취소).
  - 바닥 줄은 기존 게시 중 표시인 "게시 결과 확인 중입니다."를 그대로 쓴다. 따로 단계를 두지 않았다.

**검증** (마지막 변경 뒤, macOS, Node 24)

- `pnpm typecheck`, `pnpm lint` 통과
- `pnpm test`(데스크톱): 44개 파일, 테스트 840개 통과
- 게시를 누를 때의 확인(`pre-post-check.test.ts`, 가짜 Flow API·가짜 시계·메모리 저장소, 감지·묶음·게시를 함께 돌림)
  - 이미 답함: 다른 데서 쓴 내 답이 있으면 이미 답함, 편집본 보존, 카운트다운 지움, 게시 요청 없음
  - 원문 사라짐
    - 표기만 제거되면 원문 사라짐이고, 되돌린 뒤 다시 누르면 게시된다.
    - 머리 댓글이 지워졌으면 원문 사라짐이고, 게시하지 않는다.
  - 화면에 없던 변화
    - 새 글은 준비됨으로 돌아가고 알림 줄의 새 글이 된다.
    - 원문 수정(표기 남음)도 멈춘다.
    - 나를 멘션한 새 글도 멈추고, 다음 폴링의 알림은 그 묶음에 "새 멘션 1건"으로 합쳐진다.
    - 알림 줄의 글이 그 뒤 또 고쳐져도 멈춘다.
    - 일부 멘션이 사라지면 "멘션 1건 사라짐"이다.
  - 이미 알림 줄에 떠 있던 변화뿐(새 글·원문 수정)이면 그대로 게시한다.
  - 조회 실패
    - `503`·네트워크·`429`면 4,999ms에는 보내지 않고 5,000ms에 게시한다.
  - 시간 경계
    - 조회가 늦으면 카운트다운 뒤 4,999ms에는 보내지 않고 5,000ms에 게시하며, 늦게 온 이미 답함 결과는 버린다.
    - 대기 중 끝난 조회는 통과면 그 자리에서 게시하고, 이미 답함이면 게시하지 않는다.
    - 취소하면 결과를 버리고, 다시 누르면 새로 조회한다.
  - 그사이 들어온 멘션
    - 확인 전에 오면 손댄 초안은 "새 멘션 1건", 손대지 않은 초안은 다시 만든다.
    - 확인 뒤에 오면 새 묶음이 되고 게시는 그대로 진행한다.
  - 답한 범위
    - 조회한 멘션을 저장하고, 조회 실패면 남은 멘션을 저장한다.
    - 알림 줄의 새 글로 보인 나를 멘션한 글도 범위에 들어, 나중에 온 그 알림은 이미 답함이 된다.
- 맥락 조회: `myMentions`(본문 묶음, 댓글 스레드의 머리 댓글과 대댓글, 표기를 지우면 빠짐)
- 기존 테스트 조정
  - 게시 테스트 가운데 게시 요청 뒤의 다시 조회를 실패시키던 대본은, 그 실패가 [게시]를 누를 때의 확인에 먼저 쓰이지 않게 게시 요청이 닿을 때 건다.
  - "카운트다운 중 새 멘션은 새 묶음" 테스트는 확인이 끝난 뒤에 멘션을 넣는다(43·45 테스트 3건, 44 테스트 6건).
- 렌더러(정적 렌더링): 멈춘 게시 토스트 문구 세 가지와 [되돌리기]·[보기]
- 빌드: 작업 폴더 밖 임시 폴더로 `electron-vite build` 성공
