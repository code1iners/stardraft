# 49: 최근 멘션으로 시험

**Spec:** [스펙](../spec.md) 13절 "최근 멘션으로 시험", 7절 시험 묶음

**What to build:** 감지 중 묶음이 없을 때의 빈 작은 창과 설정 "초안" 칸의 [최근 멘션으로 시험]을 누르면 최근 멘션 10건이 보이고, 하나를 고르면 실제와 똑같이 초안이 만들어진다. 시험 묶음에는 "시험" 표시와 "Flow에는 아무것도 올라가지 않습니다"가 붙고 [게시] 대신 [시험 끝내기]가 있다. 끝내면 묶음이 지워진다.

**Blocked by:** 39, 41

**Status:** resolved

- [x] 감지를 시작한 뒤에만 쓸 수 있다. 멘션 고르기 목록은 판정 규칙을 통과한 최근 10건(72시간 제한 없음)을 송신자·Flow 프로젝트·첫 줄·시각으로 보이고, 이미 답한 멘션에 "답함"을 붙이되 고를 수 있다. 자동 선택은 없다.
- [x] 실제 에이전트·저장소로 선택 실행과 초안 실행이 대기열 맨 앞에서 돌고, 트레이 숫자와 "[시험] …" OS 알림이 평소처럼 나온다. 재생성, 지시, 저장소 바꾸기, 근거 보기, 연결이 모두 된다.
- [x] 직접 답 확인과 변화 감시는 건너뛴다. 코드와 무관하면 저장소 확인 필요로 끝난다. 한 번에 하나만.
- [x] 끝내기나 무시를 누르면 묶음과 실행 기록을 지우고 처리됨·기준점에 남기지 않는다.
- [x] 가짜 포트로 목록 구성, 시험 묶음의 차이점, 삭제가 테스트된다.

## Comments

### 2026-10-22 구현과 검증 기록

**구조**

- 멘션 고르기 목록(`core/trial/recent-mentions.ts`, `core/trial/trial-run.ts`)
  - 최신 알림부터 쪽을 넘기며 감지와 같은 판정 규칙으로 10건을 모은다. 72시간 제한, 기준점, 이미 기록한 멘션 위치와 상관없다. 10건을 모으면 더 넘기지 않고, 최대 10쪽에서 멈춘다.
  - "답함"은 멘션보다 나중에 쓴 내 답이 묶음 자리에 있을 때 붙고, 고를 수 있다. 자동 선택은 없다.
  - 감지를 시작했고 시험 묶음이 없을 때만 연다. 키 거부면 전역 문제 "키 확인 필요"를 알린다.
- 시험 묶음(`MentionBundles.startTrial`·`endTrial`)
  - 실제 묶음과 같은 상태를 쓰고 `trial` 표시만 다르다. 멘션은 `trial_mention` 표(마이그레이션 16)에 따로 둔다. 같은 멘션 위치의 실제 묶음이 있어도 들어가고, 감지의 "이미 기록한 위치"로 세지 않는다. 기준점은 옮기지 않는다.
  - 초안 대기열은 시험 묶음을 사용자 우선순위(`user`)로 넣어 감지해서 기다리는 묶음보다 앞에 둔다. 다시 켠 뒤 이어서 하던 실행(`resume`)과 먼저 누른 재생성보다는 뒤다.
  - 직접 답 확인(`prepareRun`의 이미 답함 판정)과 변화 감시(`watchWaiting`)를 건너뛴다. 새 멘션도 시험 묶음에 합치지 않는다.
  - 게시는 막는다. 끝내기와 무시는 묶음, 멘션, 실행 기록을 지우고 처리됨·최소 기록에 남기지 않는다. 생성 중이면 돌던 실행이 멈춘다.
  - OS 알림 제목에 "[시험] "을 붙인다.
- 화면
  - 작은 창 빈 화면과 설정 "초안" 칸에 [최근 멘션으로 시험]이 있고, 연 창에 멘션 고르기 시트가 뜬다.
  - 시험 묶음에는 "시험" 태그와 "Flow에는 아무것도 올라가지 않습니다"를 붙인다. 준비됨이면 [게시] 대신 [시험 끝내기]가 있다. 무시해도 되돌리기 토스트를 띄우지 않는다(지워져 되돌릴 수 없음).

**"코드와 무관하면 저장소 확인 필요" 해석**

- 매핑이 없는 Flow 프로젝트는 선택 실행이 `unrelated`로 판정하면 저장소 확인 필요로 끝난다. 실제 묶음과 같은 흐름이고 테스트로 확인했다.
- 매핑이 있는 Flow 프로젝트는 5절대로 선택 실행 없이 초안 실행이 돌아 짧은 초안을 쓴다. 초안 실행에는 "코드와 무관" 판정이 없어 시험에서도 같다. 이 경우도 저장소 확인 필요로 끝내야 한다면 초안 출력 계약을 바꿔야 하므로 따로 정해야 한다.
