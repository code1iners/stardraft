# 50: 초안·일반 설정

**Spec:** [스펙](../spec.md) 6절 "비밀 파일 패턴", "초안 문체와 지침"의 추가 지침, "실행 제어"의 설정 변경 반영, 13절 "설정 창"

**What to build:** 설정 "초안" 칸에서 모든 초안에 적용되는 추가 지침을 적고, 읽기 전용 기본 목록 아래에 비밀 파일 패턴을 추가할 수 있다. 패턴을 추가하면 실행 중인 실행이 새 패턴으로 다시 돌고, 게시하지 않은 초안의 근거가 다시 검사된다. "일반" 칸에 로그인 시 자동 시작 토글과 알림 시험이 있다.

**Blocked by:** 36, 37

**Status:** resolved

- [x] 추가 지침은 여러 줄 입력이며 칸을 벗어날 때 저장하고 "저장됨"을 표시한다. 기본 지침 뒤에 붙고 다음 실행부터 적용되며 이미 만든 초안은 다시 만들지 않는다.
- [x] 비밀 파일 패턴은 추가만 할 수 있고 앱 전체에 적용된다. 기본 패턴 삭제와 저장소별 패턴은 없다.
- [x] 패턴 추가 시 실행 중인 실행을 취소해 대기열 맨 앞에 다시 넣고, 게시하지 않은 초안의 근거 경로를 다시 검사해 걸리면 결과를 버리고 실패("비밀 파일을 근거로 듦")로 둔다.
- [x] "일반" 칸: 로그인 시 자동 시작 토글, 알림 시험 버튼, 에디터 직접 지정(42), 폴더 열기와 버전(24).
- [x] 가짜 실행기와 임시 저장소로 패턴 반영 두 경우가 테스트된다.

## Comments

### 2026-10-22 구현과 검증 기록

**구조**

- 설정 "초안" 칸(`core/drafts/draft-settings.ts`의 `DraftSettings`)
  - 추가 지침은 `settings.json`의 `extraInstructions`에 저장만 한다. 초안 대기열이 실행마다 설정을 새로 읽으므로 다음 실행부터 기본 지침 뒤에 붙고, 이미 만든 초안은 다시 만들지 않는다. 상한은 4,000자다.
  - 비밀 파일 패턴은 `extraSecretPatterns`에 추가만 한다. 지우는 명령은 없다. 앞뒤 공백을 떼고, 기본 목록이나 추가한 패턴에 이미 있으면(대소문자 무시) 받지 않는다.
  - 실행기 deny 규칙(`Read(//**/<패턴>)`, Codex `"**/<패턴>"="deny"`)을 깨는 패턴도 받지 않는다. 따옴표, 괄호, 역슬래시, 제어 문자가 들었거나, `!`로 시작하거나(gitignore 되돌리기), 200자를 넘는 패턴이다. 스펙에는 없는 안전장치다.
  - 추가 지침과 패턴 저장은 한 줄로 직렬화해, 거의 동시에 바꿔도 앞의 변경을 덮지 않는다.
- 패턴 추가의 반영(저장한 뒤 이 순서로 한다)
  1. `DraftQueue.restartForSecretPatterns`가 실행 중인 실행을 끊는다. 그 묶음은 대기열 맨 앞(`resume`)에서 새 패턴으로 처음부터 다시 만든다. 실행 기록의 결과는 `secret-patterns-changed`다.
  2. `MentionBundles.discardSecretEvidenceDrafts`가 게시하지 않은 초안의 근거 경로를 기본 목록과 추가 패턴 전부로 다시 검사한다. 출력 검증과 같은 `findSecretEvidence`로, 적은 경로와 심볼릭 링크를 푼 실제 경로를 모두 본다. 끊기에는 늦어 이미 저장하는 중인 초안도 저장이 끝난 뒤에 함께 검사한다.
  - 걸린 묶음이 준비됨, 게시 실패, 카운트다운 중인 게시 중이면 초안과 편집본을 버리고 "비밀 파일을 근거로 듦" 실패로 둔다.
  - 카운트다운 중이었으면 게시를 멈추고 "게시하지 않았습니다: 비밀 파일을 근거로 든 초안" 토스트를 띄운다(`PostStop`의 `secret-evidence`).
  - 게시 요청을 이미 보낸 게시 중과 게시됨은 검사하지 않는다.
- 설정 "일반" 칸
  - [알림 시험]이 묶음을 가리키지 않는 시험 알림을 띄운다. 알림이 보이지 않으면 OS 알림 설정을 확인하라고 OS별로 안내한다.
  - 로그인 시 자동 시작, 에디터 직접 지정(42), 폴더 열기와 버전(24)은 이전 티켓에서 이미 있었다. 순서는 13절과 같다.

**스펙 해석: 처리됨 묶음**

- 무시함, 이미 답함, 원문 사라짐 묶음의 초안이 새 패턴에 걸리면 초안과 편집본만 버리고 상태는 그대로 둔다. 되돌리면 초안이 없으므로 새로 만든다.
- 6절 "걸리면 결과를 버리고 실패로 둔다"를 문자 그대로 따르면 처리한 묶음이 실패 목록과 트레이 빨간 점으로 되살아나므로 이렇게 정했다.
- 대가는 두 가지다. 사용자가 초안이 사라진 까닭을 화면에서 볼 수 없고, 되돌리면 안내 없이 다시 만들며 사용량을 쓴다. 스펙에 이 해석을 적을지와 되돌릴 때 사유를 보일지는 따로 정할 일이다.
