# 55: 앱 내 업데이트: 다시 시작 흐름과 표시

**Spec:** [스펙](../spec.md) 14절(설치 시점, 다시 시작 흐름, 미루는 조건, 표시 표, 설치 실패, 되돌리기와 데이터), 8절 작은 창 띠와 오른쪽 클릭 메뉴

**What to build:** 설치 준비가 되면 오른쪽 클릭 메뉴에 "다시 시작해서 업데이트 (0.2.0)", 작은 창 띠에 "새 버전 0.2.0이 준비됐습니다" [다시 시작] [변경 내역], 설정 "일반"에 같은 것이 보인다. macOS에서 [다시 시작]을 누르면 Keychain 안내와 예시 화면이 있는 확인 화면이 먼저 뜬다. 에이전트 실행이나 게시 카운트다운·요청 중이면 끝날 때까지 미루고 "다시 시작 대기"를 보인다. 다시 켰을 때 버전이 그대로면 "0.2.0으로 업데이트하지 못했습니다"가 뜬다.

**Blocked by:** 48, 54

**Status:** ready-for-agent

- [ ] 표시 표의 아홉 상태가 메뉴·띠·설정 세 곳에 맞게 보인다. 띠 자리는 전역 문제 띠가 우선. 트레이 아이콘과 OS 알림은 쓰지 않는다. [변경 내역]과 [사이트에서 받기]는 사이트의 해당 섹션을 연다.
- [ ] macOS 확인 화면: 제목, 스펙의 Keychain 문구 두 문장, 예시 화면("예시 화면" 띠와 빗금 틀, "항상 허용" 강조), [다시 시작] [나중에]. 매번 보여 주고 "다시 보지 않기"는 없다. Windows는 바로 다시 시작.
- [ ] 미루는 조건: 카운트다운·게시 요청·에이전트 실행이 끝날 때까지. 그동안 다음 실행은 시작하지 않고 폴링은 계속. [지금 다시 시작]은 실행을 끊고 [취소]는 대기를 푼다. 조건이 끝나면 바로 다시 시작. 다시 시작 전에 편집기 내용을 저장한다.
- [ ] 다시 시작 직전에 "업데이트 시도"(지금 버전, 새 버전, 시각)를 기록하고, 다시 켰을 때 버전이 그대로면 설치 실패 문구와 [다시 시도] [사이트에서 받기]. Squirrel 거부(`did not pass validation`)면 "이 버전은 앱 안에서 업데이트할 수 없습니다. 사이트에서 받아 설치하세요."와 [사이트에서 받기]만.
- [ ] 업데이트 직후 첫 실행에 "0.2.0으로 업데이트했습니다" [변경 내역]을 한 번 보인다. 마이그레이션 전 사본은 새 버전이 정상으로 뜬 지 7일 뒤 지운다.
- [ ] 가짜 시계·가짜 대기열 상태로 미루기와 재개, 설치 실패 판정, 띠 우선순위가 테스트된다.
