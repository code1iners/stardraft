# 55: 앱 내 업데이트: 다시 시작 흐름과 표시

**Spec:** [스펙](../spec.md) 14절(설치 시점, 다시 시작 흐름, 미루는 조건, 표시 표, 설치 실패, 되돌리기와 데이터), 8절 작은 창 띠와 오른쪽 클릭 메뉴

**What to build:** 설치 준비가 되면 오른쪽 클릭 메뉴에 "다시 시작해서 업데이트 (0.2.0)", 작은 창 띠에 "새 버전 0.2.0이 준비됐습니다" [다시 시작] [변경 내역], 설정 "일반"에 같은 것이 보인다. macOS에서 [다시 시작]을 누르면 Keychain 안내와 예시 화면이 있는 확인 화면이 먼저 뜬다. 에이전트 실행이나 게시 카운트다운·요청 중이면 끝날 때까지 미루고 "다시 시작 대기"를 보인다. 다시 켰을 때 버전이 그대로면 "0.2.0으로 업데이트하지 못했습니다"가 뜬다.

**Blocked by:** 48, 54

**Status:** resolved

- [x] 표시 표의 아홉 상태가 메뉴·띠·설정 세 곳에 맞게 보인다. 띠 자리는 전역 문제 띠가 우선. 트레이 아이콘과 OS 알림은 쓰지 않는다. [변경 내역]과 [사이트에서 받기]는 사이트의 해당 섹션을 연다.
- [x] macOS 확인 화면: 제목, 스펙의 Keychain 문구 두 문장, 예시 화면("예시 화면" 띠와 빗금 틀, "항상 허용" 강조), [다시 시작] [나중에]. 매번 보여 주고 "다시 보지 않기"는 없다. Windows는 바로 다시 시작.
- [x] 미루는 조건: 카운트다운·게시 요청·에이전트 실행이 끝날 때까지. 그동안 다음 실행은 시작하지 않고 폴링은 계속. [지금 다시 시작]은 실행을 끊고 [취소]는 대기를 푼다. 조건이 끝나면 바로 다시 시작. 다시 시작 전에 편집기 내용을 저장한다.
- [x] 다시 시작 직전에 "업데이트 시도"(지금 버전, 새 버전, 시각)를 기록하고, 다시 켰을 때 버전이 그대로면 설치 실패 문구와 [다시 시도] [사이트에서 받기]. Squirrel 거부(`did not pass validation`)면 "이 버전은 앱 안에서 업데이트할 수 없습니다. 사이트에서 받아 설치하세요."와 [사이트에서 받기]만.
- [x] 업데이트 직후 첫 실행에 "0.2.0으로 업데이트했습니다" [변경 내역]을 한 번 보인다. 마이그레이션 전 사본은 새 버전이 정상으로 뜬 지 7일 뒤 지운다.
- [x] 가짜 시계·가짜 대기열 상태로 미루기와 재개, 설치 실패 판정, 띠 우선순위가 테스트된다.

## Comments

### 2026-10-22 구현과 검증 기록

**구조**

- core: `apps/desktop/src/core/update/update-restart.ts`의 `UpdateRestart`
  - 앱 내 업데이트(`InAppUpdate`)의 상태 위에 다시 시작 단계와 설치 실패, 업데이트 직후 첫 실행을 얹어 화면 상태 `UpdateState`를 만든다.
    - `status`: 54의 상태에 `restart-pending`(`waitingFor`: 에이전트 실행·게시)과 `install-failed`(`reason`: `not-applied`·`rejected`)를 더한 표시 상태.
    - `justUpdated`, `restartConfirm`(macOS 확인 화면의 버전), `dismissedBanners`(작은 창에서 닫은 띠 이름들).
  - 명령: `requestRestart`([다시 시작]), `confirm`·`cancelConfirm`(확인 화면), `restartNow`·`cancelRestart`(다시 시작 대기), `retryInstall`(설치 실패의 [다시 시도]), `dismissBanner`.
  - 미루기: 다시 시작을 시작하면 초안 대기열의 다음 실행을 잡아 두고(`RestartActivity.holdDrafts`), 에이전트 실행·게시 카운트다운·게시 요청이 남아 있으면 기다리다가 모두 끝나는 즉시 다시 시작한다. 에이전트 실행은 최대 10분만 기다린다(`DRAFT_WAIT_LIMIT_MS`). 폴링은 건드리지 않는다.
  - 다시 시작: 편집기 내용 저장(`mentionBundles.whenIdle`)을 기다리고, "업데이트 시도"를 남긴 뒤 업데이트 피드의 `install()`을 부른다. 앱이 꺼지며 진행 중인 실행은 기존 종료 정리로 끊기고 다시 켜면 대기열 맨 앞에 다시 든다.
  - 켤 때(`load`): 남은 업데이트 시도를 읽고 지운다. 버전이 새 버전이면 업데이트 직후 첫 실행, 그대로면 설치 실패, 둘 다 아니면(사이트에서 다른 버전 설치) 아무것도 보이지 않는다.
- 업데이트 시도: `state.db` 형식 18의 `update_attempt` 표(한 줄, 지금 버전·새 버전·시각·`rejected`). 계정과 상관없어 다른 계정으로 처음부터 시작해도 남긴다(`TABLES_KEPT_ON_RESET`). 상태 저장소 포트에 `getUpdateAttempt`·`setUpdateAttempt`·`clearUpdateAttempt`를 더했다.
- 업데이트 피드 포트에 `install()`과 `onInstallFailed()`를 더했다. 앱의 피드(`main/update-feed.ts`)는 `quitAndInstall(true, true)`를 부르고, 그 뒤 electron-updater `error`의 문구에 `did not pass validation`이 있으면 `rejected`, 아니면 `failed`로 알린다.
- 초안 대기열: `isRunning()`과 `holdForRestart(held)`(멈춤 까닭 `restart`). 실행 중인 실행은 끝까지 간다.
- 게시: `isActive()`(카운트다운과 확인을 기다리는 시간, 응답을 기다리는 게시 요청, `429` 뒤 다시 보내기). 진행 여부가 바뀌면 `onChange`로 알린다. 올라갔는지 다시 확인하는 일은 다시 켠 뒤에도 이어지므로 세지 않는다.
- 마이그레이션 전 사본: `core/storage/migration-backups.ts`의 `MigrationBackups`. 앱이 시작을 마친 뒤 사본 폴더마다 `healthy-since`(정상으로 뜬 시각)를 적고, 켤 때와 하루마다 7일이 지난 사본 폴더를 지운다.
- 표시: 표의 열마다 switch 하나다.
  - 오른쪽 클릭 메뉴: `shared/update-text.ts`의 `updateMenuItem`. "설정…" 아래에 둔다. 아이콘은 바꾸지 않는다.
  - 작은 창 띠: `renderer/src/update-text.ts`의 `updateBannerView`. 띠 자리는 하나라 전역 문제 띠가 있으면 업데이트 띠를 그리지 않는다.
  - 설정 "일반": 같은 파일의 `updateFieldView`. 버튼 이름과 명령은 `UpdatePrompts.tsx`의 `UPDATE_BUTTONS` 하나다.
  - macOS 확인 화면: `UpdatePrompts.tsx`의 `RestartConfirm`. 띄우면 작은 창에는 이 화면만 보인다. 메뉴나 설정에서 눌러도 main이 작은 창을 열어 보이고, 작은 창이 닫히면 [나중에]와 같다.
- IPC: 스냅숏 `update: UpdateStateSnapshot | null`, 명령 `restart-to-update`, `confirm-update-restart`, `cancel-update-restart-confirm`, `restart-update-now`, `cancel-update-restart`, `retry-update-install`, `dismiss-update-banner`. `open-site`에 `changelog` 섹션을 더했다.

**스펙에 없던 것을 정한 결정** (검토 대상)

- **다시 시작 대기 문구는 기다리는 일에 맞춘다.** 에이전트 실행이면 스펙 문구 "초안 생성이 끝나면 다시 시작합니다", 게시만이면 "게시가 끝나면 다시 시작합니다", 둘 다면 "초안 생성과 게시가 끝나면 다시 시작합니다".
- **에이전트 실행 10분 상한이 지나도 게시는 끝날 때까지 기다린다.** 게시는 카운트다운 10초와 `429` 최대 60초라 길지 않다.
- **메뉴의 "다시 시작 대기 중…"은 누르면 작은 창을 연다.** [지금 다시 시작] [취소]가 거기 있다.
- **업데이트 직후 첫 실행 띠에 [닫기]를 더했다.** "한 번만"은 다음 실행에서 다시 보이지 않는 것으로 구현했고, 이번 실행에서도 띠 자리를 오래 차지하지 않게 닫을 수 있게 했다. 닫은 띠는 이번 실행에서만 기억한다.
- **앱이 켜진 채 설치하지 못한 경우도 그 자리에서 설치 실패를 보인다.**
  - Squirrel.Mac 거부: 앱이 꺼지지 않는다. 시도 기록에 `rejected`를 남겨 다시 켜도 같은 문구를 보이고, 그 버전은 [다시 시작]이 듣지 않는다.
  - 그 밖의 설치 오류: "업데이트하지 못했습니다"를 보이고, 이미 알렸으므로 시도 기록을 지운다.
  - 설치를 맡기고 2분이 지나도 꺼지지 않고 오류도 없으면 설치 실패로 본다. Windows `install()`이 오류 없이 `false`를 돌려주는 경우를 받으려는 것이다. 늦게라도 설치됐을 수 있어 기록은 남긴다.
- **설치 실패 [다시 시도]**: 받아 둔 업데이트를 다시 확인(캐시 파일을 다시 검증)하고, 설치 준비됨이 되면 바로 다시 시작 흐름(macOS는 확인 화면)으로 간다.
- **설치 실패는 그 버전에 머무는 동안 앱 내 업데이트의 상태보다 앞선다.** 1분 뒤 확인이 같은 버전을 다시 받아 설치 준비됨이 되어도 설치 실패를 보인다. 더 새 버전을 받거나 서명 검증 실패·바꿀 수 없는 위치가 생기면 그 상태를 보인다.
- **확인 화면이나 대기 중에 설치 준비됨이 아니게 되면 다시 시작을 거둔다.** 예를 들어 4시간 확인이 더 새 버전을 받기 시작한 경우다.
- **설정 "일반"의 업데이트 직후 칸("버전")**: 칸 아래의 기존 앱 버전 표기로 둔다. 업데이트 칸은 평소 상태를 보인다.
- **전역 문제가 있는 동안의 다시 시작 대기**: 스펙대로 띠 자리를 전역 문제가 차지해 작은 창에서 [지금 다시 시작] [취소]가 보이지 않는다. 대기는 실행이 끝나거나 10분이 지나면 저절로 끝난다.
- **마이그레이션 전 사본의 "정상으로 뜬 시각"**은 앱이 시작(트레이·서비스 준비)을 마친 때다. 시각이 없는 앞선 버전의 사본도 그때부터 센다.
- **사이트 변경 내역 섹션의 앵커는 `#changelog`다.** 56이 사이트를 만들 때 변경 내역 섹션에 같은 id를 둔다.
- 키체인 예시 화면의 문구는 macOS 한국어 대화상자를 재현한 것이다. 실제 문구와 같은지는 첫 릴리스 실기(59)에서 확인한다.

**확인하지 못한 것** (실제 확인은 59, Windows는 60)

- 실제 설치본에서 [다시 시작]을 눌러 새 버전으로 다시 켜지는지, 앱의 종료 정리(`before-quit` 지연)와 ShipIt·NSIS 설치가 함께 도는지.
- 다시 켤 때 실제 키체인 대화상자와 확인 화면의 예시 화면이 맞는지.
- 실제 Squirrel.Mac 거부 문구로 거부 띠가 뜨는지.
- 트레이 메뉴의 업데이트 항목을 실제로 누르는 것, 메뉴·설정에서 눌렀을 때 작은 창이 확인 화면을 띄운 채 바로 닫히지 않는지.
- 위 항목은 앱 내 업데이트가 설치본에서만 돌아 소스 실행으로는 볼 수 없다.
