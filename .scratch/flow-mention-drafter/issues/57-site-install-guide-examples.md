# 57: 다운로드 사이트: 설치 안내 예시 화면

**Spec:** [스펙](../spec.md) 16절 "설치 안내", "예시 화면과 스크린숏", "모션"

**What to build:** 설치 안내 섹션에 OS 탭(기본값은 감지 결과)과 macOS 5단계·Windows 4단계가 있다. 단계마다 제목, "이 문구가 보이면", 지시(버튼 이름 굵게), 눌러 볼 수 있는 HTML 예시 화면, 완료 기준, "여기서 막히면" 펼침이 있다. 예시 화면이 보이는 위치까지 스크롤하면 커서가 누를 곳으로 움직이고 강조 테두리가 깜빡인다. 막히는 네 곳에는 실제 스크린숏 자리를 두고 "예시"로 바꿀 수 있다.

**Blocked by:** 56

**Status:** resolved

- [x] 단계 내용과 "여기서 막히면" 열 항목(손상됨, 휴지통으로 이동, Intel Mac, 그래도 열기 안 보임, 노치, 알림 허용 놓침, 실행 버튼 없음, 스마트 앱 컨트롤 차단, 실행 중입니다 창, 트레이 숨김 영역)이 스펙 문구대로다. macOS 1단계에 `~/Applications` 한 줄이 있다. 스마트 앱 컨트롤 단계는 상태별 표다.
- [x] 예시 화면: 누를 곳을 누르면 다음 상태로 넘어가고, 잘못된 버튼은 경고를 띄우며 "처음부터"가 있다. 위에 노란 띠 "예시 화면 · 눌러 볼 수 있지만 실제 창이 아닙니다", 빗금 배경, 항상 단계 안의 틀 속.
- [x] 막히는 네 곳은 실제 스크린숏이 기본이고 "예시"로 전환된다. 스크린숏 파일 자리는 비워 두고 59·60에서 채운다. Keychain 예시 화면은 앱의 다시 시작 확인 화면과 같은 것을 쓴다.
- [x] 커서 이동·강조·장면 전환은 `prefers-reduced-motion`이면 모두 멈추고 마지막 모습만 보이며 커서는 누를 곳에 바로 놓인다(CSS와 JS 모두).
- [x] 다른 OS용 받기를 누르면 탭도 그 OS로 바뀐다. 넣지 않는 것(`xattr`, 연락 절차, SAC 끄기 안내, 우클릭 열기)이 없다.
- [x] 예시 화면의 상태 전환과 reduced-motion 분기가 테스트된다.

## Comments

- 2026-10-22 구현 기록
  - 설치 안내는 React 섬 하나(`InstallGuide`, `client:load`)다. 첫 화면의 다운로드 링크가 고른 OS를 페이지 이벤트(`stardraft:install-os`)로 알리고, 설치 안내가 들어 탭을 바꾼다. 섬이 보이기 전에도 들어야 해서 `client:visible`이 아니라 `client:load`로 깨운다. 첫 화면의 모든 다운로드 링크(대표 버튼 포함)가 알린다.
  - 탭 기본값은 감지한 OS다. 빌드한 HTML, 감지 전, 휴대폰·그 밖의 OS는 macOS다. 두 OS의 단계를 모두 그려 두고 고른 탭만 보이므로, 탭을 오가도 예시 화면 진행이 남는다.
  - 예시 화면의 상태 전환은 `src/lib/example-scenes.ts`의 표 하나에 모았다(모습, 누를 곳, 잘못된 버튼과 경고).
    - 잘못된 버튼과 경고는 셋이다: "휴지통으로 이동", "실행 안 함", 한 번 더 묻는 창의 "완료".
    - Windows 3단계(설치 진행)는 실제로 누를 곳이 없어 클릭 전환과 [처음부터]가 없고, 진행 막대만 움직인다.
  - 커서 위치는 `src/lib/motion.ts`의 `planCursor`가 정한다.
    - 동작 줄이기면 보이기 전이라도 누를 곳에 바로 놓는다.
    - CSS는 전역 `prefers-reduced-motion: reduce` 블록이 모든 애니메이션과 전환을 끈다. 옮겨 간 DMG 아이콘은 빈자리로 둔다.
    - JS는 장면 전환 class, 깜빡임 class, 커서 이동 전환을 빼고, 진행 막대를 다 찬 모습으로 그린다.
  - 막히는 네 곳의 스크린숏은 `apps/site/src/assets/screenshots/`에 `mac-blocked.png`, `mac-settings.png`, `win-smartscreen.png`, `win-sac.png`를 넣으면 빌드할 때 찾아 쓴다(`import.meta.glob`). 표와 찍는 때는 `apps/site/README.md`에 적었다.
    - 파일이 있으면 실제 화면이 기본이고 [예시]로 바꿀 수 있다.
    - 파일이 없는 곳은 예시 화면만 보이고 바꾸는 버튼을 숨긴다. 59와 60 사이에 빈 자리가 공개 사이트에 보이지 않게 하려는 것이다. 그래서 스펙의 "실제 스크린숏을 기본으로"는 59·60에서 파일을 넣어야 화면에서 확인된다.
  - Keychain 예시 화면은 앱의 다시 시작 확인 화면(`RestartConfirm`)과 같은 마크업·문구를 사이트에 따로 두었다. 사이트의 Ignored Build Step은 앱 폴더 변경을 보지 않아서, 앱 코드를 import하면 앱만 고친 푸시에서 사이트가 낡는다. 대신 앱 소스와 문구·버튼 순서·강조를 대조하는 테스트(`KeychainExample.test.tsx`)를 두었다.
  - 재현 화면의 OS 문구 중 실제 화면과 다를 수 있는 것은 59·60에서 스크린숏을 찍을 때 맞춘다: macOS 암호 창의 제목과 버튼(설정 수정), 한 번 더 묻는 창, 알림 배너, Windows 보안의 메뉴 이름(앱 & 브라우저 컨트롤).
- 검증
  - 루트 `pnpm lint`, `pnpm typecheck`(사이트는 `astro check`), `pnpm test`(사이트 80, 데스크톱 1210)가 통과했다. `VERCEL_GIT_REPO_OWNER=example-owner astro build`도 통과했다.
  - 개발 서버를 Playwright Chromium으로 열어 1280px·390px에서 다음을 확인했다.
    - 기본 탭과 탭 전환: macOS UA는 macOS 탭, Windows UA는 Windows 탭이 기본이다. 첫 화면의 Windows용 링크를 누르면 탭이 Windows로 바뀐다. 화살표 키로도 탭이 바뀐다.
    - 예시 화면 조작: 보이는 위치까지 스크롤하면 커서가 누를 곳으로 움직이고 테두리가 깜빡인다. 누르면 다음 모습으로 넘어가고, 잘못된 버튼은 경고를 띄우며, [처음부터]가 첫 모습으로 되돌린다. 키보드로 눌러도 초점이 유지된다.
    - 스크린숏 자리: 임시 PNG를 넣으면 실제 화면이 기본이 되고 예시와 서로 바뀐다. 확인 뒤 임시 파일은 지웠다.
    - `reducedMotion: 'reduce'`: 커서가 스크롤 전부터 누를 곳에 놓이고, 애니메이션·전환이 모두 none이며, 진행 막대는 다 찬 모습이다.
    - 390px에서 가로 넘침이 없다.
  - 실제 Safari·Firefox, 실제 OS의 동작 줄이기 설정, 실제 스크린숏은 확인하지 못했다. 실제 스크린숏과 재현 문구 대조는 59·60의 몫이다.
