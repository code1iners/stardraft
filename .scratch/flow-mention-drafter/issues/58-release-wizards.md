# 58: 출시 마법사 작성

**Spec:** [스펙](../spec.md) 테스트 결정 "실기 점검 목록", 15절 "릴리스 흐름", 14절 "서명 키", 16절 "코드와 호스팅"

**What to build:** `wizard` 스킬로 bash 마법사 두 개를 만든다. 하나는 저장소 주인이 Mac에서 처음 출시할 때 손으로 해야 하는 일을 처음부터 끝까지 안내하는 **출시 마법사**이고, 다른 하나는 Windows PC에서 돌리는 **Windows 점검 마법사**다. 사람이 해야 하는 일은 모두 이 두 마법사에 들어 있어야 하고, 각 스테이지는 열 URL, 누를 것, 복사할 값, 확인 질문을 담는다. 값은 `.env`나 GitHub 비밀값에 쓴다. 마법사는 앱 저장소의 스크립트 폴더에 두고 커밋한다(다음 사람도 쓰는 반복 절차).

**Blocked by:** 49, 50, 51, 55, 57

**Status:** ready-for-agent

- [ ] **출시 마법사** 스테이지(순서대로): ① `gh` 로그인 상태 확인 ② 공개 저장소 `stardraft`(MIT) 생성과 로컬 이력 푸시, PR CI 통과 확인 ③ 저장소 설정 — immutable releases 켜기, 외부 PR 워크플로 승인 필요로 설정, `release` 환경 만들고 `v*` 태그에만 허용 ④ `pnpm release:keygen` 실행과 개인 키의 비밀번호 관리자 보관 확인, 공개 키 커밋 ⑤ Vercel 프로젝트 생성(Root Directory, Ignored Build Step, 공개 읽기 토큰), `stardraft.squadify.app` 도메인 연결 ⑥ 테스트 저장소에서 "공개 Release → 사전 릴리스 전환 시 `releases/latest`가 이전 버전으로 돌아가는지" 확인 ⑦ `v0.1.0` 태그 푸시와 태그 워크플로 결과 확인, 초안 Release의 다섯 파일 확인 ⑧ 초안 Release의 DMG를 브라우저로 받아 설치("열지 않음" → 시스템 설정 → 그래도 열기) ⑨ 온보딩 실제 실행 — Flow 키 확인, Claude Code 연결, 작업 폴더, [감지 시작], 알림 허용 배너 ⑩ 최근 멘션으로 시험 ⑪ 미서명 macOS 점검 — 알림 표시, 알림 클릭(배너·알림 센터), 로그아웃 뒤 자동 시작, 첫 실행에 Keychain을 묻지 않음 ⑫ macOS 스크린숏 두 곳(열지 않음 대화상자, 그래도 열기 위치)을 한국어 OS에서 찍어 사이트에 넣고 재현 화면 문구 맞추기 ⑬ 표준 계정과 `~/Applications`에서 위치 확인 판정 보기(선택) ⑭ Release 공개, 사이트에서 버전·다운로드·`/api/releases` 확인 ⑮ 두 번째 버전으로 앱 내 업데이트 실측 — 받는 중 표시, 다시 시작 확인 화면, Keychain "항상 허용", 업데이트 직후 띠, yml 변조 두 경우의 오류 표시 ⑯ 동료와 함께 — 받는 사람에게 멘션 알림이 가는지, `PROBE-GROUP`·`PROBE-DM` 표지로 채팅 멘션이 알림 목록에 오는지(결과는 스펙의 범위 밖 항목에 기록).
- [ ] **Windows 점검 마법사** 스테이지: 스펙 "팀 배포 전 Windows 점검 목록"의 13개 항목을 하나씩, 그리고 Windows 스크린숏 두 곳(PC 보호 화면, 스마트 앱 컨트롤 설정)과 메뉴 이름·상태 이름 확인. 결과를 기록 파일로 남긴다.
- [ ] 각 스테이지는 템플릿의 `stage`/`open_url`/`ask_secret`/`write_env`/`set_secret`/`confirm`를 쓰고, 되돌리기 어려운 행동(공개, 사전 릴리스 전환) 앞에는 `confirm`이 있다. 비밀값은 숨김 입력이다. 실제 UI 경로를 모르는 단계는 지어내지 않고 사용자에게 확인하라고 적는다.
- [ ] `bash -n`과 `shellcheck`를 통과하고 실행 권한이 있다. 실행 방법이 README에 적혀 있다.
