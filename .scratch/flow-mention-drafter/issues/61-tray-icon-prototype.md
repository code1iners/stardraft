# 스타크래프트 느낌의 트레이 아이콘 비교

Type: prototype
Status: resolved

## Question

사용자가 제공한 스타크래프트 아이콘의 형태를 Stardraft 트레이에 어떻게 적용할 것인가?
숫자 없이 단색 아이콘의 비움·채움으로 알림 유무를 구분하고, 실제 크기에서 윤곽을 비교한다.

## Prototype

- 보관 브랜치: `prototype/tray-icon-20261023` (제품 브랜치에 병합하지 않음).
- 비교 시안 `prototype/tray-icon-20261023:.scratch/flow-mention-drafter/prototypes/tray-icon/index.html`: 선택한 A 윤곽으로 알림 없음·검토 대기·문제 있음 세 상태를 나란히 비교한다.
- 실행: 이 브랜치 작업 폴더에서 `pnpm prototype:tray`, 주소 `http://127.0.0.1:4387/?variant=A`.
- 브라우저 시뮬레이션이다. 실제 운영체제 트레이의 렌더링·배율·테마 검증을 대신하지 않는다.
- 알림 없음은 빈 윤곽선으로 정지, 검토 대기는 단색 채움과 무한 pulse, 문제 있음은 빈 윤곽선과 45도 취소선으로 정지한다. 2026-10-23 사용자가 이 세 상태 시안을 채택했다. 양쪽 운영체제 모두 숫자·점·느낌표 배지를 붙이지 않는다.
- 프로토타입 승인 당시 제품의 기존 숫자·배지 표시는 유지되어 있었다. 이 티켓의 시안은 사용자가 요청한 새 표시 방식을 비교하며, 제품 코드는 아직 수정하지 않았다.
- 원본 게임 자산을 추출한 결과가 아니라 코드로 다시 그린 형태다. 최초 컬러 시안과 검증 기록은 커밋 `055626c`에 보관되어 있다.
- 원본 참고: [사용자 제공 답글](https://www.threads.com/@neosc_out/post/DJNm4mwzGvr), [이미지가 있는 원글](https://www.threads.com/@youblogify/post/DJNmC3PS2s7/media).
- 같은 보관 브랜치의 `prototypes/tray-icon/README.md`에 실행 방법, `preview-states.jpg`에 세 상태 캡처가 있다.

## Answer

2026-10-23 사용자가 명시한 표시 방식:

1. 색을 나누지 않고 주변 아이콘처럼 단색으로 표현한다. 알림이 있을 때 내부를 꽉 채운다.
2. 오른쪽 숫자를 없애고 아이콘만 표시한다. 알림이 없을 때는 내부가 빈 윤곽선으로 표시한다.

추가로 사용자가 명시한 답:

- Q1 `agree`: A 참조 윤곽을 기준으로 진행한다.
- Q3: 채워진 상태에서 pulse를 무한 반복한다. 세 번만 반복하는 제안은 채택하지 않았다.
- Q4 `agree`: 창을 열었다고 알림을 없애지 않고, 처리·해결해야 빈 아이콘으로 돌아간다.
- Q6 `agree`: 크기와 채워진 형태를 유지하고, 2초 주기로 불투명도 65%와 100%를 부드럽게 왕복한다. 시스템 동작 줄이기에서는 채움 상태로 정지한다.
- Q7 `agree`: 문제와 검토 대기가 함께 있으면 문제 취소선을 우선한다. 검토할 초안은 유지하고, 문제를 해결하면 남은 검토 대기의 채움·무한 pulse로 돌아간다.

Q2에서 사용자는 상태별 아이콘 분리와 45도 취소선을 제안했다. Q5에는 "각 상태별로 시안 보여줘"라고 답했고, 세 상태 시안을 본 뒤 "오케이 이걸로 가자"라고 승인했다. 따라서 다음 시각안과 상태 구분을 채택했다.

| 상태 | 표시 |
| --- | --- |
| 확인할 일 없음 | 빈 윤곽선, 정지 |
| 검토할 초안 있음 | 단색 채움, 무한 pulse |
| 설정 필요·연결 문제·작업 실패 | 빈 윤곽선과 45도 취소선, 정지 |

승인 전 화면을 보존한 프로토타입과 캡처에는 "검토안" 문구가 남아 있지만 이 승인 기록을 최신 결정으로 본다.

최종 표시 우선순위는 **문제 취소선 → 검토 대기의 채움·무한 pulse → 빈 윤곽선**이다. 창을 여는 것만으로 이 상태를 해제하지 않는다. 문제를 해결한 뒤 검토 대기가 남아 있으면 채움·pulse, 남아 있지 않으면 빈 윤곽선으로 돌아간다.

시각안과 상태 표시 계약에 남은 질문은 없다. 이 티켓의 `resolved`는 프로토타입·설계 합의 완료를 뜻한다. 실제 상태 분류·우선순위·네이티브 pulse 및 제품 코드는 변경하지 않았고, 실제 운영체제 트레이 검증도 수행하지 않았다.
