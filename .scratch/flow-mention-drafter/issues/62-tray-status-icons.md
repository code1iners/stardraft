# 트레이 세 상태와 무한 pulse 구현

Type: task
Status: claimed
Blocked by: 61

## 목표

[승인된 시안과 결정](61-tray-icon-prototype.md)을 실제 macOS/Windows 트레이에 적용한다.

## 완료 조건

- [x] 문제 > 검토 > 대기 상태 계산과 툴팁
- [x] A 윤곽, 빈 아이콘 / 채운 아이콘 / 45도 취소선
- [x] 2초 ease-in-out 무한 pulse, 65–100% 불투명도
- [x] 동작 줄이기, 테마 변경, 절전·복귀, 종료 처리
- [x] 자동 검사 및 빌드
- [ ] macOS 실제 트레이 확인

## 구현 계약

아이콘 옆 숫자·점·색상 배지를 제거한다. 문제는 전역 문제 > 설정 필요 > 실패 순이다. 생성 중만으로는 빈 아이콘을 유지하고 툴팁에 표시한다. 검토 수 변경이나 창 열기는 pulse를 다시 시작하거나 알림을 지우지 않는다. 동작 줄이기는 완전히 채운 정지 아이콘이다. 미리 생성한 프레임을 캐시하고, 틱마다 이미지 생성이나 파일 읽기를 하지 않는다.

## 검증

2026-10-23, 구현 브랜치 `feat/tray-status-icons`, 기반 `1d4021b`.

- `src/main/tray-animation.ts`: 단조 시계, 50ms 예약, 1초 동작 줄이기 확인. 가상 시계로 반복·검토 수 유지·문제 전환·동작 줄이기 변경·절전/복귀·중복 폐기를 확인했다.

- `pnpm --filter @stardraft/desktop lint`, `typecheck`: 통과.

- `pnpm --filter @stardraft/desktop icons:check`: SVG 원본과 커밋한 프레임 일치.
- `pnpm --filter @stardraft/desktop dist`: macOS arm64 앱·DMG·zip 생성 통과. 배포·업로드하지 않았다.
- `pnpm --filter @stardraft/desktop verify:mac`: 앱과 zip에서 푼 앱의 깊은 서명 검사 및 식별자 요구조건 통과.

### 검증 미확인과 후속 작업

구현 5개 조건은 완료했다. 실제 화면 수용 조건 2개는 유지하며 **미확인**으로 남긴다. 비필수 제외는 없다. `claimed`에서 `ready-for-agent`로 전환한 이유는 현재 화면 도구가 앱 창만 보여 주어 실제 메뉴 막대 아이콘의 형태·pulse를 관찰할 수 없었고, 현재 호스트가 macOS여서 Windows 실행 증거가 없기 때문이다. 네이티브 이미지 검사와 가상 시계 결과를 화면 확인으로 취급하지 않는다.

다음 단계는 이 티켓을 재개하여 각 운영체제에서 `pnpm --filter @stardraft/desktop preview:tray`를 실행하는 것이다. 검증 앱은 임시 사용자 데이터로 실행되며 종료하면 해당 임시 파일을 지운다.

1. macOS 메뉴 막대에서 숫자 없이 빈 윤곽·채움·45도 취소선이 읽히는지, 채움만 2초 주기로 65–100% 밝기로 반복하는지 확인한다. 실제 밝은/어두운 메뉴 막대, 동작 줄이기와 절전·복귀도 확인한다.
2. Windows 작업 표시줄에서 밝은/어두운 **시스템** 테마, 100·125·150·200% 배율, 동작 줄이기, 절전·복귀를 확인한다. 앱 테마와 시스템 테마를 다르게 둔 경우도 포함한다.
3. 실제 아이콘의 왼쪽 클릭과 오른쪽 메뉴, 검토 수 변경·문제 발생/해결·창 열기 뒤 상태 유지, 종료 후 아이콘 제거를 확인한다. 화면 캡처와 운영체제·배율·동작 줄이기 값을 기록하고 남은 두 조건을 충족한 뒤 `resolved`로 바꾼다.

운영 계정 데이터 수정·실제 게시·푸시·릴리스는 후속 검증에 필요하지 않다.

## Comments

### 2026-10-23 재개

- 사용자가 `$implement`로 62번 진행을 요청했다. 현재 브랜치 `feat/tray-status-icons`, 시작 커밋 `6757607`에서 이어간다.
- 사용자 답변: **“windows 는 완료 조건에서 제외.”** Windows 실기 확인 항목을 필수 완료 조건에서 제거한다. Windows 구현은 유지하고, 실기 검증 완료로 간주하지 않는다.
- 사용자 지정 코드 리뷰 비교 기준은 `6757607` 이후 이번 변경이다.
- macOS 메뉴 막대 수용 조건은 유지한다. 현재 CUA 화면 도구는 앱 창을 보여 주지만 메뉴 막대는 포함하지 않는다. 기본 스크린샷 단축키를 보내도 새 캡처가 확인되지 않았고, Screenshot.app 선택은 시간 초과했다. 다른 캡처 방법 사용에 대한 사용자의 답변을 기다리면서 독립 작업을 진행한다.

- 검증 앱에 상태 전환 메뉴를 추가했다. 가운데 아이콘에 `trayIndicator()`와 `AppTray.show()`를 연결하여 검토 수·실패 발생/해결·전체 처리·생성 중을 실제 메뉴에서 바꾼다. 왼쪽 클릭은 검증 창을 열거나 닫고 우클릭의 창 열기는 다시 연다. 제품 코드나 운영 데이터는 바꾸지 않았다.
- 사용자가 `screencapture` 사용을 명시적으로 요청했다. 아이콘 주변과 기본 화면 원점에서 캡처를 시도했으나 모두 `could not create image from rect`로 실패했다. `CGPreflightScreenCaptureAccess()` 결과가 `false`이므로 화면 기록 접근 권한을 추가로 확인 중이다.
