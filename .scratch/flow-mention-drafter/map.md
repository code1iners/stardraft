## Destination

이 지도가 끝나면 **구현 착수용 스펙**(`.scratch/flow-mention-drafter/spec.md`)이 나온다.

스펙이 다루는 대상은 두 가지다.

- **트레이/메뉴바 데스크톱 앱**(미서명 dmg/exe)
  - Flow의 업무 멘션을 감지한다. 채팅 멘션은 확인 결과에 따라 포함한다.
  - 로컬 CLI 에이전트가 저장소를 읽고 **요구·초안·근거**를 만든다.
  - 업무 멘션은 승인하면 내 명의 댓글로 게시하고, 채팅 멘션은 복사해 붙여넣는다.
- 그 앱의 **다운로드 사이트**

스펙만 보고 티켓을 나눠 바로 구현에 들어갈 수 있으면 도착이다.

### 차팅 중 확정된 전제

티켓 없이 정한 사항이다. 바꾸려면 지도를 다시 그려야 한다.

- **사용자**: 내가 먼저 써 보고, 괜찮으면 팀원에게 배포한다. 배포는 dmg/exe를 내려받는 웹사이트로 한다.
- **플랫폼**: Mac과 Windows 둘 다 지원한다. MVP 검증은 Mac에서 하고, 기술 선택은 Windows에서도 동작하는 것으로 한정한다.
- **앱 형태**: 트레이/메뉴바 데스크톱 앱. 코드 서명은 하지 않고, 설치할 때 뜨는 경고는 사용자가 동의하고 넘어간다.
- **감지**: 개인 API 키로 폴링한다. 허용 지연은 1~5분이다.
- **감지 범위**: 업무와 채팅에서 나를 `@`로 직접 지목한 멘션만 감지한다. 업무 멘션은 MVP에 확정이고, 채팅 멘션은 확인 결과에 따라 넣는다.
- **에이전트**: 내 PC에 설치된 CLI를 비대화형으로 호출한다. 실행기는 교체할 수 있게 만든다.
- **안전 장치**: 에이전트는 읽기 전용으로 실행하고, 비밀 파일은 탐색에서 뺀다. 초안은 반드시 사람이 검토한다.
- **저장소 선택**: 직접 등록한 저장소 매핑을 먼저 쓴다. 매핑이 없으면 에이전트가 작업 폴더에서 저장소를 고른다.
- **맥락과 생성**: 에이전트에게 게시물 본문과 댓글 스레드를 맥락으로 준다. 초안은 자동으로 생성하고, 요구와 근거를 함께 표시한다.
- **알림**: 초안이 준비되면 OS 알림을 띄우고, 알림을 클릭하면 검토 화면이 열린다.
  - 미서명 앱에서 알림 클릭이 동작하는지는 [미서명 Tauri 앱 macOS 실기 검증](issues/11-tauri-macos-unsigned-check.md)에서 확인한다. 그 전까지는 확정이 아니다.
- **데이터 반출**: 회사 코드와 Flow 메시지를 에이전트 제공사로 보내는 것은 기존 Claude Code/Codex 사용 범위 안에서 허용된 것으로 본다.

## Decisions so far

- [CLI 에이전트 비대화형 실행 능력 조사](issues/02-cli-agent-headless-research.md): Claude Code(`claude -p --json-schema`)와 Codex(`codex exec --output-schema`) 모두 비대화형 구조화 출력과 읽기 전용 실행이 되지만, 비밀 파일 제외는 Codex에서 베타 기능에 의존하고, `claude -p`는 저장소 훅을 막는 플래그가 필수다.
- [트레이 데스크톱 앱 프레임워크와 미서명 배포 조사](issues/03-tray-app-framework-research.md): 미서명 전제에서는 Tauri v2가 유리하다(Electron 42 이상은 macOS 알림과 로그인 항목에 서명이 필요하다). 다만 Tauri의 macOS 알림 클릭은 폐기 예정 API에 기대 실기 검증이 필요하고, Apple Silicon에는 ad-hoc 서명이 필수이며, Windows 스마트 앱 컨트롤이 켜진 PC에서는 미서명 앱이 실행되지 않는다.

## Not yet specified

- **설정·비밀 저장과 첫 실행 온보딩**: 개인 API 키 입력과 보관, 작업 폴더 지정, 기본 에이전트 선택을 어떤 순서와 화면으로 할지 정해야 한다.
  - GUI 앱은 셸 PATH를 물려받지 못한다. 그래서 온보딩에 CLI 경로를 찾는 단계와 로그인 상태(`claude auth status`, `codex login status`)를 점검하는 단계가 들어가야 한다.
  - 미서명 앱은 업데이트할 때마다 Keychain 접근 허용을 다시 물을 수 있다. 개인 API 키를 어디에 보관할지 정할 때 이 점을 고려한다.
  - 데스크톱 프레임워크가 정해진 뒤에 구체화한다.
- **게시 세부**: 초안을 원 게시물의 댓글로 달지, 멘션이 달린 댓글의 대댓글로 달지 정해야 한다. 근거를 게시 본문에 넣을지 검토 화면에만 둘지도 남아 있다. 검토 화면 프로토타입과 멘션 감지 방식 결정 뒤에 구체화한다.
- **채팅 멘션의 대안 경로**: 알림 API에 채팅 멘션이 없으면 다른 감지 경로를 찾아야 한다. 후보는 Flow MCP의 `flow_search`나 OS 알림을 읽는 방식이다. 이걸 MVP에 넣을지는 멘션 감지 방식 결정에서 판단한다.

## Out of scope

- **코드 서명과 공증**: 미서명으로 배포하고, 설치 경고는 사용자가 동의하고 넘어가기로 했다.
  - 이 경계는 [서명 정책 재검토](issues/10-signing-policy-review.md)에서 다시 보는 중이다. 재검토가 필요해진 이유는 두 가지다. Apple Silicon에서는 ad-hoc 서명이 필요하고, Windows 스마트 앱 컨트롤이 켜진 PC에서는 미서명 앱이 실행되지 않는다.
- **앱 내 자동 업데이트**: 새 버전은 다운로드 사이트에서 다시 받는다.
- **서버형 중앙 처리**: 저장소와 에이전트가 각자의 PC에 있어서 중앙 서버로는 처리할 수 없다.
- **검토 없는 자동 게시**: 동료에게 나가는 글이므로 사람이 반드시 검토한다.
- **담당자 지정과 그룹 멘션 감지**: 잡음이 많아 멘션의 정의에서 뺐다.
- **에이전트의 저장소 수정**: 에이전트는 읽기 전용으로 실행한다.
- **구현 자체**: 이 지도의 도착점은 스펙이다.
