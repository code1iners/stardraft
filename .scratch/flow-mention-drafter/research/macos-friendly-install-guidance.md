# macOS 첫 실행의 현실적인 사용자 안내 조사

- 조사일: 2026-10-26
- 범위: 일반 사용자가 터미널 없이 설치하는 동선 조사. 제품 코드·배포·보안 설정은 변경하지 않는다.
- 결론: **정식 배포는 Developer ID 서명과 Apple 공증으로 차단 원인을 해결한다. 그 전의 Mac 시험 배포에는 다운로드 페이지의 실제 설정 열기 버튼과 짧은 화면 안내를 제공한다.** 명령어를 사용자에게 입력시키는 방식은 제품 안내로 사용하지 않는다.

## 확인된 사실

1. Apple은 앱을 먼저 열어 차단된 뒤 시스템 설정의 개인정보 보호 및 보안에서 해당 앱의 `그래도 열기`를 선택하는 경로를 안내한다. 예외가 저장되면 이후에는 앱을 두 번 클릭해 연다. [Apple: Mac에서 앱 안전하게 열기](https://support.apple.com/ko-kr/102445)
2. `그래도 열기` 버튼은 실행 시도 후 약 1시간 동안 제공된다. 보이지 않으면 앱을 다시 실행해 경고를 확인한 다음 설정으로 돌아오게 안내한다. 뒤 문장은 시간 제한에서 도출한 안내 권고다. [Apple Mac 사용자 가이드](https://support.apple.com/guide/mac-help/open-a-mac-app-from-an-unknown-developer-mh40616/mac)
3. macOS Sequoia부터 올바르게 서명되거나 공증되지 않은 소프트웨어에 대해 Control-click으로 Gatekeeper를 우회하는 방식이 제거되었다. `우클릭 → 열기`를 최신 Mac의 해결책으로 안내하면 안 된다. [Apple 개발자 공지](https://developer.apple.com/news/?id=saqachfa)
4. Developer ID 서명과 공증은 배포자가 준비하는 작업이다. 사용자에게 개발 도구나 터미널을 요구하지 않는다. Apple은 앱 외에도 배포하는 설치 패키지의 서명을 안내한다. 공증은 자동 보안 검사 후 Gatekeeper가 확인할 티켓을 발급하는 절차다. [Apple Developer ID](https://developer.apple.com/developer-id/)
5. 공증을 해도 인터넷에서 내려받은 앱을 처음 여는 일반 확인창까지 모두 없어지는 것은 아니다. 목표는 현재의 미확인 앱 차단과 수동 예외 허용 단계를 없애는 것이다. [Apple 지원](https://support.apple.com/ko-kr/102445)

## 현실적인 선택지

| 선택지 | 사용자 행동 | 판단과 한계 |
|---|---|---|
| 서명·공증한 앱 배포 | 내려받기 → 응용 프로그램으로 이동 → 열기 | 일반 사용자 배포의 우선안. 빌드·서명·공증 절차와 내려받은 결과물의 실제 실행 시험 필요 |
| 다운로드 페이지의 `보안 설정 열기` 버튼 | 버튼 클릭 → 브라우저의 외부 앱 열기 확인 → 설정의 해당 앱 `그래도 열기` | 현재 시험 배포의 현실적인 보완안. 사용자가 주소나 명령을 입력하지 않음. 설정 이동을 줄일 뿐 예외 허용 자체는 사용자가 결정 |
| 화면 캡처와 수동 설정 경로 | Apple 메뉴 → 시스템 설정 → 개인정보 보호 및 보안 → 아래쪽 보안 | 버튼이 동작하지 않을 때 필수 대체 경로. 앱을 먼저 실행해야 함을 앞에 둠 |
| DMG 안 설치 안내 문서 또는 안내 웹페이지 바로가기 | 설치 화면에서 안내를 두 번 클릭 | 다운로드 페이지를 닫은 사람을 위한 보조안. 실제 내려받은 DMG에서 파일 연동·격리·브라우저 이동을 아직 검증하지 않음. 우선은 정적 안내 문서와 일반 웹주소를 고려 |
| 별도 설치 도우미 앱·설치 패키지 | 도우미 실행 | 미서명·미공증 실행 파일을 추가해도 같은 검사 대상이 되므로 문제를 옮길 수 있음. 서명·공증을 할 수 있다면 본 앱 배포에 먼저 적용하는 편이 단순함. 이 판단은 Apple 서명 안내에 근거한 추론 |

막힌 Stardraft 내부에서 안내 창을 띄우거나 시스템 차단 경고에 자체 버튼을 넣는 방식은 첫 실행 전 차단을 해결하지 못한다. 기존 조사에서 공개 확장 지점을 확인하지 못했으며, 앱 실행 전에는 앱의 안내 코드에 도달할 수 없다는 판단이다. [기존 조사](macos-gatekeeper-settings-shortcut.md)

## 권장 설치 동선

현재 `apps/site/src/components/install-steps.tsx`에는 Mac 설치 5단계, `mac-blocked`·`mac-settings` 화면 슬롯, 수동 경로, 약 1시간 안내가 있다. 현재 실제 스크린샷 자산은 없고 예시 화면으로 대체되는 구조이므로, 실제 한국어 차단 화면과 보안 설정 화면을 보강하는 것이 필요하다. 이 기존 동선을 활용한다.

1. 다운로드 직후에도 설치 안내를 계속 볼 수 있게 한다.
2. 앱을 응용 프로그램으로 옮겨 한 번 실행하는 단계 다음에 차단 화면과 안내를 배치한다.
3. 기존 설정 이동 단계에 **실제로 클릭할 수 있는 `보안 설정 열기` 버튼**을 넣는다. 특수 주소는 버튼 안에 연결하고 사용자에게 노출하거나 입력시키지 않는다.
4. 브라우저의 확인 후 보안 설정으로 이동하면 Stardraft 이름 옆의 `그래도 열기`를 찾게 한다.
5. 접힌 `설정이 열리지 않나요?` 안내에는 수동 경로와 버튼이 없을 때의 방법을 둔다.

위 동선은 제안이며 아직 구현하지 않았다. GitHub Release 본문에는 임의 프로토콜 주소를 직접 넣는 대신 일반 설치 안내 페이지 링크를 제공하는 편을 권한다. GitHub의 임의 프로토콜 처리 여부는 검증하지 않았다.

## 사용자에게 보여줄 문구 초안

> **Stardraft가 열리지 않나요?**
>
> 현재 Mac 시험판은 Apple 공증 전이라 첫 실행 시 차단될 수 있습니다.
>
> 1. 경고창에서 **완료**를 누르세요.
> 2. **보안 설정 열기**를 누르고, 브라우저에서 시스템 설정을 열도록 허용해 주세요.
> 3. Stardraft 옆의 **그래도 열기**를 누른 뒤 Mac의 안내를 따라 주세요.
>
> **[보안 설정 열기]**
>
> 설정이 열리지 않으면: 왼쪽 위 ** → 시스템 설정 → 개인정보 보호 및 보안**을 열고 아래 **보안**으로 내려가세요.
>
> **그래도 열기**가 없으면 Stardraft를 다시 실행한 뒤 이 화면으로 돌아오세요.

이 안내는 공식 배포처에서 받은 Mac 시험판의 해당 차단 경고에만 적용한다. `컴퓨터를 손상시킵니다` 또는 `앱이 손상되었습니다` 같은 다른 경고를 같은 절차로 통합하지 않는다. Apple도 악성 콘텐츠 감지·서명 취소·파일 손상 경고를 별도로 설명한다. [Apple 지원](https://support.apple.com/ko-kr/102445)

## 검증 경계와 다음 최소 시험

- 기존 실제 관찰: macOS 27.0.1의 Chrome·Safari에서 로컬 HTML 링크 `x-apple.systempreferences:com.apple.preference.security?General` 클릭 → 일회성 외부 앱 열기 확인 → `그래도 열기`가 보이는 보안 항목까지 자동 이동했다. 명령어 입력은 필요하지 않았다. [기존 검증 기록](macos-gatekeeper-settings-shortcut.md)
- 미검증: 실제 배포 웹사이트의 보안 연결 페이지, 다른 macOS·브라우저 버전, 관리형 Mac, DMG 안내 파일.
- 최소 시험: 실제 다운로드 페이지에 버튼을 적용한 시험 화면에서 처음 받는 사용자 역할로 `다운로드 → 앱 이동 → 실행 차단 → 안내 버튼 → 설정 → 해당 앱 확인` 흐름을 Safari와 Chrome에서 확인한다. 설정 화면이 열렸다는 사실만으로 전체 설치 성공을 주장하지 않는다.
- 정식 배포 검증: 서명·공증된 결과물을 새 다운로드 경로로 받아 현재 차단 경고가 사라졌는지 별도로 확인한다.
