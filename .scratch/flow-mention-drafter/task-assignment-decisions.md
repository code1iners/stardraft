| Q1 신규 기준 | 업무 생성일과 관계없이 기능을 켠 이후 나에게 새로 배정된 업무를 포함한다. 기능을 켜기 전부터 맡고 있던 업무는 제외한다. |
| Q2 초안 대상 | 생성 시점에 조회한 최신 업무 제목·본문을 대상으로 한다. 댓글은 보조 맥락이다. 생성 당시 수정 전 본문의 복원은 요구하지 않는다. |
| Q3 생성 횟수 | 업무별 최초 초안은 한 번 자동 생성한다. 담당 해제 후 재지정으로 자동 재생성하지 않는다. 실패 재시도와 사용자 요청 재생성은 허용한다. |
| Q4 대상 담당자 | 내가 만든 업무에 나를 담당자로 넣는 경우는 제외한다. 여러 담당자 중 내가 포함된 경우는 포함한다. |
| Q5 멘션 중복 | 같은 업무 본문의 직접 멘션과 담당자 지정은 한 초안으로 합친다. 이후 댓글 멘션은 기존 방식으로 처리한다. |
| Q6 후속 흐름 | 기존 검토 화면에서 확인·수정하고, 사용자가 승인하면 해당 업무 댓글로 게시한다. |
| Q7 담당 해제 | 초안 생성 중 담당자에서 제외되면 생성을 중단한다. 이미 만든 초안은 제외 사유와 함께 보존하되 게시를 막는다. |
| Q8 받는 사람 | 담당 업무 초안의 댓글은 업무 작성자를 기본으로 멘션한다. 실제 담당자 지정자가 다르더라도 작성자가 기본이며, 검토할 때 뺄 수 있다. |
| Q9 이미 답함 | 초안 생성 전에 배정 이후 작성한 내 업무 댓글이 있으면 기존 방식처럼 ‘이미 답함’으로 처리한다. 배정 전 댓글은 판정에서 제외한다. |
| Q10 완료 업무 | 새 배정 시 이미 완료된 업무는 자동 초안 대상에서 제외한다. |

## 질문 결과

현재 조사 범위에서 사용자에게 추가로 확인할 제품 질문은 없다. 아래 기술 검증은 합의 완료와 구분하며, 검증 결과 합의된 동작을 제공할 수 없다면 제약과 대안을 다시 논의한다.

## 기술 검증 경계

- 생성 시 지정과 생성 후 지정의 실제 발견 경로, 현재 담당자 응답 형태를 확인해야 한다.
- 최초 동기화 기준과 이후 신규 배정 감지를 구분해야 한다. 업무 작성 시각으로 신규 배정을 대체하지 않는다.
- 일반 담당 업무 알림만으로 새 배정이라 단정하지 않는다. 초기 상태와 업무별 처리 기록이 필요하다.
- Q9의 배정 이후 여부를 판단할 시각 근거를 확인해야 한다. 최초 관측 시각이나 업무 생성 시각을 실제 배정 시각으로 단정하지 않는다.
- 업무 완료 상태와 담당 해제의 실제 응답을 확인해야 한다. 직접 멘션과 합친 초안에서도 각 감지 사유의 유효성을 구분할 필요가 있다.
- 알림 누락 보완, 조회 주기·접근 범위, 같은 본문의 멘션과 담당 업무 중복 방지는 구현 설계·검증 대상이다.
- 현재 구현은 멘션 전용이다. 이 문서와 용어집 갱신은 제품 동작의 변경이나 실제 환경 검증이 아니다.
