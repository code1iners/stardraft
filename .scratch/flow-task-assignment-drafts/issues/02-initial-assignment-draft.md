# 02: 생성 시 배정된 업무의 최초 초안과 게시

Status: ready-for-agent
Blocked by: 01 (Flow 신규 배정 판별 근거 검증)

**What to build:** 다른 사람이 업무를 생성하면서 나를 담당자로 지정하면 최신 업무 제목·본문과 관련 코드에 대한 초안을 받고, 기존 화면에서 검토·수정하여 승인 후 업무 댓글로 게시할 수 있다.

스펙: [담당 업무 최초 초안](../spec.md)
연결 요구: Q1~Q4, Q6, Q8, Q10. 사용자 이야기 1, 4~12, 18~21, 27.

- [ ] 기능 활성화 기준과 초기 담당 업무 상태를 저장한다. 기능 시작 전부터 맡고 있던 업무를 초기 초안으로 일괄 생성하지 않는다.
- [ ] 01에서 검증된 실제 발견·판정 경로로 생성 시 나 지정 업무를 수집한다. 담당자 지정을 가짜 직접 멘션으로 변환하지 않는다.
- [ ] 내가 만든 업무에 나를 담당자로 넣은 경우와 새 배정 시 이미 완료된 업무는 제외한다. 다른 사람이 만든 업무의 복수 담당자 중 내가 포함되면 처리한다.
- [ ] 조회 실패를 미담당·완료로 단정하지 않는다. 불완전한 최초 조회를 성공한 기준 상태로 기록하지 않는다.
- [ ] 기존 저장소 매핑과 자동 선택을 거쳐 최신 업무 제목·본문을 답변 대상으로 전달하고 댓글은 보조 맥락으로 사용한다. 변경 알림 문구를 요청 본문으로 사용하지 않는다.
- [ ] 검토 화면에서 담당 업무 초안임을 알 수 있고, 기존 초안 수정 및 사용자 승인 후 게시 흐름을 사용할 수 있다.
- [ ] 업무 작성자를 기본 받는 사람으로 사용한다. 실제 지정자가 달라도 작성자가 기본이며, 사용자가 제거한 멘션은 게시 본문에 포함하지 않는다.
- [ ] 승인한 초안이 해당 업무의 댓글로 게시된다. 사용자 승인 없이 게시하지 않는다.
- [ ] 계정과 업무를 구분하는 최초 처리 기록을 저장하고 같은 업무의 반복 알림·일반 댓글·상태 변경으로 초기 초안을 중복 생성하지 않는다. 실패를 성공적인 최초 생성으로 기록하지 않는다.
- [ ] 필요한 감지 사유와 저장 구조는 기존 멘션과 함께 사용할 수 있게 확장한다. 기존 저장 데이터·계정 격리·직접 멘션 동작을 유지하며 별도 대규모 이름 변경을 선행하지 않는다.
- [ ] 기존 초안 대기열 통합 테스트에서 감지부터 게시까지 검증하고, 새 외부 응답 해석·저장 구조·검토 화면에 필요한 기존 테스트를 확장한다. 사용자에게 보이는 결과를 검증하며 내부 호출 순서를 고정하지 않는다.
- [ ] 마지막 변경 이후 정적 검사와 관련 자동 테스트를 실행하고, 데스크톱 검토·수정·게시 화면을 확인한다. 가짜 Flow 게시 결과와 실제 Flow 게시 증거는 구분한다.
