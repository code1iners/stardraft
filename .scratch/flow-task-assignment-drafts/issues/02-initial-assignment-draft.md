# 02: 생성 시 배정된 업무의 최초 초안과 게시

Status: resolved
Blocked by: 없음 (2026-10-30 사용자 승인: 미확정 업무는 보류·재조회하며 구현 진행)

**What to build:** 다른 사람이 업무를 생성하면서 나를 담당자로 지정하면 최신 업무 제목·본문과 관련 코드에 대한 초안을 받고, 기존 화면에서 검토·수정하여 승인 후 업무 댓글로 게시할 수 있다.

스펙: [담당 업무 최초 초안](../spec.md)
연결 요구: Q1~Q4, Q6, Q8, Q10. 사용자 이야기 1, 4~12, 18~21, 27.

- [x] 기능 활성화 기준과 초기 담당 업무 상태를 저장한다. 기능 시작 전부터 맡고 있던 업무를 초기 초안으로 일괄 생성하지 않는다.
- [x] 01에서 검증된 실제 발견·판정 경로로 생성 시 나 지정 업무를 수집한다. 담당자 지정을 가짜 직접 멘션으로 변환하지 않는다.
- [x] 내가 만든 업무에 나를 담당자로 넣은 경우와 새 배정 시 이미 완료된 업무는 제외한다. 다른 사람이 만든 업무의 복수 담당자 중 내가 포함되면 처리한다.
- [x] 조회 실패를 미담당·완료로 단정하지 않는다. 불완전한 최초 조회를 성공한 기준 상태로 기록하지 않는다.
- [x] 기존 저장소 매핑과 자동 선택을 거쳐 최신 업무 제목·본문을 답변 대상으로 전달하고 댓글은 보조 맥락으로 사용한다. 변경 알림 문구를 요청 본문으로 사용하지 않는다.
- [x] 검토 화면에서 담당 업무 초안임을 알 수 있고, 기존 초안 수정 및 사용자 승인 후 게시 흐름을 사용할 수 있다.
- [x] 업무 작성자를 기본 받는 사람으로 사용한다. 실제 지정자가 달라도 작성자가 기본이며, 사용자가 제거한 멘션은 게시 본문에 포함하지 않는다.
- [x] 승인한 초안이 해당 업무의 댓글로 게시된다. 사용자 승인 없이 게시하지 않는다.
- [x] 계정과 업무를 구분하는 최초 처리 기록을 저장하고 같은 업무의 반복 알림·일반 댓글·상태 변경으로 초기 초안을 중복 생성하지 않는다. 실패를 성공적인 최초 생성으로 기록하지 않는다.
- [x] 필요한 감지 사유와 저장 구조는 기존 멘션과 함께 사용할 수 있게 확장한다. 기존 저장 데이터·계정 격리·직접 멘션 동작을 유지하며 별도 대규모 이름 변경을 선행하지 않는다.
- [x] 기존 초안 대기열 통합 테스트에서 감지부터 게시까지 검증하고, 새 외부 응답 해석·저장 구조·검토 화면에 필요한 기존 테스트를 확장한다. 사용자에게 보이는 결과를 검증하며 내부 호출 순서를 고정하지 않는다.
- [x] 마지막 변경 이후 정적 검사와 관련 자동 테스트를 실행하고, 데스크톱 검토·수정·게시 화면을 확인한다. 가짜 Flow 게시 결과와 실제 Flow 게시 증거는 구분한다.

## Comments


### 2026-10-30 — 구현 및 검증

사용자가 이 대화에서 “진행할 수 있다는거지?”를 확인한 뒤 `$implement 진행해줘`로 실행을 승인했다. 미확정 판별 계약은 임의로 성공 처리하지 않고 보류·재조회한다. 생성 시 지정의 실제 사례는 기존 합의대로 06번 사용 중 검증에서 추적한다. 01번 전체를 해결한 것으로 간주하지 않는다.

#### 구현 범위와 보류 조건

- 기존 감지 시작 설정에 연결한다. 계정별 최초 실행 시각, 초기 알림에 나타난 업무, 완료한 알림 기준점, 미완료 순회 커서와 보류 후보를 `assignment_detection`에 남긴다. 첫 조회 실패·중간 실패·반복 커서·주기별 50쪽 상한을 완료한 초기 상태로 기록하지 않는다. 상한과 중간 실패는 다음 주기에 이어 받는다.
- `WORKER`는 후보 발견에만 쓴다. 이번 02번의 보수적 적격 조건은 **활성화 후 생성, 본문 위치 알림, 알림·생성·수정 시각 일치, 다른 작성자, 단일 업무 식별, 본인 포함 담당자 배열, 확인된 미완료 범주**다. 다른 조건은 보류하며 생성 후 배정·배정 시각 복원은 03번 범위다. 일반 댓글과 변경 알림의 문구를 답변 대상으로 쓰지 않는다.
- 초기 알림 목록은 모든 프로젝트 담당 업무의 완전한 스냅샷이라고 주장하지 않는다. 활성화 이전에 작성된 업무를 02번에서 생성하지 않는 경계를 함께 사용하여 오래된 업무에 새 알림이 와도 초안을 만들지 않는다. 초기 조회 구간의 불명확한 사건, 알림 누락, 수정된 뒤 처음 발견한 후보는 무누락 감지를 보장하지 않는다.
- `mention_bundle.assignment`에 담당 업무 정보를 별도로 저장하고 `mentions`에 가짜 직접 멘션을 넣지 않는다. `assignment_record`는 계정·프로젝트·업무별 **최초 묶음 발견** 기록이며 초안 생성 성공 기록이 아니다. 실패/준비됨/게시됨은 기존 묶음 상태로 구분하고, 실패는 같은 묶음에서 재시도한다. 계정 초기화 때 감지·최초 묶음 기록을 함께 지운다.
- 기존 저장소 매핑·자동 선택·최신 맥락 수집·초안 대기열·편집·승인 후 댓글 게시를 재사용한다. 담당 업무 입력은 최신 제목·본문을 답변 대상으로 표시하며 댓글은 보조 맥락이다. 받는 사람은 최신 업무 작성자이며 제거한 멘션은 게시 본문에서 제외된다.
- 기존 검토 화면에 담당 업무 초안과 업무 본문을 표시한다. 게시 카운트다운·실패·무시 문구도 직접 멘션으로 오인시키지 않는다. 알림 조회 실패가 기존 직접 멘션 감지를 중단시키지 않게 오류 경계를 분리했다.
