# 03: 기존 업무의 신규 배정과 ‘이미 답함’ 처리

Status: resolved
Blocked by: 없음 (02 해결)

**What to build:** 오래전에 생성된 업무라도 기능 시작 후 나에게 새로 배정되면 초안을 받는다. 배정 이후 이미 내 댓글로 답했다면 초안을 만들지 않고 ‘이미 답함’으로 확인할 수 있다.

스펙: [담당 업무 최초 초안](../spec.md)
연결 요구: Q1, Q2, Q9. 사용자 이야기 2, 3, 24, 25, 27.

- [x] 생성 후 나를 담당자로 추가한 업무가 기존 초안 검토·승인 후 게시 흐름으로 이어진다. 업무 작성일이 기능 시작 전이라는 이유만으로 제외하지 않는다.
- [x] 최초부터 담당하던 업무의 일반 댓글·상태 변경을 신규 배정으로 오판하지 않는다. 01의 검증된 기준 상태와 발견 방식을 사용한다.
- [x] 배정 후 초안 생성 전에 작성한 내 업무 댓글이 있으면 ‘이미 답함’으로 처리하고 불필요한 생성을 시작하지 않는다. 이 판정은 생성 시 지정과 생성 후 지정 양쪽에 적용된다.
- [x] 배정 전에 작성한 내 댓글은 새 배정의 답변으로 보지 않는다. 담당자 변경 등의 시스템 기록도 내 답변으로 보지 않는다.
- [x] 배정 시점 근거가 없거나 댓글 조회가 실패하면 임의 시각으로 ‘이미 답함’을 확정하지 않는다. 미확인 상태를 재시도할 수 있고 실제 제약을 숨기지 않는다.
- [x] 검토 화면 또는 기존 처리됨 표시에서 ‘이미 답함’을 확인할 수 있다. 초기 초안 생성과 동일한 업무 처리 기록을 사용하여 반복 조회로 중복 생성하지 않는다.
- [x] 기존 통합 테스트에서 오래된 업무 신규 배정, 초기 담당 업무 제외, 배정 전후 댓글, 시스템 댓글, 조회 실패를 검증한다. 정상 대상은 검토·승인 후 댓글 게시까지 연결됨을 확인한다.
- [x] 마지막 변경 이후 정적 검사·관련 자동 테스트와 변경된 데스크톱 표시를 확인한다. 실제 생성 후 지정의 발견 근거는 가짜 응답 검증과 별도로 기록한다.

## Comments


### 2026-10-30 — 구현 및 검증

사용자가 `/implement`로 실행을 승인했다. 구현 중 두 가지 판정 기준을 사용자에게 확인했고, 사용자는 둘 다 권장안을 골랐다.

#### 사용자 결정

1. **생성 후 배정 확정 기준.** S41 담당 변경 시스템 기록과 현재 사용자 ID를 교차 확인한다. ID 전후 비교만 쓰는 대안은 배정 전 미담당 상태를 `WORKER` 알림으로 관측할 수 없어 사례 A·C를 감지하지 못한다. [동명이인 조사](../research/assignment-identity-disambiguation-2026-10-30.md)
2. **답글 포함.** ‘이미 답함’에는 일반 댓글과 모든 스레드의 내 답글을 포함한다.

#### 판정 규칙

- **생성 후 지정.** 아래 조건이 모두 맞아야 확정한다.
  - 최신 S41 기록부터 거슬러 올라가며 내 현재 표시 이름이 ‘이후 담당자’에 정확히 한 번씩 이어진다.
  - 그중 ‘이전 담당자’에 내 이름이 없는 기록이 하나로 정해진다.
  - 현재 `WORKER_REC`에 내 ID가 있다.
  - 담당자 컬럼(`USER_NM`)상 현재 담당자 중 내 이름은 나 하나뿐이다.
- **배정 시각.** 그 S41 기록의 서버 시각이다. 기능 시작 전 기록이면 제외한다. 알림·관측·업무 작성 시각으로 대체하지 않는다.
- **해석하는 S41 형식.** 실응답에서 관측한 `S41^^'이전'^^'이후'`와 `S41^^'이후'@$%` 두 가지뿐이다.
- **생성 시 지정.** 02번의 보수 조건을 유지하고, 업무 작성 시각을 배정 시각으로 쓴다.
- **보류와 후보 제외.**
  - 조회 실패와 쪽 상한으로 끝까지 받지 못한 경우는 보류하고 매 주기 재조회한다.
  - 끝까지 받았는데 근거가 없거나 형식 이상·동명이인·이름 불일치·기능 시작 전 배정이면 후보에서 뺀다. 이런 경우는 같은 기록을 다시 조회해도 결과가 같고, 반복 조회가 쌓이는 것을 막기 위해서다. 해당 업무에 새 알림이 오면 다시 판정한다.
  - 기능 시작 전 알림에 나온 업무, 자기 작성 업무, 완료 업무도 후보에서 뺀다.
- **‘이미 답함’ 판정.**
  - 배정 시각보다 뒤에 쓴 내 사람 글(댓글과 모든 스레드의 답글)이 있으면 생성하지 않는다. 같은 업무 처리 기록(`assignment_record`)에 ‘이미 답함’ 묶음으로 남긴다.
  - 배정 전 내 댓글과 내 명의 시스템 기록(S45 등)은 답으로 세지 않는다.
  - 생성 직전(`prepareRun`)에도 같은 기준으로 다시 판정한다.
  - 되돌리면 그때의 답을 빼고 다시 만든다.
  - 배정 시각이 없는 02번 시절 묶음은 판정하지 않는다.
- **남는 한계.**
  - 내가 과거에 표시 이름을 바꿨다면 이 경우를 구별하지 못한다.
  - 기능 시작 전부터 맡다가 해제된 뒤 다시 배정된 업무는, 기능 시작 전 알림에 나왔다면 계속 제외된다.
  - 준비됨 이후 쓴 내 답은 ‘이미 답함’으로 옮기지 않는다. 스펙은 생성 전만 요구한다.
