# 03: 기존 업무의 신규 배정과 ‘이미 답함’ 처리

Status: ready-for-agent
Blocked by: 02 (생성 시 배정된 업무의 최초 초안과 게시)

**What to build:** 오래전에 생성된 업무라도 기능 시작 후 나에게 새로 배정되면 초안을 받는다. 배정 이후 이미 내 댓글로 답했다면 초안을 만들지 않고 ‘이미 답함’으로 확인할 수 있다.

스펙: [담당 업무 최초 초안](../spec.md)
연결 요구: Q1, Q2, Q9. 사용자 이야기 2, 3, 24, 25, 27.

- [ ] 생성 후 나를 담당자로 추가한 업무가 기존 초안 검토·승인 후 게시 흐름으로 이어진다. 업무 작성일이 기능 시작 전이라는 이유만으로 제외하지 않는다.
- [ ] 최초부터 담당하던 업무의 일반 댓글·상태 변경을 신규 배정으로 오판하지 않는다. 01의 검증된 기준 상태와 발견 방식을 사용한다.
- [ ] 배정 후 초안 생성 전에 작성한 내 업무 댓글이 있으면 ‘이미 답함’으로 처리하고 불필요한 생성을 시작하지 않는다. 이 판정은 생성 시 지정과 생성 후 지정 양쪽에 적용된다.
- [ ] 배정 전에 작성한 내 댓글은 새 배정의 답변으로 보지 않는다. 담당자 변경 등의 시스템 기록도 내 답변으로 보지 않는다.
- [ ] 배정 시점 근거가 없거나 댓글 조회가 실패하면 임의 시각으로 ‘이미 답함’을 확정하지 않는다. 미확인 상태를 재시도할 수 있고 실제 제약을 숨기지 않는다.
- [ ] 검토 화면 또는 기존 처리됨 표시에서 ‘이미 답함’을 확인할 수 있다. 초기 초안 생성과 동일한 업무 처리 기록을 사용하여 반복 조회로 중복 생성하지 않는다.
- [ ] 기존 통합 테스트에서 오래된 업무 신규 배정, 초기 담당 업무 제외, 배정 전후 댓글, 시스템 댓글, 조회 실패를 검증한다. 정상 대상은 검토·승인 후 댓글 게시까지 연결됨을 확인한다.
- [ ] 마지막 변경 이후 정적 검사·관련 자동 테스트와 변경된 데스크톱 표시를 확인한다. 실제 생성 후 지정의 발견 근거는 가짜 응답 검증과 별도로 기록한다.
