# 04: 담당자 지정과 본문 멘션의 중복 통합

Status: ready-for-agent
Blocked by: 02 (생성 시 배정된 업무의 최초 초안과 게시)

**What to build:** 같은 업무 본문에 나를 직접 멘션하면서 담당자로도 지정한 경우 초안 하나만 받아 검토·게시한다. 이후 댓글 멘션은 기존처럼 별도로 처리한다.

스펙: [담당 업무 최초 초안](../spec.md)
연결 요구: Q3, Q5. 사용자 이야기 11, 12, 16, 17.

- [ ] 동일 업무 본문의 직접 멘션과 담당자 지정 후보가 하나의 검토 대상과 초기 초안으로 합쳐진다. 업무 식별자와 본문 위치의 관계는 검증된 계약을 따른다.
- [ ] 멘션 먼저·지정 먼저·같은 조회에서 함께 수집되는 경우와 중복 알림을 검증한다. 대기 중·생성 중·검토 중인 동일 본문에 두 번째 감지 사유가 들어와도 별도 초기 초안을 만들지 않는다.
- [ ] 합쳐진 초안에도 각 감지 사유를 보존한다. 담당 업무의 현재 담당 여부와 직접 멘션 존재를 혼동하지 않는다.
- [ ] 합쳐진 초안은 최신 업무 제목·본문에 답하고, 검토·수정·받는 사람 제거·승인 후 댓글 게시까지 기존 흐름으로 이어진다. 이중 게시가 발생하지 않는다.
- [ ] 같은 업무의 이후 댓글·대댓글 직접 멘션은 기존 멘션 위치와 댓글 스레드 기준으로 처리된다. 업무별 최초 초안 기록이 후속 멘션을 막지 않는다.
- [ ] 이미 초기 초안을 생성·처리한 동일 본문에 뒤늦게 중복 알림이 도착해도 또 다른 초기 초안을 생성하지 않는다.
- [ ] 기존 통합 테스트에서 알림 순서와 진행 상태별 초안 수·검토 대상 수·게시 결과를 검증한다. 기존 본문 및 댓글 멘션 회귀 검증도 통과한다.
- [ ] 마지막 변경 이후 정적 검사·관련 자동 테스트와 데스크톱의 단일 검토 대상 표시를 확인한다.
