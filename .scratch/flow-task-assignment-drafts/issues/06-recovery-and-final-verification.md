# 06: 재시작·재시도·재지정 복구와 최종 검증

Status: ready-for-agent
Blocked by: 03 (기존 업무의 신규 배정과 ‘이미 답함’ 처리), 04 (담당자 지정과 본문 멘션의 중복 통합), 05 (담당 해제 시 생성 중단과 게시 차단)

**What to build:** 앱 재시작과 재지정에도 같은 업무의 초기 초안이 중복되지 않고, 실패 재시도와 사용자 요청 재생성은 정상적으로 이어진다. 모든 감지·검토·게시 규칙이 함께 동작하는지 실제 사용 흐름으로 확인한다.

스펙: [담당 업무 최초 초안](../spec.md)
연결 요구: Q1~Q10 종합. 사용자 이야기 13~15, 26 및 전체 기능의 완료 검증.

- [ ] 앱 재시작 후 초기 담당 기준과 업무별 처리 기록을 복원한다. 같은 업무의 반복 알림·일반 변경·담당 해제 후 재지정으로 초기 초안을 자동 재생성하지 않는다.
- [ ] 생성 실패·진행 중 종료·성공 완료를 구분한다. 실패한 작업은 기존 재시도 흐름으로 복구할 수 있고, 실패를 성공한 최초 생성으로 취급하거나 중복 실행하지 않는다.
- [ ] 사용자가 지시를 덧붙여 재생성할 수 있다. 자동 중복 방지는 수동 재생성을 막지 않으며 기존 초안 교체 동작을 유지한다.
- [ ] 기존 저장 데이터에서의 이전과 재시작 지속성을 실제 데이터베이스 테스트로 검증한다. 계정 전환 후 다른 계정의 담당 업무 기록·초안·처리 기준이 섞이지 않는다.
- [ ] 멘션과 담당자 지정이 합쳐진 상태에서 재시작·담당 해제·조회 실패·후속 댓글 멘션을 함께 검증한다. 담당 업무 초안의 게시 차단과 기존 직접 멘션 흐름을 무심코 덮어쓰지 않는다. 합의된 규칙만으로 충돌을 해소할 수 없으면 임의 정책을 추가하지 않고 보고한다.
- [ ] 생성 시 지정과 생성 후 지정 각각에서 업무 발견 → 최신 제목·본문 및 코드 기반 초안 → 검토·수정 → 사용자 승인 후 업무 댓글 게시를 통합 검증한다. 작성자 기본 멘션과 제거를 포함한다.
- [ ] 자기 작성 업무·초기 담당 업무·완료 업무 제외, 복수 담당자 포함, 배정 전후 내 댓글, 중복 알림과 담당 해제의 모든 합의 사례를 검증한다.
- [ ] 마지막 변경 이후 정적 검사와 관련 자동 테스트를 실행한다. 기존 서비스 통합 경계와 필요한 어댑터·데이터베이스·화면 검증을 활용하고 구현 내부를 그대로 따라가는 테스트를 추가하지 않는다.
- [ ] 실제 데스크톱에서 초안 출처·수정·받는 사람 제거·이미 답함·담당 해제 사유·게시 차단·복구 상태를 확인한다. 자동 서비스 검증을 실제 화면 검증으로 대신하지 않는다.
- [ ] 실제 Flow의 생성 시 지정·생성 후 지정·담당 해제·완료 상태·배정 시점 판단에 대한 근거를 최종 구현과 대조한다. 실제 게시까지 확인했다면 그 실행 범위와 결과를 별도로 남기고, 외부 조작이 필요한 경우 승인된 범위 안에서만 수행한다.
- [ ] 자동 테스트·데스크톱 확인·실제 Flow 증거를 구분한 완료 보고를 작성한다. 실제 연동의 필수 미검증 항목이 남으면 전체 기능 완료로 표현하지 않는다. 이번 티켓은 배포나 코드 자동 수정 기능을 포함하지 않는다.

## Comments

### 2026-10-30 — 구현 후 사용 중 확인할 사례

사용자 합의로 **다른 사람이 업무를 생성하면서 본인을 담당자로 지정한 실제 사례**의 검증을 01번의 선행 조건에서 이 티켓으로 이관했다. 구현 후 사용하면서 실제 후보 발견과 초안 생성을 확인하고 관측 날짜·방법·결과를 남긴다. 아직 검증 완료한 항목은 아니다. 생성 시 지정의 자동 테스트는 그대로 수행하며, 나머지 실제 Flow 검증의 시점과 조건을 일괄 유예한 결정은 아니다.
