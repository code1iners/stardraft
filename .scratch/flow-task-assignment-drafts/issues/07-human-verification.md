# 07: 실제 데스크톱과 실제 Flow의 사람 확인

Status: ready-for-human
Blocked by: 06 (재시작·재시도·재지정 복구와 최종 검증)

**What to build:** 새 기능을 만들지 않는다. 담당 업무 최초 초안 전체를 실제 계정으로 쓰며 확인한다. 에이전트 검증(자동 테스트, 대역 연결 Electron 렌더)으로 대신할 수 없는 부분이 대상이다. 2026-10-30 사용자 결정에 따라 06번의 사람 확인을 이 마지막 티켓으로 옮겼다.

스펙: [담당 업무 최초 초안](../spec.md)
연결 요구: 스펙 Testing Decisions의 “실제 Flow 검증은 별도 증거”, 데스크톱 화면 확인. 01번 미검증 경계, 02·03번 실제 사용 검증 경계.

- [ ] 실제 설치본(또는 실제 계정으로 켠 앱)에서 다음을 화면으로 확인한다.
  - 담당 업무 초안의 출처 표시, 수정, 받는 사람 제거.
  - 이미 답함, 담당 해제 사유, 게시 차단.
  - 복구 상태: 실패 → 다시 시도, 앱을 끄고 켠 뒤 이어서 생성.
- [ ] 다른 사람이 업무를 생성하면서 나를 담당자로 지정한 실제 사례에서 후보 발견과 초안 생성을 확인한다(01번에서 이관). 관측 날짜·방법·결과를 남긴다.
- [ ] 생성 후 지정의 실제 사례를 확인한다.
  - 감지되는지, ‘이미 답함’이 맞게 처리되는지.
  - 동명이인·이름 변경·새 S41 형식 때문에 보류되는 사례가 있는지.
  - 주기마다 늘어나는 댓글 조회 호출량(03번 기록).
- [ ] 실제 담당 해제, 완료 상태, 배정 시점 근거를 최종 구현과 대조한다. 감지 지연이나 누락(알림 누락, 수정 후 최초 발견, 초기 조회 중 경계 사건)을 관찰하면 기록한다.
- [ ] 승인한 초안이 실제 업무 댓글로 게시되는지 확인한다. 외부 업무의 생성·변경·게시는 사용자가 승인한 범위에서만 수행하고, 실행 범위와 결과를 따로 남긴다.
- [ ] 06번에서 사용자 결정으로 남긴 두 가지를 실제 사용에 비추어 정한다.
  - 합친 묶음의 받는 사람.
  - 담당 업무 실패 화면에 보이는 직접 멘션용 문구.
- [ ] 자동 검증·데스크톱 확인·실제 Flow 증거를 구분해 최종 완료를 보고한다. 필수 미검증 항목이 남으면 전체 기능 완료로 표현하지 않는다.
