# 01: 멘션 수동 요청 코어

**What to build:** 사용자가 최근 멘션 하나를 골라 게시할 수 있는 실제 묶음("수동 요청 묶음")으로 만드는 서비스 경로. 이 티켓은 화면을 바꾸지 않고, 서비스와 저장 계층에서 동작을 완성한다. 스펙: `../spec.md`의 "고르기 동작", "수동 요청 묶음", "저장과 기준점".

- 최근 멘션 조회가 "한 번에 불러오는 개수(10건)"와 이어 불러오기 커서를 지원한다. 기존 판정 규칙은 그대로 쓰고 72시간 제한, 기준점, 기존 기록 여부는 보지 않는다. 쪽 수 상한과 Flow 읽음 상태 불변은 유지한다.
- 항목을 고르면 묶음 상태에 따라 갈린다. 처리되지 않은 묶음이 있으면 새로 만들지 않고 그 묶음을 돌려준다. 7일 안의 처리됨 묶음도 새로 만들지 않고 그 묶음을 돌려준다. 최소 기록만 있으면 최소 기록을 지우고 새 묶음을 만든다. 기록이 없으면 새 묶음을 만든다.
- 수동 요청 묶음은 게시할 수 있는 실제 묶음이다. 만들 때와 초안 실행 직전에 "이미 답함" 판정을 하지 않는다. 게시 직전 확인과 변화 감시는 일반 묶음과 같다. 저장소 매핑·자동 선택, 대기열 사용자 우선 규칙도 일반 묶음과 같다.
- 수동 요청 묶음은 감지 기준점을 바꾸지 않는다. 묶음과 처리 기록만 한 번에 저장한다. 수동 요청 여부를 묶음에 표시로 남기고 재시작 뒤에도 유지한다.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 72시간이 지난 멘션과 기준점 앞의 멘션이 조회 결과에 나오고, 고르면 게시할 수 있는 묶음이 만들어진다(서비스 통합 테스트).
- [x] 이어 불러오기가 다음 10건을 돌려주고 끝에서 멈춘다. 나에게 온 멘션이 아닌 알림은 나오지 않는다.
- [x] 이미 묶음이 있는 항목은 새 묶음이 만들어지지 않고 기존 묶음이 돌아온다. 최소 기록만 있는 항목은 새 묶음이 만들어지고 최소 기록이 사라진다.
- [x] "이미 답함"인 멘션도 초안이 만들어지고, 초안 실행 직전에도 이미 답함으로 처리되지 않는다.
- [x] 수동 요청 묶음을 만든 뒤 `detection.baseline_alarm_id`가 그대로이고, 같은 위치의 알림이 와도 자동 감지가 묶음을 만들지 않는다.
- [x] 수동 요청 표시가 앱 재시작 뒤에도 남는다(실제 DB·마이그레이션 테스트).
- [x] 조회 실패(키 없음, 키 거부, 연결 실패, 요청 한도)가 기존처럼 구분되어 돌아온다.
- [x] 마지막 변경 이후의 정적 검사와 관련 자동 테스트가 통과한다. 내부 호출 순서나 사설 필드 구조를 고정하는 테스트는 쓰지 않는다.
