# 02: 최근 멘션 확인 화면 연결 (멘션만, 시험은 그대로 둠)

**What to build:** 빈 화면과 설정 "초안" 칸의 버튼이 새 "최근 멘션 확인" 흐름을 연다. 사용자는 "확인할 항목 고르기" 시트에서 멘션을 보고, 고르면 수동 요청 묶음이 만들어져 기존 검토 화면으로 이어진다. 시험 기능은 이 티켓에서 지우지 않고 옆에 둔다(expand). 스펙: `../spec.md`의 "목록 구성", "줄 상태 태그", "인터페이스 변화", "문구", "화면 계약".

- 새 IPC 명령과 스냅숏 상태(시트 열림, 로딩·실패·후보·더 보기 커서)를 추가한다. 시험 쪽 명령과 상태는 아직 지우지 않는다.
- 시트: 제목 "확인할 항목 고르기", 줄마다 보낸 사람·Flow 프로젝트·첫 줄·시각과 상태 태그(답함, 이미 묶음 있음 + 상태, 처리됨), "더 보기", [다시 불러오기], 불러오기 실패 문구, 안내 문구("게시 전에는 Flow에 아무것도 올라가지 않습니다"), Esc로 닫기. 안내 문구에 알림이 없는 업무는 나오지 않는다는 한계는 07에서 더한다.
- 이미 묶음이 있는 줄을 고르면 그 묶음으로 이동한다. 새 줄을 고르면 수동 요청 묶음이 만들어지고 시트가 닫힌다.
- 수동 요청 묶음의 상세 머리에 "수동 요청" 태그를 보인다.
- 빈 화면과 설정 "초안" 칸의 버튼 문구를 "최근 멘션 확인"으로 바꾸고 새 흐름에 연결한다. 감지를 시작했고 쓸 수 있는 Flow 키가 있을 때만 누를 수 있다.
- UI 변경이므로 `DESIGN.md`(또는 `docs/DESIGN.md`) 계약과 기존 제품 패턴을 먼저 확인한다. 문서와 충돌하면 차이를 보고한다.

**Blocked by:** 01 (멘션 수동 요청 코어)

**Status:** ready-for-agent

- [x] 빈 화면과 설정 "초안" 칸의 버튼에서 새 시트가 열린다(화면 테스트).
- [x] 줄 태그, "더 보기", 실패 문구(키 없음, 키 거부, 연결 실패, 요청 한도), 로딩 표시, Esc 닫기가 화면 테스트에서 동작한다.
- [x] 새 줄을 고르면 수동 요청 묶음이 만들어지고 검토 화면에서 "수동 요청" 태그가 보인다. 기존 묶음이 있는 줄을 고르면 새로 만들지 않고 그 묶음이 선택된다.
- [x] IPC·스냅숏 변경에 대한 기존 계약 테스트가 확장되어 통과한다.
- [x] 기존 시험 흐름은 이 티켓 뒤에도 그대로 동작한다(기존 테스트 통과).
- [ ] 실제 데스크톱 앱에서 시트와 묶음 상세 태그를 확인한다(에이전트가 실행해 확인하고, 확인하지 못했으면 성공으로 표현하지 않는다).
- [x] 마지막 변경 이후의 정적 검사와 관련 자동 테스트가 통과한다.

## Comments

- 2026-11-13 구현 메모
  - 새 흐름: `ManualCheckSession`(core/manual-check)이 시트 열림·불러오기·더 보기 상태를 들고, 고르면 `ManualMentionCheck.request`로 묶음을 만든 뒤 작은 창에서 그 묶음을 보인다(설정 창에서 골라도 작은 창이 열린다). 스냅숏 `manualCheck`, 이벤트 `manual-check-changed`, 명령 `open/close/reload/load-more/pick-manual-check`. 줄 태그는 스냅숏을 만들 때 `MentionBundles.manualPlaceOf`로 정하므로 묶음 상태가 바뀌면 따라 바뀐다. 이어 불러오기 커서는 main 메모리에만 둔다.
  - 시험과의 관계(확인 필요): 티켓이 두 버튼의 문구를 "최근 멘션 확인"으로 바꾸고 새 흐름에 연결하라고 해서 `TrialButton`을 화면에서 뺐다. 시험 명령·상태·시트·묶음 표시는 코드에 그대로 있으나 시작할 버튼이 없어 이 티켓 뒤 시험은 사실상 도달 불가다. 시험 시작 버튼 테스트는 새 버튼 테스트로 바꿨다. 03에서 시험 코드를 지운다.
  - `DESIGN.md`/`docs/DESIGN.md`는 저장소에 없어 기존 시트·태그 패턴(`sheet`, `tag`)을 따랐다. "수동 요청" 태그는 옅은 테두리(`.tag.manual`)다. 문서 계약과의 차이는 없다.
  - 미완료(Status 유지): "실제 데스크톱 앱에서 시트와 묶음 상세 태그 확인"은 하지 못했다. 앱에서 시트를 열려면 감지 시작과 쓸 수 있는 Flow 키가 필요한데, 이 작업 환경에서는 사용자의 실제 계정·데이터를 건드리지 않고는 만들 수 없었다. `pnpm build`는 통과했다.
  - 검증(마지막 변경 이후): `pnpm typecheck`, `pnpm lint` 통과, `pnpm vitest run` 68개 파일 1318건 통과.
