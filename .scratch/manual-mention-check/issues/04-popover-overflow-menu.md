# 04: 작은 창 ⋯ 메뉴 입구

**What to build:** 묶음이 있을 때도 작은 창에서 바로 "최근 멘션 확인"을 열 수 있다. 작은 창 머리에 ⋯ 메뉴를 두고 "최근 멘션 확인"과 "펼쳐 보기"를 그 안에 넣어 머리를 깔끔하게 유지한다. 스펙: `../spec.md`의 "입구". 시안: `https://macbook-m5-pro.tail9db1f7.ts.net:8445/stardraft/manual-check-entry.html`의 A2. 시안에는 "펼쳐 보기"가 머리에 남아 있지만 합의대로 메뉴 안으로 옮긴다.

- 작은 창 머리의 [펼쳐 보기] 버튼을 ⋯ 메뉴로 옮긴다. 설정 아이콘은 머리에 그대로 둔다.
- 감지를 시작하지 않았거나 쓸 수 있는 Flow 키가 없으면 "최근 멘션 확인" 항목이 막히고 이유가 보인다.
- 키보드로 메뉴를 열고 닫고 항목을 고를 수 있다. Esc로 닫는다.
- 묶음이 없을 때의 빈 화면과 설정 칸 버튼은 02에서 이미 바뀐 상태로 유지한다.
- UI 변경이므로 `DESIGN.md` 계약과 기존 제품 패턴을 확인한다.

## Comments

- 실제 앱 확인은 사용자 수동 확인으로 미룸(사용자 결정). 실제 Flow 키·감지 시작이 필요해 07번 뒤 사용자가 한 번에 확인한다. 이 완료 조건은 체크하지 않았다.
- 대신 한 화면 테스트: `review-screens.test.tsx`의 "작은 창 ⋯ 메뉴"(열린 메뉴 항목 순서, 막힘 상태와 이유 문구, 펼칠 묶음 없음, 키보드 ↓↑ Home End Esc Tab 규칙). 작은 창 머리 테스트는 ⋯ 트리거와 설정 아이콘 유지를 확인한다.
- 구현: `PopoverMenu.tsx`(⋯ 메뉴, `menuKeyAction` 순수 함수), `PopoverView.tsx`(머리의 "펼쳐 보기" 버튼을 메뉴로 교체, 설정 아이콘은 그대로), `styles.css`. "펼쳐 보기"의 `expand-review` 동작은 그대로다.
- 검증: typecheck, lint, desktop test 1308/1308 통과. DOM 환경이 없어 포커스 이동은 순수 함수 단위로만 검증했고, 메뉴의 실제 위치·크기·포커스 동작은 위 수동 확인에서 본다.
