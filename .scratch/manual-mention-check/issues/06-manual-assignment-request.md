# 06: 담당 업무 수동 요청 생성

**What to build:** 사용자가 담당 업무 후보 하나를 골라 게시할 수 있는 수동 요청 묶음으로 만든다. 규칙은 멘션과 같다. 이 티켓은 화면을 바꾸지 않는다. 스펙: `../spec.md`의 "고르기 동작", "수동 요청 묶음", "저장과 기준점".

- 기존 묶음이 있으면 새로 만들지 않고 그 묶음을 돌려준다. 최소 기록만 있으면 기록을 지우고 새로 만든다. 기록이 없으면 새로 만든다.
- 만들 때와 초안 실행 직전에 "이미 답함" 판정을 하지 않는다. 게시 직전 확인과 변화 감시는 일반 묶음과 같다(담당 해제 감지 포함).
- 담당 업무 감지 상태(기준점, 초기 업무 목록, 후보, 기능 시작 시각)를 바꾸지 않는다. 묶음과 처리 기록만 한 번에 저장한다. 같은 본문 자리는 처리 기록으로 중복되지 않는다.
- 묶음의 배정 정보는 선택한 후보의 배정 시각과 담당 업무 ID, 작성자를 가진다. 추정 시각이면 그 사실을 묶음에 남겨 상세가 표시할 수 있게 한다.
- 담당 업무 초안의 기본 받는 사람(업무 작성자), 받는 사람 제거 같은 기존 규칙은 그대로 적용된다.

**Blocked by:** 01 (멘션 수동 요청 코어), 05 (담당 업무 후보 조회 코어)

**Status:** resolved

- [x] 고른 업무가 게시할 수 있는 수동 요청 묶음으로 만들어지고 초안 생성이 시작된다(서비스 통합 테스트).
- [x] 이미 묶음이 있는 업무는 새 묶음이 만들어지지 않는다. 최소 기록만 있는 업무는 새 묶음이 만들어지고 최소 기록이 사라진다.
- [x] 내가 이미 답한 업무도 초안이 만들어지고 초안 실행 직전에도 이미 답함으로 처리되지 않는다.
- [x] 수동 요청 뒤에 담당 업무 감지 상태가 바뀌지 않고, 같은 업무의 자동 감지가 묶음을 또 만들지 않는다.
- [x] 담당 해제를 감지하면 일반 담당 업무 묶음처럼 중단되거나 게시가 막힌다.

## Comments

- 2026-11-13 구현 메모
