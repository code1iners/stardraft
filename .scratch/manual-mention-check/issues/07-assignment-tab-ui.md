# 07: "멘션 | 담당 업무" 탭 UI

**What to build:** "확인할 항목 고르기" 시트에 담당 업무 탭이 생겨, 사용자가 감지에서 빠진 담당 업무를 보고 골라 진행할 수 있다. 스펙: `../spec.md`의 "목록 구성"과 "담당 업무 목록 조회". 시안: `https://macbook-m5-pro.tail9db1f7.ts.net:8445/stardraft/manual-check-entry.html`의 B2.

- 시트 위쪽에 "멘션 | 담당 업무" 탭을 둔다. 멘션 탭이 기본이다. 담당 업무 탭은 처음 열 때 조회하고, 탭마다 자기 "더 보기" 커서와 [다시 불러오기], 로딩·실패 상태를 가진다.
- 담당 업무 줄은 보낸 사람(작성자), Flow 프로젝트, 업무 제목, 시각, 상태 태그(답함, 이미 묶음 있음 + 상태, 처리됨)와 "감지에서 빠진 이유" 태그를 보인다.
- 업무를 고르면 06의 경로로 수동 요청 묶음이 만들어지거나 기존 묶음이 선택된다. 묶음 상세에서 추정 배정 시각은 "추정"으로 표시한다.
- 안내 문구에 알림이 없는 업무는 목록에 나오지 않는다는 한계를 적는다.
- UI 변경이므로 `DESIGN.md` 계약과 기존 제품 패턴을 확인한다.

**Blocked by:** 02 (최근 멘션 확인 화면 연결), 06 (담당 업무 수동 요청 생성)

**Status:** ready-for-agent

- [ ] 탭 전환, 담당 업무 탭의 지연 조회, 탭별 "더 보기"와 다시 불러오기, 실패 문구가 화면 테스트에서 동작한다.
- [ ] 줄의 "빠진 이유" 태그와 상태 태그가 화면 테스트에서 올바르게 보인다.
- [ ] 업무 줄을 고르면 수동 요청 묶음이 만들어지고 검토 화면으로 이어지며, 이미 묶음이 있는 줄은 그 묶음이 선택된다.
- [ ] 추정 배정 시각이 묶음 상세에서 추정으로 표시된다.
- [ ] 실제 데스크톱 앱에서 탭과 줄 표시를 확인한다(확인하지 못했으면 성공으로 표현하지 않는다).
- [ ] 마지막 변경 이후의 정적 검사와 관련 자동 테스트가 통과한다.
