# 07: "멘션 | 담당 업무" 탭 UI

**What to build:** "확인할 항목 고르기" 시트에 담당 업무 탭이 생겨, 사용자가 감지에서 빠진 담당 업무를 보고 골라 진행할 수 있다. 스펙: `../spec.md`의 "목록 구성"과 "담당 업무 목록 조회". 시안: `https://macbook-m5-pro.tail9db1f7.ts.net:8445/stardraft/manual-check-entry.html`의 B2.

- 시트 위쪽에 "멘션 | 담당 업무" 탭을 둔다. 멘션 탭이 기본이다. 담당 업무 탭은 처음 열 때 조회하고, 탭마다 자기 "더 보기" 커서와 [다시 불러오기], 로딩·실패 상태를 가진다.
- 담당 업무 줄은 보낸 사람(작성자), Flow 프로젝트, 업무 제목, 시각, 상태 태그(답함, 이미 묶음 있음 + 상태, 처리됨)와 "감지에서 빠진 이유" 태그를 보인다.
- 업무를 고르면 06의 경로로 수동 요청 묶음이 만들어지거나 기존 묶음이 선택된다. 묶음 상세에서 추정 배정 시각은 "추정"으로 표시한다.
- 안내 문구에 알림이 없는 업무는 목록에 나오지 않는다는 한계를 적는다.
- UI 변경이므로 `DESIGN.md` 계약과 기존 제품 패턴을 확인한다.

**Blocked by:** 02 (최근 멘션 확인 화면 연결), 06 (담당 업무 수동 요청 생성)

## Comments

- 2026-11-13 구현 메모
  - 세션: `ManualCheckSession`이 탭별 `TabList`(상태·더 보기 커서·불러온 번호)를 따로 든다. 멘션 탭이 기본이고 담당 업무 탭은 `selectTab('assignments')`로 처음 열 때만(`idle`일 때) 조회한다. 탭을 오가도 다시 조회하지 않고, 닫으면 둘 다 비운다. 고르기는 지금 보는 탭의 목록에서만 찾아 `request`/`requestAssignment`로 보낸다.
  - 화면 계약: 스냅숏은 지금 보는 탭의 상태만 넘긴다(`sheet.tab` + 기존 `status`/`rows`). 줄에 `kind: 'mention' | 'assignment'`와 `missReasons`를 더했고, 명령 `select-manual-check-tab`을 더했다. 담당 업무 줄은 업무 작성자·프로젝트·업무 제목·알림 시각, 태그(답함, 이미 묶음 있음+상태, 처리됨)와 빠진 이유 경고색 태그 네 가지를 보인다. 안내 문구는 탭마다 다르고 담당 업무 탭에 "알림이 오기 전에 배정된 업무나 알림이 없는 업무는 목록에 없습니다" 한계를 적었다.
  - 추정 배정 시각: `BundleSnapshot.assignment`에 `assignedAt`·`assignedAtEstimated`를 더했고, 상세 머리에 "배정 시각 … [추정]"을 보인다(추정일 때만).
  - `DESIGN.md`/`docs/DESIGN.md`는 저장소에 없다. 시안 B2(탭 밑줄)와 기존 `.tag`·시트 패턴을 따랐다.
  - 실제 앱 확인은 사용자 수동 확인으로 미룸(사용자 결정). 실제 계정·데이터로 앱을 띄우지 않았다. 대신 한 화면 테스트: `review-screens.test.tsx`(탭 표시·선택, 담당 업무 줄·빠진 이유 네 가지·상태 태그, 불러오는 중·실패 다섯 가지·없음·더 보기, 탭 전환 명령, 추정 표시), `review-snapshot.test.ts`(담당 업무 줄 스냅숏·추정 시각), `draft-queue.test.ts`(지연 조회·탭별 더 보기·실패 격리·고르기·기존 묶음 이동). `pnpm build`는 통과했다.
