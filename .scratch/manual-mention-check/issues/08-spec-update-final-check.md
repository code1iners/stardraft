# 08: 스펙 문서 갱신과 최종 점검

**What to build:** 저장소 문서가 시험 폐지와 "최근 멘션 확인"을 정확히 설명하고, 전체 변경이 마지막 변경 이후의 검사를 통과한다. 스펙: `../spec.md`의 "문서 갱신".

- `flow-mention-drafter/spec.md`의 시험 관련 부분을 새 동작에 맞게 고친다. 대상은 스토리 18, 시험 묶음 상태 표, 빈 화면과 설정 "초안" 칸 설명, 알림 목록의 "[시험] …", 시작 시 정리 규칙, 대기열 우선순위 설명이다.
- 다른 스펙·티켓·조사 문서에서 시험을 참조하는 곳을 점검해 이 변경과 어긋나는 서술을 고친다. 과거 기록(조사 문서 등)은 날짜와 맥락을 남기고 현재 동작처럼 읽히는 부분만 고친다.
- `GLOSSARY.md`가 없으므로 "최근 멘션 확인"과 "수동 요청 묶음" 용어는 스펙 갱신 안에서 정리한다.
- 마지막 변경 이후의 전체 정적 검사와 자동 테스트를 실행해 결과를 구분해 보고한다. 실제 Flow의 WORKER 알림 해석과 실제 게시는 사용자의 수동 통합 테스트 대상이며 이 티켓의 완료 조건이 아니다. 해당 경계는 검증하지 못했다고 보고한다.
