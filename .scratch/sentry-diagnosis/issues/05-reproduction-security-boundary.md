## Question

진단 실행에서 에이전트에게 무엇을 허용하고 무엇을 막을지 정한다. 지금의 읽기 전용 원칙을 바꾸는 결정이라 ADR 후보다.

- 허용할 도구: 셸 명령(전부 또는 목록), Playwright(MCP 또는 명령), 시뮬레이터·에뮬레이터 명령.
- 실행 위치: 원본 저장소, git worktree, 임시 사본 중 무엇이고 끝나면 어떻게 정리하는지.
- 네트워크: 로컬 dev 서버만, 외부 접근 허용 여부, 운영 환경·운영 데이터 접근 금지를 어떻게 지킬지.
- 시간 제한과 중단, 남은 프로세스 정리.
- 비밀 파일 보호를 명령 실행 아래에서도 유지하는 방법.
- 저장소마다 재현 허용을 사용자가 켜야 하는지(기본은 읽기 전용 분석만).

## Answer

2026-11-12 grilling 세션에서 정했다. 근거 사실은 [권한 조사](../research/agent-reproduction-permissions.md)와 지금 실행기 코드(`core/agent/claude-code-executor.ts`, `codex-executor.ts`, `secret-patterns.ts`, `node-process-runner.ts`)다. 조사의 선택지 A~F 중 어느 하나를 그대로 고르지 않았다. 샌드박스로 가두는 방향(B~E) 대신 **이미 세팅된 내 개발 환경을 사본으로 그대로 쓰고, 에이전트가 사용자의 MCP로 웹·앱을 직접 조작하는** 방향으로 정했다. 읽기 전용 원칙의 예외라서 [ADR 0003](../../../docs/adr/0003-reproduction-opens-agent-boundary.md)으로 남겼다.

### 켜는 방식

- 기본값은 지금과 같은 **분석만**(읽기 전용)이다. 사용자가 **저장소마다** `재현 허용`을 켠다. 단계는 `분석만 / 재현 허용` 둘이고 웹·모바일을 나누지 않는다.
- 재현이 꺼진 저장소의 오류 이슈는 재현 결과를 "불가(허용 안 됨)"로 적는다.

### 실행 위치와 정리

- 원본 작업 폴더를 APFS 복제(`cp -c`)로 앱 데이터 폴더 아래 임시 사본으로 만든다. `.git`만 빼고, 의존성(`node_modules`, `Pods` 등)·커밋하지 않은 변경은 그대로 들어간다. 의존성을 새로 설치하지 않는다.
- 쓰기는 그 사본에만 허용한다. 매핑된 다른 저장소는 원본을 읽기 전용으로 둔다. `git push`처럼 원격을 바꾸는 일은 사본에 `.git`이 없어서 생기지 않는다.
- 보고서에는 실행 시점의 HEAD 해시와 커밋하지 않은 변경이 있었는지를 적는다. Sentry release와 커밋을 맞추는 일은 하지 않는다.
- 사본은 실행이 끝나면 성공·실패·취소와 상관없이 지운다. 스크린샷·로그 같은 첨부는 지우기 전에 앱 쪽으로 옮긴다(형식은 [07](07-diagnosis-report-format.md)).

### 비밀

- 저장소마다 파일 선택기로 **재현용 환경 파일**을 지정할 수 있다. 지정한 파일이 사본의 `.env`가 된다. 지정하지 않으면 원본 `.env`를 그대로 쓰고 더 강한 경고를 띄운다.
- 실행 중인 앱만 값을 읽고 에이전트는 못 읽게 하는 방법은 없다(샌드박스는 에이전트와 그 자식 프로세스에 똑같이 걸린다). 그래서 이 파일의 값이 에이전트와 모델 제공자에게 노출된다는 점을 받아들이고, 재현을 켜는 화면에서 "운영 키를 넣지 말 것"을 안내한다.
- 비밀 패턴 중 `.env` 계열만 재현 사본에서 푼다. 나머지(`*.pem`, `id_rsa*`, `.npmrc` 등)와 저장소 밖 개인 비밀(`~/.ssh`, `~/.aws` 등)은 계속 막는다.
- 환경 변수는 재현 실행에 최소 목록(`PATH`, `HOME`, `LANG`, `TMPDIR` 등)만 넘긴다. Codex는 `shell_environment_policy`, Claude는 `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`·`sandbox.credentials.envVars`로 구현한다.

### 네트워크

- 연다. 운영 서버를 부르지 않게 하는 장치는 재현용 환경 파일과, 지침의 "운영 서버로 데이터를 바꾸는 요청을 보내지 말라" 문구다. 지침 문구는 강제력이 없다는 점을 알고 정했다.

### 도구

- 셸 명령을 허용하고, 에이전트가 **사용자가 Claude Code·Codex에 설정해 둔 MCP**로 웹·iOS·Android를 직접 조작한다. MCP 서버는 두 CLI 모두 샌드박스 밖에서 돈다는 점을 받아들인다.
- 사용자 설정에서는 **MCP 서버 정의만** 가져온다. 권한 규칙·훅·샌드박스·승인 정책·모델·Codex rules는 지금처럼 앱이 정한다. 이것들을 불러오면 앱의 경계가 뒤집힌다(예: Codex의 `sandbox_mode`가 어디든 있으면 권한 프로필 전체가 무시된다). 플래그로 MCP만 골라 가져올 수 없는 CLI는 앱이 사용자 설정 파일의 MCP 부분만 읽어 인라인으로 넘긴다. 방법은 [10 재현용 MCP 불러오기와 위험 도구 목록 조사](10-reproduction-mcp-research.md)에서 확인한다.
- 앱 전체 설정에 **재현 도구 권한** 항목을 둔다(MCP 설정 자체가 사용자 단위라서 저장소마다 두지 않는다).
  - `자동`(기본값): 사용자 MCP를 모두 싣고, 앱이 관리하는 고정 위험 도구 deny 목록만 적용한다(예: Playwright MCP `browser_run_code_unsafe`).
  - `직접 선택`: MCP 서버마다 켜고 끈다.
- Slack·Gmail·Flow 같은 MCP가 `자동`에서 함께 실려 진단 중 외부로 글을 보낼 수 있다. 지침에 "외부로 보내거나 쓰는 도구를 쓰지 말 것"을 넣고, 막고 싶으면 `직접 선택`으로 끈다.
- 필요한 MCP가 없어 특정 플랫폼을 조작할 수 없으면 재현 결과를 "불가(도구 없음)"로 적는다. 앱은 MCP를 설치하거나 재현 환경을 준비하지 않는다(지도 전제).

### 시간 제한과 정리

- 진단 실행 한 번의 상한은 **20분** 고정이다. 상한에 닿거나 취소하면 지금처럼 프로세스 그룹 전체에 SIGKILL을 보내고 사본을 지운다. 재현 결과는 "불가(시간 초과)"로 남긴다. Claude에는 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`를 상한에 맞춰 넘긴다.
- 실행 전에 켜져 있던 시뮬레이터·에뮬레이터 목록을 기록하고, 실행 뒤 **새로 켜진 것만** 끈다. adb 서버는 사용자도 쓰는 공용 데몬이라 그대로 둔다.

### Claude Code와 Codex

- 사용자에게 보이는 경계는 둘이 같다. CLI마다의 구현은 스펙에 표로 적는다. 어느 한쪽에서 기술적으로 안 되는 것은 기능을 줄이지 않고 그 실행의 재현 결과를 "불가"로 적는다.

### 스펙에 적을 실측 항목

- APFS 복제 시간(`node_modules`가 큰 저장소).
- Claude·Codex의 백그라운드 명령과 MCP 서버가 그룹 SIGKILL로 함께 끝나는지.
- Claude의 `Read(//**/…)` deny가 샌드박스 `denyRead`로 합쳐질 때의 부작용(TLS 인증서, `.git`, `~/.npmrc`)과 작업 루트로 범위를 좁힌 형식.
- 시뮬레이터·에뮬레이터 "새로 켜진 것" 판별과 종료 명령.
