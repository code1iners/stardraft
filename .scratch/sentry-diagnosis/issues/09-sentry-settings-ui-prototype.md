## Question

[Sentry 계정 연결, 진단 대상 필터, 저장소 매핑 설정](04-sentry-connection-and-mapping.md)에서 정한 동작을 화면으로 어떻게 보여 줄지 시안 2~3개를 비교해 정한다. `ui-design`을 함께 쓰고, 지금 설정 창(`renderer/src/SettingsView.tsx`, `FlowAccountSection.tsx`, `RepositoriesSection.tsx`, `Onboarding.tsx`)의 패턴을 따른다.

- `Sentry` 칸: 토큰 입력과 두 단계 연결 확인, 조직별 프로젝트 목록에서 등록, 프로젝트마다 환경·레벨 필터, "접근 불가"와 "토큰 확인 필요" 상태 표시.
- `저장소` 칸: 저장소 매핑을 "Flow 프로젝트"·"Sentry 프로젝트" 묶음으로 나누는 방식, 등록했지만 매핑이 없는 Sentry 프로젝트를 드러내는 방식.
- 저장소마다 **재현 허용** 켜기와 **재현용 환경 파일** 선택(파일 선택기), 노출 경고 문구. 정한 동작은 [재현 실행의 보안 경계](05-reproduction-security-boundary.md)에 있다.
- 앱 전체의 **재현 도구 권한**: `자동`(기본값)과 `직접 선택`(MCP 서버마다 켜고 끄기), `자동`에서 외부로 보내는 MCP도 실린다는 안내.
- 온보딩 체크리스트: 필수(에이전트 연결, 작업 폴더)와 선택(Flow, Sentry)을 구분하는 방식, 연결된 프로바이더가 없을 때의 안내.

## Answer

2026-11-13 시안 두 차례와 질문으로 정했다. 시안은 `~/.claude-mukkebi/mockups/stardraft/sentry-settings.html`(2차, 확정안)과 `sentry-settings-v1.html`(1차, 후보 비교)이다. 원본은 버리는 브랜치 `prototype/sentry-settings-ui`(커밋 `ce7421b`)의 `.scratch/sentry-diagnosis/prototypes/`에 있다. 색·간격·목록·버튼은 지금 `styles.css`를 그대로 따른다.

### 작업 폴더와 자동 선택을 없앤다 (Flow 동작 변경)

- 앱 전체 개념인 **작업 폴더**를 없앤다. 에이전트가 읽을 저장소는 **저장소 매핑**으로만 정한다.
- Flow의 **자동 선택**도 없앤다. 매핑이 없는 Flow 프로젝트의 멘션은 Sentry 오류 이슈처럼 매핑이 생길 때까지 기다린다. 프로젝트마다 자동 선택 폴더를 두는 안(가)은 고르지 않았다.
- 멘션 묶음 하나에만 저장소를 고르는 경로(`userRepos`)는 작업 폴더 후보 목록 없이 파일 대화 상자로만 고른다.
- "이 PC에서 찾은 폴더" 제안도 함께 사라진다.
- 지금 코드에서 작업 폴더를 쓰는 곳은 `core/repos/work-folders.ts`, `repo-candidates.ts`, `repo-picker.ts`, `core/drafts/draft-queue.ts`(자동 선택 실행), `core/onboarding/onboarding.ts`, `RepositoriesSection.tsx`, `RepoPickerSheet.tsx`다. 저장소 매핑은 파일 대화 상자로 고르므로 작업 폴더에 기대지 않는다.
- 기존 사용자의 전환과 매핑이 없는 Flow 묶음의 상태는 [13 작업 폴더·자동 선택 폐지의 Flow 전환](13-flow-without-work-folders.md)에서 정한다.
- `GLOSSARY.md`에서 **작업 폴더**·**자동 선택**을 지우고, **저장소 매핑**의 정의와 _Avoid_에 그 사실을 적었다.

### 온보딩

- 필수 항목은 **에이전트 연결** 하나뿐이다(`SETUP_REQUIREMENTS`에서 `flow-key`와 `work-folders`를 뺀다).
- 작은 창 체크리스트는 시안 A다. "필수" 묶음(에이전트 연결)과 "감지할 대상 · 선택" 묶음(Flow 계정, Sentry)으로 나눈다. 선택 항목의 상태는 연결되면 `✓`, 아니면 "연결 안 함"이다.
- 필수를 마쳤는데 연결된 프로바이더가 없으면 [감지 시작] 위에 "연결한 프로바이더가 없어 아직 감지할 대상이 없습니다. 지금 시작하고 나중에 Flow나 Sentry를 연결해도 됩니다."를 띄우고 막지 않는다.
- 설정 창 맨 위 띠는 진행 막대 없이 "필수 설정: 에이전트 연결"과 [에이전트 설정]을 보인다. 칸 목록의 점은 에이전트 칸에만 찍힌다.

### 설정 창 칸 구성

칸 순서는 `Flow 계정 · Sentry · 에이전트 · 저장소 · 초안 · 일반`이다.

- **Sentry 칸 (시안 C)**
  - 토큰 카드: 조직 수와 이름, 권한, "연결됨"/"토큰 확인 필요".
  - "진단할 프로젝트" 목록의 줄에는 요약만 보인다. 요약은 `조직 / 프로젝트`, `환경 · 레벨 · 저장소 이름`, 상태다. 상태는 감지 중, 저장소 매핑 없음 · n건 대기, 접근 불가, 토큰 확인 필요로 멈춤 중 하나다.
  - [편집]과 [프로젝트 추가…]는 모달을 연다. 모달에는 프로젝트(추가할 때만), 환경·레벨 필터, 저장소(선택)가 있고, 편집 모달에는 [등록 해제]가 있다.
  - 모달의 저장소 칸은 저장소 칸의 Sentry 매핑과 같은 값이고 같은 방식(`폴더 고르기…`·`바꾸기…`·`빼기`)으로 다룬다. 등록과 매핑을 한 흐름에서 끝낼 수 있다.
  - 토큰이 없으면 토큰 입력만 보인다. "토큰 확인 필요"이면 [프로젝트 추가…]를 막는다.
- **저장소 칸 (시안 A를 고침)**
  - 작업 폴더 항목이 없다. "저장소 매핑" 항목 안에 `Flow` | `Sentry` 탭을 둔다.
  - 두 탭의 줄 모양은 같다. 프로젝트 줄 아래에 저장소 줄을 두고, 파일 대화 상자로 연결한다.
  - 차이는 셋이다. Sentry는 저장소가 하나라서 [폴더 추가…] 대신 [바꾸기…]를 둔다. Sentry 탭에는 등록한 프로젝트가 모두 오르고, Flow 탭에는 매핑한 프로젝트와 매핑이 없어 멘션이 기다리는 프로젝트가 오른다. 새 Flow 매핑은 지금처럼 프로젝트 선택 상자와 [폴더 골라 연결…]로 만든다.
  - 매핑이 없어 기다리는 프로젝트는 각 탭 맨 위에 "저장소 매핑 없음 · n건 대기"와 [폴더 고르기…]로 보인다. 그런 프로젝트가 있는 탭에는 점을 찍는다. 매핑된 폴더가 없으면 저장소 줄에 "폴더를 찾을 수 없음"을 보인다.
  - 탭 아래 "재현" 항목은 매핑된 저장소마다 **재현 허용** 체크 상자를 둔다. 켜면 환경 파일과 [바꾸기…]/[파일 고르기…]를 보인다. 환경 파일을 지정하지 않았으면 "지정 안 함 · 원본 .env 사용"을 빨간 글씨로 보인다.
  - 재현을 켜는 순간 확인 모달이 뜬다. 모달에는 허용되는 일(셸·네트워크·MCP), 재현용 환경 파일 고르기, 원본 `.env` 경고, "운영 키를 넣지 마세요"가 들어간다.
- **에이전트 칸**: 칸 안에 `연결` | `재현` 탭을 둔다. `연결`은 지금 화면 그대로다. `재현`에는 앱 전체의 **재현 도구 권한**이 들어간다.
  - 라디오 `자동`(기본)과 `직접 선택`이 있다.
  - MCP 서버 목록의 각 줄에는 이름, 하는 일, 출처 CLI, 앱이 뺀 위험 도구가 보인다. 외부로 보낼 수 있는 서버에는 "외부로 보냄" 꼬리표를 붙인다.
  - `자동`에서는 외부로 보내는 MCP도 실린다는 경고를 보인다. `직접 선택`에서는 줄마다 체크 상자를 둔다.
  - MCP를 못 찾으면 "셸로만 재현, 조작이 필요하면 불가(도구 없음)"라고 안내한다.

### 모달은 모두 화면 가운데

- 앱의 확인 창을 창 위쪽에 붙는 시트(`.sheet`, 지금 `AccountSwitchSheet`·`RepoPickerSheet`·`EditorPickerSheet`)에서 **화면 가운데 모달**로 모두 바꾼다. 둥근 모서리 10px, 배경을 어둡게 덮는다. 기존 화면도 바뀌므로 스펙 범위에 넣는다.

### 구현 메모

- 칸 안 탭은 지금 코드에 없는 새 패턴이다. 밑줄형 탭이고, 탭 하나에 점 하나까지 붙는다.
- 1차에서 고르지 않은 것: Sentry 칸 A(줄 안 필터)·B(조직별 표+체크 등록), 저장소 칸 B(저장소 중심)·C(새 `재현` 칸), 온보딩 B(한 목록+꼬리표).
