## Question

[프로바이더 공통 경계 결정](08-provider-seam-decision.md)에서 Flow와 Sentry가 하나의 **생성 대기열**을 쓰고 대상만 어댑터로 나누기로 했다. 그 대기열이 진단 실행(`RunKind` `'diagnosis'`, 상한 20분)을 Flow 초안과 함께 어떻게 돌릴지 정한다.

- **직렬 여부**: 지금은 직렬 하나다(`draft-queue.ts:207-208,221-224`). 진단 하나가 Flow 초안을 최대 20분 늦춰도 되는지, 아니면 진단 전용 슬롯을 두어 초안과 동시에 돌릴지 정한다. 같은 CLI 에이전트를 동시에 돌리면 로그인 세션과 사용량 한도를 함께 쓴다.
- **진단끼리 동시 실행**: 재현 실행은 시뮬레이터·dev 서버 포트를 나눠 쓴다. 진단을 한 번에 하나만 돌릴지 정한다.
- **우선순위**: 지금 `resume` > `user` > `auto`다. 진단은 모두 자동으로 들어온다. Flow 자동 초안과 진단 사이의 순서, 사용자가 다시 진단(지시)을 요청했을 때의 순서를 정한다.
- **시간 상한과 일시적 실패 재시도**: 종류별 `timeoutMs`(진단 20분)를 어댑터가 정하는 것은 확정이다. 20분짜리 실행이 일시적 실패로 끝났을 때도 1회 자동 재시도할지 정한다.
- **취소·앱 종료**: 재현 중 취소나 앱 종료 때 사본·새로 켠 시뮬레이터 정리를 기다릴지(지금은 최대 5초, `draft-queue.ts:48-52`) 정한다. Codex MCP 프로세스 정리는 [재현용 MCP 적용 방식 결정](11-reproduction-mcp-wiring.md)의 범위다.
