# 진단 실패와 데이터 부족의 처리

Map: [Sentry 오류 이슈 진단 보고서](../map.md)
Type: grilling
Mode: HITL
Status: resolved
Blocked by:

## Question

진단이 온전한 보고서로 끝나지 않는 경우에 보고서와 상태를 어떻게 남길지 정한다. 재현 결과의 성공·실패·불가 표기와 "불가(허용 안 됨·시간 초과)"를 앱이 채운다는 점은 [보고서 형식](07-diagnosis-report-format.md)에서, 일시적 실패 1회 재시도와 전역 실패 멈춤은 [진단 실행 큐](12-diagnosis-run-queue.md)에서 정했다.

- **이벤트 데이터 부족**: 스택트레이스·breadcrumbs·release가 없거나 `events/latest/`를 받지 못한 오류 이슈를 진단할지, 건너뛸지, 부족하다는 사실을 보고서에 어떻게 적을지.
- **실행 실패**: 재시도 뒤에도 실패(구조화 출력 없음, 시간 초과, 취소)한 진단의 상태 이름과 다음 행동(다시 시도 버튼, 자동 재시도 없음 등). 20분 시간 초과 때 그때까지의 부분 결과를 보고서로 남길지.
- **재현 실패·불가인 보고서**: 재현 없이 코드 읽기만으로 쓴 보고서를 정상 보고서와 같은 상태로 둘지.
- **Sentry 쪽 변화**: 진단 대기·진행 중에 오류 이슈가 해결·삭제되면 어떻게 할지. 프로젝트 등록이 풀릴 때는 [Sentry 실행 상태의 저장 위치](15-sentry-run-state-storage.md)에서 정했다(진단 취소, 보고서는 남김).
- **상태 목록**: 위 결정을 모아 오류 이슈 진단의 상태 전체(대기·진행·검토 대기·실패·저장소 매핑 필요·저장소 확인 필요·완료 등)를 확정하고 글로서리에 올릴 것을 가린다.

## Answer

2026-11-24 grilling 세션에서 정했다. Flow의 실패 처리는 `apps/desktop/src/core/drafts/draft-queue.ts`다(실패한 묶음에 사유를 붙이고, 취소도 사유의 하나다). 실행 중인 에이전트에게 메시지를 전하는 방법은 [조사](../research/mid-run-steering.md)에 있다.

### 데이터가 부족한 오류 이슈

- 건너뛰지 않고 항상 진단한다. 앱은 "충분한지"를 미리 판정하지 않는다.
- 앱은 없는 항목(스택트레이스 없음, 소스맵 적용 안 됨 등)을 지침과 보고서의 오류 이슈 정보에 그대로 적는다.
- 재현을 못 할 만큼 부족한지는 에이전트가 판단해 `impossible` + `insufficient_data`로 답한다.

### 이벤트 데이터를 받는 시점

- `events/latest/`는 감지할 때가 아니라 진단을 시작할 때 받는다. 줄 서 있던 동안의 최신 이벤트를 쓴다.
- 일시적 실패(네트워크·5xx·`429`)는 진단 실패로 치지 않는다. Sentry 쪽 멈춤으로 보고 그 진단은 줄에 남긴다. Flow 초안과 다른 실행은 계속 돈다.
- 토큰 문제(401·403)도 같은 방식으로 기다리고, Sentry 연결 문제로 알린다.
- 404는 아래 "삭제됨"으로 처리한다.

### 진단 실패

- 재시도 뒤에도 실패했거나 사용자가 취소한 진단은 **진단 실패** 상태 하나에 사유를 붙여 남긴다. 사유는 Flow의 것을 그대로 쓴다(결과 형식 오류, 시간 초과, 취소함, 비밀 파일 근거 등).
- 자동으로 더 재시도하지 않는다.
- 버튼은 [다시 시도](`user` 칸에 선다)와 [완료]다. 실패한 진단의 [완료]는 지울 본문이 없으므로 확인 없이 최소 기록으로 넘긴다.
- 사용자가 치우기 전까지 목록에 남는다.
- 같은 오류 이슈에 진단 실패가 남아 있는데 새 재발이 감지되면, 실패한 진단을 새 진단으로 바꾼다. 새 진단은 `auto` 칸에 선다. [따라잡기와 중복 억제](16-catch-up-and-dedupe.md)의 "진단이 살아 있는 동안의 재발"에 더하는 네 번째 경우다.

### 시간 상한이 가까울 때

재현하는 진단에만 적용한다. 읽기 전용 진단과 Flow 초안은 묻지 않고 상한에서 끊는다.

- 상한 5분 전(15분)에 사용자에게 [계속 진행]·[멈추기]를 묻는다. 시스템 알림 하나와 앱 안의 그 진단 항목에 보인다. 창을 강제로 앞에 띄우지 않는다.
- **[계속 진행]**: 상한을 10분 늘리고 새 상한 5분 전에 다시 묻는다. 합계 60분에서는 묻지 않고 [멈추기]와 같이 처리한다. 실행 중 전달이 되는 에이전트에게는 "10분이 더 있다"를 알린다.
- **[멈추기]**
  - 실행 중 전달이 되는 에이전트: "재현을 그만두고 지금까지 알아낸 것으로 보고서를 써라"를 보낸다. 5분 안에 결과가 나오면 보통의 진단 보고서로 **검토 대기**가 된다. 재현 결과는 에이전트가 적은 그대로다. 5분 안에 안 나오면 끊고 **진단 실패(시간 초과)**로 남긴다.
  - 전달이 안 되는 에이전트: 바로 끊고 **진단 실패(시간 초과)**로 남긴다.
- **답이 없을 때**: 상한(20분)에 [멈추기]와 똑같이 처리한다. 끊는 시점은 최대 25분이 된다.
- 부분 결과는 따로 남기지 않는다. 에이전트 결과는 실행이 끝날 때 구조화 출력으로 한 번만 나온다.
- 재현하던 진단이 **진단 실패(시간 초과)**가 되면 [다시 시도]·[완료]에 [재현 없이 다시 시도]를 더한다. 읽기 전용 진단으로 돌고, 그 보고서의 재현 칸은 앱이 "불가(시간 초과)"로 채운다. "불가(시간 초과)"는 이 경로로 만든 보고서에만 나온다([보고서 형식](07-diagnosis-report-format.md)과 [진단 실행 큐](12-diagnosis-run-queue.md)의 표기를 이렇게 좁힌다).

### 실행 중 전달

- 실행기 포트에 "실행 중 전달"을 선택 능력으로 둔다. 대기열은 능력이 있는지만 보고 갈린다.
- Claude Code는 `--input-format stream-json`으로 갖춘다. 메시지는 도구 호출이 끝나는 자리에서만 반영되므로(긴 빌드 중이면 늦는다) 강제로 끊는 상한은 그대로 둔다.
- Codex는 이번에 `codex exec` 그대로 두고 전달이 안 되는 에이전트로 다룬다. `codex app-server`(experimental)의 `turn/steer`로 옮기지 않는다.
- 받아들인 대가: 같은 상황에서 Claude는 보고서가 남고 Codex는 진단 실패로 남는다.
- 지침의 시간 배분(상한 20분, 재현은 10분쯤에서 끊기)은 [`diagnosing-bugs` 절차의 전달 방식](17-diagnosing-bugs-delivery.md) 그대로다. 10분 지점은 에이전트가 스스로 지키는 약속이고 앱이 강제하지 않는다.

### 재현 실패·불가인 보고서

- 정상 보고서와 같은 **검토 대기**다. 재현 결과는 상태가 아니라 보고서의 속성이다. 내보내기·완료도 같다.

### Sentry 쪽 변화

- 진단을 시작하기 직전에 오류 이슈 상태를 한 번 확인한다.
- 해결됨·보관됨·삭제됨(404)이면 진단하지 않고 조용히 뺀다. 화면에는 남기지 않고 로그에만 적는다. 다른 오류 이슈로 병합돼 id가 바뀐 경우도 삭제와 같이 다룬다.
- 중복 억제 기록은 남긴다. 나중에 재발하면 그때 새 재발로 진단한다.
- 이미 실행 중인 진단은 끊지 않고 끝까지 돌려 보고서를 남긴다. 실행 중에는 Sentry 상태를 다시 보지 않는다.
- 검토 대기 중인 보고서는 Sentry에서 해결돼도 그대로 둔다.

### 상태 목록

| 상태 | 뜻 | 벗어나는 길 |
|---|---|---|
| **저장소 매핑 필요** | 프로젝트에 매핑이 없다 | 매핑을 저장하면 자동 재개 |
| **저장소 확인 필요** | 매핑된 폴더가 없다 | 폴더가 돌아오거나 매핑을 고치면 자동 재개 |
| 대기 | 줄 서 있다 | 차례가 오면 진행, 사용자 취소 |
| 진행 중 | 에이전트가 실행 중이다 | 보고서 완성, 실패, 사용자 취소 |
| 검토 대기 | 보고서가 있다(재현 결과와 무관) | 완료 |
| **진단 실패** | 보고서 없이 끝났고 사유가 붙는다 | 다시 시도, 완료, 새 재발이 오면 교체 |
| **완료** | 최소 기록만 남았다 | 없음 |

상태로 두지 않는 것:

- Sentry 연결 문제로 기다리는 진단은 대기 그대로다.
- 시작 직전에 빠진 진단(해결·보관·삭제)은 화면에 남기지 않는다.
- 시간 연장을 묻는 중과 마무리를 기다리는 5분은 진행 중 그대로다.

### 글로서리

- **진단 실패**를 더했다. 대기·진행 중·검토 대기는 일반 낱말이라 올리지 않았다.

### 스펙에 적을 실측 항목

- Claude Code의 `--input-format stream-json`을 앱의 플래그 묶음(`--restricted`, `--append-system-prompt-file`, `--mcp-config`)과 함께 쓸 때 실행 중 메시지가 반영되고 구조화 출력이 나오는지.
- Codex `app-server`의 `turn/steer` 동작과 `exec`에서 옮기는 비용(권한 프로필·`--ignore-user-config`·MCP 넘기기의 재검증). 조사 때는 계정의 사용량 한도로 실측하지 못했다.
