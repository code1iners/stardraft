## Question

검토 화면을 그리기 전에 화면에 보이지 않는 동작을 정한다. **내보내기**와 **완료**의 행동은 [보고서 형식](07-diagnosis-report-format.md)에서 정했고, 사용자가 요청한 진단이 `user` 칸에 선다는 점은 [진단 실행 큐](12-diagnosis-run-queue.md)에서 정했다.

- **다시 진단**: 사용자가 **지시**를 붙여 진단을 다시 시킬 수 있게 할지. 둔다면 앞선 보고서를 에이전트에게 넘길지, 새 보고서가 앞선 것을 덮는지 판으로 쌓이는지, 재현을 다시 하는지.
- **보고서 수정**: 앱 안에서 진단 보고서 본문을 고칠 수 있게 할지. 고친 내용이 **내보내기**에 실리는지.
- **Flow 초안과의 공유 범위**: Flow 초안의 다시 만들기·지시 흐름과 어디까지 같은 규칙을 쓸지.
- **완료 뒤**: 완료한 오류 이슈가 다시 재발했을 때 앞선 보고서를 참고로 보일지([따라잡기와 중복 억제](16-catch-up-and-dedupe.md)의 억제 기준과 맞춘다).

## Answer

2026-11-24 grilling 세션에서 정했다. Flow 초안의 재생성은 `apps/desktop/src/core/drafts/draft.ts`(`RegenerationPath`)와 `apps/desktop/src/core/bundles/mention-bundles.ts`에 있다.

### 다시 진단

- 검토 대기인 진단 보고서에 **다시 진단**을 둔다. 경로는 둘이다.
  - 지시 없이 다시 진단(Flow의 `again`): 앞선 보고서를 넘기지 않고 처음부터 한다. 쌓인 지시는 비운다.
  - **지시**를 덧붙여 다시 진단(Flow의 `directive`): 앞선 보고서와 지금까지 덧붙인 지시 전부를 넘긴다.
- Flow의 요구 고치기(`requirement`)는 진단에 "요구"가 없으므로 두지 않는다.
- 다시 진단은 `user` 칸에 선다([진단 실행 큐](12-diagnosis-run-queue.md)). 재현하는 진단 한 번에 하나, 시간 상한, 연장 묻기는 처음 진단과 같다([진단 실패와 데이터 부족의 처리](18-diagnosis-failure-handling.md)).
- 이벤트 데이터는 다시 진단을 시작할 때 새로 받는다.
- 다시 진단하는 동안의 재발은 "줄 서 있거나 실행 중"의 규칙대로 흡수한다([따라잡기와 중복 억제](16-catch-up-and-dedupe.md)).

### 에이전트에게 넘기는 것

- 앞선 보고서는 에이전트 결과 스키마의 칸 그대로다. 요약, 재현 결과와 방법, 원인과 확신도, 개선 방향, 남은 의문, 근거.
- 첨부 파일은 넘기지 않는다.
- 지시는 그 진단에 쌓이고 매번 전부 넘긴다.

### 앞선 보고서의 운명

- 새 보고서가 앞선 것을 덮는다. 판은 쌓지 않는다. 남기고 싶은 보고서는 다시 진단 전에 내보낸다.
- 덮는 시점은 Flow와 다르다. Flow는 재생성을 시작할 때 직전 초안을 지우지만, 진단은 새 보고서가 나왔을 때 바꾼다. 진단은 한 번에 20분까지 걸려 실패하면 잃는 것이 크기 때문이다.
  - 다시 진단하는 동안: 앞선 보고서와 첨부를 보관한다. 상태는 진행 중이다.
  - 성공: 앞선 보고서와 첨부를 지우고 새 것으로 바꾼다.
  - 실패·취소: **진단 실패**로 가지 않는다. 앞선 보고서의 검토 대기로 돌아가고 "다시 진단하지 못했다"와 사유를 알린다. 쌓인 지시는 남겨 다시 걸 수 있게 한다.
- 다시 진단하는 동안에는 내보내기와 완료를 할 수 없다. 하려면 먼저 취소한다.

### 재현을 다시 하는지

- 재현 허용이 켜진 저장소에서 지시를 덧붙여 다시 진단할 때 사용자가 "재현도 다시 하기"를 고른다.
  - 켬: 재현하는 진단으로 처음처럼 돈다. 재현 칸과 첨부를 새 결과로 바꾼다.
  - 끔: 읽기 전용 진단으로 돈다. 재현 칸과 첨부는 앞선 보고서의 것을 앱이 그대로 옮기고, 에이전트는 나머지 칸만 쓴다(읽기 전용 진단은 지침과 스키마에 재현이 없다, [`diagnosing-bugs` 절차의 전달 방식](17-diagnosing-bugs-delivery.md)).
  - 기본값: 앞선 재현이 성공이면 끔, 실패·불가면 켬.
- 지시 없는 다시 진단은 처음부터 하는 것이므로 재현 허용이 켜져 있으면 항상 재현한다.
- 재현 허용이 꺼진 저장소면 고르는 칸이 없고 읽기 전용으로 돈다.

### 보고서 수정

- 앱 안에서 진단 보고서 본문을 고치는 기능은 두지 않는다. Flow 초안은 내 이름으로 게시되므로 편집이 필요하지만, 진단 보고서는 게시하지 않는다.
- 내용을 바꾸려면 지시로 다시 진단한다. 글 자체를 손보려면 내보낸 마크다운 파일을 고친다.
- 내보내기에는 항상 에이전트가 쓴 그대로가 실린다.

### Flow 초안과 같은 것, 다른 것

| | Flow 초안 | 진단 보고서 |
|---|---|---|
| 지시 없이 다시 | 있음 | 있음 |
| 지시를 덧붙여 다시(직전 결과 + 지시 전부) | 있음 | 있음 |
| 요구 고치기 | 있음 | 없음 |
| 본문 편집 | 있음(게시에 실림) | 없음 |
| 직전 결과를 지우는 때 | 시작할 때 | 새 결과가 나왔을 때 |
| 다시 만들기가 실패하면 | 실패 상태, [다시 시도] | 앞선 보고서로 돌아감 |
| 재현 다시 하기 | 해당 없음 | 사용자가 고름 |

### 재발했을 때 앞선 진단의 참고

- **앞선 보고서가 검토 대기 중**(새 진단을 따로 만드는 경우): 앞선 보고서의 요약·원인·개선 방향을 "앞선 진단"으로 새 진단의 에이전트에게 넘긴다. 지침에 "참고일 뿐이고 이 원인이 틀렸을 수 있다"를 함께 적는다. 새 보고서의 오류 이슈 정보에 앞선 진단이 있다고 적는다.
- **완료한 뒤**: 에이전트에게는 아무것도 넘기지 않는다. 새 보고서의 오류 이슈 정보에 "앞서 진단함(완료한 날짜)"과 마지막으로 내보낸 파일 경로를 적는다. 파일이 그 자리에 없으면 날짜만 적는다. 내보낸 파일은 사용자가 고치거나 옮겼을 수 있어 에이전트 입력으로 읽지 않는다.
- 이를 위해 완료 최소 기록에 **마지막으로 내보낸 파일 경로**를 더한다([보고서 형식](07-diagnosis-report-format.md)과 [저장 위치](15-sentry-run-state-storage.md)의 최소 기록에 더하는 항목이다).

### 글로서리

- **지시**의 뜻에 다시 진단을 넣었다. 새 용어는 없다.
