## Question

진단 보고서를 앱에서 검토하는 화면을 시안으로 정한다. 보고서의 구성은 [보고서 형식](07-diagnosis-report-format.md), 상태 목록은 [진단 실패와 데이터 부족의 처리](18-diagnosis-failure-handling.md), 다시 진단·수정 동작은 [다시 진단(지시)과 보고서 수정](19-rediagnosis-and-report-editing.md)을 따른다.

- **목록**: 오류 이슈 진단이 Flow 초안 목록과 한 목록에 섞이는지, 따로 나뉘는지. `ReviewSnapshot`에 `diagnoses`를 따로 두기로 했다([경계 결정](08-provider-seam-decision.md)).
- **보고서 보기**: 결론 먼저 형식의 배치, 첨부(이미지·로그) 보기, 메타데이터와 실행 정보의 자리.
- **버튼의 자리**: **내보내기**·**완료**, 다시 진단, 실패한 진단의 다시 시도.
- **상태별 모양**: 진행 중·실패·재현 불가인 진단이 어떻게 보이는지.
- **시간 연장 묻기**: 재현하는 진단의 상한 5분 전에 그 진단 항목에 보이는 [계속 진행]·[멈추기]의 자리와 문구, 마무리를 기다리는 동안의 모양.
- **진단 실패의 버튼**: [다시 시도]·[재현 없이 다시 시도](시간 초과일 때만)·[완료]의 자리.
- **Flow 초안 검토 화면과의 공유**: 같은 틀을 쓰는 부분과 갈리는 부분.

화면 문구는 쉬운 말로 쓰고 특정 서비스 이름에 묶지 않는다([병렬 작업 수 시안](14-concurrency-setting-ui-prototype.md)).

## Answer

2026-11-24 시안 비교로 정했다. 사용자가 목록·보고서 보기·버튼 자리·연장 묻기 자리를 모두 **안 C**로, 검토 대기 보고서의 주 버튼을 **[내보내기]**로 골랐고 시안의 문구에 동의했다. 시안은 `~/.claude-mukkebi/mockups/stardraft/diagnosis-review.html`의 `?variant=C`다. 색·간격·클래스는 지금 `styles.css`를 따른다.

### 목록

- 펼친 창의 왼쪽 목록을 종류로 묶는다. 위가 `진단 n`, 아래가 `초안 n`이다. Flow 초안의 상태별 묶음(검토 대기·생성 중·실패·처리됨)은 쓰지 않고, 상태는 줄의 태그로만 보인다.
- 진단 줄은 첫 줄에 오류 제목과 감지 시각, 둘째 줄에 보고서 요약(보고서가 없으면 `프로젝트 · 자리`), 태그 줄에 재현 결과와 상태를 둔다.
- 상태 태그: `대기`·`진단 중`·`다시 진단 중`(회색), `준비됨`(파랑), `진단 실패`(빨강), `완료함`(옅은 회색), `저장소 매핑 필요`·`저장소 확인 필요`(노랑). 시간 연장을 묻는 동안에는 `진단 중` 앞에 `확인 필요`(노랑)를 붙인다.
- 재현 태그는 보고서가 있을 때만 붙인다. `재현 성공`(초록), `재현 실패`(노랑), `재현 안 함`(테두리, 재현 불가).

### 보고서 보기

- 상세 머리: 오류 제목, `프로젝트 · 신규/재발 · 감지 시각`, [Sentry에서 열기], 에이전트와 걸린 시간, 상태 태그, [접어 보기].
- 머리 아래에 탭 넷을 둔다. 보고서가 없는 상태(대기·진행·실패·완료)에는 탭이 없다.

| 탭 | 내용 |
|---|---|
| `보고서` | 요약 → 재현(결과를 제목 옆에) → 원인(확신도를 제목 옆에) → 개선 방향 → 남은 의문 |
| `근거 n` | 번호·설명·`저장소 · 파일 · 줄`·[에디터에서 열기]. Flow 초안의 근거 목록과 같은 모양이다. |
| `첨부 n` | 이미지는 작은 그림, 로그는 앞부분 몇 줄을 보이고 아래에 파일 이름을 적는다. |
| `정보` | 오류 정보(앱이 채운 표)와 진단 정보(실행 정보) |

- 원인 글 안의 근거 번호(①②)는 Flow 초안과 같은 표시다.
- 완료 뒤 재발한 진단은 `정보`의 오류 정보에 "앞선 진단: 완료한 날짜 · 마지막으로 내보낸 파일"을 적는다([다시 진단(지시)과 보고서 수정](19-rediagnosis-and-report-editing.md)).
- 재현 불가(허용 안 됨)의 재현 칸에는 "이 저장소는 재현을 허용하지 않아 코드만 읽고 진단했습니다"와 [저장소 설정 열기]를 둔다.

### 바닥 줄의 버튼

끝내는 버튼([완료])은 항상 왼쪽, 나아가는 버튼은 오른쪽이다.

| 상태 | 왼쪽 | 오른쪽 |
|---|---|---|
| 검토 대기 | [완료] | [다시 진단 ▾] · **[내보내기]** |
| 내보내지 않고 [완료]를 누름 | "내보내지 않았습니다. 완료하면 이 보고서가 사라집니다." | [취소] · [내보내기] · **[완료]** |
| 대기 | "차례를 기다리는 중입니다." | [취소] |
| 진행 중 | "진단하는 중입니다 · n분 지남" | [취소] |
| 시간 연장 묻기 | (노란 바닥 줄) "**5분 뒤 멈춥니다. 계속할까요?** 계속하면 10분을 더 씁니다. 답이 없으면 지금까지 알아낸 것으로 보고서를 마무리합니다." | [멈추기] · **[계속 진행]** |
| 마무리를 기다림 | "보고서를 마무리하는 중입니다. 5분 안에 끝납니다." | [취소] |
| 다시 진단하는 중 | "다시 진단하는 중입니다. 끝나면 이 보고서를 바꿉니다." | [취소] |
| 진단 실패 | [완료] | **[다시 시도]** |
| 진단 실패(시간 초과, 재현하던 진단) | [완료] | [재현 없이 다시 시도] · **[다시 시도]** |
| 완료함 | "완료한 진단입니다. 보고서는 지웠습니다." | 없음 |

- [다시 진단 ▾]의 항목은 "다시 진단"과 "지시를 덧붙여 다시 진단" 둘이다.
- 내보내면 토스트 "내보냈습니다: `<파일 이름>`"과 [폴더 열기]를 띄운다. 상태는 바뀌지 않는다.
- 실행 중 전달이 안 되는 에이전트(Codex)는 답이 없을 때 보고서 없이 실패하므로, 연장 묻기의 둘째 문장을 그에 맞게 바꿔야 한다. 그 문구는 스펙에서 정한다.

### 지시 입력

- "지시를 덧붙여 다시 진단"을 고르면 Flow 초안처럼 바닥 줄이 펼쳐진다.
- 위에서 아래로: 이름 "지시" → "앞서 덧붙인 지시도 함께 넘깁니다."와 앞선 지시 목록 → 입력 칸 → 체크 "재현도 다시 하기"(도움말 "끄면 앞선 재현 결과를 그대로 둡니다.") → "새 보고서가 나오면 지금 보고서를 바꿉니다. 남기려면 먼저 내보내세요." → [취소] · [다시 진단].
- 재현을 허용하지 않은 저장소면 체크를 보이지 않는다.

### 보고서가 없는 상태의 몸통

- 대기·진행 중: `진행`(대기면 "앞에 n개가 있습니다.", 진행이면 단계와 읽은 파일 수) 아래에 `오류 정보`(난 자리, 발생 수, 스택 앞부분, 오류 정보 표)를 보인다.
- 진단 실패: `오류` 칸에 Flow와 같은 빨간 상자로 사유와 마지막 단계를 적고, 아래에 `오류 정보`를 둔다.
- 완료함: `기록`에 완료한 때와 마지막으로 내보낸 파일만 보인다.

### 다시 진단하지 못하고 돌아왔을 때

- 보고서 위 알림 줄(노랑): "다시 진단하지 못했습니다: `<사유>`. 앞선 보고서를 그대로 둡니다." 오른쪽에 [다시 걸기](지시 입력을 쌓인 지시와 함께 연다).

### 작은 창

- 진단도 초안과 같은 차례(`2 / 6`)에 넣고, 머리에 `진단` 태그를 붙인다.
- 탭 대신 접는 구역으로 보인다(요약·재현·원인·개선 방향은 펴고, 근거·남은 의문·오류 정보·진단 정보는 접는다). 바닥 줄의 버튼 자리는 펼친 창과 같다.

### Flow 초안 검토 화면과 같은 것, 다른 것

- 같은 것: 창 틀(목록 260px + 상세), 상세 머리, 바닥 줄, 지시 입력, 근거 목록, 실패 상자, 알림 줄, 토스트, 작은 창의 접는 구역.
- 다른 것: 초안 상세는 접는 구역 그대로이고 진단 상세만 탭이다. 초안의 주 버튼은 [게시], 진단은 [내보내기]다.
- **Flow 초안 목록도 바뀐다**: 목록이 종류별 묶음이 되면서 초안의 상태별 묶음 머리가 사라지고, 처리됨 아래의 보관 안내("7일이 지나면…")가 놓일 자리를 스펙에서 다시 정해야 한다.

### 사용자가 따로 답하지 않아 시안대로 적은 것

시안과 함께 물었지만 답이 없어 추천안(시안에 그린 모양)으로 적었다. 스펙을 쓰기 전에 뒤집을 수 있다.

- 완료한 진단은 목록에 `완료함`으로 남긴다. 남기는 기간은 Flow의 처리됨과 같이 7일로 본다.
- 진단을 작은 창의 차례에 넣는다.

### 구현 메모

- 탭은 설정의 확인 시트 탭(`.manual-check-tabs`)과 같은 밑줄 모양을 쓴다.
- 노란 바닥 줄은 `.review-foot`에 `--warn-bg`를 입힌 새 변형이다.

### 다른 티켓으로 넘긴 것

- 연장을 묻는 시스템 알림과 진단 실패·보고서 준비 알림의 기준: [저장소 대기 상태 표시와 알림 시안](21-repo-blocked-and-notification-ui-prototype.md).
- 목록의 `저장소 매핑 필요`·`저장소 확인 필요` 줄을 골랐을 때의 상세 모양: 같은 티켓.
