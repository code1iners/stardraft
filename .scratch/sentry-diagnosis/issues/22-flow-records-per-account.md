## Question

지금은 다른 사람의 Flow 키로 바꾸면 확인을 거쳐 `state.db`의 Flow 기록(멘션, 묶음, 초안, 대기열, 최소 기록)을 모두 지운다(`resetForAccount`, `apps/desktop/src/core/storage/state-database.ts:418`). 처음 스펙이 "두 계정의 멘션이 섞이지 않게 한다", "계정을 오가는 기능은 없다"로 정한 동작이다(`.scratch/flow-mention-drafter/spec.md:120,637`). 이를 지우지 않고 계정별로 보관하도록 바꾼다. [Sentry 실행 상태의 저장 위치](15-sentry-run-state-storage.md)를 정하다가 사용자가 요청해 이 지도에 넣었다.

- **필요한 경우의 확인**: 계정별 보관이 쓰이는 것은 한 PC의 한 앱에서 서로 다른 사람의 Flow 키를 오갈 때다. 다른 사람이 자기 PC에서 앱을 쓰는 경우는 `state.db`가 따로라 지금도 섞이지 않는다. 어떤 경우를 위한 것인지 먼저 맞춘다.
- **나누는 방법**: Flow 표마다 계정 열을 더할지, 계정마다 파일을 나눌지. Sentry 표는 계정에 매이지 않고 같은 `state.db`에 있다.
- **돌아왔을 때**: 떠나 있던 동안의 멘션을 어디부터 다시 감지할지(기준점, 72시간 규칙), 그때 남아 있던 초안·대기열·게시 카운트다운을 어떻게 할지.
- **보관과 지우기**: 지금 쓰지 않는 계정의 Flow 글을 이 PC에 얼마나 둘지. 지금은 지운 글이 파일에 남지 않게 덮어쓴다(`secure_delete`). 사용자가 한 계정의 기록을 직접 지우는 길을 둘지.
- **화면**: 다른 계정의 키를 넣을 때의 확인 문구가 "지우고 처음부터 시작"에서 무엇으로 바뀌는지.
- **기존 데이터의 이전**: 지금 있는 줄을 현재 계정의 것으로 채우는 이전.
