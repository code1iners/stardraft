# 25: Sentry API 실측

**Spec:** [스펙](../spec.md) 5절, 테스트 결정의 "실기 점검 목록 · Sentry API"

**What to build:** [API 조사](../research/sentry-api-facts.md)는 문서와 공개 코드만 읽은 결과다. 24번에서 받은 계정으로 실제 호출을 해 보고, 감지 규칙이 기대는 사실을 확인해 조사 문서에 "실측" 절로 적는다. 앱 코드는 바꾸지 않는다. 결과가 스펙과 다르면 멈추고 사용자에게 확인받는다.

**Blocked by:** 24

**Status:** ready-for-agent

- [ ] 신규 조회(미해결 + 처음 보인 시각 필터)와 재발 조회(`is:regressed`)가 기대한 오류 이슈를 돌려주는지 확인했다. 환경을 줬을 때 처음 보인 시각이 환경 기준인지도 확인했다.
- [ ] 오류 이슈를 해결 처리한 뒤 다시 일으켜, 상세 응답에 재발 활동과 재발을 일으킨 이벤트 ID가 보이는지 확인했다. 보이지 않으면 스펙 5절의 낮춘 규칙이 필요하다고 적고 멈춘다.
- [ ] 최신 이벤트 응답에서 스택트레이스, breadcrumbs, release, 태그(환경·레벨)가 스펙 7절이 쓰는 자리에 있는지 확인했다.
- [ ] 한 주소의 조직 목록에 모든 지역의 조직이 나오는지, 조직별 지역 주소가 응답에 있는지 확인했다.
- [ ] `429` 응답의 헤더는 일부러 한도를 넘기지 않고, 정상 응답에 한도 헤더가 붙는지만 확인했다. 확인하지 못한 것은 "확인 못 함"으로 남겼다.
- [ ] 결과를 조사 문서에 적었고, 응답 예시에는 실제 조직·프로젝트 이름, 토큰, 오류 원문을 넣지 않았다.
