# 26: 재현 경계와 CLI 실측

**Spec:** [스펙](../spec.md) 7절 "CLI별 구현", 테스트 결정의 "실기 점검 목록 · 재현 경계, 병렬 작업"

**What to build:** 재현하는 진단이 기대는 CLI 동작을 이 PC의 실제 Claude Code와 Codex로 확인하고, 스펙 7절의 "CLI별 구현" 표를 정확한 플래그로 굳힌다. 결과는 `research/` 아래 새 문서에 적는다. 앱 코드는 바꾸지 않는다. 표의 방향과 다른 결과가 나오면 멈추고 사용자에게 확인받는다.

**Blocked by:** 24

**Status:** ready-for-agent

- [ ] 24번에서 받은 저장소로 APFS 복제 시간을 쟀다(`.git` 제외, 의존성 폴더 포함).
- [ ] 두 CLI에서 "사용자 설정은 막고, 셸과 사본 쓰기와 네트워크는 연다"가 되는 플래그 묶음을 찾아 적었다. 사본 밖 쓰기와 `.env` 계열 말고 다른 비밀 패턴 읽기가 막히는지 확인했다.
- [ ] Claude Code의 읽기 deny를 OS 수준 차단으로 합쳤을 때의 부작용(TLS 인증서, `.git`, 사용자 홈의 설정 파일)과 작업 루트로 좁힌 형식을 확인했다.
- [ ] 강제 종료 때 두 CLI의 백그라운드 명령과 MCP 서버가 함께 끝나는지, Codex 자손을 모아 그룹마다 끝내는 순서가 통하는지 확인했다.
- [ ] Codex에서 MCP 도구 승인을 자동 허용으로 줬을 때 조작 도구가 실행되는지, 그 서버에 없는 도구 이름을 비활성 목록에 넣어도 되는지, 실린 서버와 연결 실패한 서버를 읽는 방법을 확인했다.
- [ ] Claude Code의 스트림 입력을 앱의 플래그 묶음과 함께 쓸 때 실행 중 메시지가 반영되고 구조화 출력이 나오는지 확인했다.
- [ ] 시뮬레이터·에뮬레이터의 "새로 켜진 것" 판별과 종료 명령을 확인했다.
- [ ] 같은 로그인으로 두 CLI를 각각 2~5개 함께 돌려 세션·인증 충돌과 사용량 한도 오류의 모양을 확인했다. 문제가 있으면 병렬 작업 수 상한을 낮추자고 적고 멈춘다.
- [ ] Codex 한도 때문에 못 한 항목은 "확인 못 함"과 까닭을 적었다.
