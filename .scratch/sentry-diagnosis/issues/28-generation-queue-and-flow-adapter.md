# 28: 생성 대기열과 Flow 어댑터로 나누기

**Spec:** [스펙](../spec.md) 2절, 8절 "멈춤은 두 층", ADR 0004

**What to build:** 사용자가 보는 Flow 동작은 그대로 두고, 초안 대기열을 프로바이더와 무관한 **생성 대기열**과 **Flow 어댑터**로 나눈다. 대기열은 대상을 `(종류, 대상 ID)`로만 안다. Flow 키 문제는 대기열 전체가 아니라 Flow 대상만 멈춘다. 이 티켓은 병렬 실행을 더하지 않는다(직렬 그대로).

**Blocked by:** 24

**Status:** ready-for-agent

- [ ] 생성 대기열이 실행 자리, 우선순위, 대기열 저장과 복원, 실행 직전 에이전트 확인, 일시적 실패 1회 재시도, 전역 실패 멈춤, 취소, 앱 종료를 맡고, Flow 타입을 import하지 않는다.
- [ ] 대상 어댑터 인터페이스가 준비(지침·입력·출력 스키마·저장소·시간 상한·실행 종류, 또는 건너뜀·어댑터 멈춤·잠시 뒤 다시), 결과 읽기, 저장, 실패 기록, 저장소 대기 기록, "아직 생성 중인가" 판정을 갖는다.
- [ ] Flow 어댑터가 기존 멘션 묶음 모듈을 감싸고, 담당 업무 초안은 그 안에 그대로 있다.
- [ ] 대기열 표에 대상 종류 열을 더하는 이전이 있고 기존 줄은 Flow로 채워진다. 이전은 실제 SQLite 파일로 테스트된다.
- [ ] 멈춤이 두 층이다. 에이전트를 쓸 수 없으면 전부 멈추고, Flow 키 거부·Flow 미도달은 Flow 어댑터의 대상만 멈춘다. 멈춘 대상은 실패가 되지 않고 순서를 지킨다. 가짜 둘째 어댑터의 대상이 멈춘 Flow 대상을 지나가는 테스트가 있다.
- [ ] 기존 초안 대기열 테스트가 고치지 않은 기대값으로 통과한다(우선순위, `resume` 재진입, 저장된 대기열 복원).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
