# 29: 병렬 작업 수

**Spec:** [스펙](../spec.md) 8절 "병렬 작업 수", 14절 "에이전트 칸 · 병렬 작업"

**What to build:** 설정의 에이전트 칸에 `병렬 작업` 탭이 생기고, 슬라이더로 1~5를 고르면 초안이 그 수만큼 함께 진행된다. 기본값 1은 지금과 같다.

**Status:** resolved

- [x] 에이전트 칸에 `연결` · `병렬 작업` 탭이 있다(`재현` 탭은 41번이 더한다). 칸 안 탭은 밑줄형이고 재사용할 수 있는 컴포넌트다.
- [x] 탭 안에 이름, 도움말 "올리면 사용량 한도를 더 빨리 씁니다.", 눈금 숫자 없는 슬라이더와 현재 값, 두 줄 표와 툴팁이 스펙의 문구대로 있다.
- [x] 대기열이 최대 n개를 함께 돌린다. 값을 바꾸면 다음 실행을 꺼낼 때부터 쓰고, 줄여도 돌던 실행을 끊지 않는다. 진행 중이 값보다 많을 때만 노란 띠가 보인다.
- [x] 어댑터가 "함께 돌 수 없는 자원"을 알리면 그 자원을 쓰는 실행은 한 번에 하나만 돌고, 대기열은 그 뒤에서 돌 수 있는 것을 꺼낸다(가짜 어댑터로 테스트. 실제 사용은 42번).
- [x] 전역 실패 때 함께 돌던 실행은 끊기지 않고, 성공하면 저장되며 실패하면 같은 판정을 거친다.
- [x] 앱 종료 때 돌던 실행을 모두 끊고, 다시 켜면 원래 시작한 순서대로 `resume` 칸 맨 앞에 선다.
- [x] 진행 단계 알림이 실행마다 따로 간다.
- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.

## Comments

### 구현 기록 (2026-11-26)

- 생성 대기열(`GenerationQueue`)이 실행 자리를 여러 개 둔다. 새 옵션 `parallelWork: ParallelWorkLimit`(`count()`, `onChange()`)의 값을 다음 실행을 꺼낼 때마다 읽는다.
  - 값을 올리면 바로 자리가 난다. 값을 줄여도 돌던 실행은 끊지 않고, 진행 중인 실행이 새 값보다 적어질 때까지 꺼내지 않는다.
  - 진행 중인 수는 `runningCount()`로 읽는다.
- 함께 돌 수 없는 자원은 `TargetAdapter.exclusiveResource?(targetId): string | null`로 받는다.
  - 같은 자원을 쓰는 대상은 한 번에 하나만 돈다. 기다리는 대상은 자리를 지키고, 대기열은 그 뒤에서 돌 수 있는 대상을 꺼낸다.
  - 자원은 생성이 끝날 때(어댑터의 정리 포함) 놓는다. 42번은 Sentry 어댑터에서 재현하는 진단에 `'reproduction'` 같은 키를 돌려주면 된다.
- 전역 실패가 나면 대기열은 새 실행을 꺼내지 않는다. 함께 돌던 실행은 끝까지 돌고, 성공하면 저장되며, 실패하면 같은 판정을 거쳐 `resume` 칸으로 돌아간다.
  - 리뷰에서 반영: 함께 돌던 실행의 연결 확인이 통과하면 에이전트 변경 알림이 없어도 전역 멈춤을 푼다.
  - 리뷰에서 반영: 다시 만들려고 대기열에 되돌린 대상은, 앞 실행이 정리를 마칠 때까지 꺼내지 않는다(같은 대상이 두 번 도는 것을 막음).
- 앱을 끌 때는 돌던 실행을 모두 끊고 기록을 합쳐 최대 5초 기다린다. 남기는 대기열은 돌던 대상들이 시작한 순서대로 `resume` 칸 맨 앞이다.
- 설정 값은 `settings.json`의 `parallelWorkCount`(기본 1)다. 키가 없는 옛 파일은 기본값으로 읽어 형식 버전은 그대로 두었다. 범위 밖 값은 1~5로 맞춘다.
  - 저장 모듈은 `core/generation/parallel-work.ts`의 `ParallelWork`다.
  - IPC는 스냅숏 `parallelWork: { count, running }`, 이벤트 `parallel-work-changed`, 명령 `set-parallel-work-count`다.
- 화면은 다음과 같다.
  - 재사용 밑줄 탭: `renderer/src/UnderlineTabs.tsx`(`UnderlineTabs`, 탭마다 `dot`)
  - 물음표 툴팁: `HelpTip.tsx`
  - 탭 내용: `ParallelWorkPanel.tsx`
  - 에이전트 칸의 탭은 `연결` · `병렬 작업`이다. 41번은 `AGENT_TABS`에 `재현`을 더하면 된다.
  - 리뷰에서 반영: `check-agents`는 칸을 열 때 한 번만 보낸다. 탭을 오갈 때는 다시 보내지 않는다.
- `restart-recovery.test.ts`의 "남긴 대기열의 순서와 자리 그대로…" 테스트는 고정 시간 `settle` 안에 세 묶음을 차례로 SQLite에 저장해야 한다.
  - 전체 실행의 부하에서 6번 중 2번, 셋째 묶음이 아직 생성 중인 채로 실패했다. 기준 커밋에서는 5번 모두 통과했다.
  - 단언은 그대로 두고 조건이 맞을 때까지(상한 2초) 기다리는 `settleUntil`로 바꿨다. 고친 뒤 5번 연속 통과했다.
