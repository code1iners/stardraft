# 30: Flow 저장소 대기 두 상태와 자동 재개

**Spec:** [스펙](../spec.md) 15절 "작업 폴더와 자동 선택 폐지"(묶음 상태, 묶음 하나에만 고르기, 저장소가 정해지지 않은 초안, 기존 사용자의 전환), 6절

**What to build:** 저장소 매핑이 없는 Flow 프로젝트의 멘션과 담당 업무가 자동 선택을 타지 않고 **저장소 매핑 필요**로 기다린다. 매핑된 폴더가 없으면 **저장소 확인 필요**로 멈춘다. 매핑을 저장하거나 폴더가 돌아오면 저절로 초안이 만들어진다. 화면은 지금 검토 화면의 저장소 확인 필요 표시를 두 상태에 맞게 최소로 고치고, 새 목록과 노란 바닥 줄은 32번이 한다.

**Blocked by:** 28

**Status:** resolved

- [x] 매핑도 고른 저장소도 없는 묶음은 저장소 매핑 필요가 되고 선택 실행이 돌지 않는다. 정해 둔 저장소의 폴더가 없으면 저장소 확인 필요가 된다.
- [x] Flow 프로젝트에 매핑을 저장하면(설정 칸, 선택 창의 [연결] 어느 경로든) 그 프로젝트에서 기다리던 묶음이 모두 `auto` 칸에 선다.
- [x] 폴더가 돌아오면 저장소 확인 필요 묶음이 재개된다. 다시 확인하는 때는 앱 시작, 절전에서 깸, 매핑 변경, 그리고 그런 대상이 있는 동안 60초마다다.
- [x] 저장소 대기 묶음에서 [저장소를 골라 만들기]로 그 묶음만 만들 수 있고, 매핑은 저장되지 않으며 같은 프로젝트의 다른 묶음은 계속 기다린다. 선택 창 후보에 작업 폴더 무리가 없다.
- [x] 초안은 있는데 매핑도 고른 저장소도 없는 묶음은 "다시 만들기"와 "지시를 덧붙여 다시 만들기"가 꺼지고 알림 줄 문구가 보인다. 게시, 무시, "다른 저장소로 다시 만들기"는 된다. 새 멘션이 합쳐져도 저절로 다시 만들지 않는다.
- [x] 처리됨에서 되돌린 묶음에 초안도 매핑도 고른 저장소도 없으면 저장소 매핑 필요가 된다.
- [x] 업데이트 뒤 첫 시작에서, 초안 없이 생성 중이던 매핑 없는 묶음은 저장소 매핑 필요가 되고, 옛 사유로 멈춰 있던 묶음과 선택 실행이 실패한 묶음은 한 번 다시 판정된다(매핑 있음 → 대기열, 폴더 없음 → 저장소 확인 필요, 없음 → 저장소 매핑 필요).
- [x] 자동 선택으로 만든 기존 초안은 그대로 검토·게시되고, 저장된 자동 선택 값은 지워지지 않는다. DB 마이그레이션이 없다.
- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.

## Comments

### 구현 기록 (2026-11-26)

- 저장소 매핑 필요는 새 묶음 상태가 아니라 기존 `repo-check-needed` 상태의 사유 `RepoCheck.kind === 'unmapped'`로 둔다. 저장소 확인 필요는 `missing-folders`다. DB 마이그레이션은 없고 설정 스키마 버전도 그대로다. 옛 사유(`no-candidates`, `unsure`, `unrelated`, 사유 없음)는 타입에 남기고 읽기만 한다(제거는 31번).
- 묶음 모듈(`core/bundles/mention-bundles.ts`):
  - `reposForRun`은 고른 구성이나 매핑으로 읽을 저장소를 정하고, 없으면 선택 실행 없이 묶음을 저장소 매핑 필요로, 폴더가 없으면 저장소 확인 필요로 올린다. Flow 어댑터(`flow-target-adapter.ts`)에서 선택 실행 경로를 걷어 냈다.
  - `resumeRepoWaiting`은 저장소 대기 묶음을 처음 보인 순서(`compareBundles`)로 다시 판정해, 읽을 저장소가 생기면 생성 중으로 올린다. 기다리는 동안 합쳐진 새 멘션 수는 0으로 돌리고 이번 초안에 넣는다. 확인하다 예외가 나면 그 묶음은 건드리지 않는다.
  - `reconcileRepoStates`는 앱을 켤 때(대기열 시작 전) 초안 없이 생성 중이던 매핑 없는 묶음, 선택 실행이 실패한 묶음(`failure.runKind === 'selection'`), 옛 사유 묶음을 다시 판정한다. 다시 판정한 묶음은 조건에서 빠지므로 별도의 "한 번만" 표지 없이도 되풀이되지 않는다(마이그레이션 없음 조건 때문에 표지를 저장하지 않았다). 알림은 띄우지 않는다.
  - `regenerate`(다시 만들기·지시 덧붙이기·요구 고치기)는 저장소가 정해지지 않은 초안(`isRepoUndetermined`: 초안 있음, 고른 저장소 없음, 매핑 없음)이면 아무것도 하지 않고, 새 멘션이 합쳐져도 저절로 다시 만들지 않는다(`applyDetection`). `regenerateWithRepos`(다른 저장소로 다시 만들기)와 무시는 된다. 처리됨에서 되돌릴 때는 고른 저장소를 먼저 본다.
  - 저장된 자동 선택 값(`draft.autoSelection`, `regeneration.autoSelected`)은 지우지 않고 읽지 않는다. 새 재생성은 `autoSelected: null`로 남긴다.
- 자동 재개는 `core/bundles/repo-wait-monitor.ts`(`RepoWaitMonitor`)가 맡는다. 앱 시작, 절전에서 깸(`powerMonitor.resume`), 매핑 변경(`repoMappings.onChange`)에서 지금 확인하고, 저장소 확인 필요(폴더 없음) 묶음이 있는 동안 60초마다 확인한다. 저장소 매핑 필요뿐이면 주기로 확인하지 않는다(매핑이 바뀔 때만 풀림). 연결은 `main/index.ts`다.
- 저장소 선택 창에서 작업 폴더 무리와 작업 폴더 훑기(`findWorkFolderRepos`), 로딩 상태를 없앴다. 후보는 "지금 쓰는 저장소", "다른 Flow 프로젝트의 매핑 저장소", "직접 고른 폴더"다.
- 화면(최소 변경): 저장소 매핑 필요 태그와 사유 문구, 저장소가 정해지지 않은 초안의 알림 줄 문구와 재생성 메뉴(다시 만들기·지시 덧붙이기 꺼짐, 다른 저장소로 다시 만들기 켜짐). 스냅숏에 `RepoCheckSnapshot`의 `unmapped`와 `DraftSnapshot.repoUndetermined`를 더했다. 준비됨 묶음에서만 `repoUndetermined`가 참이다.
- 알려 둘 점:
  - 스펙은 [다시 만들기 ▾]의 두 항목만 끈다고 했지만, 요구 고치기(망치)도 같은 저장소로 다시 만드는 경로라 함께 막았다(`canRegenerate: false`). 안 막으면 초안을 지우고 저장소 매핑 필요로 가서 초안을 잃는다.
  - 알림 제목만 "저장소 매핑 필요"로 갈랐다. 알림 단위(프로젝트에 한 번), 트레이 수, 노란 바닥 줄, [저장소 매핑하기] 버튼, `저장소` 구역의 "정해진 저장소가 없습니다."는 32번이다. 자동 선택·작업 폴더 코드와 설정 항목 제거는 31번이다.
  - `regenerate`와 감지가 "매핑 있음"을 묶음 변경 줄 밖에서 판정해, 판정 직후 매핑이 지워지는 아주 좁은 틈에서는 다시 만들며 초안이 지워질 수 있다(이후 저장소 매핑 필요로 기다린다). 고치려면 변경 콜백을 비동기로 넓혀야 해서 두었다.
- 테스트: `draft-queue.test.ts`의 자동 선택 블록을 저장소 매핑 필요, 폴더가 돌아오면 재개, 저장소가 정해지지 않은 초안, 업데이트 뒤 첫 시작 블록으로 바꿨다. `repo-wait-monitor.test.ts`를 새로 만들었고 선택 창·스냅숏·화면 테스트를 맞췄다.
- 검증: `pnpm lint`, `pnpm typecheck`는 통과했다. desktop 테스트 1381개가 모두 통과했다. `pnpm test`는 site `index-page` 환경성 실패로 turbo가 중단된다. 실제 앱에서 절전 복귀와 폴더 복귀는 확인하지 못했다(자동 테스트는 가짜 시계와 임시 폴더).
