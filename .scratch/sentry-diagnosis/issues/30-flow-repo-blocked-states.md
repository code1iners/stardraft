# 30: Flow 저장소 대기 두 상태와 자동 재개

**Spec:** [스펙](../spec.md) 15절 "작업 폴더와 자동 선택 폐지"(묶음 상태, 묶음 하나에만 고르기, 저장소가 정해지지 않은 초안, 기존 사용자의 전환), 6절

**What to build:** 저장소 매핑이 없는 Flow 프로젝트의 멘션과 담당 업무가 자동 선택을 타지 않고 **저장소 매핑 필요**로 기다린다. 매핑된 폴더가 없으면 **저장소 확인 필요**로 멈춘다. 매핑을 저장하거나 폴더가 돌아오면 저절로 초안이 만들어진다. 화면은 지금 검토 화면의 저장소 확인 필요 표시를 두 상태에 맞게 최소로 고치고, 새 목록과 노란 바닥 줄은 32번이 한다.

**Blocked by:** 28

**Status:** ready-for-agent

- [ ] 매핑도 고른 저장소도 없는 묶음은 저장소 매핑 필요가 되고 선택 실행이 돌지 않는다. 정해 둔 저장소의 폴더가 없으면 저장소 확인 필요가 된다.
- [ ] Flow 프로젝트에 매핑을 저장하면(설정 칸, 선택 창의 [연결] 어느 경로든) 그 프로젝트에서 기다리던 묶음이 모두 `auto` 칸에 선다.
- [ ] 폴더가 돌아오면 저장소 확인 필요 묶음이 재개된다. 다시 확인하는 때는 앱 시작, 절전에서 깸, 매핑 변경, 그리고 그런 대상이 있는 동안 60초마다다.
- [ ] 저장소 대기 묶음에서 [저장소를 골라 만들기]로 그 묶음만 만들 수 있고, 매핑은 저장되지 않으며 같은 프로젝트의 다른 묶음은 계속 기다린다. 선택 창 후보에 작업 폴더 무리가 없다.
- [ ] 초안은 있는데 매핑도 고른 저장소도 없는 묶음은 "다시 만들기"와 "지시를 덧붙여 다시 만들기"가 꺼지고 알림 줄 문구가 보인다. 게시, 무시, "다른 저장소로 다시 만들기"는 된다. 새 멘션이 합쳐져도 저절로 다시 만들지 않는다.
- [ ] 처리됨에서 되돌린 묶음에 초안도 매핑도 고른 저장소도 없으면 저장소 매핑 필요가 된다.
- [ ] 업데이트 뒤 첫 시작에서, 초안 없이 생성 중이던 매핑 없는 묶음은 저장소 매핑 필요가 되고, 옛 사유로 멈춰 있던 묶음과 선택 실행이 실패한 묶음은 한 번 다시 판정된다(매핑 있음 → 대기열, 폴더 없음 → 저장소 확인 필요, 없음 → 저장소 매핑 필요).
- [ ] 자동 선택으로 만든 기존 초안은 그대로 검토·게시되고, 저장된 자동 선택 값은 지워지지 않는다. DB 마이그레이션이 없다.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
