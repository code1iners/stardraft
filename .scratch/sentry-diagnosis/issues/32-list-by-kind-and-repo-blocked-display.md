# 32: 종류별 목록과 저장소 대기 표시·알림

**Spec:** [스펙](../spec.md) 12절 "목록", "바닥 줄"의 저장소 대기 표, 13절, 15절 "저장소 대기 알림과 목록"

**What to build:** 펼친 창의 목록이 상태별 묶음 대신 종류별 묶음과 태그로 보인다(지금은 `초안 n` 하나). 저장소 대기 상태의 이유와 버튼은 노란 바닥 줄에 있고, 저장소 대기 알림과 트레이 수는 프로젝트 단위다.

**Blocked by:** 30

**Status:** resolved

- [x] 목록이 종류 묶음 머리와 줄의 상태 태그로 그려진다. 종류 묶음과 줄, 태그는 진단이 그대로 쓸 수 있는 컴포넌트다.
- [x] 끝낸 항목이 하나라도 있으면 목록 맨 아래에 "끝낸 항목은 7일이 지나면 목록에서 사라집니다."가 한 줄 보인다.
- [x] 저장소 매핑 필요·저장소 확인 필요 묶음의 상세에 이유 상자가 없고, 노란 바닥 줄에 스펙의 글과 [무시] · [저장소를 골라 만들기] · 주 버튼([저장소 매핑하기] 또는 [매핑 고치기])이 있다. 작은 창에서는 글이 윗줄, 버튼이 아랫줄이다.
- [x] [저장소 매핑하기]와 [매핑 고치기]가 설정의 그 프로젝트 매핑 편집으로 이동한다.
- [x] 저장소가 정해지지 않은 초안의 알림 줄에 [저장소 매핑하기]가 있고 `저장소` 구역에는 "정해진 저장소가 없습니다."만 있다.
- [x] 저장소 대기 OS 알림은 프로젝트가 그 상태가 될 때 한 번 뜬다. 풀리기 전에 또 오면 뜨지 않고, 풀린 뒤 다시 그 상태가 되면 다시 뜬다. 누르면 그 프로젝트의 첫 건이 열린다. 제목과 본문은 스펙 13절의 문구다.
- [x] 트레이 검토 수가 저장소 대기를 프로젝트마다 1로 센다.
- [x] 알림이 가리키는 대상이 "종류와 대상 ID"로 넓혀져 있다.
- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.

## Comments

- 구현 메모: 알림 중복 방지는 스펙 13절대로 프로젝트 단위다(사유가 바뀌어도 풀리기 전이면 다시 알리지 않는다). 바닥 줄의 "기다리는 멘션 n건"은 같은 프로젝트·같은 사유의 묶음 수다.
- 진단 쪽 이어붙일 곳: 알림 대상 `kind: 'diagnosis'`는 타입만 있고 main은 작은 창만 연다. 진단용 노란 바닥 줄 글("오류 n건", [무시] 없음)은 진단 티켓이 만든다. 목록 컴포넌트는 `ReviewList.tsx`다.
- 검증: `pnpm lint`·`pnpm typecheck` 통과. desktop 전체 테스트 1380개 통과(앞선 한 번은 이 PC의 zsh 설정에 따른 zsh rc 환경성 테스트가 실패했고 다시 돌리자 통과). site 테스트 1건(index-page)은 이 PC의 환경성 실패. 작은 창 줄 나눔은 CSS라 실기 렌더링은 확인하지 못했다.
