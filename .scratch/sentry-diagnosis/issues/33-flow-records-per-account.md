# 33: Flow 기록의 계정별 보관

**Spec:** [스펙](../spec.md) 15절 "Flow 기록의 계정별 보관"

**What to build:** 다른 Flow 계정의 키로 바꿔도 기록이 지워지지 않고 계정별로 보관된다. 원래 계정의 키를 다시 넣으면 기록과 준비된 초안이 그대로 돌아온다.

**Blocked by:** 27, 28

**Status:** ready-for-agent

- [ ] 스키마 이전이 계정 표를 계정마다 한 줄로 바꾸고, 감지 기준점·담당 업무 감지 상태·멘션 묶음·최소 기록·담당 업무 기록·대기열의 Flow 줄을 계정에 맨다. 기존 줄은 모두 현재 계정의 것으로 채워진다. 실제 SQLite 파일로 테스트된다.
- [ ] "이미 본 것" 조회와 유일성 제약이 계정을 포함해, 두 계정에 같은 ID가 있어도 섞이지 않는다.
- [ ] 화면과 감지, 초안 생성, 게시는 움직이는 계정의 기록만 다룬다.
- [ ] 떠날 때: 생성 중이던 Flow 실행은 취소되고, 카운트다운은 게시 없이 준비됨으로 돌아가며, 줄 서 있던 Flow 초안은 대기열에서 빠진다. 대기열의 다른 종류 줄은 그대로다.
- [ ] 돌아왔을 때: 그 계정의 기준점 이후 중 72시간 안의 멘션만 가져오고, 끊긴 생성은 대기열에 다시 서며, 응답을 못 받은 게시는 실제로 올라갔는지 확인한다. 준비됨 초안은 그대로 보이고, 떠나 있던 동안 비밀 패턴이 추가됐을 때만 게시 전 초안을 다시 만든다.
- [ ] 처리한 묶음의 7일 규칙이 보관 중인 계정에도 적용된다.
- [ ] 마지막으로 쓴 지 30일이 지난 계정은 기록 전체가 지워지고(덮어쓰기와 WAL 비우기 포함), 그 뒤 그 키를 넣으면 처음 넣는 계정처럼 시작한다.
- [ ] 확인 창의 제목에 이름과 이메일이 함께 나오고, 본문이 처음 넣는 계정과 보관해 둔 계정에서 스펙의 문구대로 갈린다. 버튼은 [취소] · [계정 바꾸기]이고 처음 초점은 [취소]다.
- [ ] 상태 DB를 비우던 계정 리셋 경로가 남아 있지 않다.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
