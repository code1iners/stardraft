# 34: Sentry 토큰 연결

**Spec:** [스펙](../spec.md) 4절 "토큰", "연결 확인", "문제의 범위", 14절 "Sentry 칸", "온보딩"

**What to build:** 설정에 `Sentry` 칸이 생기고, 개인 토큰을 붙여 넣어 연결한다. 연결되면 토큰 카드에 조직이 보인다. 토큰 문제는 Sentry만 멈춘다.

**Blocked by:** 31

**Status:** ready-for-agent

- [ ] Sentry API 포트와 sentry.io 어댑터가 있고, 조직 목록을 쪽 넘김까지 읽으며 조직별 지역 주소를 설정에 저장한다. 서버 주소 설정은 없다.
- [ ] 토큰은 Flow 키와 같은 방식으로 암호화해 별도 파일에 저장된다. 로그와 화면에 토큰 값이 나오지 않는다.
- [ ] 토큰을 넣으면 조직 목록으로 확인하고, 실패하면 빠진 scope(`org:read`)를 짚어 알린다.
- [ ] 설정 칸 순서가 `Flow 계정 · Sentry · 에이전트 · 저장소 · 초안 · 일반`이다. 토큰이 없으면 토큰 입력만 보이고, 있으면 토큰 카드(조직 수와 이름, 권한, "연결됨" 또는 "토큰 확인 필요")가 보인다.
- [ ] 토큰이 거부되거나 저장된 토큰을 풀 수 없으면 전역 문제 "토큰 확인 필요"가 뜨고 이유(거부, scope 부족, 읽기 불가)가 구분되어 보인다. Flow 감지와 Flow 초안은 멈추지 않는다. 새 토큰이 확인되면 해제된다.
- [ ] 연결을 끊으면 토큰만 지워진다.
- [ ] 온보딩 체크리스트의 선택 묶음에 Sentry 줄이 있다.
- [ ] 가짜 Sentry API로 응답 코드별(`401`, `403`, 응답 없음) 동작이 테스트된다.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
