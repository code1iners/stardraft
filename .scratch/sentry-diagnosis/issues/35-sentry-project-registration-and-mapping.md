# 35: 프로젝트 등록과 Sentry 저장소 매핑

**Spec:** [스펙](../spec.md) 4절 "등록", "필터", "기준 시각", 6절 "Sentry 매핑", 14절 "Sentry 칸", "저장소 칸"

**What to build:** Sentry 칸에서 진단할 프로젝트를 등록하고 환경·레벨 필터와 저장소를 정한다. 저장소 칸의 매핑이 `Flow` | `Sentry` 탭으로 나뉜다. 이 티켓까지는 감지가 돌지 않는다.

**Blocked by:** 34

**Status:** ready-for-agent

- [ ] [프로젝트 추가…] 모달에서 조직의 프로젝트를 골라 등록한다. 등록할 때 그 프로젝트의 오류 이슈 목록을 한 건 불러 `event:read`를 확인하고, 실패하면 빠진 scope를 알린다.
- [ ] 등록은 프로젝트 `id`를 키로 설정에 저장되고, 등록한 시각이 기준 시각이 된다. 필터를 바꿔도 기준 시각은 그대로이고, 등록을 풀었다가 다시 등록하면 새로 잡힌다.
- [ ] 환경은 프로젝트의 환경 목록에서 고르고 `production`이 있으면 기본값이다. 레벨 기본값은 `error`와 `fatal`이다.
- [ ] Sentry 매핑은 프로젝트 하나에 저장소 하나이고, 같은 저장소를 여러 프로젝트에 매핑할 수 있다. Flow 매핑과 키가 겹치지 않는다. 매핑은 등록할 때 필수가 아니다.
- [ ] "진단할 프로젝트" 줄에 `조직 / 프로젝트`, `환경 · 레벨 · 저장소 이름`, 상태가 보인다. [편집] 모달에 필터, 저장소, [등록 해제]가 있다. "토큰 확인 필요"이면 [프로젝트 추가…]가 막힌다.
- [ ] 저장소 칸의 "저장소 매핑"에 `Flow` | `Sentry` 탭이 있고 두 탭의 줄 모양이 같다. Sentry 탭에는 등록한 프로젝트가 모두 오르고 [폴더 추가…] 대신 [바꾸기…]가 있다. Sentry 칸 모달의 저장소와 같은 값이다.
- [ ] 매핑이 없는 등록 프로젝트는 탭 맨 위에 "저장소 매핑 없음"과 [폴더 고르기…]로 보이고 탭에 점이 찍힌다. 매핑된 폴더가 없으면 "폴더를 찾을 수 없음"이 보인다.
- [ ] 등록한 프로젝트가 404이거나 접근이 거부되면 그 줄만 "접근 불가"가 된다(등록 확인 호출 기준. 폴링에서의 처리는 36번).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
