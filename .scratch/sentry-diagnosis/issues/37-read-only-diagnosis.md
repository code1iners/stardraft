# 37: 읽기 전용 진단

**Spec:** [스펙](../spec.md) 7절(실행 종류, 지침과 진단 절차의 읽기 전용, 입력, 출력), 8절, 9절, 11절 "앱이 채우는 것"

**What to build:** 감지된 오류 이슈를 에이전트가 매핑된 저장소를 읽어 진단하고, 진단 보고서가 저장되어 상세에 보인다. 보고서 없이 끝나면 **진단 실패**로 남고 다시 시도하거나 완료로 치울 수 있다. 이 티켓의 상세 화면은 보고서 내용을 한 화면에 순서대로 보이는 최소 모양이고, 탭과 상태별 바닥 줄은 38번이 한다.

**Blocked by:** 36

**Status:** ready-for-agent

- [ ] Sentry 어댑터가 생성 대기열에 붙는다. 감지된 진단은 `auto` 칸에, [다시 시도]는 `user` 칸에 선다. 매핑을 저장하거나 폴더가 돌아오면 저장소 대기 진단이 처음 보인 순서대로 재개된다.
- [ ] 실행 종류 `diagnosis`가 있고 두 실행기가 지금의 읽기 전용 경계 그대로 돈다(MCP 없음, 시간 상한 20분, 묻지 않고 끊음). 사용자 추가 지침은 붙지 않는다.
- [ ] 시작 직전에 오류 이슈 상태를 확인해 해결·보관·삭제·병합이면 조용히 빼고 로그에 적는다. 중복 억제 기록은 남는다.
- [ ] 이벤트 데이터는 시작할 때 받는다. 일시적 실패와 토큰 문제는 진단 실패가 아니라 Sentry 어댑터 멈춤이고, 그 진단은 줄에 남으며 Flow 초안은 그 앞으로 지나간다.
- [ ] 지침에 읽기 전용 **진단 절차**(코드 상수), 확신도 규칙, 한국어 규칙, 없는 데이터 항목이 들어간다. 출력 스키마에 재현이 없다.
- [ ] 에이전트 결과가 스키마대로 읽히고, 근거 위치 검사와 비밀 파일 근거 검사가 Flow 초안과 같은 것으로 돈다. 보고서의 재현 칸은 앱이 "불가(허용 안 됨)"로 채운다.
- [ ] 앱이 오류 이슈 정보와 실행 정보(저장소 경로, HEAD 해시, 커밋하지 않은 변경 유무, 에이전트와 버전, 걸린 시간, 생성 시각)를 채운다.
- [ ] 재시도 뒤에도 실패했거나 취소한 진단은 사유가 붙은 진단 실패가 되고 자동으로 더 재시도하지 않는다. [다시 시도]와 [완료](확인 없이 최소 기록으로)가 된다. 진단 실패가 남은 오류 이슈에 새 재발이 오면 새 진단으로 바뀐다.
- [ ] 상세에 대기("앞에 n개가 있습니다."), 진행(단계와 읽은 파일 수), 보고서, 실패 사유가 보이고 줄 서 있거나 진행 중인 진단을 취소할 수 있다.
- [ ] 가짜 Sentry API와 가짜 실행기로 위 흐름이 테스트되고, 실행기 어댑터 테스트가 진단의 인수 묶음이 읽기 전용 경계임을 검사한다.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
