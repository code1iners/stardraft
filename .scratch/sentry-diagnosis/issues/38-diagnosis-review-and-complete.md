# 38: 진단 검토 화면과 완료

**Spec:** [스펙](../spec.md) 12절(진단 상세, 바닥 줄, 작은 창), 11절 "완료", 13절의 준비됨·실패

**What to build:** 진단 보고서를 `보고서` · `근거` · `첨부` · `정보` 탭으로 읽고 **완료**로 끝낸다. 상태마다 바닥 줄이 달라지고, 작은 창에서도 진단을 차례대로 넘겨 본다. 보고서가 준비되면 알림이 온다.

**Blocked by:** 37

**Status:** ready-for-agent

- [ ] 상세 머리에 오류 제목, `프로젝트 · 신규/재발 · 감지 시각`, [Sentry에서 열기], 에이전트와 걸린 시간, 상태 태그가 있다.
- [ ] 보고서가 있으면 탭 넷이 있고 내용이 스펙의 표대로다. 근거 탭은 Flow 초안의 근거 목록과 같은 모양이고 [에디터에서 열기]가 된다. 원인 글의 근거 번호 표기가 Flow 초안과 같다. 첨부 탭은 첨부가 없으면 빈 상태를 보인다(첨부는 42번부터 생긴다).
- [ ] 재현 불가(허용 안 됨)의 재현 칸에 안내와 [저장소 설정 열기]가 있다.
- [ ] 바닥 줄이 검토 대기, 대기, 진행 중, 진단 실패, 완료함에서 스펙의 표대로다([다시 진단 ▾]와 [내보내기], [재현 없이 다시 시도]는 39·40·44번이 더한다).
- [ ] [완료]는 최소 기록(오류 이슈 ID, 재발 식별자, 완료 시각)만 남기고 본문과 첨부 폴더를 지운다. Sentry에는 아무 요청도 가지 않는다.
- [ ] 완료한 진단은 7일 동안 `완료함`으로 남고 `기록`만 보이며, 7일 뒤 목록에서 사라진다. 최소 기록은 남는다. 프로젝트 등록을 풀어도 검토 대기 보고서와 최소 기록은 남는다.
- [ ] 목록의 진단 줄 둘째 줄에 보고서 요약이 보이고, 보고서가 있으면 재현 태그가 붙는다.
- [ ] 작은 창에서 진단이 초안과 같은 차례에 들어가고 머리에 `진단` 태그가 붙으며, 접는 구역으로 보인다.
- [ ] 보고서가 준비되면 건마다 OS 알림이 뜨고(본문은 프로젝트 이름과 재현 결과뿐) 트레이 검토 수에 더해진다. 진단 실패는 알림 없이 트레이 "!"로만 보인다.
- [ ] 검토 대기 중 재발은 새 진단을 따로 만들고, 완료한 뒤의 재발도 새 진단을 만든다. 둘은 목록에서 각각 한 줄이다.
- [ ] 렌더링 테스트가 상태별 상세와 바닥 줄을 검사한다.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
