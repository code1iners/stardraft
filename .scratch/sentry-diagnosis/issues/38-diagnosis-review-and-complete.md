# 38: 진단 검토 화면과 완료

**Spec:** [스펙](../spec.md) 12절(진단 상세, 바닥 줄, 작은 창), 11절 "완료", 13절의 준비됨·실패

**What to build:** 진단 보고서를 `보고서` · `근거` · `첨부` · `정보` 탭으로 읽고 **완료**로 끝낸다. 상태마다 바닥 줄이 달라지고, 작은 창에서도 진단을 차례대로 넘겨 본다. 보고서가 준비되면 알림이 온다.

**Blocked by:** 37

**Status:** resolved

- [x] 상세 머리에 오류 제목, `프로젝트 · 신규/재발 · 감지 시각`, [Sentry에서 열기], 에이전트와 걸린 시간, 상태 태그가 있다.
- [x] 보고서가 있으면 탭 넷이 있고 내용이 스펙의 표대로다. 근거 탭은 Flow 초안의 근거 목록과 같은 모양이고 [에디터에서 열기]가 된다. 원인 글의 근거 번호 표기가 Flow 초안과 같다. 첨부 탭은 첨부가 없으면 빈 상태를 보인다(첨부는 42번부터 생긴다).
- [x] 재현 불가(허용 안 됨)의 재현 칸에 안내와 [저장소 설정 열기]가 있다.
- [x] 바닥 줄이 검토 대기, 대기, 진행 중, 진단 실패, 완료함에서 스펙의 표대로다([다시 진단 ▾]와 [내보내기], [재현 없이 다시 시도]는 39·40·44번이 더한다).
- [x] [완료]는 최소 기록(오류 이슈 ID, 재발 식별자, 완료 시각)만 남기고 본문과 첨부 폴더를 지운다. Sentry에는 아무 요청도 가지 않는다.
- [x] 완료한 진단은 7일 동안 `완료함`으로 남고 `기록`만 보이며, 7일 뒤 목록에서 사라진다. 최소 기록은 남는다. 프로젝트 등록을 풀어도 검토 대기 보고서와 최소 기록은 남는다.
- [x] 목록의 진단 줄 둘째 줄에 보고서 요약이 보이고, 보고서가 있으면 재현 태그가 붙는다.
- [x] 작은 창에서 진단이 초안과 같은 차례에 들어가고 머리에 `진단` 태그가 붙으며, 접는 구역으로 보인다.
- [x] 보고서가 준비되면 건마다 OS 알림이 뜨고(본문은 프로젝트 이름과 재현 결과뿐) 트레이 검토 수에 더해진다. 진단 실패는 알림 없이 트레이 "!"로만 보인다.
- [x] 검토 대기 중 재발은 새 진단을 따로 만들고, 완료한 뒤의 재발도 새 진단을 만든다. 둘은 목록에서 각각 한 줄이다.
- [x] 렌더링 테스트가 상태별 상세와 바닥 줄을 검사한다.
- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.

## Comments

- 구현 메모: 화면은 `DiagnosisDetail.tsx`(머리 `DiagnosisHead`·작은 창 `DiagnosisMeta`, 펼친 창 탭 `DiagnosisTabs`, 작은 창 접는 구역 `DiagnosisFolds`, 바닥 줄 `DiagnosisFooter`), 글은 `diagnosis-text.ts`다. 원인 글의 `[근거 n]`은 원문자 번호 단추가 되어 근거 탭(작은 창은 근거 구역)으로 가서 그 근거를 강조한다. 새 명령은 `open-diagnosis-in-sentry`(주소는 main이 정하고 공식 sentry.io https 주소만 연다)와 `open-diagnosis-evidence-in-editor`이고, `expand-review`·`collapse-review`에 선택 인자 `diagnosisId`를 더했다. core는 `SentryDiagnoses`가 보고서 준비 알림, `complete`(진단 실패와 검토 대기), `archiveExpired`(완료 7일), `reviewCount`·`hasFailure`를 맡는다. 7일이 지난 완료 진단은 목록에서 빠지고 줄은 최소 기록(오류 이슈 ID, 재발 식별자, 완료 시각)만 남긴다(`SentryStore.scrubCompleted`). 켤 때 이미 7일이 지난 진단도 같이 비운다. 첨부 폴더 위치는 `core/sentry/diagnosis-attachments.ts` 한 곳이다(완료·완료함 사라짐 때 지우고, 켤 때 표에 없는 폴더를 치운다).
- 해석으로 정한 것: (1) 작은 창 차례는 초안 뒤에 진단을 세운다(`1 / n`이 처음 열 때의 첫 초안과 같고, 펼친 창 목록의 진단 위·초안 아래 배치와는 반대다). 스펙이 순서를 정하지 않았고, 처음 열 때 첫 묶음을 보이는 지금 동작을 지키려는 선택이다. (2) 완료함은 처리됨 묶음처럼 작은 창 차례에 넣지 않고 열려 있으면 "완료한 진단"으로 보인다. (3) 완료한 진단은 7일 동안 오류 제목이 목록에 보여야 해서 `issue`를 지우지 않고, 7일 뒤에 비운다. (4) 진단 알림을 누르면 펼친 창이 열려 있을 때는 거기에, 아니면 작은 창에 그 진단을 연다. (5) 오류 정보 표 맨 끝에 `신규·재발`·`감지 시각` 줄을 더했다(스펙 11절 오류 이슈 정보).
- 이 티켓에 없는 것(뒤 티켓): [다시 진단 ▾]·[내보내기]와 "내보내지 않고 완료" 확인은 39·40번이다. 그 전까지 검토 대기의 [완료]는 확인 없이 바로 보고서를 지운다. 앞선 진단 표시(오류 이슈 정보)와 실린 MCP 서버(진단 정보)는 40·43번이 채우고, 첨부는 42번이 만들 때까지 첨부 탭이 빈 상태다(`DiagnosisSnapshot.attachments`는 지금 늘 비어 있다). 대기·진행 중 상세의 스택 앞부분은 37번 범위라 건드리지 않았다.
