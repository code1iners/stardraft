# 39: 내보내기

**Spec:** [스펙](../spec.md) 11절 "내보내기", "완료"의 확인, 12절 바닥 줄, 14절 "보고서를 내보낼 폴더"

**What to build:** 검토 대기인 진단 보고서를 마크다운 파일로 **내보낸다**. 내보내지 않고 완료하려 하면 확인을 받는다.

**Blocked by:** 38

**Status:** resolved

- [x] 검토 대기의 주 버튼이 [내보내기]다. 누르면 설정의 폴더에 `YYYY-MM-DD-<Sentry 프로젝트 이름>-<짧은 ID>.md`가 만들어지고(날짜는 감지한 날), 같은 이름이 있으면 `-2`, `-3`이 붙는다.
- [x] 파일의 순서가 제목 → 요약 → 재현 → 원인과 확신도 → 개선 방향 → 근거 → 남은 의문 → 오류 이슈 정보 → 실행 정보다. 재현이 실패·불가일 때만 "시도한 것"이 들어간다.
- [x] 첨부가 있으면 보고서와 같은 이름의 폴더에 복사되고 상대 링크로 걸린다.
- [x] 내보내면 토스트 "내보냈습니다: `<파일 이름>`"과 [폴더 열기]가 뜨고 상태는 바뀌지 않는다. 몇 번이든 할 수 있다.
- [x] 지금 보이는 보고서를 내보낸 적이 없으면 [완료]가 바닥 줄 확인("내보내지 않았습니다. 완료하면 이 보고서가 사라집니다.", [취소] · [내보내기] · [완료])을 거친다. 내보낸 적이 있으면 바로 완료된다.
- [x] 완료 최소 기록에 마지막으로 내보낸 파일 경로가 남고, `완료함`의 `기록`에 보인다.
- [x] Sentry 칸 맨 아래에 "보고서를 내보낼 폴더"가 있고(기본값은 사용자 문서 폴더 아래 `Stardraft/Reports/Sentry/`), [바꾸기…]와 [폴더 열기]가 된다. 토큰이 없어도 보인다.
- [x] 파일 이름, 번호 붙이기, 첨부 폴더, 확인의 기준이 임시 디렉터리에서 테스트된다.
- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.

## Comments

- 구현 메모: 내보내기는 `core/sentry/diagnosis-export.ts`(파일 이름·번호·첨부 복사·마크다운)와 `diagnosis-exports.ts`(`DiagnosisReportFolder` 설정, `DiagnosisExports` 흐름)다. 내보낸 기록은 진단의 `lastExport`(경로, 시각, 내보낸 보고서의 생성 시각)이고 `state.db` 27번 이전(`last_export` 열)으로 저장한다. "지금 보이는 보고서를 내보냈는지"는 `hasExportedCurrentReport`가 `lastExport.reportCreatedAt`과 `report.run.createdAt`을 비교해 정하므로, 다시 진단으로 보고서가 바뀌면 40번이 따로 지울 필요 없이 내보내지 않은 것이 된다. 폴더는 설정 `diagnosisReportFolder`(없으면 문서 폴더 아래 `Stardraft/Reports/Sentry`, 스키마 버전은 올리지 않음).
- 해석으로 정한 것: (1) 첨부는 앱 데이터의 진단별 폴더 안 파일을 그대로 복사한다(첨부 저장은 42번). (2) 보고서와 같은 이름의 폴더가 이미 있으면 그 번호를 건너뛴다. (3) 파일 이름 조각은 금지 글자를 `-`로 바꾸고 60자로 줄이며, 짧은 ID가 없으면 `issue-<오류 이슈 ID>`를 쓴다. (4) 확인 중 [내보내기]를 누르면 확인을 닫고 평소 줄로 돌아가 사용자가 다시 [완료]를 누른다. (5) 내보내기 실패는 토스트 "내보내지 못했습니다…"로 알린다. (6) 날짜는 PC 시간대 기준이다.
- 이 티켓에 없는 것(뒤 티켓): 오류 이슈 정보의 "앞선 진단"은 40번, 실행 정보의 "실린 MCP 서버와 빠진 서버·이유"는 43번이 채운다. [다시 진단 ▾]는 40번이다.
