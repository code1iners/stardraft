# 40: 다시 진단과 앞선 진단 참고

**Spec:** [스펙](../spec.md) 10절, 7절 "앞선 진단의 참고", 11절 "앞선 진단 표시", 12절 "지시 입력"

**What to build:** 검토 대기인 보고서를 지시 없이 또는 **지시**를 덧붙여 다시 진단한다. 새 보고서가 나오면 앞선 것을 바꾸고, 실패하거나 취소하면 앞선 보고서로 돌아간다. 재발한 오류 이슈의 새 진단은 앞선 진단을 참고하고 보고서에 표시한다. 이 티켓의 다시 진단은 읽기 전용으로 돌고, "재현도 다시 하기"는 42번이 더한다.

**Blocked by:** 38

**Status:** ready-for-agent

- [ ] [다시 진단 ▾]에 "다시 진단"과 "지시를 덧붙여 다시 진단"이 있고 `user` 칸에 선다.
- [ ] 지시 없이: 앞선 보고서를 넘기지 않고 쌓인 지시를 비운다. 지시를 덧붙여: 앞선 보고서(결과 스키마의 칸)와 쌓인 지시 전부를 넘긴다. 첨부는 넘기지 않는다. 이벤트 데이터는 새로 받는다.
- [ ] 지시 입력이 바닥 줄에서 펼쳐지고 스펙의 순서와 문구대로다.
- [ ] 다시 진단하는 동안 앞선 보고서와 첨부가 보관되고, 목록 태그는 `다시 진단 중`, 바닥 줄은 안내와 [취소]다. 내보내기와 완료는 할 수 없다.
- [ ] 성공하면 앞선 보고서와 첨부가 지워지고 새 것으로 바뀌며, 내보내지 않은 것으로 돌아간다. 준비됨 알림이 뜬다.
- [ ] 실패하거나 취소하면 진단 실패가 아니라 앞선 보고서의 검토 대기로 돌아가고, 알림 줄에 사유와 [다시 걸기]가 보인다. 쌓인 지시는 남는다.
- [ ] 다시 진단하는 동안의 재발은 새 진단을 만들지 않고 키만 기록된다.
- [ ] 검토 대기 중 재발로 만든 새 진단의 입력에 앞선 보고서의 요약·원인·개선 방향이 "참고일 뿐" 문구와 함께 들어가고, 새 보고서의 오류 이슈 정보에 앞선 진단이 있다고 적힌다.
- [ ] 완료한 뒤 재발한 진단의 입력에는 아무것도 넘어가지 않고, 오류 이슈 정보에 완료한 날짜와 마지막으로 내보낸 파일 경로가 적힌다. 파일이 없으면 날짜만 적힌다.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
