# 42: 재현하는 진단

**Spec:** [스펙](../spec.md) 7절(재현하는 진단의 경계, CLI별 구현, 재현하는 진단의 절차, 출력의 재현 기준과 첨부, 시뮬레이터 정리), 8절의 재현 하나 제한, 10절 "재현도 다시 하기", ADR 0003

**What to build:** 재현 허용이 켜진 저장소의 진단이 내 개발 환경의 사본에서 셸로 오류를 **재현**해 보고, 재현 결과와 첨부가 보고서에 실린다. 이 티켓은 MCP를 싣지 않는다(43번). 시간 상한은 묻지 않고 20분에 끊는다(44번이 연장을 더한다). 26번의 실측 결과에 맞춰 구현하고, 표와 다르게 구현해야 하면 멈추고 사용자에게 확인받는다.

**Blocked by:** 26, 29, 37, 41

**Status:** ready-for-agent

- [ ] 재현하는 진단은 원본 저장소를 APFS 복제한 사본(`.git` 제외, 의존성과 커밋하지 않은 변경 포함)에서 돈다. 사본의 `.env`는 재현용 환경 파일이고, 지정하지 않았으면 원본 `.env`다.
- [ ] 두 실행기가 재현 경계로 돈다. 사용자 설정은 끌어오지 않고, 셸과 사본 쓰기와 네트워크가 열리며, `.env` 계열 말고 다른 비밀 패턴과 저장소 밖 개인 비밀은 막힌다. 환경 변수는 최소 목록만 넘어간다. 실행기 어댑터 테스트가 이 인수 묶음을 검사한다.
- [ ] 지침에 재현하는 **진단 절차**(루프, 재현과 최소화, 가설, 계측, 사본 안 코드 고치기 허용, 시간 배분, 저장소 안내 문서 읽기, 운영 서버와 외부 도구 금지 문구)가 들어가고, 출력 스키마에 재현이 있다.
- [ ] 재현 결과(성공·실패·불가와 사유), 방법, 순서가 보고서에 실리고, 목록의 재현 태그와 준비됨 알림 본문에 반영된다.
- [ ] 첨부는 허용한 종류와 한도(10개, 20MB) 안의 것만 사본을 지우기 전에 진단별 폴더로 옮겨지고, 넘는 것은 "첨부 n개 생략"으로 적힌다. 첨부 탭과 내보내기에 보인다. 앱을 켤 때 표에 없는 첨부 폴더가 치워진다.
- [ ] 사본은 성공·실패·취소와 상관없이 지워지고, 앱을 켤 때 사본 폴더가 비워진다.
- [ ] 실행 전에 켜져 있던 시뮬레이터·에뮬레이터를 기록하고 실행 뒤 새로 켜진 것만 끈다. adb 서버는 그대로 둔다.
- [ ] 재현하는 진단은 한 번에 하나만 돈다. 다음 재현 진단은 프로세스 종료와 시뮬레이터 정리가 끝난 뒤에 시작하고, 그사이 읽기 전용 진단과 초안은 진행된다.
- [ ] 실행 정보에 재현 허용 여부가 적힌다. 재현 허용이 꺼진 저장소와 Windows의 진단은 37번의 읽기 전용 그대로다.
- [ ] 지시를 덧붙여 다시 진단할 때 "재현도 다시 하기" 체크가 보이고(기본값: 앞선 재현이 성공이면 끔), 끄면 읽기 전용으로 돌며 앞선 재현 칸과 첨부가 그대로 옮겨진다. 지시 없는 다시 진단은 항상 재현한다. 재현 허용이 꺼진 저장소에는 체크가 없다.
- [ ] 24번에서 받은 저장소로 재현하는 진단을 실제로 한 번 돌려, 사본이 만들어지고 지워지며 원본이 바뀌지 않았음을 확인했다.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
