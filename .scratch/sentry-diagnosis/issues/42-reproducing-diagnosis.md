# 42: 재현하는 진단

**Spec:** [스펙](../spec.md) 7절(재현하는 진단의 경계, CLI별 구현, 재현하는 진단의 절차, 출력의 재현 기준과 첨부, 시뮬레이터 정리), 8절의 재현 하나 제한, 10절 "재현도 다시 하기", ADR 0003

**What to build:** 재현 허용이 켜진 저장소의 진단이 내 개발 환경의 사본에서 셸로 오류를 **재현**해 보고, 재현 결과와 첨부가 보고서에 실린다. 이 티켓은 MCP를 싣지 않는다(43번). 시간 상한은 묻지 않고 20분에 끊는다(44번이 연장을 더한다). 26번의 실측 결과에 맞춰 구현하고, 표와 다르게 구현해야 하면 멈추고 사용자에게 확인받는다.

**Blocked by:** 26, 29, 37, 41

**Status:** resolved

- [x] 재현하는 진단은 원본 저장소를 APFS 복제한 사본(`.git` 제외, 의존성과 커밋하지 않은 변경 포함)에서 돈다. 사본의 `.env`는 재현용 환경 파일이고, 지정하지 않았으면 원본 `.env`다.
- [x] 두 실행기가 재현 경계로 돈다. 사용자 설정은 끌어오지 않고, 셸과 사본 쓰기와 네트워크가 열리며, `.env` 계열 말고 다른 비밀 패턴과 저장소 밖 개인 비밀은 막힌다. 환경 변수는 최소 목록만 넘어간다. 실행기 어댑터 테스트가 이 인수 묶음을 검사한다.
- [x] 지침에 재현하는 **진단 절차**(루프, 재현과 최소화, 가설, 계측, 사본 안 코드 고치기 허용, 시간 배분, 저장소 안내 문서 읽기, 운영 서버와 외부 도구 금지 문구)가 들어가고, 출력 스키마에 재현이 있다.
- [x] 재현 결과(성공·실패·불가와 사유), 방법, 순서가 보고서에 실리고, 목록의 재현 태그와 준비됨 알림 본문에 반영된다.
- [x] 첨부는 허용한 종류와 한도(10개, 20MB) 안의 것만 사본을 지우기 전에 진단별 폴더로 옮겨지고, 넘는 것은 "첨부 n개 생략"으로 적힌다. 첨부 탭과 내보내기에 보인다. 앱을 켤 때 표에 없는 첨부 폴더가 치워진다.
- [x] 사본은 성공·실패·취소와 상관없이 지워지고, 앱을 켤 때 사본 폴더가 비워진다.
- [x] 실행 전에 켜져 있던 시뮬레이터·에뮬레이터를 기록하고 실행 뒤 새로 켜진 것만 끈다. adb 서버는 그대로 둔다.
- [x] 재현하는 진단은 한 번에 하나만 돈다. 다음 재현 진단은 프로세스 종료와 시뮬레이터 정리가 끝난 뒤에 시작하고, 그사이 읽기 전용 진단과 초안은 진행된다.
- [x] 실행 정보에 재현 허용 여부가 적힌다. 재현 허용이 꺼진 저장소와 Windows의 진단은 37번의 읽기 전용 그대로다.
- [x] 지시를 덧붙여 다시 진단할 때 "재현도 다시 하기" 체크가 보이고(기본값: 앞선 재현이 성공이면 끔), 끄면 읽기 전용으로 돌며 앞선 재현 칸과 첨부가 그대로 옮겨진다. 지시 없는 다시 진단은 항상 재현한다. 재현 허용이 꺼진 저장소에는 체크가 없다.
- [x] 24번에서 받은 저장소로 재현하는 진단을 실제로 한 번 돌려, 사본이 만들어지고 지워지며 원본이 바뀌지 않았음을 확인했다.
- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.

## Comments

- 구현 메모
  - 실행기 포트 요청에 `reproduction`(`copyRoot` 사본 실제 경로, `sourceRoot` 원본 저장소)을 더했다. 있으면 두 실행기가 26번 조사 문서의 확정 형식으로 돈다.
  - Claude Code: 도구 `Read,Glob,Grep,Bash,Edit,Write`, `Bash`·`Edit`·`Write` 허용, 샌드박스(`failIfUnavailable`, `allowUnsandboxedCommands:false`, 모든 도메인과 localhost), `.env` 계열은 루트 전체 `denyRead`에 사본 `allowRead`, 다른 비밀 패턴은 사본·원본 경로로 좁힌 `Read(...)` deny다. 최소 환경 변수에 `NODE_USE_ENV_PROXY=1`과 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`(진단 시간 상한)를 더했다. 결과 메시지를 받으면 남은 프로세스(백그라운드 명령)를 끝내고 그 결과를 쓴다.
  - Codex: `:root` 읽기, 홈 아래 `.env` 계열과 개인 비밀 막기, 원본 경로의 비밀 패턴 막기, 사본(작업 루트)만 쓰기와 그 안의 비밀 패턴·`**/.git/**`·`**/.git` 막기, 네트워크 허용이다.
  - 두 실행기 모두 강제 종료 때 `ps`로 자손을 모아 그 프로세스 그룹을 먼저 끝낸 뒤 CLI 그룹을 끝낸다(`ProcessRequest.killDescendants`, 결정 ①). 이 처리로 43번 체크 항목 "Codex 자손 그룹 먼저 종료"도 이미 된다.
  - 사본: `core/reproduction/reproduction-copies.ts`. 맨 위 항목마다 `clonefile(2)`를 osascript(JXA `ObjC.bindFunction`)로 부른다(Node에는 폴더 복제 호출이 없음). 사본 폴더는 앱 데이터가 아니라 OS 임시 폴더 아래 `stardraft-reproduction/`다. 결정 ③("사본은 홈 밖에 둔다") 때문이고, 스펙 3절의 "앱 데이터 폴더 아래"와 다르다. 앱을 켤 때 비운다.
  - 시뮬레이터: `core/reproduction/simulators.ts`. iOS는 `simctl` 켜진 목록, Android는 에뮬레이터 콘솔 포트(5554~5584)로 실행 전후를 비교한다. 실행 전에는 adb를 부르지 않는다(꺼진 adb 서버를 켜게 됨). 새로 켜진 것만 `simctl shutdown`, `adb -s emulator-N emu kill`로 끈다.
  - 생성 대기열에 실행 정리 훅 `TargetRun.release`를 더했다. 저장·실패·취소·되돌림·앱 종료 어느 쪽이든 생성이 끝나면 정리를 부르고, 정리가 끝난 뒤에 재현 자원(`exclusiveResource` = `reproduction`)을 놓는다. 그래서 다음 재현 진단은 프로세스 종료와 시뮬레이터 정리가 끝난 뒤에 시작한다. 사본 삭제는 기다리지 않는다.
  - 첨부: 사본을 지우기 전에 `staging-*` 폴더로 옮겨 두고, `saveReport`가 앞선 첨부 폴더를 지운 **뒤에** 진단 폴더로 넣는다(40번이 넘긴 주의). 저장하지 못하면 버리고, 남은 것은 앱을 켤 때 표에 없는 폴더로 치워진다. 받는 것은 사본 안의 링크가 아닌 `png`·`jpg`(`jpeg`)·`log`·`txt`이고 비밀 패턴에 맞지 않아야 하며, 10개·합계 20MB까지다. 나머지는 생략 수로 센다. 보고서 JSON에 `attachments`(이름·크기)와 `omittedAttachments`를 둔다.
  - 재현도 다시 하기: 진단에 `keepReproduction`을 두었다(`state.db` 29번 이전 `keep_reproduction`). 렌더러 명령 `rediagnose-with-directive`에 `reproduce`를 더했다.
- 해석으로 정한 것
  1. 사본을 만들지 못하면(다른 볼륨, APFS 아님, 환경 파일 없음 등) 진단을 실패로 두지 않는다. 읽기 전용으로 진단하고 재현 칸은 앱이 "불가(환경 실패)"로 채운다. 스펙 7절 "기술적으로 안 되는 것은 … 재현 결과를 '불가'로 적는다"를 따른 것이다.
  2. 실행 정보의 "재현 허용"은 그 진단을 시작할 때의 저장소 설정이다. 재현을 끈 다시 진단도 저장소가 허용했으면 "허용"이다.
  3. 재현을 끈 다시 진단 사이에 저장소의 재현 허용을 껐으면 앞선 재현을 옮기지 않고 "불가(허용 안 됨)"로 채운다.
  4. 재현 여부는 대기열이 꺼낼 때(재현 자원을 쥘 때) 정한다. 준비하는 사이 설정이 바뀌어도 자원 없이 재현하지 않는다.
  5. 에이전트가 근거의 저장소를 사본 경로로 적으면 원본 경로로 고쳐 위치를 확인한다. 지침은 원래 코드의 줄 번호를 쓰게 한다.
  6. 일시적 실패로 다시 실행할 때는 새 사본을 만든다(앞 실행이 고친 사본을 쓰지 않는다). 시뮬레이터 기록은 첫 실행 전 것을 쓴다.
