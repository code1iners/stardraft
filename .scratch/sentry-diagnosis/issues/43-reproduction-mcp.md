# 43: 재현에 MCP 싣기

**Spec:** [스펙](../spec.md) 7절 "MCP 싣기", "CLI별 구현"의 MCP 줄, 11절 실행 정보

**What to build:** 재현하는 진단에 사용자가 에이전트에 등록해 둔 MCP 서버가 실려, 에이전트가 브라우저와 시뮬레이터를 직접 조작한다. 위험 도구는 고정 목록으로 막히고, `직접 선택`이면 켠 서버만 실린다.

**Blocked by:** 42

**Status:** ready-for-agent

- [ ] 재현하는 진단에만 MCP가 실린다. 읽기 전용 진단과 Flow 초안의 인수 묶음은 그대로다.
- [ ] 실행하는 CLI 자신의 정의만 실린다. Claude Code는 사용자·로컬·프로젝트 범위를 로컬 > 프로젝트 > 사용자 순서로 하나씩, Codex는 사용자 설정의 정의다. 사용자가 꺼 둔 서버, 플러그인 MCP, 커넥터는 실리지 않는다.
- [ ] 정의가 참조한 변수의 이름만 모아 로그인 셸에서 값을 읽어 실행 환경에 더한다. 값을 찾지 못한 서버는 빠진다.
- [ ] 정의에 평문으로 든 값이 명령줄 인자에 없다. Claude Code는 사본 밖 임시 파일(0600, 실행 뒤 삭제)로, Codex는 프로세스 환경과 환경 변수 참조로 넘어간다. 앱이 그 값을 디스크에 보관하지 않는다. 테스트가 이를 검사한다.
- [ ] 실은 서버마다 도구가 허용되고, 고정 deny 목록(스펙의 표)이 두 CLI에 걸린다. Codex는 사용자가 적어 둔 비활성 도구와 합쳐진다.
- [ ] `직접 선택`이면 켠 서버만 실리고 저장소의 프로젝트 정의 파일 서버는 실리지 않는다. deny 목록은 그대로 걸린다.
- [ ] 실을 서버가 없으면 Claude Code에 MCP 설정을 넘기지 않는다.
- [ ] Codex를 강제로 끝낼 때 CLI 그룹을 죽이기 직전에 자손의 프로세스 그룹을 먼저 끝낸다.
- [ ] 일부 서버가 뜨지 않아도 실행은 진행되고, 보고서의 실행 정보에 실린 서버와 빠진 서버·이유가 이름만 적힌다.
- [ ] 가짜 MCP 서버를 등록한 임시 설정으로 재현하는 진단을 실제로 한 번 돌려, 서버가 실리고 deny한 도구가 막히는 것을 확인했다.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.
