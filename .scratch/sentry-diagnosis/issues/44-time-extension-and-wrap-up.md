# 44: 시간 연장 묻기와 마무리

**Spec:** [스펙](../spec.md) 7절 "시간 상한과 연장", 9절 "진단 실패"의 [재현 없이 다시 시도], 12절 바닥 줄, 13절 연장 묻기

**What to build:** 재현하는 진단이 상한 5분 전에 계속할지 묻는다. 계속하면 10분씩 늘고, 멈추거나 답이 없으면 Claude Code는 그때까지 알아낸 것으로 보고서를 마무리한다. 시간 초과로 실패한 진단은 재현 없이 다시 돌릴 수 있다.

**Blocked by:** 38, 42

**Status:** resolved

- [x] 실행기 포트에 "실행 중 전달"이 선택 능력으로 있고, Claude Code 실행기가 스트림 입력으로 갖춘다. Codex 실행기는 갖추지 않는다. 대기열은 능력이 있는지만 본다.
- [x] 재현하는 진단만 상한 5분 전에 묻는다. 읽기 전용 진단과 Flow 초안은 묻지 않고 상한에서 끊긴다.
- [x] 묻는 동안 목록 태그에 `확인 필요`가 붙고, 노란 바닥 줄에 글과 [멈추기] · [계속 진행]이 보인다. 실행 중 전달이 안 되는 에이전트에서는 글의 둘째 문장이 "멈추거나 답이 없으면 보고서 없이 끝납니다."다.
- [x] OS 알림이 한 번 뜨고 버튼이 없으며, 누르면 그 진단이 열린다. 창이 강제로 앞에 뜨지 않고 트레이 수는 바뀌지 않는다.
- [x] [계속 진행]은 상한을 10분 늘리고 새 상한 5분 전에 다시 묻는다. 합계 60분이 되는 때에는 묻지 않고 60분에 [멈추기]처럼 처리한다. 전달이 되는 에이전트에게 "10분이 더 있다"가 간다.
- [x] [멈추기]: 전달이 되는 에이전트에게 마무리 메시지가 가고, 5분 안에 결과가 나오면 보통의 검토 대기 보고서가 되며, 안 나오면 끊고 진단 실패(시간 초과)가 된다. 그동안 바닥 줄은 "보고서를 마무리하는 중입니다. 5분 안에 끝납니다."다. 전달이 안 되는 에이전트는 바로 끊고 진단 실패(시간 초과)가 된다.
- [x] 답이 없으면 상한에 [멈추기]와 똑같이 처리된다.
- [x] 재현하던 진단이 시간 초과로 실패했으면 [재현 없이 다시 시도]가 보인다. 읽기 전용으로 돌고 그 보고서의 재현 칸은 "불가(시간 초과)"다.
- [x] 다시 진단에도 같은 규칙이 적용되고, 다시 켜서 처음부터 도는 실행은 상한을 처음부터 센다.
- [x] 가짜 시계와 가짜 실행기(전달 능력 켬·끔)로 위 갈래가 테스트된다.
- [x] `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과한다.

## Comments

- 구현 메모
  - 실행기 포트: `Executor.supportsSteering?`(선택 능력)와 요청의 `onSteerable`(보내는 함수를 받는 콜백). 대기열은 `supportsSteering === true`인지만 본다. Claude Code 실행기가 `--input-format stream-json`으로 표준 입력을 열어 두고 사용자 메시지 한 줄(JSON)로 보낸다(`ProcessRequest.onStdin`, `ProcessInput`을 프로세스 실행기에 더함). 결과를 받으면 입력을 닫는다. Codex 실행기는 갖추지 않는다.
  - 시간 규칙은 대기열이 센다. 어댑터가 요청에 `timeExtension`(처음 상한 20분, 10분씩, 합계 60분, 5분 전에 묻기, 마무리 5분, 두 메시지, `onAsk`)을 실으면 `core/generation/time-extension.ts`가 `clock`으로 15·25·35·45분에 묻고, 60분(합계)에서는 묻지 않고 [멈추기]처럼 처리한다. 실행기에는 `timeoutMs`를 가장 늦게 끊길 때(65분)로 넘기고, 앱이 끊은 실행이 취소로 돌아오면 시간 초과로 읽는다(사용자 [취소]·앱 종료는 그대로 취소).
  - 묻는 것은 사본을 만들어 재현 경계로 도는 진단뿐이다(다시 진단 포함). 읽기 전용 진단, 사본을 만들지 못해 읽기 전용이 된 실행, Flow 초안은 규칙이 없어 처음 상한에서 끊긴다.
  - 진행 스냅숏 `progress.extension`(`asking`·`wrapping-up`, `canSteer`)으로 화면이 `확인 필요` 태그, 노란 바닥 줄, 마무리 바닥 줄을 그린다. 새 명령 `continue-diagnosis`·`stop-diagnosis`·`retry-diagnosis-without-reproduction`.
  - 연장 알림은 `SentryDiagnoses.announceTimeExtension`이 띄운다(버튼 없음, 대상은 그 진단, 본문은 프로젝트 이름뿐). 트레이 수와 실패 표시는 바뀌지 않는다.
  - 재현하던 진단의 시간 초과: 진단 실패 사유에 `reproducing`을 남기고(어댑터가 사본으로 돈 실행만), `withoutReproduction`(`state.db` 30번 이전 `without_reproduction`)으로 [재현 없이 다시 시도]를 읽기 전용으로 돌리며 재현 칸은 "불가(시간 초과)"다. 실행이 끝나면 표시를 지운다.
- 해석으로 정한 것
  1. 연장 알림은 묻는 때마다 한 번이다(최대 15·25·35·45분 네 번). 스펙 "OS 알림 하나"를 묻기마다로 읽었다.
  2. 마무리 단계(멈추기, 답 없음)까지 간 실행이 구조 실패 같은 일시적 실패로 끝나면 다시 실행하지 않고 그대로 실패한다(다시 실행하면 상한을 새로 세기 때문). 리뷰에서 고쳤다.
  3. 다시 진단이 시간 초과로 실패해 앞선 보고서로 돌아올 때는 [재현 없이 다시 시도]를 더하지 않았다(알림 줄의 [다시 걸기]만 있다). 스펙이 진단 실패에만 두었다.
  4. 진단 실패(시간 초과) 문장을 "20분 안에"에서 "정해진 시간 안에"로 바꿨다(연장하면 20분을 넘길 수 있다). 재현하는 진단 지침의 시간 절도 연장 규칙에 맞게 고쳤다.
  5. 연장·마무리 메시지의 문구는 `diagnosis-run.ts`에 둔다.
- 리뷰에서 고친 것: 마무리 뒤 재시도(위 2), 판정 함수 `timedOutWhileReproducing`을 `sentry-diagnosis.ts`로, `TimeExtension`의 주석을 규칙 값에 묶이지 않게.
- 리뷰에서 남긴 것: 5분·10분 같은 값이 규칙 상수 밖의 문장(두 메시지, 지침, 화면 글, 알림 제목)에도 글자로 있다(정책값을 바꾸면 함께 고쳐야 함). `keepReproduction`·`withoutReproduction`을 다시 시도 방식 하나로 묶는 정리는 하지 않았다. 글로서리에 `연장`·`실행 중 전달`·`재현 없이 다시 시도`가 없다: 45번 문서 정리로 넘긴다.
