## Comments

### 2026-11-26 문서 정리 결과

코드는 바꾸지 않았다. 고친 문서: `spec.md`, `GLOSSARY.md`, ADR 0003·0004.

- **스펙**: 3절(재현 사본 위치), 4절(감지 중 403), 7절 "CLI별 구현" 표(비밀 파일·네트워크·환경 변수·강제 종료·백그라운드 대기), "실기 점검 목록" 전체(항목마다 확인함/확인 못 함과 까닭), "알려진 한계" 열한 줄 추가, "구현 중 스펙과 달라진 것" 절 신설(근거 티켓). 확인하지 못한 항목은 "확인 못 함"으로 남겼다: 429 응답의 한도 헤더, 지역이 다른 조직(해당 조직 없음), Codex 재현 실행·백그라운드 명령·승인 자동 허용(미구독), 원격 MCP OAuth 재사용, Windows 알림 클릭, 브라우저·시뮬레이터를 띄운 채의 Codex 정리, 화면 실기.
- **글로서리**: 구현된 동작과 어긋난 정의는 없었다. 빠졌던 `재현 사본`, `첨부`, `연장`, `실행 중 전달`, `재현 없이 다시 시도`를 더했다.
- **ADR**: 두 ADR 모두 결정 방향과 어긋나지 않는다. 0003은 상한 문구에 연장을 적고 "구현 뒤 확인"(사본 위치, Claude 강제 종료·네트워크, Codex 비밀 차단, 확인 못 함)을 붙였다. 0004는 33번이 넘긴 "계정 전환 때의 종류별 멈춤은 두 층과 다른 장치"와 37번의 어댑터 멈춤 범위를 붙였다. **사용자에게 알릴 것**: 사본 위치가 스펙 3절·ADR 맥락과 달라졌고(42번), 이 둘은 사용자가 확정한 26번 결정에서 이어진 것이다.
- **화면 문구 검색**: "프로바이더"와 없앤 개념(작업 폴더, 자동 선택)은 화면 문구에 없다. 코드 주석과 옛 저장값 처리 코드에만 남는다(`draft.ts`, `mention-bundles.ts`, `state-database.ts` 등, 폐지 설명용). "실행"은 일반 동사("실행할 수 없음", "소스 실행")와 `DraftsSection.tsx`의 "다음 실행부터 씁니다" 같은 문장에 남아 있다. 개발 용어로 보이는 곳은 이 한 문장 정도이고, 코드를 바꾸지 않는 티켓이라 손대지 않았다. 보고서 내보내기의 제목 "실행 정보"는 스펙 11절이 정한 것이다(화면은 "진단 정보").
- **처음 Flow 스펙의 고지 블록**: `.scratch/flow-mention-drafter/spec.md` 9행이 가리키는 "15절"이 Sentry 스펙의 "15. Flow 동작 변경"과 맞는다.
- **구현 티켓**: `issues/` 아래 45번을 뺀 모든 티켓이 `resolved`다.
