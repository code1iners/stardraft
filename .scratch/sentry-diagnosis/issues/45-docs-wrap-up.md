# 45: 문서 정리

**Spec:** [스펙](../spec.md) 추가 참고 전체

**What to build:** 구현과 실측에서 확인한 사실을 문서에 반영해, 스펙·글로서리·ADR이 실제 동작과 같은 말을 하게 한다. 코드는 바꾸지 않는다.

**Blocked by:** 33, 39, 40, 43, 44

**Status:** ready-for-agent

- [ ] 25·26번의 실측 결과로 스펙 7절의 "CLI별 구현" 표와 "실기 점검 목록", "알려진 한계"를 고쳤다. 확인하지 못한 항목은 그대로 "확인 못 함"으로 남겼다.
- [ ] 구현 중 사용자 확인을 받아 스펙과 달라진 결정이 있으면 스펙의 해당 절을 고치고 근거 티켓을 적었다.
- [ ] GLOSSARY의 정의가 구현된 동작과 맞는지 확인했고, 화면 문구에 "프로바이더"·"실행"이나 없앤 개념(작업 폴더, 자동 선택)이 남아 있지 않은지 저장소 전체를 검색해 확인했다.
- [ ] ADR 0003과 0004가 구현과 어긋나지 않는지 확인하고, 어긋나면 사용자에게 알렸다.
- [ ] 처음 Flow 스펙의 고지 블록이 가리키는 절 번호가 맞는지 확인했다.
- [ ] 사용자가 할 수동 통합 테스트에 쓸 수 있게, 이 지도의 `issues/` 아래 구현 티켓이 모두 `resolved`인지 확인했다.
