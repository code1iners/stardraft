# 재현 실행은 읽기 전용 원칙의 예외로, 내 개발 환경을 사본으로 그대로 쓴다

Stardraft의 에이전트 실행은 읽기 전용이다. Claude Code에는 `Read,Glob,Grep`만 주고 MCP와 사용자 설정을 막는다. Codex는 셸을 쓰되 권한 프로필로 쓰기·네트워크를 막는다. Sentry 진단에서 에이전트가 오류 이슈를 **재현**하려면 이 경계를 열어야 한다.

사용자가 저장소마다 `재현 허용`을 켜면, 그 저장소의 진단 실행은 다음 경계로 돈다(기본값은 지금과 같은 분석만).

- 원본 작업 폴더를 APFS 복제로 사본을 만들어 실행한다. `.git`만 빼고 의존성·커밋하지 않은 변경은 그대로 둔다. 쓰기는 사본에만 허용하고, 끝나면 사본을 지운다.
- 사본의 `.env`는 사용자가 지정한 **재현용 환경 파일**(없으면 원본 `.env`)이다. 그 값은 에이전트와 모델 제공자에게 노출될 수 있다. 나머지 비밀 패턴과 저장소 밖 개인 비밀은 계속 막는다.
- 셸 명령과 네트워크를 연다.
- 사용자가 Claude Code·Codex에 설정해 둔 **MCP 서버 정의만** 가져와, 에이전트가 웹·iOS·Android를 직접 조작하게 한다. 권한·훅·샌드박스·승인·모델은 앱이 정한다. 앱이 관리하는 위험 도구 deny 목록을 기본으로 적용하고, 사용자가 서버마다 켜고 끌 수 있다.
- 실행 한 번의 상한은 20분이고, 실행 중 새로 켜진 시뮬레이터·에뮬레이터만 끝에 끈다.

이렇게 정한 이유는 재현의 목적이 "이미 세팅된 개발 환경에서 개발자처럼 앱을 조작해 보는 것"이기 때문이다. 샌드박스에 가두면 의존성·`.env`·직접 조작이 모두 빠져, 웹·모바일 앱의 실제 재현이 대부분 "불가"가 된다.

## Considered Options

- **읽기 전용 유지**: 새 위험은 없지만 재현을 못 한다.
- **사본 쓰기 + 셸 + 네트워크 차단**(필요하면 패키지 저장소 도메인·localhost·시뮬레이터 XPC를 단계별로 염): 비밀과 유출 경로를 OS 수준에서 막는다. 그러나 `.git` 없는 사본에서 의존성을 다시 설치해야 하고, `.env`가 없어 API를 부르는 앱이 뜨지 않으며, 에이전트는 스크립트를 짜서 돌릴 뿐 화면을 보며 조작하지 못한다. Codex는 시뮬레이터 XPC를 열 설정이 없다.
- **전체 권한 + VM 격리**: 마찰은 가장 적지만 앱이 VM을 관리해야 하고, iOS 시뮬레이터는 VM으로 옮길 수 없다.
- **`.env` 제외, 실행 중인 앱만 비밀을 읽게 하기**: 샌드박스는 에이전트와 그 자식 프로세스에 똑같이 걸리므로, 앱만 읽고 에이전트는 못 읽게 나눌 수 없다.
- **앱이 고른 MCP만 싣기**: 외부로 글을 보내는 MCP가 섞이지 않지만, 사용자가 이미 세팅한 조작 도구를 앱이 다시 정해야 한다. 기본값 대신 `직접 선택` 모드로 남겼다.

## Consequences

- 재현을 켠 저장소에서는 재현용 환경 파일의 값이 모델 제공자로 전송될 수 있다. 화면에서 "운영 키를 넣지 말 것"을 안내하는 것 말고 막을 수단이 없다.
- 네트워크가 열려 있어서, 환경 파일이 운영 서버를 가리키면 재현이 운영 서버에 실제 요청을 보낸다. 지침 문구로만 금지하므로 강제력이 없다.
- MCP 서버는 두 CLI 모두 샌드박스 밖에서 사용자 권한으로 돈다. 사본 밖 쓰기 금지·비밀 차단은 셸 명령에만 걸리고 MCP 도구에는 걸리지 않는다. 기본 `자동` 모드에서는 Slack·Gmail·Flow 같은 MCP도 실려, 진단 중 외부로 글을 보낼 수 있다.
- 사용자 설정을 통째로 싣지 않고 MCP 정의만 골라야 한다. 권한 규칙·훅·Codex `sandbox_mode`가 섞이면 이 경계가 조용히 사라지므로, 실행기 테스트가 이 플래그 묶음을 지켜야 한다.
- 이 결정을 되돌려 샌드박스 방향으로 가면, 이미 재현을 켠 사용자에게 재현 범위가 줄어든다는 것을 알려야 한다.
