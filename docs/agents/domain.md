# 도메인 문서

엔지니어링 Skill이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 어떻게 읽는지 정한다.

## 탐색 전에 읽을 것

- 루트의 **`GLOSSARY.md`**
- **`docs/adr/`**: 작업할 영역과 관련된 ADR

이 파일들이 없으면 **조용히 진행한다**. 없다는 사실을 알리거나 미리 만들자고 제안하지 않는다. `/domain-modeling` Skill이 용어나 결정이 실제로 정리될 때 필요한 만큼 만든다.

## 파일 구조

이 저장소는 single-context 구조다.

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-<결정>.md
│   └── 0002-<결정>.md
└── src/
```

나중에 여러 컨텍스트로 나뉘면 루트에 `GLOSSARY-MAP.md`를 두고 컨텍스트마다 `GLOSSARY.md`와 `docs/adr/`를 둔다. 루트에 `GLOSSARY-MAP.md`가 있으면 그 맵을 먼저 읽고 주제와 관련된 `GLOSSARY.md`를 각각 읽는다.

## 글로서리 용어를 쓴다

출력물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름 등)에서 도메인 개념을 가리킬 때는 `GLOSSARY.md`에 정의된 용어를 쓴다. 글로서리가 `_Avoid_`로 표시한 동의어로 바꿔 쓰지 않는다.

필요한 개념이 글로서리에 없으면 신호로 받아들인다. 프로젝트가 쓰지 않는 말을 지어내고 있는지 다시 생각하거나, 실제 빈틈이라면 `/domain-modeling`에서 다룰 수 있게 기록해 둔다.

## ADR 충돌을 드러낸다

출력물이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 명시한다.

> _ADR-0007(<결정>)과 어긋나지만, … 이유로 다시 논의할 가치가 있다._
