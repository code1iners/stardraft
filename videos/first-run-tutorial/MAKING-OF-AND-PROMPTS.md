# Stardraft 튜토리얼 제작 방식과 프롬프트

이 문서는 이번 제작에서 실제 사용한 방식과 지시문을 기록한다. **실제 대화에서 사용한 요청**, **합의된 제작 조건**, **다시 제작할 때 쓸 수 있도록 사후 정리한 통합 프롬프트**를 구분했다.

## 1. 제작 결과와 기준

| 항목 | 실제 적용 내용 |
|---|---|
| 기준 코드 | `fcbad7a30d7ac958aa00a8106c340939c2900f7f` |
| 대상 | Flow와 Claude Code·Codex에 익숙하고 Stardraft는 처음인 개발자 |
| 목적 | 설치 후 설정부터 첫 초안 검토·게시까지 전체 흐름 이해 |
| 환경 | macOS |
| 길이·화질 | 150초, 1920×1080, 초당 30프레임 |
| 구성 | 장면 16개, 한국어 내레이션·자막 구간 31개 |
| 전달물 | MP4, SRT 자막, 편집 가능한 HyperFrames 소스 |
| 영상 성격 | 실제 앱 컴포넌트를 가상 데이터로 렌더링한 사용 예시 |

실제 사용자 계정·Flow 게시·에이전트 호출을 촬영하지 않았다. 인물, 프로젝트, 저장소, 답변은 가상 예제다. 앞서 수정한 개발 실행 오류 관련 미커밋 변경은 영상의 제품 동작 기준에 포함하지 않았다.

## 2. 실제 사용한 제작 방식

### 2.1 제품 흐름 조사와 브리프 확정

`GLOSSARY.md`, 온보딩·설정·검토 화면 컴포넌트, 관련 테스트와 스펙을 읽었다. 질문을 통해 대상, 목표, 길이, 운영체제, 시나리오, 화면 표현, 음성, 산출물을 확정했다.

특히 다음 제품 규칙을 영상에 반영했다.

- 감지를 시작해도 과거 멘션을 자동으로 가져오지 않는다.
- 새 업무의 직접 개인 멘션을 중심으로 설명한다.
- 코드 근거를 먼저 확인한 뒤 문장을 수정한다. 직접 편집하면 근거 번호가 숨겨진다.
- 게시 후 5초 동안 취소할 수 있다.
- ‘최근 멘션으로 시험’은 실제 에이전트 사용량을 쓰지만 Flow에 게시하지 않는다.

최종 방향은 **가상의 질문 한 건이 설정·감지·코드 근거·검토·게시로 이어지는 여정**이다. 설치와 macOS 보안 차단 해제, 에이전트 설치, 재생성·저장소 변경은 설명 범위에서 제외했다.

### 2.2 앱 화면 생성

[화면 생성 소스](source/screens.tsx)에서 실제 앱의 React 컴포넌트에 가상 상태를 전달했다.

- `renderToStaticMarkup`: 실제 컴포넌트를 정적 HTML로 렌더링.
- esbuild: 화면 생성용 TSX를 실행 가능한 Node.js 번들로 변환.
- Playwright: 독립 Chromium에서 화면을 열고 2배 해상도의 PNG로 촬영.
- 실제 앱의 `styles.css`와 트레이 이미지 사용.
- 연결 전·후, 연결 확인의 각 단계, 원래 초안·편집본, 게시 전 카운트다운 등 상태별 화면 생성.

[촬영 스크립트](source/capture-screens.mjs)가 생성한 PNG는 `assets/screens/`에 있다. 메뉴 막대와 Flow 질문·게시 결과는 HTML/CSS로 설명용 재현을 만들고 화면에 재현임을 표기했다.

### 2.3 모션 구성

HyperFrames **0.8.186**과 GSAP **3.14.2**를 사용했다. 에이전트가 브리프를 HTML/CSS/JavaScript와 Python 생성 스크립트로 구현하고, HyperFrames가 시간별 화면을 영상 프레임으로 렌더링했다.

- `index.html`: 150초 루트 타임라인, 장면 배치, 음성·음악·효과음.
- `compositions/*.html`: 장면별 편집 가능한 HTML과 정지 상태의 GSAP 타임라인.
- `assets/style.css`: 기존 앱 팔레트와 영상용 글자·배치.
- [생성 스크립트](source/build.py)의 `SCENES`: 장면 시간, 제목, 내레이션의 공통 원본.
- HyperFrames 레지스트리의 `oversized-cursor`: 화살표와 클릭 동작을 실제 버튼 좌표에 맞게 적용.

전체 앱 화면을 작게 유지하기보다 핵심 영역을 자르고 확대했다. 근거 장면에서는 답변의 ‘30분’과 파일 위치를 순서대로 크게 보여 준다. 최종 구현은 제목 58px, 화면 안내 글자 최소 28px, 자막 31px를 사용했다. `SPEC.md`의 초기 글자 크기 제안보다 최종 CSS와 검토 기록이 실제 출력에 가깝다.

### 2.4 한국어 내레이션과 자막

음성은 **macOS `say` 명령의 Yuna 한국어 음성**으로 문장별 생성했다. 외부 음성 생성 서비스나 유료 호출은 사용하지 않았다.

```bash
say -v Yuna -r 205 -o line.aiff '동료가 비밀번호 재설정 링크의 유효 시간을 물었습니다.'
ffmpeg -i line.aiff -ar 48000 -ac 1 line.wav
```

실제 스크립트는 31개 문장에 각각 적용한다. 음성 파일의 길이는 `ffprobe`로 측정했다. 장면 길이를 넘는 음성만 FFmpeg의 `atempo`로 압축하고, 측정된 길이에 따라 음성과 자막을 배치했다.

음성 입력에는 ‘플로우’, ‘에이피아이’, ‘삼십 분’처럼 발음하기 쉬운 표기를 사용했다. 화면 자막과 SRT는 ‘Flow’, ‘API’, ‘30분’으로 변환했다. 자막은 음성 입력 원문을 바탕으로 생성했으며, 음성을 다시 받아쓰기한 결과는 아니다.

### 2.5 음악·효과음·글꼴

- 배경음: Kevin MacLeod의 **Wallpaper**를 다운로드해 150초로 발췌하고 음량과 페이드를 조정했다. 별도 음악 생성 프롬프트는 사용하지 않았다.
- 효과음: HyperFrames `media-use`의 로컬 번들에서 `click-soft`, `notification`을 가져왔다.
- 글꼴: Noto Sans KR을 로컬 에셋으로 보존했다.
- 출처와 라이선스: [CREDITS.md](CREDITS.md). 음악 크레딧은 영상 마지막에도 표시했다.

### 2.6 검토와 최종 렌더

1. HyperFrames `check`로 린트·런타임·레이아웃·대비 검사.
2. 전체 장면의 시작·중간, 장면 경계, 휴대전화 폭 축소 이미지 검토.
3. 별도 리뷰 에이전트가 대본과 이미지로 가독성·이해 흐름 검토.
4. 에이전트 연결 진행, 상위 폴더 구조, 근거 확대를 보강.
5. 로컬 미리보기 개방 후 delivery 품질 MP4 렌더링.
6. `ffprobe`로 150초·1080p·30fps 확인. 완성 MP4의 99초와 119.5초 프레임을 디코딩해 확인.
7. 오디오 레벨 측정: 통합 음량 -14.68 LUFS, true peak -1.83 dBTP.

오류 0건을 확인했다. 설명을 읽기 위한 고정 구간과 같은 장면 안의 상태별 화면 수에 관한 경고는 검토 후 유지했다. 자동 모션 수치 감사는 기본 설정에서 비활성 상태였으며 프레임 검토로 보완했다. **전체 음성을 사람이 청취한 검수는 하지 않았다.** 자세한 기록은 [REVIEW.md](REVIEW.md)에 있다.

## 3. 실제 사용자가 입력한 제작 요청

### 최초 기획 요청 — 원문

```text
$grill-me
head 기준으로 최초 설치자가 이 앱을 어떻게 사용할 수 있는지 감을 잡기 위한 튜토리얼 목적으로 모션 그래픽 영상을 만들고 싶어. 작업에 필요한 내용들 질문해줘.
```

### 실제 제작 실행 요청 — 원문

```text
$hyperframes 최종 제작 브리프 참고해서 모션 그래픽 영상 만들어줘.
```

실제 작업은 이 요청과 앞선 합의, 활성 스킬의 지침을 함께 적용했다. 텍스트에서 영상을 생성하는 외부 모델에 하나의 장문 프롬프트를 보내는 과정은 없었다.

## 4. 재사용용 통합 프롬프트 — 사후 정리

아래는 당시의 요청과 합의를 다른 작업에서도 사용할 수 있게 합친 프롬프트다. **실제로 한 번에 입력했던 원문이 아니라, 제작 후 재구성한 버전**이다.

```text
$hyperframes

Stardraft 저장소의 커밋 fcbad7a30d7ac958aa00a8106c340939c2900f7f를 기준으로,
최초 설치자가 전체 사용 흐름을 이해할 수 있는 macOS 튜토리얼 모션 그래픽 영상을 만들어줘.

대상과 목적:
- Flow와 Claude Code 또는 Codex에 익숙하지만 Stardraft는 처음인 개발자.
- 설치 후 전달하는 사용 가이드.
- 영상을 보고 설정부터 초안 검토·게시까지 무엇을 하는 앱인지 감을 잡을 수 있어야 한다.

영상 사양:
- 약 2분 30초, 가로 1920×1080, 초당 30프레임.
- 차분하고 또렷한 한국어 합성 음성, 화면 자막과 별도 SRT.
- 낮은 배경음과 동작에 맞는 짧은 클릭·완료 효과음.
- 완성 MP4와 수정 가능한 HyperFrames 소스를 함께 제공.
- 유료 서비스 사용은 별도 합의 전 진행하지 않는다.

내용과 순서:
1. 가상의 동료가 ‘비밀번호 재설정 링크의 유효 시간이 얼마인가요?’라고 질문한다.
2. 메뉴 막대의 별 아이콘을 여는 장면에서 사용을 시작한다.
3. Flow 개인 API 키, 로그인된 로컬 에이전트, 로컬 코드 저장소를 준비물로 안내한다.
4. Flow 계정 확인, Claude Code 연결, 저장소가 모인 상위 작업 폴더 선택을 압축해 보여준다.
5. 감지 시작 이후 새 업무 멘션이 들어온다.
6. 관련 저장소에서 초안이 생성된다.
7. 원문과 에이전트가 이해한 요구, 초안을 비교한다.
8. 코드 근거 번호를 눌러 설명과 파일 위치를 확인한다.
9. 문장을 직접 수정하고 받는 사람을 확인한다.
10. 게시를 누른 뒤 5초 동안 취소할 수 있음을 보여준다.
11. 내 명의로 동료에게 답변이 게시되는 결과를 설명한다.
12. 마지막에 ‘최근 멘션으로 시험’으로 혼자 연습하는 방법을 안내한다.

제품 사실:
- 감지 시작 시 과거 멘션을 자동으로 가져오지 않는다.
- 새 업무의 직접 개인 멘션을 예제로 사용한다.
- 직접 편집하면 근거 번호가 숨겨지므로 근거 확인을 먼저 한다.
- 코드 근거 자체는 Flow 게시 본문에 포함되지 않는다.
- 시험은 실제 에이전트 사용량을 쓰지만 게시할 수 없고 ‘시험 끝내기’로 마친다.
- 실제 키·계정·회사 데이터·Flow 게시를 사용하지 않는다.
- 30분이라는 답은 가상 저장소의 예제 값으로 표시한다.

표현:
- HEAD의 실제 React 컴포넌트와 CSS를 가상 데이터로 렌더링해 앱 화면을 사용한다.
- 앱의 색상·구성과 버튼명을 유지한다.
- 확대, 커서, 클릭 강조, 장면 전환으로 무엇을 해야 하는지 보여준다.
- Flow → Stardraft → 로컬 저장소의 관계만 간단한 도형으로 보충한다.
- 메뉴 막대와 Flow 결과 재현은 설명용 예시임을 표시한다.
- 읽는 동안 글자는 고정하고, 작은 화면을 오래 띄우거나 장식 모션을 반복하지 않는다.
- 설치·보안 차단 해제, 에이전트 설치, 재생성·저장소 변경은 이번 영상에서 제외한다.

검증과 전달:
- 장면별 타이밍·대본·브리프·출처·검토 기록을 Markdown으로 남긴다.
- HyperFrames 검사 후 장면의 시작·중간·경계·축소 이미지를 확인해 수정한다.
- 완성 MP4의 길이·화질·프레임과 오디오 레벨을 확인한다.
- 실제 설치·게시 검증과 가상 시연을 구분하고, 청취 검수를 하지 못했다면 명시한다.
```

## 5. 실제 리뷰 에이전트 지시문

아래는 제작 중 별도 시각 리뷰에 전달한 지시문이다. 원문에서 절대 파일 경로만 `<프로젝트>`와 `<리뷰 이미지 폴더>`로 치환했다.

```text
한국어로 읽기 전용 영상 리뷰를 해 주세요.
<프로젝트>/STORYBOARD.md 와 <리뷰 이미지 폴더>/ 의
review-beats-1.jpg, review-beats-2.jpg, review-phone-1.jpg,
review-phone-2.jpg, review-seam-12.jpg만 읽어 보세요(view_image 사용).
초보 사용자의 이해를 깨는 P0, 흐름·가독성을 약화하는 P1만
```

## 6. 주요 실행 명령

프로젝트 위치는 `videos/first-run-tutorial/`이다. 최초 준비에 사용한 핵심 명령과 재실행 순서는 다음과 같다. 아래는 주요 명령의 정리이며 모든 탐색·수정 명령을 포함한 터미널 전문은 아니다.

```bash
# 저장소 루트에서 최초 프로젝트 생성
npx hyperframes usage --json
npx hyperframes init videos/first-run-tutorial

# 이후 프로젝트 폴더에서
cd videos/first-run-tutorial
npm ci
npx hyperframes browser ensure
npx hyperframes catalog --query 'agent cursor' --json
npx hyperframes add oversized-cursor --json

# 실제 앱 컴포넌트의 가상 화면과 영상 소스 생성
node source/capture-screens.mjs
python3 source/build.py

# 구조·레이아웃 검사와 장면 검토
npx hyperframes check --json
npx hyperframes snapshot --review --describe false --json
npx hyperframes preview --background --port 3017

# 최종 렌더와 출력 검사
npx hyperframes render --quality delivery --fps 30 --output renders/stardraft-first-use.mp4
ffprobe -v error -show_entries format=duration:stream=codec_name,width,height,r_frame_rate -of json renders/stardraft-first-use.mp4
npx hyperframes audio renders/stardraft-first-use.mp4 --json
```

프로젝트의 `npm run dev`, `npm run check`, `npm run render`는 HyperFrames 0.8.186을 고정해서 호출한다. 실제 화면 재생성에는 저장소의 앱 의존성도 필요하고, 새 음성을 생성할 때는 Yuna 음성이 설치된 macOS가 필요하다. 완성된 에셋을 사용하는 영상 편집·렌더에는 실제 Flow 계정이 필요하지 않다.

## 7. 실제 음성 생성에 넣은 문장

각 문장은 `say -v Yuna -r 205`에 전달한 음성 입력이다. 전체 대본은 [STORYBOARD.md](STORYBOARD.md), 표시용 자막은 [SRT](stardraft-tutorial.ko.srt)를 참고한다.

### 0–10초 · 이 멘션, 코드에서 답을 찾으려면

```text
동료가 비밀번호 재설정 링크의 유효 시간을 물었습니다.
스타드래프트에서 코드에 근거한 초안을 만들고, 직접 검토해 게시해 보겠습니다.
```

### 10–18초 · 메뉴 막대의 별에서 시작합니다

```text
설치한 앱을 켜고, 맥 메뉴 막대의 별 아이콘을 누릅니다.
설정 열기에서 처음 필요한 세 가지를 연결합니다.
```

### 18–26초 · 준비할 것은 세 가지입니다

```text
플로우 개인 에이피아이 키, 로그인된 로컬 에이전트, 그리고 코드 저장소가 필요합니다.
키 발급과 에이전트 설치는 미리 마쳐 주세요.
```

### 26–34초 · 내 Flow 계정을 확인합니다

```text
플로우 계정에 내 개인 키를 붙여 넣고, 확인을 누릅니다.
연결된 이름과 소속이 내 계정인지 확인하세요.
```

### 34–42초 · 로그인된 Claude Code를 연결합니다

```text
에이전트에서는 찾기, 버전, 로그인, 작동 확인이 진행됩니다.
작동 확인은 실제 사용량을 조금 씁니다. 코덱스도 선택할 수 있습니다.
```

### 42–50초 · 저장소가 모인 작업 폴더를 고릅니다

```text
저장소에서 폴더 추가를 누르고, 코드 저장소가 모인 상위 폴더를 고릅니다.
연결이 없는 멘션은 여기서 찾은 저장소를 바탕으로 처리합니다.
```

### 50–60초 · 이제 새 멘션을 기다립니다

```text
필수 설정을 마쳤다면 감지 시작을 누릅니다.
이때부터 새 업무 멘션을 감지합니다. 과거 멘션을 자동으로 가져오지는 않습니다.
```

### 60–70초 · 동료가 새 업무 멘션을 보냅니다

```text
동료가 업무 댓글에서 나를 직접 지목해 질문합니다.
채팅이나 담당자 지정이 아닌, 나를 직접 지목한 새 업무 멘션이 대상입니다.
```

### 70–80초 · 관련 저장소에서 초안을 만듭니다

```text
연결된 저장소가 없으면 작업 폴더에서 적절한 저장소를 고릅니다.
로컬 에이전트가 관련 코드를 읽고, 멘션에 답할 초안을 만듭니다.
```

### 80–90초 · 초안이 나오면, 먼저 읽어 봅니다

```text
알림이나 별 아이콘의 숫자로 초안이 준비된 것을 알 수 있습니다.
열린 화면에서 원문과 에이전트가 이해한 요구, 답변 초안을 비교합니다.
```

### 90–102초 · 근거 번호로 답의 출처를 확인합니다

```text
초안 문장 옆의 근거 번호를 누르면, 설명과 파일 위치를 확인할 수 있습니다.
이 예제에서는 링크가 삼십 분 동안 유효하다는 코드 근거를 확인합니다.
```

### 102–114초 · 내가 보낼 문장으로 다듬습니다

```text
문장을 눌러 동료에게 보낼 표현으로 직접 수정하고, 받는 사람도 확인합니다.
편집하면 초안의 근거 번호는 숨겨집니다. 근거 확인을 먼저 마쳐 두세요.
```

### 114–125초 · 게시 전, 마지막으로 확인합니다

```text
내용이 맞으면 게시를 누릅니다.
오 초 동안은 취소할 수 있습니다. 시간이 지나면 내 이름으로 플로우에 게시됩니다.
```

### 125–130초 · 동료에게 내 답변이 도착합니다

```text
게시되는 것은 답변 본문이며, 코드 근거는 포함되지 않습니다.
```

### 130–142초 · 혼자라면, 최근 멘션으로 시험합니다

```text
새 멘션을 기다리지 않고 연습하려면, 최근 멘션으로 시험을 누르세요.
실제 에이전트 사용량은 쓰지만 플로우에는 게시하지 않습니다. 시험 끝내기로 마칩니다.
```

### 142–150초 · 근거를 확인하고, 내 답변으로 게시하세요

```text
설정을 마치고, 근거를 확인하고, 내 답변으로 다듬어 게시하세요.
지금은 최근 멘션으로 시험부터 시작해 보세요.
```
